# 004 编写 ling 需求规格

> 日期：2026-10-27
> 涉及文档：`docs/ling/01-需求规格.md`、`docs/ling/brief/01-需求规格.md`、`docs/ling/00-总览与术语.md`、`README.md`

## 发生了什么

ling 的第二份设计文档 `01-需求规格` 起草完成，详细版与简版同时产出。共 115 条需求：功能需求 88 条（十组），非功能需求 27 条（五组）。

## 为什么这么定

| 决定 | 理由 |
|---|---|
| 需求不标 MVP 优先级、不标实现阶段 | 用户明确：MVP 只作为里程碑的一部分，与项目需求本身关联不大，独立于需求之外 |
| 非功能需求给具体数字 | 用户明确：一开始就要算数字，用于可行性报告 |
| 需求按机制分十组，不按界面流程分 | 宿主没有界面，功能全部是机制；按流程分会让同一条需求出现在多处 |
| 功能需求全部带验收标准列 | 规范 §6.1 要求每条能判断真伪；写不出的不写进需求 |

## 数字从哪来

| 区间 | 来源 |
|---|---|
| 089–093（调用延迟、广播、装载、图重算、侧车往返） | 沿用 old 设计文档的性能预算，未重新取值 |
| 094–102、104–107（启动、命令耗时、内存、CPU、账本上限、并发、长稳） | 本轮设定，无实测依据，标为设计目标 |

可行性报告引用时必须注明"设计目标"，实测数据出来后补对照表，不删目标数字。

## 顺带修掉的两处矛盾

| 位置 | 问题 | 处理 |
|---|---|---|
| `README.md` 非目标 | 写着"不支持移动端"，与已定的多平台目标（Windows / Linux / Android）直接冲突 | 从非目标删除，并把多平台写进目标行 |
| `docs/ling/01-需求规格.md` §6 | 引用了 `00-总览与术语.md §5` 的文档地图，实际文档地图不在 §5 | 改为引用「ling 文档地图」章节名 |

## 留下的未决问题

六个，写在 01 的 §7.1：新错误码 `E_PAYLOAD_TOO_LARGE` 是否采纳、Android 降级细节、性能数字的使用口径、账本条目上限、长稳测试是否进常规验收、Android 是否保留管理端口。

| 检查项 | 结论 |

| 编号唯一且连续 | 115 条，001–115 无缺号、无重号 |
