## 四、MVP 期间与完整口径的偏差

这些是 `11` §3.2 已经允许的缩范围，逐条记下实际做到哪：

| 条目 | 完整要求 | MVP 实际 |
|---|---|---|
| 071 | 13 个子命令 | 10 个（无 `reload`、`restart`、`doctor`） |
| 079 | 五件套预装 | 三件：`core-settings`、`core-plugin-manager`、`core-log` |
| 081 | 五个可卸 | 三个可卸且卸后能启动；用户卸过的内置插件升级时不装回（`registry.json` 的 `removed_builtins`） |
| 095 | 20 插件含 2 侧车 | 未测，无侧车 |
| 109 | 四个超时 | 只有方法调用 30 秒与订阅者 5 秒告警；两者在 MVP 都是「事后记账」，不是强制切断 |
| 113 | 三平台 | 只有 Windows x64 实测 |
| 118 | 六类日志 | 六类都有，但「调和的每一步」只有装载与卸载两步 |
| 122 | trace id 三处 | 两处（宿主内调用、命令帧） |

另外三处实现与文档的偏差，已在对应文档里写明：

1. `04/06` §4.1 说 `kernel.*` 方法「走同一条调用路由」，实现上是 `Kernel::handle_kernel` 里的分发，不经 `Router`。对外语义一致，内部实现更简单。
2. `04/02` §4.1 的事件回调原本只有 `(ctx, payload, len)`，拿不到主题，已改成 `(ctx, topic, payload, len)`。
3. `04/01` §6.1 原本要求订阅主题「以自己编号开头或非 `kernel.`」，这与「插件要订阅内核事件」直接矛盾，已改为只管形状。

## 六、MVP 交付后能做什么、不能做什么

能：起一个宿主，装自己写的 C++ 插件，让插件之间互相调用与广播事件，看插件日志，干净卸载（保留或删除数据）。

不能：用 Python 写插件、改插件不重启、依赖声明与自动调和、图形界面、Android。这五项按 `10-路线图与里程碑.md` 分别在 M3、M3、M3、M5、M6。
