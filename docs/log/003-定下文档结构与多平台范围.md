# 003 定下 ling 文档结构与多平台范围

> 日期：2026-10-27
> 类型：结构决策

## 发生了什么

上一轮遗留的两件事有结论：文档编号方案、平台范围。同时确定 MVP 单独成文。

## 定了什么

| 事项 | 结论 |
|---|---|
| 编号方案 | 折中：顶层按软件工程序列 00–09，`03-详细设计` 拆成 7 份子文档，`08` 运行时预案、`09` 路线图顺延 |
| 拆出的子文档 | 内核四服务、插件装载与接口、上下文与效应账本、依赖解析与调和、热更新、管理端口与命令行、内置插件 |
| old 内容归属 | old 的 01（417 行）拆进 02、03/01、03/02、03/04、05 五处；old 的 07 拆成 06 测试与 09 路线图 |
| 引用格式 | 一律完整路径加章节号，不用 03.01 简称 |
| 平台范围 | 多平台是目标：Windows 主要平台、Linux 对齐、Android 受限降级 |
| MVP | 单独一份 `10-MVP范围.md`，定型后再并入 09 路线图 |
| `.gitkeep` | 暂不删，等目录内有真实文件再清 |

## 为什么

- 纯主题编号（old 的做法）看不出文档处于软件工程的哪一段；纯软件工程编号又会让详细设计膨胀成一份巨文。顶层给软件工程、下层按子系统拆，两头都照顾到。
- 多平台影响插件产物格式与装载逻辑，必须在架构设计之前定，不能留到后面再补。
- MVP 要反复讨论范围，单独成文比塞进路线图好改。

## 影响

- `docs/ling/00-总览与术语.md`：目标增加"多平台"，新增 §2.4 平台、§2.5 规模参照（原 2.4 顺延），新增"ling 文档地图"表
- `docs/common/00-文档编写规范.md`：新增 §5.1 允许拆子目录、§5.2 引用格式，原 §5.1 顺延为 §5.3
- 简要版同步更新，标题与详细版逐条对应
