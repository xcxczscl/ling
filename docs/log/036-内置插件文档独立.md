# log 036 内置插件文档独立与构建解耦

> 日期：2026-10-31
> 触发：使用者要求把内置插件的文档与代码都拆开，ling 那边只留引用

## 一、为什么拆

原来的问题：五个内置插件的说明全挤在 `docs/ling/04-详细设计/07-内置插件.md` 一份里，`core-ui` 一动笔就是几千行；代码虽然已经在 `main/builtin-plugins/<插件名>/`，但构建声明集中在 `plugins/CMakeLists.txt`，加一个插件要改外面的文件。

拆开之后各管各的：

```
docs/ling/builtin-plugins/
  core-log/
    00-总览与边界.md
    01-需求与用例.md
    02-设计与接口.md
  brief/core-log/            同结构简版
  core-settings/             待迁移
  core-plugin-manager/       待迁移
  core-job/                  待编写
  core-ui/                   待编写

main/builtin-plugins/
  CMakeLists.txt             只负责串起来
  core-log/
    CMakeLists.txt           一行业务声明
    main.cpp
    plugin.toml
```

`04/07` 保留「内置插件总览」的职责（五个插件一览、无特权、卸载矩阵、预装规则、源码位置），每个插件的细节改成指向新目录的引用。

## 二、三个文件的边界

| 文件 | 回答什么 | 不写什么 |
|---|---|---|
| `00-总览与边界` | 它是什么、不做什么、和别的组件怎么分、没装它时怎样 | 方法签名、代码细节 |
| `01-需求与用例` | 什么场景用它、要成什么样、怎么判对错、本期明确不做什么 | 实现方式 |
| `02-设计与接口` | 方法参数与返回、数据放哪、失败怎么处理、并发与规模、代码位置 | 需求从哪来 |

拆三份而不是一份，是因为 `core-ui` 那种体量写成单文件会翻不动；拆更细又是负担。这条界线以 `core-log` 为样板定下来，后面四个照此办理。

## 三、core-log 作为样板顺带修的四处

写文档时对照代码，发现四处文档要求与实现不符，一并改掉：

| 问题 | 原状 | 现状 |
|---|---|---|
| `tail` 读大文件 | 把整个文件读进内存再取末 N 行 | 从文件尾按 64 KB 块往前读，凑够行数即停。56 MB 文件实测 92 毫秒（含进程启动） |
| `query` 的内存 | 先全部读进 `vector` 再过滤 | 逐行读、命中的才留，内存只与命中行数有关 |
| 单行长度无上限 | 插件写一行 100 MB 直接落盘 | 截断到 8 KB，并在行尾注明原长 |
| `message` 缺省 | 缺了按空串写，产生只有时间戳的空行 | 缺 `message` 直接返回错误码 |

写盘失败的处理也改了：原来静默返回成功，现在往 stderr 留一句。**返回成功这条不变**——日志写不进去不该让业务失败，但「没写进去」这件事本身得有人知道。

## 四、构建解耦

每个插件目录自带 `CMakeLists.txt`：

```cmake
add_ling_plugin(core-log "${CMAKE_CURRENT_SOURCE_DIR}")
```

`plugins/CMakeLists.txt` 与 `main/builtin-plugins/CMakeLists.txt` 只剩 `add_subdirectory`。加一个插件只要在自己的目录写这一行、在上层加一个 `add_subdirectory`，`LingPlugin.cmake` 里的路径拼接逻辑不用改。

## 五、一个环境坑

删掉 `run/build/win-release` 重新配置时配置失败，报：

```
RC Pass 1: command "rc /fo .../manifest.res ..." failed
no such file or directory
CMAKE_MT-NOTFOUND
```

看着像编译器坏了，实际是 `rc.exe` 不在 PATH。它和 `cl.exe` 不在同一目录，在 `Windows Kits\10\bin\<SDK 版本>\x64`。增量构建用不到它，所以这个坑平时藏着，只在全量重配时出现。已写进 `docs/ling/05-构造与开发指南.md` §7.1。
