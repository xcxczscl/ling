# 012 内存安全、崩溃分类与术语补齐

> 2026-10-28

## 起因

四件事同时提出：

1. 用 C++ 写要注意安全，用现代特性防内存不安全。
2. 问「进程内插件崩溃一定会导致内核崩溃吗」。
3. Python 侧车的消耗不必大改文档，在插件规范里提一句即可；侧车相关条款可能要调。
4. 侧车没在术语表里，其他词也是。

## 做了什么

### 一、`docs/ling/02-技术选型.md` 新增 §8.4「内存安全靠机制，不靠小心」

写法层七条：所有权用 `unique_ptr` 表达、容器代替裸数组、不做指针算术、`string_view` 只作入参、边界只传指针加长度、定宽整数、所有权不跨边界移交。

工具层四项：编译器警告全开并视为错误、每轮测试跑 ASan 与 UBSan、提交前跑 `clang-tidy`、边界函数做负向测试。

同时 §8.1 禁用清单补三行：裸 `new`/`delete`、C 风格数组与指针算术、`reinterpret_cast`。

要点：这些配置由构建脚本统一提供，**不配就编不过**，不靠人记。

### 二、§5.5 由「崩溃一定拖垮宿主」改为按故障分类

原来的写法是粗的，把「插件崩溃」当成一件事。实际分五类，结论不同：

| 故障 | Windows | Linux 与 Android |
|---|---|---|
| 同步异常 | 能捕获并隔离该插件 | 只能退出进程 |
| 栈溢出 | 不能 | 不能 |
| 堆破坏 | 不能 | 不能 |
| 死循环、死锁 | 超时切断，宿主继续 | 同左 |
| 写坏宿主共享结构 | 无检测手段 | 同左 |

同时写明一条区分：**能挡住不等于能恢复**。恢复只意味着标记该插件故障、拒绝后续调用、撤销其效应，不是修复后继续正常跑。

### 三、侧车内存约束

`docs/ling/02-技术选型.md` §3.4 与 §4.5.3 各补一段：一个空载 Python 侧车 25–40 MB，五个就超过 LING-REQ-099 的 120 MB 预算，所以侧车默认按需启停。常驻数量的判定规则归插件规范（`docs/ling/04-详细设计/02-插件装载与接口.md`），本文只说明约束存在。

按用户意见，不在本文定具体上限，也不改 01 的 099。

### 四、构建版本改为构建时确定

§6.1 的「最新稳定版」删掉，改为「工具与依赖的具体版本在构建时固定」，并写明：编译器小版本、CMake、vcpkg 基线、Python 运行时、NDK 版本写入 `docs/ling/05-构造与开发指南.md`，同时提交锁文件。理由：写「最新稳定版」等于没写，不同时间构建会得到不同依赖。

### 五、术语补齐

`docs/common/01-术语表.md` 原来是空的，而 `docs/ling/00-总览与术语.md` §5.1 早就声称宿主、插件、能力、事件、侧车、上下文、热更新这七个词登记在那里。已登记 13 个公共术语：插件、侧车、错误码、方法、轨道、进程内插件、内置插件、能力、热更新、上下文、事件、宿主、载荷。

`docs/ling/00-总览与术语.md` 补 ling 专属词 6 个：§5.4 加「调和」「拓扑序」，新增 §5.7「与运行管理相关」放能力门禁、管理端口、命令帧、数据根、内核事件。
