# log 041 界面服务端与受限代理

> 日期：2026-10-31
> 关联：`docs/ling/builtin-plugins/core-ui/02-服务端与接口.md`、`docs/ling/04-详细设计/06-管理端口与命令行.md` §4.5

## 1. 起点：`core-ui` 装不进去

动手前先确认了现状，结论比预想的直接：**侧车轨道根本不存在**。

- `main/src/manifest.cpp` 里 `kMvpRejectSidecar = true`，带 `[sidecar]` 段的插件在清单校验阶段就被拒；
- `Kernel::activate` 只做 `LoadLibrary`，没有「起子进程、传环境变量、读就绪行」的任何代码；
- `04/02` §8 定的侧车帧协议（`hello` / `activate` / `invoke` …）一行没实现。

所以 `core-ui` 作为插件现在不可能被装载。侧车轨道是 M4 的活（`11-MVP 范围.md` §4.1），不是这一轮该顺手做掉的。

**决定**：把它的服务端先做成独立可执行文件 `ling-ui`。理由是服务端不依赖侧车轨道——它本来就是一个独立 HTTP 进程，连的是管理端口而不是内核。侧车打通后，把这个 exe 装进插件目录、清单里加 `[sidecar]` 段即可，代码不用重写。

## 2. 第二道坎：管理端口只放行 `kernel.*`

按 `04/06` §3.4，管理端口收到非 `kernel.*` 的方法一律 `E_NAMESPACE_VIOLATION`。但界面的十三个动作里有七个转的是插件方法：

| 动作 | 方法 | 被挡 |
|---|---|---|
| `config.list/get/set` | `core-settings.*` | 是 |
| `jobs.list/schedule/cancel` | `core-job.*` | 是 |
| `orphans` | `core-plugin-manager.orphans` | 是 |

也就是说，不做处理的话，界面改不了配置、建不了任务——而这正是界面最该干的两件事。同一个缺口也解释了之前那个问题：**命令行为什么没有 `ling job add`**。

**加了 `kernel.call` 受限代理**，按前缀白名单只放开这三个插件的管理类方法：

```json
{"op":"call","method":"kernel.call",
 "args":{"method":"core-settings.write","args":{"plugin":"demo-a","key":"demo-a.timeout","value":30}}}
```

为什么这不违背 §3.4 的原意：那条要挡的是「插件借管理端口调别的插件」，绕过能力校验与调用归属。`kernel.call` 走同一张路由表、同一套参数校验，只是入口变成「本机持有口令的人」；白名单把范围压在管理动作上，业务插件的方法一个都不放（`demo-a.ping` 实测被拒）。能拿到口令的人本来就能 `install` 任意插件，开放这三个前缀不增加能力边界。

**留下的不足**（已写进文档）：`core-settings.write` 的 `plugin` 字段在 `Context` 路径上由内核填死，走 `kernel.call` 时只能靠调用方自填。界面这一侧按键名前缀反推插件名，不采信请求体；脚本直调 `kernel.call` 时没有这层保护。根治要给 `kernel.call` 带上「以谁的身份调」，那是 M3 插件身份的活。

## 3. 做出来的东西

| 文件 | 内容 |
|---|---|
| `main/include/ling/ui_server.hpp` | 界面服务端接口 |
| `main/src/ui_server.cpp` | 单线程 select 轮询、HTTP 解析、口令校验、十三个动作的转发表、占位页 |
| `main/ui/main.cpp` | 入口：读环境变量或 `--data-dir`、自检、写 `ui_port`、就绪行、宿主退出后自行收尾 |
| `main/CMakeLists.txt` | 新目标 `ling-ui`（服务端代码放进 `ling_core`，将来侧车也复用它） |

几条实现上的取舍：

- **每个动作都走管理端口**，包括 `plugins`。界面不直连内核，这样界面与命令行的行为、错误文案不会分叉。
- **`Connection: close`**，不做长连接。请求量是「人点一下」，省掉连接状态机更划算。
- **口令比较不提前返回**，逐字符累积差异。
- **占位页也要口令**。拿到地址不等于有权看这台机器装了哪些插件。
- **响应带 `X-Content-Type-Options: nosniff`**，页面不引任何外部资源。
- **`kernel.call` 之外没有第二条路**：界面没有「直接调插件」的口子。

顺带两处修正：

1. `AdminReply` 加了 `kTimeout`。原来「宿主忙到不应答」和「宿主断了」都归到 `kProtocol`，而它们给使用者的下一步完全不同（等一等 / 重启宿主）。`read_line` 现在按 `WSAETIMEDOUT` 与 `EAGAIN` 区分，界面据此回 504。
2. `Kernel::save_registry` 重写 `registry.json` 时保留 `ui_port`。那个字段是界面进程写的，内核不持有；不保留的话，任何一次插件状态变化都会把它抹掉。另外 `serve` 启动时调 `clear_stale_ui_port`，清掉上一次界面被强杀后留下的陈旧端口。
