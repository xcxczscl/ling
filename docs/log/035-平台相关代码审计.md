# log 035 平台相关代码审计

> 日期：2026-10-31
> 触发：使用者问「现在的代码和平台没有强绑定吧」，并要求有绑定的地方点名

## 一、结论

**没有硬绑定。** 平台差异全部收在 `#ifdef _WIN32` 里，业务逻辑（清单校验、路由、账本、事件、装载流程）不含任何平台判断，换平台只需要补那几段分支。

但有三件事要说清楚：

1. **Linux 分支写了，从没编译过。** 从 S0 到现在所有构建都在 Windows 上跑，`#else` 那半边是「照 POSIX 写的」，不是「验证过的」。
2. **还有一处真缺口**：Linux 上 Ctrl+C 没有处理，进程会被直接杀掉，`session.json` 留在磁盘上。本次已补。
3. **还有一处小 bug**：`--help` 里的默认数据目录写死了 `%APPDATA%\ling`，在 Linux 上显示错误。本次已补。

## 三、Windows 上存在、其他平台没有的行为

这三条不是 bug，是「Windows 这边先做了」：

| 行为 | Windows | Linux | Android |
|---|---|---|---|
| 控制台中文 | 切换代码页到 65001 | 由 locale 决定，程序不管 | 无控制台 |
| Ctrl+C 收尾 | 控制台回调 | **本次补的信号处理** | 无 |
| `session.json` 权限 | 还没收紧 ACL（已知不足，见 log 031） | 可设 `0600` | 未实现 |

## 四、真要上 Linux 之前必须做的

按风险从高到低：

1. **在 Linux 上完整构建一次**，把 `-Wall -Wextra -Wpedantic -Werror` 下暴露的问题修掉。`#else` 分支没编译过，几乎肯定有几处类型与头文件的毛病。
2. **跑一遍验收脚本**。脚本用的是 Python 与命令行，跨平台没问题，但 `--preset linux-release` 的产物路径要核对。
3. **核对 `dlopen` 的产物名**。Windows 找 `<插件名>.dll`，Linux 找 `lib<插件名>.so`，装载器的查找规则要按平台分支。
4. **`session.json` 设 `0600`**。Linux 上这条比 Windows 简单，顺手做掉。

Android 更远：它的沙箱不允许随便 `dlopen` 应用私有目录以外的库，插件装载路径要重新设计。`docs/ling/02-技术选型.md` 已把 Android 定为「受限降级」，等真正要做时再单独议。
