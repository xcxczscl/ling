# 010 内核日志内置，与 core-log 划界

> 日期：2026-10-28
> 涉及文档：`docs/ling/00-总览与术语.md` 与简版、`docs/ling/01-需求规格.md` 与简版、`docs/ling/03-架构设计.md` 与简版、`README.md`

## 发生了什么

用户重读 `00` 后提出：上一版项目**没有运行时日志**，出了问题没法定位；这一版要内置日志，并与 core-log 区分——core-log 是给其他插件提供日志功能的。

## 查到的三个缺口

| # | 缺口 | 后果 |
|---|---|---|
| 1 | `01` 关于内核日志只有 LING-REQ-111，只规定了写到哪、怎么轮转，**没规定写什么** | 实现时可以只记一条「启动完成」，形式上满足、实际无用 |
| 2 | `LING-REQ-077` 让查看日志走 core-log 插件 | core-log 没装或坏了就看不到日志，而「修宿主的工具不能依赖被修对象」这条 `03` 已用于命令行，日志这里漏了 |
| 3 | `00` 的术语表里没有「内核日志」一词 | 概念在项目里不存在，自然不会有人实现 |

三条合起来正是上一版失败的直接原因：现象能看到，原因看不到。

## 决定

| 决定 | 内容 |
|---|---|
| 两层日志 | 内核日志内置、不可卸载、不依赖插件；core-log 是给插件用的公共服务，可卸载 |
| 日志级别 | 四级 error / warn / info / debug，默认 info；debug 才记录每次方法调用与事件广播 |
| 调用日志 | 正常调用默认不记，靠默认级别实现；不用另做开关 |
| trace id | 全链追溯：一次操作一个编号，宿主内调用、侧车帧、管理端口命令帧都携带 |
| 写入门槛 | 异步且有界，队列满丢弃并计数，不阻塞业务调用 |
| 崩溃 | 先刷盘并追加调用栈再退出，刷盘最多耗时 100 毫秒 |

## 新增 10 条需求（117–126）

| 编号 | 内容 |
|---|---|
| 117 | 内核日志内置，不依赖插件，卸光插件仍可写可读 |
| 118 | 必记六类：启停、状态变化、装卸与调和每步、被拒操作与错误码、侧车启停退出、崩溃栈 |
| 119 | `logs --kernel` 直读日志文件，不经 core-log |
| 120 | 每条六个字段：时间戳、级别、来源模块、主体、错误码、trace id |
| 121 | 四级，默认 info，debug 才记调用 |
| 122 | trace id 随请求跨插件跨侧车传递 |
| 123 | 异步有界，满了丢弃并计数 |
| 124 | 崩溃先刷盘再退出 |
| 125 | core-log 未装时插件日志落 stderr 并带前缀 |
| 126 | 两层日志同字段同格式，两种 `logs` 输出同构 |
