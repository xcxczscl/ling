# log 050 M6 可发布：Windows 端起步

> 日期：2026-11-01
> 版本：`0.1.0-b1`（M6 起步，Windows 端已出包）
> 前一份：`docs/log/049-M5可用.md`

## 1. 这一轮做了什么

M6 的判定是「三端各出一个包，干净机器装完能用」。Linux 和 Android 卡在环境与前置工作（POSIX 分支没编译过、Android 要重做插件装载），所以这一轮只做 **Windows 端**，把能交付的先交付。

### 1.1 口令体验

用户提了一句「口令能不能选择性不填」。落地两件互补的事：

- **`ling open`**：一条命令自动读口令、拼好地址、用默认浏览器打开。不再手动复制 token。
- **可选关闭**：设置页加「是否要求口令」开关，存 `core-settings` 的 `core-ui.auth`（`on`/`off`），默认开。改动约两秒生效（界面每两秒同步一次），本机单用户可关，之后直接开 `127.0.0.1:8010`。

### 1.2 desktop 版：WebView2 窗口

core-ui 从「只有 webui」拆成两种形态，共用 `main/ui/app.cpp` 的握手、自检、起服务：

| 形态 | 入口 | 页面由谁显示 |
|---|---|---|
| webui（默认） | `ui/main.cpp` | 浏览器（`ling open`） |
| desktop | `ui/win_main.cpp` | WebView2 独立窗口 |

desktop 版：Win32 窗口（1100×760）、WebView2 导航到本机界面地址、GUI 子系统不弹黑框、右键菜单关掉开发工具。CMake 加 `LING_CORE_UI_DESKTOP` 开关，默认 OFF。

引入 WebView2 SDK（NuGet 包 `Microsoft.Web.WebView2` 1.0.4314.35），只留 x64 静态库 + 头文件进 `third_party/webview2/`。运行时是系统自带的（Win10/11）。

### 1.3 嵌入 Python 运行时

下载 Python 3.13.12 embeddable，放进 `<程序目录>/runtime/python/`。宿主 `python_interpreter()` 按 `LING_PYTHON` → 随包运行时 → 系统 PATH 的顺序找，现在第二条有东西了，Python 侧车脱离系统环境。实测 `demo-py` 用的是 `runtime\python\python.exe`。

### 1.4 打包

`tools/package.py`：出便携 zip（含 `ling.exe`、五个内置插件、Python SDK、Python 运行时），并生成 Inno Setup 脚本。zip 实测解压即用——起宿主、预装五个内置插件、拉起 desktop 界面。

安装包编译已通：装了 Inno Setup 6（用户级，装在 `%LOCALAPPDATA%\Programs\Inno Setup 6`，`package.py` 已能识别），`python tools/package.py iss` 产出 `dist/ling-0.1.0-b1-win64-setup.exe`（约 11 MB）。

### 1.5 VC++ 运行库随包分发

验包时发现一个会让干净机器起不来的缺口：`ling.exe` 与侧车 `core-ui.exe` 都是 `/MD` 动态链接 CRT（项目在 `LingOptions.cmake` 里明确统一成动态 CRT，不能改 `/MT`，否则进程内插件跨 DLL 崩）。它们依赖 `MSVCP140.dll`、`VCRUNTIME140.dll`、`VCRUNTIME140_1.dll`，这些不是 Win10/11 系统自带，干净机器会报「找不到 MSVCP140.dll」。

修法：把 VS 的 `VC/Redist/MSVC/<版本>/x64/Microsoft.VC145.CRT` 全套 10 个 DLL 固化为 `third_party/vc-redist/`，`package.py` 打包时放**两份**——根（宿主 + 进程内插件）与 `plugins/core-ui/`（侧车是独立进程，DLL 搜索只看自己目录）。UCRT 的 `api-ms-win-crt-*.dll` 是系统自带，不带。

### 1.6 数据位置由用户决定（便携模式）

用户要求数据位置可自选。引入「便携标记」机制：

- exe 同目录有空的 `ling.portable` 文件 → 数据根 = `<程序目录>\data`（数据跟程序走）；没有 → 平台默认（Windows `%APPDATA%\ling`）。
- **便携 zip** 打包时固定写入 `ling.portable`，解压即用、数据跟程序走。
- **安装包** 加「便携模式」任务选项（默认不勾）：勾选则安装器写入 `ling.portable`。为此安装目录改成用户级 `%LOCALAPPDATA%\Programs\ling`（`PrivilegesRequired=lowest`），否则普通用户运行时写不进 Program Files，「数据存程序目录」不成立。
- 取数据根顺序：`--data-dir` 参数 > 便携标记 > 平台默认。

实现落在 `main/app/main.cpp` 与 core-ui（`main/builtin-plugins/core-ui/app.cpp`）的 `default_data_root()`，打包侧在 `tools/package.py`。实测两种模式都正确落盘。

### 1.7 平台抽象层（main/Sys/）

用户要求把散在业务代码里的平台相关代码集中。落地：

- 新增 `main/Sys/`：统一接口 `main/include/ling/sys.hpp`；`Sys/Windows/` 与 `Sys/Posix/` 各放一份实现（`sys.cpp` 平台函数 + `sidecar_host.cpp` 侧车进程）。
- 抽出的平台能力：取 exe 目录、读环境变量、命令行转码、控制台代码页（RAII）、Ctrl+C、打开浏览器、动态库、套接字（句柄/初始化/收发超时/select）、本地时间、原子替换文件、共享库后缀。
- 业务代码（kernel、admin_*、ui_server、log、manifest、app、core-ui、三个内置插件）去掉 `#ifdef _WIN32`，改调 `ling::sys::*`。
- 目录整理：`main/ui/` → `main/builtin-plugins/core-ui/`（core-ui 是第五个内置插件）；`main/python/` → `main/SDK/python/`（Python 侧车 SDK）。
- 平台函数单独成 `ling_sys` 静态库：进程内插件是独立 DLL、不链接 `ling_core`，但也要用 `local_time`/`atomic_replace`，所以拆出来让插件和宿主都能链接。
- 保留的小 #ifdef（非通用平台 API）：core-job 的 `sscanf_s`（MSVC 安全函数）、kernel 的权限检查、`python.exe`/`bin/python3` 运行时布局、帮助文案、插件导出宏、win_main.cpp 的 WebView2（纯 Windows 文件）。
- 验证：win-release 编译通过；单元测试 45 用例 293 断言、验收脚本 `--script all` 全过。

## 2. 两个环境限制

- **Inno Setup 装的是用户级**：winget 装到了 `%LOCALAPPDATA%\Programs\Inno Setup 6`，不在默认的 `Program Files (x86)`。`package.py` 的查找顺序已覆盖这条路径。
- **下载大文件走国内镜像**：python.org 的 embeddable 直连下不动，改华为云镜像才成功。打包脚本注释里记了这条，别的机器构建时若下不动 Python，换镜像。
