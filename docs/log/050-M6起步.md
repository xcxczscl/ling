# log 050 M6 可发布：Windows 端起步

> 日期：2026-11-01
> 版本：`0.1.0-b1`（M6 起步，Windows 端已出包）
> 前一份：`docs/log/049-M5可用.md`

## 1. 这一轮做了什么

M6 的判定是「三端各出一个包，干净机器装完能用」。Linux 和 Android 卡在环境与前置工作（POSIX 分支没编译过、Android 要重做插件装载），所以这一轮只做 **Windows 端**，把能交付的先交付。

### 1.1 口令体验

用户提了一句「口令能不能选择性不填」。落地两件互补的事：

- **`ling open`**：一条命令自动读口令、拼好地址、用默认浏览器打开。不再手动复制 token。
- **可选关闭**：设置页加「是否要求口令」开关，存 `core-settings` 的 `core-ui.auth`（`on`/`off`），默认开。改动约两秒生效（界面每两秒同步一次），本机单用户可关，之后直接开 `127.0.0.1:8010`。

### 1.2 desktop 版：WebView2 窗口

core-ui 从「只有 webui」拆成两种形态，共用 `main/ui/app.cpp` 的握手、自检、起服务：

| 形态 | 入口 | 页面由谁显示 |
|---|---|---|
| webui（默认） | `ui/main.cpp` | 浏览器（`ling open`） |
| desktop | `ui/win_main.cpp` | WebView2 独立窗口 |

desktop 版：Win32 窗口（1100×760）、WebView2 导航到本机界面地址、GUI 子系统不弹黑框、右键菜单关掉开发工具。CMake 加 `LING_CORE_UI_DESKTOP` 开关，默认 OFF。

引入 WebView2 SDK（NuGet 包 `Microsoft.Web.WebView2` 1.0.4314.35），只留 x64 静态库 + 头文件进 `third_party/webview2/`。运行时是系统自带的（Win10/11）。

### 1.3 嵌入 Python 运行时

下载 Python 3.13.12 embeddable，放进 `<程序目录>/runtime/python/`。宿主 `python_interpreter()` 按 `LING_PYTHON` → 随包运行时 → 系统 PATH 的顺序找，现在第二条有东西了，Python 侧车脱离系统环境。实测 `demo-py` 用的是 `runtime\python\python.exe`。

### 1.4 打包

`tools/package.py`：出便携 zip（含 `ling.exe`、五个内置插件、Python SDK、Python 运行时），并生成 Inno Setup 脚本。zip 实测解压即用——起宿主、预装五个内置插件、拉起 desktop 界面。

## 2. 两个环境限制

- **Inno Setup 没装**：安装包脚本已生成（`package.py iss`），但机器上没有 ISCC.exe，安装包要等装了 Inno Setup 再编译。便携 zip 不依赖它，已经能交付。
- **下载大文件走国内镜像**：python.org 的 embeddable 直连下不动，改华为云镜像才成功。打包脚本注释里记了这条，别的机器构建时若下不动 Python，换镜像。

## 3. 验证

- `l5_ui.py` 29 项（webui 版）全过，重构抽取 app.cpp 没破坏。
- desktop 版作为侧车能正常拉起（activated + ui_port + HTTP 接口可用）。
- 便携 zip 解压到临时目录，`serve` 起宿主、五个内置插件预装、core-ui desktop 拉起。
