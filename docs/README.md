# 文档索引

想知道某件事该读哪份文档，从这里找。本文只写「文档在哪、回答什么」，不重复文档里的具体数值；端口、路径、上限、事件字段这类常查的取值，统一放在 [`common/03-常用取值速查.md`](common/03-常用取值速查.md)。

---

## 1. 目录地图

| 目录 | 放什么 |
|---|---|
| `docs/common/` | 跨项目公共文档：编写规范、术语、版本约定、取值速查 |
| `docs/ling/README.md` | ling 项目结构、宿主与内置插件的版本、内置插件职责 |
| `docs/ling/main/` | ling 宿主的设计文档，从总览一直到测试验收 |
| `docs/ling/main/04-详细设计/` | 宿主内部实现细节：内核四服务、依赖解析、热更新、管理端口 |
| `docs/ling/plugin-support/` | 写插件要遵守的契约：清单、C ABI、Context、侧车、样板 |
| `docs/ling/builtin-plugins/` | 五个内置插件的文档，一个插件一个子目录 |
| `docs/ling/log/` | ling 的开发日志，按事件记，只增不改 |
| `docs/ling/archive/` | 归档：`main/<宿主版本>/` 与 `builtin-plugins/<插件名>/<插件版本>/` |
| `docs/plugins/` | 第三方插件文档：`<插件名>/` 正文、`archive/` 档案、`log/` 日志 |
| `docs/other/` | 预留目录，目前为空 |

正式文档都有简版，放在同级 `brief/` 子目录，文件名与详细版相同。赶时间读简版，要理由读详细版。

## 5. 怎么判断文档是不是最新

三处一起看：

| 看什么 | 在哪 | 说明 |
|---|---|---|
| 状态 | 每份文档第 2 行 | 初定 = 可作依据但不承诺稳定；已定稿 = 用户确认 |
| 最后更新 | 同一行 | 与变更记录末行一致 |
| 变更记录 | 每份文末 | 一行一次改动，写清改了什么、为什么 |

三处不一致时，以变更记录为准，并顺手修另外两处。

`README.md` 不写状态与变更记录：它随目录结构频繁变化，状态块只会变成欠账。
