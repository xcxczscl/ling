## 2. 端口与认证

### 2.1 只绑回环

固定 `127.0.0.1`，不提供配置项。一旦可配就会出现「为了局域网访问改成 0.0.0.0」的用法，而威胁模型没有覆盖这种暴露。

### 2.2 端口选择

从 7900 起试到 7999，取第一个可绑定的，写入 `registry.json`（含 `port`、`pid`、`started_at`）。全占满则启动失败，退出码 3。

命令行读这份文件找端口，不扫端口。

### 2.3 `session.json`

内容 `{"token":"<32 字节随机数十六进制>"}`，权限 0600，每次启动重新生成，退出时删除。

重新生成意味着旧进程的 token 立即失效——多开时后启动者胜出，符合「只允许一个实例」的设计。

### 2.4 认证

首帧必须是 `{"op":"auth","token":"...","v":1}`。

| 情形 | 处理 |
|---|---|
| 正确 | 回 `ok:true`，进入命令循环 |
| 错误 | 回 `E_AUTH` 并断开 |
| 首帧不是 `auth` | 回 `E_AUTH` 并断开，不透露原因 |
| 连续 3 次错误 | 断开，同源 IP 延迟 1 秒 |
| 5 秒内未认证 | 断开 |

延迟 1 秒只是防本地脚本狂刷日志，不是安全机制。

## 3. 帧格式

### 3.1 请求帧

`{"v":1,"id":1,"op":"call","method":"kernel.plugins","args":{},"trace":"t-4f2a"}`

`v`、`id`、`op` 必填；`method` 在 `call` 时必填且必须以 `kernel.` 开头。

### 3.2 应答帧

成功 `{"v":1,"id":1,"ok":true,"result":{...}}`；失败带 `error:{code,message,detail}`。

### 3.3 版本不匹配

客户端 `v` 不同：回 `E_API_MISMATCH`（`detail` 给双方版本）并断开，其他客户端与插件不受影响。

### 3.4 协议错误

| 情形 | 处理 |
|---|---|
| 非合法 JSON、跨行、超 1 MB | 回对应错误码并断开（数据流已不可靠） |
| `op` 不认识 | `E_PROTOCOL`，不断开 |
| `method` 不以 `kernel.` 开头 | `E_NAMESPACE_VIOLATION`，不断开 |

## 4. 子命令与 `kernel.*` 方法

### 4.1 映射表

| 子命令 | 方法 | 走端口 |
|---|---|---|
| `serve` | —— | 否 |
| `shutdown` | `kernel.shutdown` | 是 |
| `plugins` | `kernel.plugins` | 是 |
| `install <路径>` | `kernel.install` | 是 |
| `uninstall <编号> [--purge]` | `kernel.uninstall` | 是 |
| `enable <编号>` | `kernel.enable` | 是 |
| `disable <编号>` | `kernel.disable` | 是 |
| `reload <编号>` | `kernel.reload` | 是 |
| `restart <编号>` | `kernel.restart` | 是 |
| `logs [编号] [--kernel]` | `kernel.logs` 或直读文件 | 视参数 |
| `doctor` | `kernel.doctor` | 是 |
| `--version` | —— | 否 |
| `--help` | —— | 否 |

走端口的命令经同一条调用路由，与插件方法用同一套机制。

`reload` 换版本，`restart` 只停用再激活不换产物。

### 4.2 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 检查发现问题（`doctor`） |
| 2 | 参数错误 |
| 3 | 宿主不可达 |
| 4 | 宿主返回错误 |

`doctor` 用 1：它成功执行了检查，只是结果有问题。

### 4.3 输出格式

默认人读，一行一条：`编号 版本 状态 轨道 未满足原因`。加 `--json` 输出与端口应答同构的 JSON。

## 5. 各子命令的行为

### 5.1 `serve`

前台运行，参数 `--port`（起始端口）、`--log-level`（默认 info）、`--data-dir`（覆盖数据根）。唯一不连端口的子命令。

### 5.2 `shutdown`

发 `kernel.shutdown`，等连接断开或 10 秒超时；超时退出码 4。

### 5.3 `plugins`

列编号、版本、状态、轨道、未满足原因。状态只有 `installed`、`activated`、`deactivated`、`failed` 四种：`Activating` 与 `Deactivating` 是瞬时状态，列表不保证看得到。

### 5.4 装载类子命令

| 子命令 | 成功后 | 失败时 |
|---|---|---|
| `install` | 插件出现在列表，状态由调和决定 | 返回错误码，不留残件 |
| `uninstall` | 目录只剩 `data/` 或不存在 | 有未撤销条目返回 `E_UNINSTALL_INCOMPLETE`，工件仍删 |
| `enable` | 转 `activated` | 依赖不满足仍成功，状态留 `deactivated` |
| `disable` | 转 `deactivated`，下游一起停 | 撤销失败记 `E_UNDO_FAILED` |
| `reload` | 七步走完，版本变化 | `E_RELOAD_FAILED`，已回滚 |
| `restart` | 停用再激活，版本不变 | 激活失败则回滚到停用前 |

`install` 与 `uninstall` 等该轮调和结束再返回，其余四个只等本次操作完成。

### 5.5 `logs` 与 `doctor`

| 用法 | 走哪条 | 依赖 |
|---|---|---|
| `logs --kernel` | 直读 `logs/kernel-YYYY-MM-DD.log` | 不依赖插件 |
| `logs <编号>` | `kernel.logs` → core-log | 未装 core-log 时报错 |

`--follow` 只对 `--kernel` 生效。`doctor` 见 §7。

### 5.6 `--version` 与 `--help`

`--version` 打印宿主版本，不连宿主。`--help` 打印子命令与一行说明；参数错误时也打印，退出码 2。

## 6. 命令行与宿主的连接

### 6.1 找端口与口令

读 `registry.json` 拿端口 → 读 `session.json` 拿 token → 连 127.0.0.1（5 秒超时）→ 发 `auth` → 发 `call`。

数据根优先级：`--data-dir` > 环境变量 `LING_DATA_DIR` > 平台默认。两者必须一致，否则连到不同实例。

### 6.2 宿主未运行时

| 情形 | 输出 | 退出码 |
|---|---|---|
| 无 `registry.json` | 宿主未运行 | 3 |
| 端口被拒 | 宿主未运行（端口无响应） | 3 |
| 无 `session.json` | 宿主正在启动或已退出 | 3 |
| 口令不匹配 | 宿主已重启过 | 4 |

第三与第四条要分开：一个是没拿到口令，一个是拿到了但不对。

### 6.3 超时

连接 5 秒、认证 5 秒、普通命令 30 秒、`install`/`uninstall`/`reload` 60 秒（等调和）、`shutdown` 10 秒。超时退出码 4，`message` 写明阶段。

## 7. `doctor`

### 7.1 四项检查

| 检查 | 判定 |
|---|---|
| 依赖图环 | 用 `04/04` §4.3 的环检测，有环列出环路 |
| 未撤销条目 | 扫描已停用插件的账本段，`count > 0` 视为未撤净 |
| 端口与口令文件 | 端口是否仍可连、`session.json` 是否 0600 |
| 越权记录 | 内核日志中越权条数与最近 10 条 |

### 7.2 退出码与输出

全部正常 0；任一项有问题 1；检查本身失败 4。

固定四段输出，**不写「已修复」类内容**——只报告，不自动修复。

## 8. 与插件的关系

### 8.1 命令行不依赖任何插件

卸掉 core-ui 后：端口、子命令、装载卸载、调和全部可用；网页界面不可用但命令行不受影响；插件日志不可用但 `--kernel` 不受影响。

这是「修宿主的工具不能依赖被修的对象」的落地。

### 8.2 两条日志路径为什么必须分开

`logs --kernel` 直读文件：core-log 正是会出问题的对象——没装、装坏了、或者它说「一切正常」。

同理 `doctor` 全部在内核里实现，不调任何插件方法。

## 9. 未决问题

| # | 问题 | 建议 |
|---|---|---|
| 1 | `restart` 与 `reload` 是否合并 | 不合并，语义不同，合并要靠布尔参数区分反而歧义 |
| 2 | Windows 上 0600 怎么实现 | 用仅当前用户的 ACL，不模拟 POSIX 模式 |
| 3 | `--json` 是否全命令实现 | 是，成本低且脚本化常用 |
| 4 | `logs --follow` 只对内核日志生效 | 接受，`--kernel` 才是排障主路径 |
