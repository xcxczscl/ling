## 2. 内核对象模型

### 2.1 内核持有哪些对象

内核持有六样：快照指针（原子读写）、请求队列、工作线程池、每插件一份的效应账本、日志器、内核线程。

| 对象 | 谁可以改 |
|---|---|
| 快照 | 只有内核线程构造新快照后原子替换 |
| 请求队列 | 任何线程入队，只有内核线程出队 |
| 工作线程池 | 只有内核线程派发任务 |
| 账本 | 内核线程追加，撤销路径消费 |
| 日志器 | 任何线程写，异步队列 |

对外只有四个方法：`snapshot()` 取只读视图、`submit()` 提交写请求、`call()` 调用方法、`emit()` 广播事件。

### 2.2 启动顺序

九步：读 `registry.json` → 初始化日志器 → 构造空快照 → 启动内核线程 → 扫描并校验清单 → 建依赖图算首次计划 → 起管理端口 → 按计划激活 → 进入事件循环。

第 6 步在建端口之前，因为端口一起来就会有命令进来，那时依赖图必须已经算好。

单插件清单非法只跳过该插件并记 warn；存在环则拒绝启动并列出环上的插件。

### 2.3 关闭顺序

七步，与启动相反，**先停插件再排空队列**：

停接新连接 → 拒绝新请求入队 → 排空队列 → 按反向拓扑序停用并卸载 → 停工作线程池 → 落盘与刷日志 → 释放快照与装载表。

## 3. 数据结构

### 3.1 路由表

`unordered_map<std::string, RouteEntry>`，key 是完整方法名。

| 字段 | 含义 |
|---|---|
| `plugin_id` | 归属插件 |
| `method_name` | 完整方法名，含前缀 |
| `handler` / `handler_ctx` | 处理函数与插件侧上下文 |
| `requires` | 该方法要求的能力位 |
| `register_seq` | 注册序号，用于与账本对账 |

key 用完整方法名而非二元组：方法名必带前缀，前缀等于唯一编号，二元组的信息已在字符串里。

### 3.2 订阅表

两级存：`exact`（精确主题 → 订阅者列表，按 `register_seq` 升序）与 `wildcard`（通配订阅单独一份，线性扫描）。

通配只用线性扫描而不用前缀树：数量与插件数同阶，几十条，建树的收益看不出来。

### 3.3 能力表

`unordered_map<编号, CapEntry>`，`CapEntry` 只有两个位集 `declared` 与 `revoked`，生效能力是 `declared & ~revoked`。

能力集首版固定四个：`fs`、`network`、`ui`、`shell`。集合外取值在清单校验阶段拒绝，不进这张表。

### 3.4 装载表

`unordered_map<编号, LoadEntry>`，字段：版本、`api` 主版本、`min_host`、轨道、状态、动态库句柄或侧车进程号、声明能力、`generation`。

状态七种：`Uninstalled`、`Installed`、`Activating`、`Activated`、`Deactivating`、`Deactivated`、`Failed`。

`generation` 每次装载自增。回调进来时比对，不相同直接拒绝——热更新期间旧指针仍被持有，靠代号拦截比指望指针都被清干净可靠。

### 3.5 不变式

| # | 不变式 |
|---|---|
| 1 | 路由表条目的插件必须在装载表里存在且不是 `Uninstalled` |
| 2 | 路由表 key 必以该插件编号加一点开头 |
| 3 | 同一插件的 `sub_id` 不重复 |
| 4 | 每个已装载插件在能力表都有条目，可以为全 0 |
| 5 | 订阅表里的插件状态为 `Activated` 或 `Deactivating` |

第 5 条允许 `Deactivating`：停用是「先改状态、再按账本倒序撤」，撤销过程中状态就是这个值。

任一条不成立即拒绝换快照并记 error。

## 4. 快照机制

### 4.1 为什么用快照

单线程内核只解决「谁能改状态」。读若也排队，一次调用就是两次线程切换，`LING-REQ-089` 的 1 微秒达不到。

### 4.2 快照包含什么

`Snapshot` 含版本号 + 四张表，用 `shared_ptr<const Snapshot>` 持有。

四张表放同一份快照，因为它们之间有跨表不变式；拆开替换会让读方拿到「路由已更新、能力表还是旧的」组合。

**账本不在快照里**：追加极频繁，复制整份快照会使单次注册成本随账本长度上升。账本用单写多读的追加结构，见 `04/03`。

### 4.3 换快照的步骤

复制当前快照 → 在副本上改 → 校验五条不变式（失败则丢弃并返回 `E_INTERNAL`）→ 版本号加一 → `std::atomic_store` 换指针 → 旧快照由读者释放。

### 4.4 读方必须遵守的规则

| 规则 | 原因 |
|---|---|
| 一次操作只取一次快照 | 中途换表会导致查到函数时能力已变 |
| 不把快照里的指针或引用保存到操作结束之后 | 旧快照无人持有就被释放 |
| 持有快照期间不提交写请求并等待结果 | 与内核线程相互等待会互锁 |

### 4.5 快照的成本

50 插件、500 条路由时，复制耗时在几十微秒量级。写操作不在调用热路径上，可以接受。插件数上到几百时改为持久化数据结构，接口不变。

## 5. 方法路由

### 5.1 注册

签名：`register_method(plugin_id, method_name, handler, handler_ctx, requires)`。

校验顺序，遇第一个失败即返回：

| 序 | 检查 | 失败返回 |
|---|---|---|
| 1 | 插件状态为 `Activating` | `E_PLUGIN_MISSING` |
| 2 | `handler` 非空 | `E_LEDGER_INVALID` |
| 3 | 方法名以插件编号加一点开头 | `E_NAMESPACE_VIOLATION` |
| 4 | 方法名不超 128 字节，只含字母、数字、下划线、点 | `E_MANIFEST_INVALID` |
| 5 | `requires` 是清单能力的子集 | `E_CAPABILITY_DENIED` |
| 6 | 完整方法名不被占用 | `E_DUPLICATE_METHOD` |

顺序是「先资格、再参数、后冲突」。反过来的话，已停用的插件来注册会先报名字冲突，把排查带偏。

成功后账本追加 `MethodRegistered`，撤销动作是注销。

### 5.2 注销

检查两条：方法存在、归属与传入编号一致。不存在返回 `E_METHOD_MISSING`，归属不符返回 `E_CAPABILITY_DENIED`。重复注销同一方法不改其他条目，结果仍是 `E_METHOD_MISSING`。

### 5.3 调用路径

签名：`call(method, args, len, trace_id) → CallResult{code, data}`。

九步：

1. 取一次快照。
2. 载荷超 1 MB 先返回 `E_PAYLOAD_TOO_LARGE`（放在查表前，免得为超限请求做无用查找）。
3. 查路由。未命中时再查装载表区分：插件在则 `E_METHOD_MISSING`，不在或未激活则 `E_PLUGIN_MISSING`。第二次查表只在失败路径发生。
4. 查能力，`requires` 不被生效能力覆盖则 `E_CAPABILITY_DENIED`。
5. 按轨道分派：进程内直调处理函数，不序列化；侧车封帧发过去等应答，上限 5 秒。
6. 同步调用超过 30 秒返回 `E_TIMEOUT`，但**不终止处理函数**（C++ 没有可移植的线程取消），结果丢弃，trace id 与插件编号写日志。
7. 返回后校验 `generation`，变了说明期间热更新过，返回值作废，返回 `E_PLUGIN_MISSING`。
8. 被拒绝类结果写 warn 日志；正常调用不写（debug 级别才记）。
9. 返回。

**「超时」是放弃等待，不是停止执行**，文档与实现都按这句写。

### 5.4 命名空间规则

| 对象 | 规则 | 校验点 |
|---|---|---|
| 方法名 | 必以 `<编号>.` 开头，点后至少一段 | 注册时 |
| 事件主题 | 同理，`kernel.` 保留给内核 | 订阅与广播时 |
| 插件编号 | 小写字母、数字、连字符，2 至 32 位，全项目唯一 | 清单校验 |

要求带前缀而不是靠二元组隔离：日志与 trace 里只有方法名字符串，带前缀能一眼看出归属。

### 5.5 本模块用到的错误码

| 错误码 | 何时返回 |
|---|---|
| `E_PLUGIN_MISSING` | 目标未装载、未激活，或调用期间热更新 |
| `E_METHOD_MISSING` | 方法未注册 |
| `E_NAMESPACE_VIOLATION` | 名字没带自己的前缀，或用了 `kernel.` |
| `E_CAPABILITY_DENIED` | 声明超出清单，或生效能力不足 |
| `E_PAYLOAD_TOO_LARGE` | 载荷超过 1 MB |
| `E_TIMEOUT` | 同步调用超 30 秒，或侧车 5 秒未应答 |
| `E_DUPLICATE_METHOD` | 方法名重复注册（本文新增） |
| `E_INTERNAL` | 不变式校验失败（本文新增） |
| `E_SHUTTING_DOWN` | 关闭中拒绝新请求（本文新增） |

后三个需登记进 `04/02` 的错误码表。

## 6. 事件广播

### 6.1 订阅

签名：`subscribe(plugin_id, pattern, callback, callback_ctx, out_sub_id)`。

校验：插件状态为 `Activating` → 回调非空 → 主题不是别人的前缀也不是 `kernel.` → 通配只允许在末尾或整串为 `*` → 单插件通配订阅不超 32 条。

不允许中缀通配（`a.*.c`）：要完整模式匹配，代码量与出错面都上升，实际只用到两种形态。

成功后分配 `sub_id`，账本追加 `EventSubscribed`。

### 6.2 匹配

两步汇总：查 `exact[topic]` 整条加入；扫 `wildcard`，`*` 全收，`<前缀>.*` 做前缀比较。结果按 `register_seq` 升序排列，这就是 `LING-REQ-021` 的派发顺序。

### 6.3 派发

签名：`emit(topic, payload, len, trace_id)`。

步骤：校验主题前缀（越权则记录并丢弃）→ 校验载荷大小 → 算收件人 → 逐个同步调用，单个超 5 秒则跳过并记录，继续下一个 → 不落盘、不重投。

`emit` 由调用方线程直接执行，不排到内核线程：它只读快照，排队反而多一次切换。代价是慢订阅者会拖住广播方 5 秒，这是 `LING-REQ-021` 明确接受的。

### 6.4 内核事件字段

`kernel.plugin.state`：`plugin_id`、`state`（activated / deactivated / uninstalled / crashed）、`version`、`generation`、`reason`（crashed 时带错误码）。

`kernel.plan.step`：`step_index`、`step_total`、`action`（activate / deactivate / unload）、`plugin_id`、`result`（ok / skipped / failed）、`error_code`。

载荷是 JSON，字段名一经发布不改，改则升 `api` 主版本。

## 7. 能力门禁

### 7.1 两处校验

| 位置 | 检查 | 失败返回 |
|---|---|---|
| 注册方法时 | `requires` 是否被清单能力覆盖 | `E_CAPABILITY_DENIED` |
| 调用瞬间 | `requires` 是否被「清单减撤销」覆盖 | `E_CAPABILITY_DENIED` |

两处都要。只做注册时，用户中途撤销能力后已注册的方法照样能调；只做调用时，没声明过的能力也能用上。

### 7.2 撤销与恢复

`set_capability_revoked(plugin_id, add, clear)` 只改 `revoked` 位，不改状态，插件保持 `Activated`。

撤销状态写入 `registry.json`，重启仍生效；不触发调和（能力不是依赖）；不广播事件，只写内核日志。

### 7.3 门禁不管什么

不管具体文件路径、网络地址、调用频率、能力语义。管路径等于在宿主里塞沙箱，违背零内容。

## 8. 内核线程与请求队列

### 8.1 请求类型

八种：注册方法、注销方法、订阅、退订、改撤销名单、装载、卸载、调和。

结构含 `kind`、`plugin_id`、`trace_id`、参数变体、`std::promise` 与「是否等结果」。

没有第九种：凡未列入的改动都得先扩这张表，不允许直接改快照。

### 8.2 队列语义

| 性质 | 规定 |
|---|---|
| 顺序 | FIFO，严格按入队顺序 |
| 并发 | 多生产者单消费者，队列用互斥锁 |
| 重入 | 内核线程执行期间不得再提交并等待，加运行时断言 |
| 失败 | 单条失败不影响后续 |
| 关闭 | 置停止标志后拒绝新请求，已入队的执行完 |

### 8.3 工作线程池

数量 `CPU 核数 − 3`，最少 2。

可做：文件读写、哈希、目录扫描、侧车启动与等待、日志落盘。

不可做：任何改内核状态的操作。用 API 限制——工作线程只拿得到快照与只读视图。

## 9. 日志

| 场景 | 级别 | 必记内容 |
|---|---|---|
| 注册、注销、订阅、退订成功 | info | 插件编号、方法名或主题、trace id、`generation` |
| 门禁拒绝、越权、载荷超限 | warn | 错误码、被拒对象、trace id |
| 调用超时、订阅者超时被跳过 | warn | 阈值、实际耗时、插件编号、trace id |
| 内核事件广播 | info | 事件名、`plugin_id`、状态 |
| 不变式失败 | error | 第几条、哪张表 |
| 崩溃捕获 | error | 插件编号、调用栈、`generation` |

正常调用不进日志，debug 级别才记摘要（方法名、耗时、返回码）。

## 10. 时序

### 10.1 注册方法

插件（Activating）→ 六项校验 → 入队并等结果 → 内核线程复制快照、插入条目、校验不变式、换快照 → 账本追加 → 返回 0。失败则不换快照。

### 10.2 调用

取快照 → 载荷检查 → 查路由（未命中再查装载表区分两个错误码）→ 查能力 → 按轨道分派（进程内直调 / 侧车封帧等应答）→ 校验 `generation` → 返回。

### 10.3 广播

校验主题 → 载荷检查 → `exact` 加 `wildcard` 匹配 → 按 `register_seq` 排序 → 逐个同步调用，单个超 5 秒跳过 → 不落盘。

### 10.4 门禁拒绝

查路由命中 → 能力表 `declared = fs`、`revoked = fs`、生效为 0 → `requires` 含 `fs` → 返回 `E_CAPABILITY_DENIED` → 写 warn 日志 → 插件状态仍为 `Activated`。

### 10.5 卸载时批量注销

状态改 `Deactivating` → 按账本倒序逐条撤销（失败记 error 并继续）→ 从能力表与装载表删条目 → 状态改 `Uninstalled` → 校验不变式 → 换快照 → 广播 `kernel.plugin.state(uninstalled)`。
