## 2. 插件目录形态

### 2.1 数据根与插件目录

```
<数据根>/                    Windows: %APPDATA%\ling    Linux: ~/.local/share/ling
├── registry.json            端口、禁用名单、撤销名单
├── session.json             口令，权限 0600
├── logs/
└── plugins/<编号>/          目录名等于 id
    ├── plugin.toml          存在即视为已安装
    ├── <编号>.dll 或 .so    进程内轨道
    ├── 或 sidecar/          侧车轨道
    └── data/                卸载默认保留
```

三条硬规则：目录名与 `id` 大小写敏感一致；只剩 `data/` 的目录算未安装，可重装沿用数据；卸载只删工件，`--purge` 才删数据。

### 2.2 一个插件只有一种产物

| 组合 | 结果 |
|---|---|
| 只有动态库，清单无 `[sidecar]` | 进程内轨道 |
| 只有 `[sidecar]` 且文件存在 | 侧车轨道 |
| 两者都有，或都没有 | `E_MANIFEST_INVALID` |

先看清单定轨道，再验文件。

### 2.3 安装来源

目录或 zip 包，一律整目录复制到 `plugins/<编号>/`，不建链接。编号已存在则拒绝并提示先卸载或升级。

## 3. 清单字段全集

### 3.1 必填字段

| 字段 | 格式 | 校验 |
|---|---|---|
| `id` | `^[a-z0-9][a-z0-9-]*$`，2 至 64 位 | 必须等于目录名 |
| `version` | 三段式，每段 0 至 65535 | 段数或范围不对即拒；不限制递增方式 |
| `api` | 主版本号字符串 | 必须在支持范围，否则 `E_API_MISMATCH` |
| `name` | 1 至 64 字符 | 缺失即拒，报缺该字段 |

### 3.2 可选字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `min_host` | 不限制 | 低于要求返回 `E_HOST_TOO_OLD`，信息含双方版本 |
| `requires.plugins` | 空 | 写法见 §3.3 |
| `sidecar.executable` | 无 | 必须在插件目录内 |
| `sidecar.restart` | `on-crash` | `on-crash`、`always`、`never` |
| `sidecar.idle_timeout` | 60 秒 | 按需侧车的空闲退出时间 |
| `capabilities` | 空 | 取值限 `fs`、`network`、`ui`、`shell` |
| `description` | 空 | 仅供 `ling plugins` 展示 |

### 3.3 `requires` 段

版本写法四种：`@1` 匹配 1.4.2 不匹配 2.0.0；`@1.2` 匹配 1.2.9 不匹配 1.3.0；`@1.2.3` 只匹配该版本；无版本匹配任意。

### 3.4 校验顺序

十步：目录名 = `id` → 四字段齐全 → `id` 格式 → `version` 格式 → `api` 范围 → `min_host` → 路径不含绝对路径与 `..` → 产物组合 → 侧车可执行文件位置 → 能力取值。

遇第一个失败即停。第 5 步在第 6 步前：协议不兼容比宿主版本旧更根本。

### 3.5 两份示例

进程内：

```toml
id = "demo-a"
version = "1.0.0"
api = "1"
name = "示例插件 A"
capabilities = ["fs"]

[requires]
plugins = ["core-ui@1"]
```

侧车：

```toml
id = "demo-b"
version = "0.2.1"
api = "1"
name = "示例插件 B"

[sidecar]
executable = "sidecar/demo-b"
restart = "on-crash"
idle_timeout = 30
```

## 4. C ABI 函数表

### 4.1 三个结构体

```c
#define LING_ABI_VERSION 1

typedef struct {
    uint32_t abi_version;
    const char* plugin_id;
    const char* plugin_version;
    const char* api;
} ling_plugin_descriptor;

typedef struct {
    uint32_t struct_size;
    void*    (*context_alloc)(const char* plugin_id, uint64_t generation);
    int32_t  (*register_method)(void* ctx, const char* name, void* fn,
                                void* undo_fn, uint32_t requires_mask);
    int32_t  (*unregister_method)(void* ctx, const char* name);
    int32_t  (*subscribe)(void* ctx, const char* pattern, void* fn,
                          void* undo_fn, uint64_t* out_sub_id);
    int32_t  (*unsubscribe)(void* ctx, uint64_t sub_id);
    int32_t  (*call)(void* ctx, const char* method, const uint8_t* args,
                     size_t args_len, uint8_t** out, size_t* out_len);
    int32_t  (*emit)(void* ctx, const char* topic, const uint8_t* payload, size_t len);
    int32_t  (*write_config)(void* ctx, const char* key, const uint8_t* value, size_t len);
    const char* (*data_dir)(void* ctx);
    void     (*free_buffer)(void* ctx, uint8_t* p, size_t len);
} ling_host_api;

int32_t ling_plugin_entry(const ling_host_api* host,
                          ling_plugin_descriptor* out_desc,
                          void** out_plugin);
```

插件只导出 `ling_plugin_entry` 一个符号，其余全经函数表转发。

### 4.2 类型与内存归属

只允许定宽类型与指针；缓冲区一律「指针 + 长度」；谁申请谁释放（宿主给的用 `free_buffer` 还）；字符串 UTF-8；不跨边界抛异常；不传 C++ 类型。

`struct_size` 用于向后兼容扩字段——加字段不必升 `abi_version`，改字段含义才升。

### 4.3 版本协商

调入口 → 比对 `abi_version`（不相同则 `E_API_MISMATCH`）→ 比对描述符 `plugin_id` 与清单 `id`（不相同则 `E_MANIFEST_INVALID`）。

第二步不能省：编号不一致会把方法挂到错误的编号下。

### 4.4 函数表逐项

| 函数 | 谁调 | 失败 |
|---|---|---|
| `context_alloc` | 宿主，activate 前 | 返回空则拒绝激活 |
| `register_method` / `unregister_method` | 插件 / 宿主撤销 | 见 `04/01` §5.1、§5.2 |
| `subscribe` / `unsubscribe` | 插件 / 宿主撤销 | 见 `04/01` §6.1 |
| `call` / `emit` | 插件 | 见 `04/01` §5.3、§6.3 |
| `write_config` | 插件 | 由 core-settings 提供 |
| `data_dir` | 插件 | 返回 `plugins/<编号>/data/` 绝对路径 |
| `free_buffer` | 插件 | 无返回值 |

`requires_mask`：`fs=1`、`network=2`、`ui=4`、`shell=8`。`generation` 原样存着，每次回调带回。

## 5. 错误码登记表

### 5.1 分族规则

族前缀：`E_MANIFEST_`、`E_API_`/`E_HOST_`、`E_NAMESPACE_`、`E_CAPABILITY_`、`E_PLUGIN_`、`E_METHOD_`、`E_DEPENDENCY_`、`E_RELOAD_`、`E_LEDGER_`/`E_UNDO_`、协议类（`E_AUTH`、`E_PROTOCOL`、`E_PAYLOAD_`）、系统类（`E_IO`、`E_INTERNAL`、`E_SHUTTING_DOWN`、`E_TIMEOUT`）。

新增码必须归入已有族；要新族先改本节。

### 5.2 全表

| 错误码 | 含义 |
|---|---|
| `E_MANIFEST_INVALID` | 清单非法：缺字段、格式错、目录名不符、路径穿越、产物非法、描述符编号不符 |
| `E_API_MISMATCH` | `api` 超范围，或 `abi_version` 不相同 |
| `E_HOST_TOO_OLD` | `min_host` 高于当前宿主 |
| `E_NAMESPACE_VIOLATION` | 名字没带自己前缀，或占用 `kernel.` |
| `E_CAPABILITY_UNKNOWN` | 清单声明了能力集外的取值 |
| `E_CAPABILITY_DENIED` | 声明超清单、生效能力不足、归属不符 |
| `E_PLUGIN_MISSING` | 未安装、未激活、重载窗口、`generation` 过期 |
| `E_PLUGIN_EXISTS` | 安装的编号已有目录 |
| `E_METHOD_MISSING` | 方法未注册或已注销 |
| `E_DUPLICATE_METHOD` | 同一完整方法名二次注册 |
| `E_DEPENDENCY_CYCLE` | 依赖成环，`detail` 给环路 |
| `E_RELOAD_FAILED` | 重载失败已回滚 |
| `E_LEDGER_INVALID` | 撤销函数或处理函数为空 |
| `E_UNDO_FAILED` | 某条撤销失败，卸载继续 |
| `E_UNINSTALL_INCOMPLETE` | 有未撤销条目，`detail` 给清单 |
| `E_AUTH` | 口令不正确 |
| `E_PROTOCOL` | 帧不是合法 JSON、跨行、缺 `op` 或 `v` |
| `E_PAYLOAD_TOO_LARGE` | 载荷超过 1 MB |
| `E_TIMEOUT` | 调用超 30 秒，或侧车 5 秒未应答 |
| `E_IO` | 清单读不到、目录不可写、复制失败 |
| `E_INTERNAL` | 不变式校验失败这类自身问题 |
| `E_SHUTTING_DOWN` | 关闭中拒绝新请求 |
| `E_LEDGER_FULL` | 当前激活代已登记 10000 条 |
| `E_CANCELLED` | 调和执行中被取消，已执行步骤回滚 |

### 5.3 错误结构

`{"ok":false,"error":{"code","message","detail"}}`。`code` 只能取上表值，不许自由文本；`message` 含出错对象名；`detail` 放结构化补充（缺的字段、环路、未撤销条目）。

C ABI 侧返回 `int32_t`，另提供查询接口取最近一次的 `message` 与 `detail`。

## 6. 装载流程

### 6.1 进程内轨道

七步：校验清单 → 复制为私有文件名再打开 → 解析 `ling_plugin_entry` → 比对版本与编号 → `context_alloc` → activate 并注册 → 状态改 `Activated` 并广播事件。

复制副本是热更新的前提，细节见 `04/05`。

### 6.2 侧车轨道

七步：校验清单 → 选空闲回环端口 → 起进程并用 `LING_SOCKET` 传端点、`LING_TOKEN` 传握手口令 → 等待连接建立，最多 10 秒→ 首帧 `hello` 协商版本 → 发 `activate` 等待注册完成，最多 10 秒→ 状态改 `Activated`。

先起进程再握手：端点由宿主选好传进去。

### 6.3 失败回滚

按账本倒序撤销本次登记；进程内不 `dlclose`，只标 `Failed`；侧车结束进程；广播 `crashed` 之外的状态事件；返回首个错误码。

---

## 7. 卸载流程

六步：停用下游 → 调 `on_deactivate` → 账本倒序撤销 → 移出四张表 → 删工件留 `data/` → 触发调和。

撤销失败记 `E_UNDO_FAILED` 并继续，最后返回 `E_UNINSTALL_INCOMPLETE`，工件仍然删除。

侧车额外：`deactivate` 给 5 秒宽限，没回应发 `shutdown` 再给 5 秒，仍未退出则结束进程。

## 8. 侧车协议

### 8.1 帧格式

jsonl，每行一个 JSON，UTF-8，`\n` 结尾，单行不超过 1 MB。

公共字段：`v`（协议版本，当前 1）、`id`、`op`、`trace`。响应统一 `{"v":1,"id":7,"ok":true,"result":{...}}` 或带 `error`。

### 8.2 侧车到宿主七种

| `op` | 时机 | 字段 |
|---|---|---|
| `hello` | 连接后第一帧 | `v`、`plugin_id`、`plugin_version`、`token` |
| `register_method` | activate 期间 | `name`、`requires` |
| `subscribe` | activate 期间 | `pattern` |
| `call` | 调别的插件 | `method`、`args`、`trace` |
| `emit` | 广播 | `topic`、`payload`、`trace` |
| `result` / `error` | 响应 `invoke` | `id`、结果或错误 |
| `deactivated` | 清理完 | 无 |

`register_method` 不带撤销函数（侧车交不出函数指针），宿主记「声明」并代为注销，这是两轨在账本上的唯一差别。

### 8.3 宿主到侧车五种

`activate`（带 `plugin_id`、`generation`、`data_dir`）、`invoke`、`event`、`deactivate`、`shutdown`。

### 8.4 握手与认证

连上即发 `hello` → 宿主先校验 `token`（与 `LING_TOKEN` 常量时间比较，不符回 `E_AUTH` 并断开）→ 再比对 `v`，不同则回 `E_API_MISMATCH` → 比对 `plugin_id` → 发 `activate`。

认证先于协商：未通过认证的连接不能探测协议版本。`LING_TOKEN` 每次启动重新生成，不落盘，只经环境变量传递。握手前收到其他 `op` 一律 `E_PROTOCOL`。

### 8.5 崩溃与重启

断连后：撤销其全部效应 → 广播 `crashed` → 按 `restart` 决定。

`on-crash`：正常退出不重启，异常退出 2 秒内重启，连续 3 次失败转 `Failed`。`always`：任何退出都重启，同样 3 次上限。`never`：保持停止。

### 8.6 数据面不走控制面

控制面只传参数、载荷、状态。文件内容与大块二进制不进 JSON 帧，侧车自己读写 `data_dir()`，另一侧只传路径。单帧上限 1 MB。

### 8.7 常驻与按需

| 规则 | 内容 |
|---|---|
| 默认 | 按需：装载后退出，调用时再起 |
| 常驻判定 | 清单 `restart = "always"` |
| 常驻上限 | 默认 1 个 Python 侧车；进程内不受限 |
| 空闲退出 | 超过 `idle_timeout`（默认 60 秒）退出 |
| 冷启动代价 | 约 200 毫秒，计入 `LING-REQ-095` |

C++ 侧车每进程约 10 至 15 MB，不受 1 个的限制，但计入总预算。

## 9. 已定结论

本节原为未决问题，2026-10-29 逐条按建议结案。结论里标「本期设定」的，是没有需求依据、由本文估定的取值——写代码时觉得不对可以改，改这里一处即可，不影响需求与接口。
| # | 事项 | 结论 |
|---|---|---|
| 1 | `write_config` 依赖可卸载的 core-settings | 卸载后返回 `E_PLUGIN_MISSING`，插件自行处理 |
| 2 | `hello` 不带能力声明 | 能力在 `register_method` 的 `requires` 里体现 |
| 3 | 重启 3 次上限无需求依据 | 保留，写进清单约束 **本期设定** |
| 4 | 新增四个错误码的命名 | 已按族归位 |
