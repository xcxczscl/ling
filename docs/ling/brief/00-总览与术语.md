## 1. ling 是什么

### 1.1 一句话

ling 是零内容的插件宿主，只负责让插件能安全地装上、调用、卸载、替换。

### 1.2 "零内容"的边界

| ling 有（机制） | ling 没有（内容） |
|---|---|
| 加载、卸载、热更新插件 | 窗口、导航、主题、图标 |
| 转发插件之间的调用 | 任何界面页面 |
| 广播事件 | 设置页面 |
| 检查插件声明的能力 | 插件管理的操作界面 |
| 解析依赖、自动激活与停用 | 任何业务概念 |
| 管理端口 | 业务逻辑 |
| 可逆效应账本 | 文件存储、数据库、网络协议 |

判断标准：少了它宿主就不成立的功能属于 ling；用户能感知到的某个用途属于插件。

### 1.3 为什么这么分

- 加功能不用改宿主；
- 宿主代码量小，维护成本可控；
- 插件出问题只影响自己。

## 2. 定位、目标与非目标

### 2.1 定位

插件宿主 + 功能插件。ling 本体只做宿主，实用功能全部由插件提供。

### 2.2 目标

| 目标 | 具体含义 |
|---|---|
| 个人使用 | 单机、单用户；不做账号体系、多用户权限、云端同步 |
| 当工具用 | 解决自己实际要做的事，不做通用框架 |
| 插件可独立演进 | 单个插件坏了，宿主和其他插件不受影响 |
| 装了就能用 | 装插件不重启宿主，改插件不重启宿主 |
| 多平台 | 同一套插件生态在多个操作系统上可用，清单见 2.4 |

### 2.3 非目标

| 非目标 | 说明 |
|---|---|
| 不做大型系统 | 几十个插件规模；不做分布式部署、多节点协同 |
| 不做多人协作平台 | 不做多人同时使用、权限分级 |
| 不做插件市场 | 不做在线分发、评分、付费 |
| 不做通用开发框架 | 只为自己的插件服务，不承诺第三方生态兼容 |

### 2.4 平台

| 平台 | 角色 | 说明 |
|---|---|---|
| Windows | 主要开发与使用平台 | 功能完整，MVP 优先做这个 |
| Linux | 次要运行平台 | 功能对齐 Windows，沙箱更完整 |
| Android | 受限运行平台 | 受系统权限限制，部分功能降级；范围待定 |

插件产物按平台不同：Windows `.dll`，Linux `.so`，Android `.so`。

### 2.5 规模参照

| 维度 | 量级 |
|---|---|
| 插件数量 | 几十个 |
| 单机数据量 | TB 级 |
| 同时在线用户 | 1 人 |

## 3. 谁在用 ling

| 角色 | 与 ling 的接触点 |
|---|---|
| 插件作者，即我自己 | 按接口规范写动态库或侧车程序，放进插件目录 |
| 使用者，即我自己 | 用插件提供的网页界面操作；用 `ling` 命令行管理宿主与插件 |
| 插件 | 通过宿主互相调用、订阅事件，不直接通信 |
| 维护者，即我自己 | 按运行时预案排查；用 `ling reload` 更新插件 |

## 4. 贯穿示例：装一个插件的全过程

| 步骤 | 做了什么 | 触发的机制 |
|---|---|---|
| 1 | 首次启动 | 内核启动、管理端口监听 |
| 2 | 内置插件自动加载 | 清单解析 → 依赖解析 → 依次激活 |
| 3 | 浏览器看到插件管理页 | 界面由 core-ui 插件提供，ling 不开窗口 |
| 4 | `ling install resources-manager` | 重算依赖 → 激活 → 界面出现入口 |
| 5 | 停用的记账插件自动恢复 | 依赖满足 → 自动激活 |
| 6 | `ling reload resources-manager` | 停用旧版 → 撤销效应 → 装载新版 → 重新激活；宿主不重启 |
| 7 | `ling uninstall ledger` | 倒序执行账本：注销方法、退订事件、撤下界面、停止侧车 |
| 8 | 卸载 resources-manager 后按钮消失 | 依赖失效 → 自动停用（挂起非卸载）；装回后自动恢复 |

| 疑问 | 答案 |
|---|---|
| 卸载会不会留垃圾 | 不会，账本逐条撤销 |
| 装新插件要不要重启 | 不用，重算依赖后自动激活 |
| 改插件代码要不要重启全局 | 不用，只换那一个插件 |

## 5. 术语

### 5.1 分级说明

- 公共术语登记在 `docs/common/01-术语表.md`，本文不重复。
- ling 专属术语在 5.2–5.5 定义，其他文档引用本节。

术语格式：定义 + 例子 + 它不是什么。

### 5.2 与加载相关

| 术语 | 定义 | 例子 | 它不是什么 |
|---|---|---|---|
| 清单 | 插件目录里的 `plugin.toml`，写明编号、版本、需要的能力、依赖谁 | resources-manager 声明需要读写文件能力 | 不是说明文档，是给程序解析的配置 |
| 动态库 | 运行时能被打开的文件：Windows 是 `.dll`，Linux 是 `.so` | `resources_manager.dll` | 不是可执行程序，不能独立运行 |
| 卸载 | 移除插件：按账本撤销全部效应 → 删除或停用文件 | `ling uninstall ledger` | 不等于停用 |
| 停用 | 暂停工作但保留安装：撤销效应，文件仍在 | resources-manager 缺失时记账插件停用 | 不是卸载，可随时恢复 |
| 激活 | 停用插件恢复工作：重新登记效应、恢复依赖 | 装回 resources-manager 后记账插件被激活 | 不是"启动"，专指依赖满足后进入工作状态 |

### 5.3 与上下文相关

| 术语 | 定义 | 例子 | 它不是什么 |
|---|---|---|---|
| 效应账本 | 宿主为每个插件单独记的账：注册过什么、每项怎么撤销 | "第 1 条：注销方法 scan.start" | 不是操作日志，账本给机器执行 |
| 逆操作 | 撤销某次修改的函数，随修改一起登记 | 注册方法时交出"注销该方法"的闭包 | 不是删除数据，是精确恢复到修改前 |
| 效应种类 | 注册方法、订阅事件、配置写入、启动侧车、登记停用回调 | 一个插件最多 5 类 | 不是业务动作；界面贡献记在 core-ui 账上 |
| 隔离命名空间 | 每个插件效应带自己的前缀，互不可见 | `ledger.` 前缀 | 不是安全沙箱，内存仍共享 |
| 违规效应 | 插件绕过上下文直接做的修改 | 直接调系统删除文件而不登记 | ling 检测不到，视为作者违约 |

### 5.4 与依赖相关

| 术语 | 定义 | 例子 | 它不是什么 |
|---|---|---|---|
| 需求声明 | 清单里的 `requires` 段 | `requires = ["capability:fs", "plugin:resources-manager@1.x"]` | 不是编译期依赖，是运行时重判的需求 |
| 满足 | 某条需求当前成立 | 已安装且已激活 → 满足 | —— |
| 依赖图 | 所有需求连成的有向图 | 装卸插件后图会变 | 不是文件目录树 |
| 激活计划 | 调和算出的有序清单 | 先 core-ui，再 resources-manager，最后 ledger | 不是任务队列 |
| 传递依赖 | A 依赖 B、B 依赖 C，则 A 间接依赖 C | 记账 → resources-manager → core-ui | —— |
| 循环依赖 | 依赖成环 | —— | 不允许，检测到即拒绝加载并报错 |

### 5.5 与热更新相关

| 术语 | 定义 | 例子 | 它不是什么 |
|---|---|---|---|
| 重载 | 停用 → 撤销效应 → 替换产物 → 装载 → 重新激活 | `ling reload resources-manager` | 不是重启整个程序 |
| 持久文件 | 插件存在 `plugins/<编号>/data/` 下的状态文件 | 目录数据库 | 不是插件产物本身 |
| 装载失败回滚 | 新版本装载出错时装回旧版本 | 新清单写错 → 自动回滚 | 不是留下半新半旧状态 |

### 5.6 与日志相关

| 术语 | 定义 | 它不是什么 |
|---|---|---|
| 内核日志 | 宿主自己写的运行记录，内置，不依赖插件 | 不是插件日志，也不是效应账本 |
| 插件日志 | 插件经 `Context` 交出、由 core-log 收集的记录 | 宿主不替插件判断记什么 |
| core-log | 内置插件，给其他插件提供日志收集与查询 | 不是内核日志的载体，卸掉不影响宿主记录 |
| trace id | 一次操作的短编号，串起它引发的全部日志 | 不是会话编号，只覆盖一次操作 |
| 日志级别 | error / warn / info / debug，默认 info | 决定是否输出，不决定属于谁 |
