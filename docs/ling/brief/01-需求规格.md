## 1. 目的与范围

### 1.1 管什么

- 只管 ling 宿主（`LING`），不管插件功能。
- 只管"做到什么"，不管"怎么做"。
- 编号 `LING-REQ-001` 起连续分配，全文档唯一，不复用；作废需求保留编号。

### 1.2 不管什么

| 不做 | 归属 |
|---|---|
| 界面、导航、设置页 | core-ui、core-settings 插件 |
| 配置存储、作业调度 | core-settings、core-job |
| 插件日志的收集与查询 | core-log；内核自身日志由宿主内置，不依赖它 |
| 业务功能（整理文件、播放内容） | resources-manager、player 插件 |
| 插件市场、在线分发 | 非目标 |
| 进程内安全沙箱 | 非目标 |
| 形式化验证 | 非目标 |
| 多用户、账号、权限分级 | 非目标 |

### 1.3 与里程碑、MVP 的关系

不标优先级，不标实现阶段。排期与 MVP 归属由 `docs/ling/10-路线图与里程碑.md` 与 `docs/ling/11-MVP 范围.md` 决定。

### 1.4 条目格式

| 字段 | 含义 |
|---|---|
| 编号 | `LING-REQ-xxx` |
| 需求 | 必须成立的行为 |
| 验收标准 | 能判真假的检查方式 |
| 平台 | `三平台` = 都要求；`W L` = Android 见第 5 节 |

第 4 节数字一律是上限。测量前提：release 构建、4 核桌面 CPU、本地 SSD、单线程、空处理函数。数字来源：089–093 沿用 old 的性能预算；094–102、104–107 为本轮设定的设计目标，尚无实测依据。每个数字后附估算依据，那是纸面推算，不是实测值。

### 1.5 运行时目录与源码目录

| 类别 | 例子 | 现在存在吗 | 进版本库吗 |
|---|---|---|---|
| 源码目录 | `main/`、`plugins/`、`docs/` | 存在，代码目录为空 | 是 |
| 运行时数据目录 | `<数据根>`、`plugins/<编号>/`、`data/`、`logs/` | 不存在，首次运行才出现 | 否 |

需求里写的目录是「跑起来之后应该长什么样」，不是仓库里已建好的文件夹。`<数据根>` 取值见 `docs/ling/03-架构设计.md` §6.3。

## 3. 功能需求

### 3.1 装载与卸载

| 编号 | 需求 | 验收标准 | 平台 |
|---|---|---|---|
| LING-REQ-001 | 插件从 `plugins/<编号>/` 读取，目录名等于清单 `id` | 目录名与 id 不符时拒绝装载，返回 `E_MANIFEST_INVALID` | 三平台 |
| LING-REQ-002 | 必填 `id`、`version`、`api`，缺项拒绝装载并指出缺项 | 逐个删字段均被拒，message 含字段名 | 三平台 |
| LING-REQ-003 | `id` 满足 `^[a-z0-9][a-z0-9-]*$`，长度 ≤ 64 | 大写、下划线、首字符短横线、65 字符四种输入全部被拒 | 三平台 |
| LING-REQ-004 | `version` 为三段式，每段 0–65535；宿主只校验格式，不限制递增方式 | `1.0`、`1.0.0.0`、`70000.0.0` 全被拒 | 三平台 |
| LING-REQ-005 | `api` 落在宿主支持范围（当前及前一主版本），不符返回 `E_API_MISMATCH`，其他插件状态不变 | api=99 被拒时其他插件仍 activated | 三平台 |
| LING-REQ-006 | 出现绝对路径或 `..` 拒绝；`sidecar.executable` 必须在插件目录内且可执行 | 三种非法写法全部被拒 | 三平台 |
| LING-REQ-007 | 安装源支持目录与 zip；一律拷贝进 `plugins/<编号>/`，删除原位置不影响已装插件 | 删原目录后插件仍 activated，可调用 | 三平台 |
| LING-REQ-008 | 一个插件只有一种产物：动态库或侧车 | 并存或都缺均被拒 | 三平台 |
| LING-REQ-009 | 重复编号安装被拒，提示先卸载或升级 | 第二次安装失败，原插件状态不变 | 三平台 |
| LING-REQ-010 | 卸载移除安装工件，保留 `data/`；`--purge` 连 `data/` 删除 | 卸载后只剩 `data/`；`--purge` 后目录不存在 | 三平台 |
| LING-REQ-011 | 已安装判定为 `plugin.toml` 存在；只剩 `data/` 可重装并沿用原数据 | 删 `plugin.toml` 后不列出；重装后数据一致 | 三平台 |
| LING-REQ-012 | 卸载顺序：停用下游 → `on_deactivate` → 账本倒序 → 移出装载表 → 触发调和 | 四类动作顺序正确，账本序号严格递减 | 三平台 |
| LING-REQ-013 | 撤销失败记录 `E_UNDO_FAILED`、继续其余，最终报告未撤销清单 | 令第 2 条失败，第 1、3 条仍执行 | 三平台 |

### 3.2 调用路由与事件广播

| 编号 | 需求 | 验收标准 | 平台 |
|---|---|---|---|
| LING-REQ-014 | 方法名必须带本插件编号前缀，否则拒绝注册并返回 `E_NAMESPACE_VIOLATION` | 无前缀被拒，带前缀成功 | 三平台 |
| LING-REQ-015 | `call` 按（编号，方法名）路由；同进程为直接函数调用，不做序列化 | P95 ≤ 1 微秒（见 089） | 三平台 |
| LING-REQ-016 | 目标未安装或未激活返回 `E_PLUGIN_MISSING`；方法未注册返回 `E_METHOD_MISSING` | 两种错误码正确，其他方法不受影响 | 三平台 |
| LING-REQ-017 | 同步调用超时 30 秒返回 `E_TIMEOUT`；`call_async` 不设宿主超时 | 睡 31 秒的同步调用返回 `E_TIMEOUT` | 三平台 |
| LING-REQ-018 | 订阅支持前缀通配，`demo-b.*` 与 `*` 均可 | 三种模式订阅后收到条数符合预期 | 三平台 |
| LING-REQ-019 | 广播主题必须以本插件编号开头，`kernel.` 只允许内核；越权返回 `E_NAMESPACE_VIOLATION` 并记录 | 越权广播被拒且留记录 | 三平台 |
| LING-REQ-020 | 广播不入账，订阅入账一条 EventSubscribed | 广播 100 次条目数不变；订阅 1 次加 1 | 三平台 |
| LING-REQ-021 | 同步派发、按登记顺序、不落盘不重投；单回调超 5 秒跳过该订阅者并记录 | 3 个订阅者中第 2 个睡 6 秒，第 1、3 个照常收到 | 三平台 |
| LING-REQ-022 | 内核广播 `kernel.plugin.state`（activated / deactivated / uninstalled / failed / crashed）与 `kernel.plan.step`（每步一条） | 事件可录制，plan.step 条数等于计划步数 | 三平台 |

### 3.3 能力门禁

| 编号 | 需求 | 验收标准 | 平台 |
|---|---|---|---|
| LING-REQ-023 | 能力集首版为 `fs`、`network`、`ui`、`shell`；集合外取值拒绝装载，返回 `E_CAPABILITY_UNKNOWN` 并提示宿主版本过旧 | 声明 `gpu` 被拒，message 含"宿主版本过旧" | 三平台 |
| LING-REQ-024 | 方法 `requires` 必须 ⊆ 清单 `capabilities`，否则拒绝注册 | 清单缺 `network` 时方法注册失败 | 三平台 |
| LING-REQ-025 | 调用瞬间核对目标生效能力（清单 − 撤销黑名单），不覆盖返回 `E_CAPABILITY_DENIED` | 撤销 `fs` 后调用其 `fs` 方法被拒 | 三平台 |
| LING-REQ-026 | 撤销能力后插件仍激活，只有依赖该能力的方法被拒；撤销状态持久化 | 重启后仍被拒，插件仍 activated | 三平台 |
| LING-REQ-027 | 门禁只判资格，不限制具体路径或地址 | 声明 `fs` 后可读写任意用户可访问路径 | 三平台 |

### 3.4 上下文与效应账本

| 编号 | 需求 | 验收标准 | 平台 |
|---|---|---|---|
| LING-REQ-028 | 修改共享环境必须经 `Context`，Context 由内核注入，插件不能自行构造 | 公开 API 无构造入口 | 三平台 |
| LING-REQ-029 | `register_method` 必须同时提交撤销函数，空函数拒绝注册 | 省略参数编译失败；传空函数返回 `E_LEDGER_INVALID` | 三平台 |
| LING-REQ-030 | `subscribe` 同样为必填参数，空函数拒绝注册 | 同上 | 三平台 |
| LING-REQ-031 | 账本记五类效应：方法注册、事件订阅、配置写入、侧车启动、停用回调；线程与句柄不入账 | 五类各触发一次条目正确；开线程后条目数不变 | 三平台 |
| LING-REQ-032 | 账本只增不改，每条有序号、种类、描述、撤销闭包 | 卸载时序号严格递减 | 三平台 |
| LING-REQ-033 | 账本不落盘，启动时重建 | 重启前后目录内无账本文件 | 三平台 |
| LING-REQ-034 | 只能读自己的账本 | 条目数等于自身效应数，无查他人账本的入口 | 三平台 |
| LING-REQ-035 | `data_dir()` 返回 `plugins/<编号>/data/`，activate 前已存在 | activate 内立即写文件成功 | 三平台 |
| LING-REQ-036 | `on_deactivate` 在停用、卸载、重载各调一次，早于账本撤销 | 三场景各一次，顺序正确 | 三平台 |
| LING-REQ-037 | 账本互相隔离，不能注销他人方法 | 同名注册后者失败，注销只影响自身 | 三平台 |
| LING-REQ-038 | 绕过 Context 的修改不还原；`doctor` 只报可观测迹象 | 越权尝试有记录，无"已还原"类输出 | 三平台 |

## 4. 非功能需求

前提：release 构建、4 核桌面 CPU、本地 SSD、单线程、空处理函数。下表数字均为上限。

### 4.1 性能

| 编号 | 指标 | 上限 | 估算依据 |
|---|---|---|---|
| LING-REQ-089 | 同进程方法调用（仅进程内轨道） | P95 ≤ 1 微秒，P99 ≤ 3 微秒 | 一次间接调用加两次哈希查找约 300–500 纳秒，留 2 倍；前提是读路径不加锁 |
| LING-REQ-090 | 广播到 10 个订阅者 | P95 ≤ 10 微秒 | 单次派发约 300 纳秒，10 个订阅者含主题匹配约 2 微秒，留 5 倍 |
| LING-REQ-091 | 单个动态库插件装载（进程内轨道） | ≤ 50 毫秒 | dlopen 5 MB 库约 5–15 毫秒，activate <1 毫秒，余量覆盖冷缓存与杀毒扫描 |
| LING-REQ-092 | 依赖图全量重算（50 插件、100 边） | ≤ 1 毫秒 | 建图与拓扑排序约 100 微秒，留 10 倍 |
| LING-REQ-093 | 侧车控制面一次往返 | P95 ≤ 100 微秒 | 本地 TCP 往返约 20–40 微秒，小 JSON 编解码约 5 微秒 |
| LING-REQ-094 | 冷启动到端口可连接（plugins 为空） | ≤ 300 毫秒 | 进程启动约 30–50 毫秒，扫目录与绑端口各 <1 毫秒，留 5 倍 |
| LING-REQ-095 | 冷启动到 20 插件全部激活（含 2 个 Python 侧车，按 200 毫秒计） | ≤ 1500 毫秒 | 20 × 50 毫秒 = 1000 毫秒，图重算 <1 毫秒，2 个侧车各约 200 毫秒 |
| LING-REQ-096 | install / uninstall / reload 端到端 | ≤ 500 毫秒 | 进程启动 30 毫秒 + 连接认证 5 毫秒 + 装载与调和 60 毫秒 |
| LING-REQ-097 | 单次调用参数与事件载荷 | ≤ 1 MB，超出返回 `E_PAYLOAD_TOO_LARGE` | 1 MB JSON 编解码约 1–3 毫秒；典型参数小于 10 KB，留 100 倍 |

### 4.2 资源占用

| 编号 | 指标 | 上限 | 估算依据 |
|---|---|---|---|
| LING-REQ-098 | 空闲 CPU | ≤ 1% 单核（60 秒平均） | 无请求时每秒唤醒不足 10 次，1% 等于每秒 10 毫秒预算 |
| LING-REQ-099 | 常驻内存 | 内核加 20 个空载插件 ≤ 120 MB；每个空载 Python 侧车 ≤ 40 MB | 主程序 15 MB + 20 × 3 MB + 表与账本 1 MB ≈ 76 MB，留 1.5 倍；Python 空载 25–30 MB；C++ 预估 60–90 MB，实测后写回 |
| LING-REQ-100 | 单插件账本条目 | ≤ 10000 条，超出后新增效应报错 | 每条约 200 字节，10000 条约 2 MB；激活期注册量通常在 100 条以内 |
| LING-REQ-101 | 100 次连续 reload 后内存增长 | ≤ 50 MB，达 30 MB 提示重启 | 私有副本每次留下一个映射，10 MB 达不到；50 MB 是明显泄漏线 |
| LING-REQ-102 | 管理端口并发连接 | 32 条 | 界面 1–2 条 + 命令行 1 条；每条约 16 KB |

4.3 至 4.5 的数字是判定阈值：2 秒（侧车恢复）= 进程创建 50–200 毫秒的十倍；5%（24 小时增长）= 无泄漏时 RSS 波动低于 2%；30 秒（1000 次调用完成）= 每次 1 毫秒的 30 倍；20 毫秒（200 插件调和）= 建图排序 2 毫秒的十倍；30 秒（调用超时）= 单次调用可花时间的上限；64 MB 与 7 天（日志）= 每天 10 万行、每行 200 字节的 3 倍。
