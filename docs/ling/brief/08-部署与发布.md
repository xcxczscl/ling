## 2. 支持平台与产物形态

### 2.1 三端产物

| 平台 | 产物 | 形态 |
|---|---|---|
| Windows | `ling-<版本>-win-x64.zip` | 免安装，解压即用，不写注册表 |
| Linux | `ling-<版本>-linux-x64.tar.gz` | 压缩包 + `install.sh` |
| Android | `ling-<版本>-android-arm64.apk` | 只作宿主启动器与前台服务，不做界面 |

三端自包含：Python 运行时（仅桌面）、核心插件、头文件都在包里。

### 2.2 包内结构

宿主与命令行、`plugin_api.h`、`sdk.hpp`、五个内置插件、`python/`、README、第三方许可证、`checksums.txt`。

五个内置插件放包根目录而非 `plugins/`：首次启动由宿主复制进数据根，放在只读位置也能运行。

### 2.3 Android 的特殊性

| 项 | 情况 |
|---|---|
| 界面 | 无原生界面，用浏览器打开 `127.0.0.1:7910` |
| 谁拉起宿主 | apk 的前台服务 |
| 通知栏 | 常驻「ling 运行中」 |
| 后台被杀 | 宿主一起退出，重开 apk 即可 |
| 插件 | 只有进程内与 C++ 侧车，**没有 Python 侧车** |

「没有 Python 侧车」必须写进发布说明，否则用户会以为同一插件包三端都能装。

不做：原生界面、开机自启、保活手段。平台的默认回收行为与「常驻宿主」冲突，硬保活要付电池与系统限制的代价。

## 3. 版本与发布

### 3.1 版本号

按 `docs/common/02-版本号与兼容约定.md`：`bN` 是构建序号不是测试轮次；功能变化加次版本；不兼容加首要版本并同时升 `api`。

### 3.2 什么时候算一次发布

| 时机 | 版本动作 | 产物 |
|---|---|---|
| 切片完成、全量回归通过 | `bN` 加一 | 三端包 |
| 一批功能做完 | 次版本加一 | 三端包 |
| 改清单字段、协议帧、错误码语义 | 首要版本加一，`api` 同步加 | 三端包 + 迁移说明 |
| 只改文档 | 不动版本，不打标签 | 无 |

### 3.3 标签与产物命名

标签 `v<版本>`；产物 `ling-<版本>-<平台>-<架构>.<扩展名>`；包内 `checksums.txt` 一行一条 sha256；pdb 单独打包作为附件。

pdb 不进主包：主包给使用者，pdb 只在排查崩溃时需要，放一起会让包大一倍。

## 4. 首次安装

### 4.1 Windows

解压到任意目录（**不要放 `Program Files`**），在该目录执行 `ling.exe serve`，浏览器打开 `http://127.0.0.1:7910`。

不写注册表、不建开始菜单、不改 PATH。不提供安装包：安装包要处理卸载登记、升级覆盖、提权，对个人工具是负担；解压即用还能并存多个版本，回滚靠这个。

### 4.2 Linux

直接解压使用，或跑 `install.sh` 装到 `~/.local`。脚本只做四件事：复制、建软链接、检查 PATH、打印结果。不碰系统目录，不需要 sudo。

### 4.3 Android

装 apk（需允许未知来源）→ 打开点启动 → 通知栏出现「ling 运行中」→ 浏览器打开应用内显示的地址。

apk 只做三件事：启动宿主、显示地址、提供停止按钮。再做原生界面等于两套界面要维护。

### 4.4 首次启动做什么

八步，任一步失败退出并打印原因：

1. 解析数据根（`--data-dir` > `LING_DATA_DIR` > 平台默认）
2. 创建数据根，权限 0700 或仅当前用户 DACL
3. 创建 `logs/`、`plugins/`，继承父目录权限
4. 生成 `session.json`（0600）
5. 选端口（7900 起顺延），写 `registry.json`
6. 扫描 `plugins/`，为空则从程序目录装五个内置插件
7. 启动 `core-ui`，写 `ui_port`；失败记 warn 但宿主继续
8. 打印四行：数据根、端口、界面地址、口令文件位置

第 2 步由宿主自己设权限，不依赖安装器——解压即用的包与将来的安装包行为一致。

第 6 步从**程序目录**复制：程序目录可只读，数据根必然可写。

第 8 步的四行输出解决「首次安装不知道去哪看端口与口令」。

## 5. 升级

### 5.1 手动替换的步骤

1. `ling shutdown` 或界面点停止
2. 确认进程已退出
3. 备份 `settings.json`（建议）
4. **解压到新目录，不覆盖旧目录**
5. 用新目录启动，数据根不变
6. 跑 `ling doctor` 确认四项正常

第 4 步是关键：覆盖会让回滚失去旧文件，且 Windows 上正在加载的 dll 无法覆盖。

### 5.2 数据与配置的兼容

| 内容 | 处理 |
|---|---|
| `plugins/<编号>/data/` | 内核不迁移，插件自己迁 |
| `settings.json` | 带 `schema_version`，`core-settings` 启动时按需迁移 |
| `registry.json` | 缺字段补默认值，多出的忽略 |
| `logs/` | 不动 |
| `session.json` | 每次启动重新生成 |

`settings.json` 的结构：

```json
{"schema_version": 1, "entries": {"demo-a.timeout": {"v": 30, "updated_at": "..."}}}
```

迁移规则：无字段视为 1；低于当前逐级迁移并先备份为 `settings.json.bak-<旧版本>`；**高于当前则拒绝启动**。

最后一条必须做：旧版本读到新格式时容易把不认识的字段丢掉，写回就降级了配置。宁可拒绝。

### 5.3 内置插件的新增与跳过

新增的自动装（先校验 `min_host`）；用户主动卸掉的不再装回；编号被业务插件占用的不装并记 warn；内置插件版本随宿主升，覆盖安装但保留 `data/`。

### 5.4 `api` 的兼容范围

宿主支持当前主版本与前一版本：`api=1` 只能装 1；`api=2` 能装 1 与 2。

升 `api` 主版本要三件事：首要版本加一、写迁移说明、保留前一版本支持至少一个大版本周期。

第三条的实际含义：宿主 `api=2` 时 `api=1` 的插件仍能用，升级不必一次改完所有插件。

## 6. 回滚

### 6.1 保留上一版

升级不覆盖旧目录，多个版本并排存在。回滚 = 用旧目录启动，数据根不变。留两三个旧版本即可。

### 6.2 数据格式回退的风险

| 内容 | 风险 | 应对 |
|---|---|---|
| `settings.json` | 新版升过 `schema_version` 后旧版拒绝启动 | 升级前备份；迁移时自动备份 |
| 插件 `data/` | 插件自己改过格式，旧版读不懂 | 无通用解法，插件自己保向下兼容 |
| `logs/` | 无 | —— |
| `registry.json` | 旧版忽略不认识的字段 | 无 |

第二条没有宿主层兜底：内核不碰插件数据，也就无法替它迁移或回退。责任在插件的作者。

### 6.3 什么时候该回滚

启动不了、目录或插件加载失败而旧版正常、数据被写坏、性能明显退化（先看 `bench-history.csv` 确认是版本问题）。

**界面不可用不必回滚**：界面是侧车，卸掉重装即可。为此回退整个版本是过度反应。

### 6.4 回滚之后要做什么

用旧版启动确认 `doctor` 正常 → 把问题记入 `docs/log/`（含版本、现象、复现）→ **保留新版目录不要删**，修好还要用。

## 7. 卸载

### 7.1 两种程度

保留数据（删程序目录，数据根留着，重装后接着用）或彻底清除（都删）。没有卸载程序与注册表项，因为没装进系统。

### 7.2 手工清理清单

程序目录；数据根（Windows `%APPDATA%\ling`，Linux `~/.local/share/ling`，Android 应用私有目录）；Linux 的 `~/.local/bin/ling` 软链接；Android 卸载时选「清除数据」。

注意：删了程序目录但留着数据根，下次装新版会接着用旧数据——有时是想要的（升级），有时不是（想重来）。

### 7.3 卸载前的建议

先 `ling plugins` 看装了什么；备份 `settings.json`；备份重要的 `plugins/<编号>/data/`（例如媒体库索引，重建要几小时）。

## 8. 分发

### 8.1 放哪

源码进私有仓库；二进制进同一仓库的 Releases，每标签一组三端包；文档随源码。

不进 winget、apt、Homebrew：私人使用，入库审核的收益为零。

### 8.2 产物清单与校验和

三端包、`checksums.txt`、pdb 压缩包（仅 Windows）、迁移说明（若升了 `api` 主版本）。

`checksums.txt` 的作用不是防篡改（自己给自己签名没有意义），是**验证下载完整性**。

### 8.3 不做的事

CI 自动构建发布、代码签名证书、自动更新、灰度发布、安装包与注册表。

不做签名的代价：Windows 首次运行会弹 SmartScreen，选「仍要运行」。这是不做签名的直接后果，不是 bug。

| # | 检查 | 依据 |
|---|---|---|
| R1 | 界面能打开、五个页签可切换 | `07` M1 |

| R3 | `doctor` 四项正常 | `07` M5 |
| R4 | 打包产物在干净账户能启动 | `07` M7 |
| R5 | 转储能被调试器打开并解析符号 | `07` M6 |
| R6 | Android 真机装插件并调用 | `07` M4 |
| R7 | `checksums.txt` 与包内文件一致 | 本文 |
| R8 | 包内不含 `data-test/`、`.dmp`、日志、调试符号 | 本文 |
| R9 | 版本号与标签一致 | 本文 |
| R10 | 从上一版升级到本版，`doctor` 无新增问题 | 本文 |

R8 最容易漏：打包按白名单复制而不是整目录压，就不会带进测试残留。

R10 要真做一遍：用上一版的包建数据根、装满插件，再用新版启动。
