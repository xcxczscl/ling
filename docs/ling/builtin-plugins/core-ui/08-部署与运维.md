# core-ui 08 部署与运维

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 依据：`docs/ling/builtin-plugins/core-ui/04-详细设计/05-进程形态与启动.md`、`docs/ling/main/08-部署与发布.md`

本文回答：装哪几个包、版本怎么兼容、怎么升级与回滚、出问题先看哪。

---

## 1. 发布产物

`core-ui` 不单独发版：它跟宿主一起打包，四个产物由宿主的构建开关决定。

产物名沿用宿主那套规则（`docs/ling/main/08-部署与发布.md` §2.1），`core-ui` 只是在包里的一份文件，不单独命名。形态作为后缀加在架构之后、扩展名之前：

| | 便携版 | 安装包 |
|---|---|---|
| `webui` | `ling-<版本>-win64-webui.zip` | `ling-<版本>-win64-webui-setup.exe` |
| `desktop` | `ling-<版本>-win64-desktop.zip` | `ling-<版本>-win64-desktop-setup.exe` |

后缀 `-webui` / `-desktop` 是 1.1.0 新增的维度，命名规则已回填到 `docs/ling/main/08-部署与发布.md` §3.3；该节同时规定了后缀在文件名里的位置（架构之后、扩展名之前）。

| 产物 | `core-ui` 的编译方式 | 子系统 | 界面在哪 |
|---|---|---|---|
| `*-webui` | `LING_CORE_UI_DESKTOP=OFF`（默认） | 控制台（就绪行走标准输出） | 默认浏览器 |
| `*-desktop` | `LING_CORE_UI_DESKTOP=ON`，链 WebView2 SDK | GUI | 独立窗口 |

四个包里的 `plugins/core-ui/` 目录是**两个文件**：`core-ui.exe` 加 `plugin.toml`。外壳页面在编译期已嵌进 exe，不带单独的前端文件；`plugin.toml` 由 CMake 的 `POST_BUILD` 命令拷到输出目录（`main/builtin-plugins/core-ui/CMakeLists.txt` 末尾），因此打包时不能只取 exe。

带面板的插件不改变打包：它们的 `ui/` 目录跟着插件自己的包走。

## 2. 版本与兼容

### 2.1 三个版本号各管什么

| 版本号 | 在哪 | 管什么 |
|---|---|---|
| 宿主版本 | `ling --version` | 整个发行包 |
| `core-ui` 版本 | `plugin.toml` 的 `version` | 界面进程的行为；1.1.0 起含面板能力 |
| 插件 API 版本 | `plugin.toml` 的 `api` | 清单与调用协议的兼容性；本次仍为 `"1"` |

`api` 不变是关键：1.1.0 只**新增**了 `[ui]` 段与 `ui` 能力的含义，没有改动任何已有字段或调用方式。老插件不需要任何修改。

### 2.2 `[ui]` 段不单独版本化

`[ui]` 跟随 `api` 走。判断依据：它是清单的一部分，而清单的兼容性由 `api` 统一保证。将来若 `[ui]` 需要不兼容的改动（例如改成数组），随 `api` 升到 `"2"` 一起做。

### 2.3 四种组合的行为

| 插件 | `core-ui` | 行为 |
|---|---|---|
| 无 `[ui]` | 任意版本 | 完全正常，只是没有界面 |
| 有 `[ui]` | 1.1.0 及以上 | 正常，侧边栏出现入口 |
| 有 `[ui]` | 1.0.0 | 装载成功（未知段被忽略），**没有界面**，其他功能正常 |
| 有 `[ui]` | 未安装 | 同上 |

第三行是兼容性的硬要求：**插件不得因为「面板没被显示」而报错或拒绝工作**。这条要写进插件开发规范，也是 `CUI-REQ-055` 的另一面。

「未知段被忽略」有代码依据：1.0.0 的清单解析只读取已知键，不因多出一段而拒绝（`main/src/kernel/manifest.cpp` 的 `require_string` 与 `table.get` 调用）。同一处的 `capabilities` 校验已接受 `ui` 取值，说明能力名早就留好，1.1.0 只是给它加上消费者。

### 2.4 向后兼容的边界

| 改动 | 是否需要升 `api` |
|---|---|
| 新增 `[ui]` 可选字段 | 否 |
| 新增消息类型 | 否（老面板不认的消息直接忽略） |
| 修改已有消息的字段名或语义 | 是 |
| 改变 `theme.css` 的令牌名 | 否，但要同步改面板；令牌名属于对外契约，改名要在一个版本里同时提供新旧两套 |
| 删除能力取值 | 是 |

## 3. 升级

### 3.1 从 1.0.0 升到 1.1.0

| 步骤 | 说明 |
|---|---|
| 1 | 关闭界面（不影响宿主里的定时任务） |
| 2 | 替换安装态下的 `<数据根>/plugins/core-ui/` 整个目录（两个文件一起换），或安装新版发行包 |
| 3 | 重启宿主，或让 `core-plugin-manager` 重载该插件 |
| 4 | 打开界面，确认侧边栏出现带面板的插件入口 |

配置不需要迁移：1.1.0 新增下面六个键，读到不存在时一律用默认值。

| 键 | 默认 | 作用 |
|---|---|---|
| `core-ui.theme` | `light` | 当前主题 |
| `core-ui.sidebar` | `true` | 侧边栏是否展开（当前状态） |
| `core-ui.sidebar_default` | `true` | 打开界面时的初始展开状态 |
| `core-ui.layout` | `{}` | 已开面板、槽位与宽度 |
| `core-ui.close_behavior` | `keep-host` | 关窗口时是否退出宿主（仅桌面版） |
| `core-ui.confirm_disable` | `true` | 停用插件时是否弹确认 |

六个键的类型与默认值以 `docs/ling/builtin-plugins/core-ui/03-架构设计.md` §8.1 的总表为准，本文不另维护一份。

### 3.2 升级后第一次打开

| 现象 | 说明 |
|---|---|
| 功能区是空的 | 正常：1.0.0 没有面板，`core-ui.layout` 为空 |
| 原来的管理视图不见了 | 它们搬进了「设置」，点侧边栏底部 |
| 界面是亮色 | 正常：`core-ui.theme` 默认 `light` |

### 3.3 插件侧要做的

| 插件 | 要做的事 |
|---|---|
| 已有插件（core-job、core-log、core-settings、core-plugin-manager） | 不用改。它们是管理功能的提供方，不是面板的提供方 |
| 将来带界面的插件 | 在清单加 `[ui]` 段、`capabilities` 加 `ui`、目录加 `ui/`；首屏用 `--ling-*` 令牌 |

## 4. 回滚

### 4.1 从 1.1.0 回到 1.0.0

| 步骤 | 说明 |
|---|---|
| 1 | 关闭界面 |
| 2 | 换回 1.0.0 的 `core-ui` 可执行文件 |
| 3 | 重启宿主 |

1.1.0 写入的五个 `core-ui.*` 键在 1.0.0 里不会被读取，留着无害。降级后侧边栏消失、原有视图回到一级界面，功能完整。

### 4.2 回滚会影响什么

| 影响 | 说明 |
|---|---|
| 面板消失 | 1.0.0 没有面板能力，带 `[ui]` 的插件退化成「无界面」 |
| 界面偏好失效 | 主题与布局不被读取；重新升级后恢复 |
| 插件本身 | 不受影响，方法照常可调 |

### 4.3 不建议回滚的情形

已经有人在用面板干活时不要回滚：回滚后他们的入口消失，会以为插件坏了。要回滚就同时通知使用者。

## 5. 排障

按现象查。每条都给「先看什么」，避免上来就翻代码。

| 现象 | 原因 | 处理 |
|---|---|---|
| 浏览器打开 8010 是空白页 | 端口被占顺延了，浏览器开的是旧地址 | `ling open`，它读 `registry.json` 的 `ui_port`；手敲地址前先看这个字段 |
| 侧边栏没有某个插件 | 插件没有 `[ui]` 段，或 `capabilities` 缺 `ui`，或 `[ui]` 校验失败 | `ling plugins` 看状态；`ling logs <插件>` 看装载错误 |
| 面板全白，外框正常 | 面板自己的脚本报错 | 用 `webui` 版打开浏览器 DevTools，切到该 iframe 看控制台 |
| 面板显示「面板文件不存在」 | `[ui].entry` 路径与实际文件不符 | 打开该插件的 `plugin.toml` 核对路径；改完重装 |
| 面板显示「面板文件读取超时」 | 磁盘慢或文件被占用 | 看 `ling logs core-ui` 有无读文件错误 |
| 切主题没反应 | `core-settings` 没启用，配置写不进去 | 启用它；或看提示「主题没能保存」 |
| 切主题后某个面板不变色 | 面板写死了颜色，没引用令牌 | 让该插件改成 `var(--ling-*)` |
| 侧边栏一直显示「ling 没有响应」 | 宿主在关闭过程，或界面持有的 token 已失效 | 重开界面；仍不行则 `ling logs core-ui` |
| 界面进程连续三次启动失败 | 8010 至 8099 全被占，或 token 不对 | 先看 `registry.json` 的 `ui_port` 与实际占用，再 `ling logs core-ui` 看具体原因 |
| 面板里的按钮报「没有权限」 | 面板调了别的插件的方法 | 这是防护生效，不是缺陷；改为经插件本体中转 |
| 界面打开就弹「口令已变」 | 宿主重启后换了 token，旧标签页还在 | 从主程序重新打开界面 |
| `desktop` 版没有窗口，只开了浏览器 | 系统缺 WebView2 运行时，已自动降级 | 正常行为；要窗口就装 WebView2 运行时 |

### 5.1 常用命令

```bash
ling plugins                 # 看 core-ui 是否在跑、状态是否正常
ling logs core-ui            # 界面进程的日志
ling open                    # 按 registry.json 的 ui_port 打开界面
curl -i http://127.0.0.1:8010/api/ui/theme.css   # 看当前主题的令牌
```

最后一条不需要 token，用来确认服务端活着并返回了主题。

## 6. 备份与恢复

界面自己不存文件，状态全在 `core-settings`：

| 键 | 丢失后的表现 |
|---|---|
| `core-ui.theme` | 回到 `light` |
| `core-ui.sidebar` | 侧边栏展开 |
| `core-ui.layout` | 不恢复上次的面板 |
| `core-ui.close_behavior` | 回到 `keep-host`（关窗口不退宿主） |
| `core-ui.window` | 窗口开在默认位置 |

这些键随 `core-settings` 的配置一起导出与还原。换机器时把配置带过去，界面偏好跟着走。

丢了也不影响可用性：全部有默认值。这是有意的设计——界面偏好不是数据。
