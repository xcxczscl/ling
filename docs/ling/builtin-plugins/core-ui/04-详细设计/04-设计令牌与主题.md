# core-ui 04 详细设计 04 设计令牌与主题

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 依据：`docs/ling/builtin-plugins/core-ui/02-技术选型.md` §10

本文回答：令牌有哪 26 个、亮暗两套取值是多少、主题怎么定义与切换、插件面板怎么用。

---

## 1. 命名规则

| 规则 | 说明 |
|---|---|
| 前缀 | 一律 `--ling-` |
| 分组 | 背景 `bg-*`、文字 `text-*`、线条 `border-*`、语义 `accent-*` `ok` `warn` `danger`、字号 `fs-*`、间距 `sp-*`、形状 `radius-*` `shadow` |
| 取值单位 | 颜色用十六进制（小写六位），长度用 `px` |
| 数量 | 26 个，不设「预留位」——需要新令牌时连同两套取值一起加 |

令牌只描述「色值与尺度」，不描述结构。它不提供 `.ling-button` 这类类名，插件自己的 DOM 结构自己定。

## 2. 令牌全表

### 2.1 颜色（14 个）

| 令牌 | 用途 | 亮色 | 暗色 |
|---|---|---|---|
| `--ling-bg` | 主背景 | `#ffffff` | `#1b1b1d` |
| `--ling-bg-raised` | 浮起面：卡片、弹窗、面板外框 | `#ffffff` | `#242427` |
| `--ling-bg-sunken` | 下沉面：侧边栏、输入框、代码块 | `#f6f7f9` | `#141416` |
| `--ling-text` | 正文 | `#1f2328` | `#e6e6e6` |
| `--ling-text-dim` | 次要文字：版本号、说明 | `#5b6472` | `#a0a7b4` |
| `--ling-text-invert` | 深色块上的文字 | `#ffffff` | `#141416` |
| `--ling-border` | 普通边框、分隔线 | `#d8dde5` | `#33383f` |
| `--ling-border-strong` | 强调边框：输入框、表格头 | `#b9c0cb` | `#4a515a` |
| `--ling-accent` | 主色：按钮、选中项、进度条 | `#2f6fed` | `#6f9bff` |
| `--ling-accent-hover` | 主色悬停 | `#2560d8` | `#8ab0ff` |
| `--ling-accent-fg` | 主色块上的文字 | `#ffffff` | `#10141c` |
| `--ling-ok` | 成功、已启用 | `#1a7f37` | `#4ac26b` |
| `--ling-warn` | 警告 | `#b26a00` | `#e0a33a` |
| `--ling-danger` | 危险、失败 | `#c0392b` | `#ff6b5e` |

提示条与标签的浅底色不设令牌，用 `color-mix` 现算：

```css
.notice-ok { background: color-mix(in srgb, var(--ling-ok) 12%, var(--ling-bg)); }
.tag-danger { color: var(--ling-danger); background: color-mix(in srgb, var(--ling-danger) 10%, var(--ling-bg)); }
```

这样省掉四个「状态底色」令牌，且新增语义色时不必再配一个底色。`color-mix` 在 WebView2 与 2023 年之后的 Chromium 内核浏览器可用；更老的浏览器整条声明失效，退化成透明底，不影响可读性。

### 2.2 字号（4 个）

| 令牌 | 取值 | 用途 |
|---|---|---|
| `--ling-fs-sm` | `12px` | 次要说明、表格辅助列 |
| `--ling-fs-md` | `13px` | 正文默认 |
| `--ling-fs-lg` | `15px` | 小标题、面板标题 |
| `--ling-fs-xl` | `18px` | 页面标题 |

### 2.3 间距（5 个）

| 令牌 | 取值 |
|---|---|
| `--ling-sp-1` | `4px` |
| `--ling-sp-2` | `8px` |
| `--ling-sp-3` | `12px` |
| `--ling-sp-4` | `16px` |
| `--ling-sp-5` | `24px` |

### 2.4 形状（3 个）

| 令牌 | 用途 | 亮色 | 暗色 |
|---|---|---|---|
| `--ling-radius` | 外框、卡片圆角 | `8px` | `8px` |
| `--ling-radius-sm` | 按钮、输入框、标签圆角 | `4px` | `4px` |
| `--ling-shadow` | 浮起面阴影 | `0 1px 2px rgba(0,0,0,0.06)` | `0 1px 2px rgba(0,0,0,0.4)` |

形状组里圆角两个不随主题变（尺度不是颜色），`--ling-shadow` 随主题变：暗色底上同样的阴影对比度更低，要加深才看得见。亮暗两列写同一个圆角值是为了让「两套一一对应」这条规则可机械校验。因此 14 + 4 + 5 + 3 = 26，与 §1 的数量一致。

## 3. 主题定义

外壳样式表开头是两套取值，其余规则只引用变量：

```css
:root {
  --ling-bg:#ffffff;          --ling-bg-raised:#ffffff;
  --ling-bg-sunken:#f6f7f9;   --ling-text:#1f2328;
  --ling-text-dim:#5b6472;    --ling-text-invert:#ffffff;
  --ling-border:#d8dde5;      --ling-border-strong:#b9c0cb;
  --ling-accent:#2f6fed;      --ling-accent-hover:#2560d8;
  --ling-accent-fg:#ffffff;   --ling-ok:#1a7f37;
  --ling-warn:#b26a00;        --ling-danger:#c0392b;
  --ling-fs-sm:12px;          --ling-fs-md:13px;
  --ling-fs-lg:15px;          --ling-fs-xl:18px;
  --ling-sp-1:4px;            --ling-sp-2:8px;
  --ling-sp-3:12px;           --ling-sp-4:16px;
  --ling-sp-5:24px;           --ling-radius:8px;
  --ling-radius-sm:4px;       --ling-shadow:0 1px 2px rgba(0,0,0,0.06);
}

:root[data-theme="dark"] {
  --ling-bg:#1b1b1d;          --ling-bg-raised:#242427;
  --ling-bg-sunken:#141416;   --ling-text:#e6e6e6;
  --ling-text-dim:#a0a7b4;    --ling-text-invert:#141416;
  --ling-border:#33383f;      --ling-border-strong:#4a515a;
  --ling-accent:#6f9bff;      --ling-accent-hover:#8ab0ff;
  --ling-accent-fg:#10141c;   --ling-ok:#4ac26b;
  --ling-warn:#e0a33a;        --ling-danger:#ff6b5e;
  --ling-shadow:0 1px 2px rgba(0,0,0,0.4);
}
```

两套之间只有颜色与阴影不同：字号、间距、圆角不随主题变，否则同一页面在亮暗之间切换时布局会跳。

## 4. `theme.css` 接口

`GET /api/ui/theme.css` 免 token，返回 §3 的完整内容加一行注释：

```http
HTTP/1.1 200 OK
Content-Type: text/css; charset=utf-8
Cache-Control: no-store

/* core-ui theme.css — 生成于 2026-11-02T21:40:00Z，当前主题 dark */
:root { … 当前主题的 26 个取值，这里展开的是暗色 … }
:root[data-theme="light"] { … 亮色全量 26 个 … }
:root[data-theme="dark"]  { … 暗色全量 26 个 … }
```

三段缺一不可：

| 段 | 作用 | 谁在用 |
|---|---|---|
| `:root` | 默认值，取**当前主题**，由服务端在生成时填入 | 还没拿到主题信息的面板 |
| `:root[data-theme="light"]` | 亮色全量 | 显式切到亮色的面板 |
| `:root[data-theme="dark"]` | 暗色全量 | 显式切到暗色的面板 |

| 项 | 规定 |
|---|---|
| 内容 | 两套取值一次给全；`:root` 默认块额外给当前主题，供首屏使用 |
| `Cache-Control` | `no-store`：主题会变，缓存会导致旧值 |
| 生成方式 | 从同一份令牌表拼字符串，不手写第二份 |

两套都给的理由：收到 `theme` 消息后只改 `data-theme` 属性即可切换，不必重新请求样式表；若只给当前那一套，切主题就得重新加载 CSS，会白闪。

`:root` 默认块给当前主题，解决的是另一件事：面板的 `<html>` 上没有 `data-theme` 时，如果 `:root` 固定写亮色，暗色用户首屏会闪一下白（`CUI-REQ-023` 不允许）。服务端生成响应时知道当前主题，把这一块填成当前主题的取值，面板一加载就是对的颜色，连 `init` 都不用等。

## 5. 主题切换

### 5.1 时序

```
1. 用户点「外观」页的暗色预览卡
2. 外壳立刻给自己的 <html> 设 data-theme="dark"        ← 乐观更新
3. 外壳向每个面板 postMessage {type:"theme", theme, tokens}
4. 外壳 POST /api/config.set {key:"core-ui.theme", value:"dark"}
5. 成功：静默
   失败：把 data-theme 改回旧值，再广播一次旧主题，并提示「主题没能保存，重启后会恢复旧设置」
```

第 2 步先做、第 4 步后做，是因为切换必须即时：等网络回来再变色会有可感知的延迟。

失败时回滚而不是提示「已切换但没保存」：界面与配置不一致会让用户困惑，回滚后状态是自洽的。

### 5.2 启动时读主题

```
1. 外壳初始化时 POST /api/config.get {key:"core-ui.theme"}
2. 校验取值：只认 light 与 dark，其余一律当 light 处理并记一条 warn（配置可手改，值不能信）
3. 设到 <html data-theme>
4. 键不存在时用 light，不回写（回写交给第一次切换）
```

在 `<head>` 里同步取不到配置，所以外壳 HTML 默认写 `data-theme="light"`，脚本读到配置后切换。暗色用户会看到一次极短的亮色闪动。

消除这次闪动的做法是让服务端在返回 `/` 时把主题作为 `<html data-theme>` 的属性直接写进 HTML。这条列为 §8 的未做项：它要求服务端在发页面前知道主题，而主题存在 `core-settings` 里，服务端要先查一次，给根页面加了 10 毫秒左右的延迟。

### 5.3 跟随系统

1.1.0 不做。理由：跟随系统要监听 `prefers-color-scheme` 变化，还要处理「用户手动选过之后是否继续跟随」，多一个三态配置（亮 / 暗 / 跟随系统）。等两套预设用出反馈再加。

## 6. 面板怎么用

### 6.1 推荐写法

```html
<link rel="stylesheet" href="/api/ui/theme.css">
<style>
  body { background: var(--ling-bg); color: var(--ling-text);
         font-size: var(--ling-fs-md); padding: var(--ling-sp-4); }
  .btn { background: var(--ling-accent); color: var(--ling-accent-fg);
         border-radius: var(--ling-radius-sm); padding: var(--ling-sp-1) var(--ling-sp-3); }
</style>
```

`<link>` 必须在面板自己的样式之前，否则同优先级的规则会按出现顺序覆盖。

### 6.2 另一种写法：用 `init` 里的 `tokens`

面板若不想多一次请求，可以从 `init` 消息的 `tokens` 里取，写到 `<html>` 的 `style` 上：

```js
for (const [k, v] of Object.entries(m.tokens)) {
  document.documentElement.style.setProperty(k, v);
}
```

**不推荐，只作为兜底。** `docs/ling/builtin-plugins/core-ui/02-技术选型.md` §10.3 已否决「把令牌塞进消息」作为主路径：`init` 到达之前首屏没有颜色，暗色用户会看到一次白闪，与 `CUI-REQ-023` 冲突。只有面板确实无法用 `<link>`（例如完全离线自包含）时才用它，并且要自行接受这次白闪。

若同时用了 `<link>` 与这条，内联 `style` 恒胜样式表，切主题时变量不再更新——两条只能选一条。

### 6.3 切主题后要做什么

面板收到 `theme` 消息后：

| 做法 | 说明 |
|---|---|
| 改 `<html data-theme>` | 如果面板用 `<link>` 引了 `theme.css`，改这一个属性即可 |
| 覆盖 CSS 变量 | 如果面板用的是 `init` 的 `tokens`，逐个 `setProperty` |

两种都要在 300 毫秒内完成（`CUI-REQ-021` 的验收标准）。

### 6.4 面板自己的颜色

面板可以有品牌色、图标色，但**背景、文字、边框、语义色必须取令牌**。判断标准：把界面切到暗色，如果面板里有一块仍然是白的，那块就是写死了。

## 7. 校验

### 7.1 硬性检查

| 检查 | 方法 | 不通过 |
|---|---|---|
| 外壳样式表里不写死颜色 | 构建脚本扫 `shell.css`：`#` 开头的十六进制只允许出现在 `:root` 与 `[data-theme]` 两个块内 | 构建失败 |
| 令牌数量与名字固定（只对 `shell.css`） | 亮色块必须恰好是那 26 个键；暗色块必须是这 26 个的子集，且恰为 14 个颜色加 `--ling-shadow` 共 15 个 | 构建失败 |
| 两套取值类型一致 | 同一令牌在两套里不能一个是颜色一个是长度 | 构建失败 |
| 默认块与主题一致（只对生成的 `theme.css`） | `theme.css` 的 `:root` 块必须与当前主题对应的那个 `[data-theme]` 块逐键相同。`shell.css` 是静态文件、`:root` 固定亮色，这条不适用 | 构建失败 |
| 对比度 | 四个组合用 WCAG AA 4.5:1 核对：`text`/`bg`、`text-dim`/`bg`、`accent-fg`/`accent`、`danger`/`bg` | 人工核对，新增令牌时做 |

对比度目前的结果（按相对亮度公式算）：

| 组合 | 亮色 | 暗色 |
|---|---|---|
| `text` / `bg` | 15.8 : 1 | 13.8 : 1 |
| `text-dim` / `bg` | 6.0 : 1 | 7.1 : 1 |
| `accent-fg` / `accent` | 4.5 : 1 | 6.9 : 1 |
| `danger` / `bg` | 5.4 : 1 | 6.2 : 1 |

上表按 WCAG 2.1 的相对亮度公式算，未取整到小数点后一位以外的精度；复算脚本用 `#` 十六进制值直接代入，不经过任何设计工具的取整。

亮色的 `accent-fg` / `accent` 是 4.5 : 1，正好等于 AA 的下限，**没有余量**。主色稍微调亮就会跌破，所以改主色时必须当场重算这一项，不能凭肉眼判断「看起来还行」。

### 7.2 禁止项

| 禁止 | 理由 |
|---|---|
| 外壳里出现 `#` 颜色字面量（`:root` 块之外） | 切主题不跟随 |
| 面板用 `!important` 覆盖令牌 | 会把外壳的统一性撕开一个口子 |
| 面板引用 `--ling-` 之外的全局变量作为颜色 | 那套变量没有契约，随时会变 |
| 在令牌里放 `font-family` | 字体由宿主的系统栈决定，令牌只管尺度 |
| 新增「只有暗色需要」的令牌 | 两套必须一一对应 |

唯一允许的颜色字面量是对话框遮罩 `rgb(0 0 0 / 32%)` 与阴影里的 `rgba(0,0,0,…)`：两者只依赖黑与透明度，切主题时观感差异可以忽略，做成令牌会让两套取值多两个几乎相同的项。扫描脚本对这两处放行，其他位置一律拦。

## 8. 未做项

| 项 | 什么时候做 | 为什么现在不做 |
|---|---|---|
| 首屏消除亮色闪动 | 等有人反馈刺眼 | 要在服务端返回根页面前查配置，给首屏加一次查询 |
| 跟随系统主题 | 等两套预设用出反馈 | 多一个三态配置与监听 |
| 自定义色值 | 不确定 | 配置项从 1 个变 20 多个，还要取色器与对比度校验 |
| 第三方主题包 | 不确定 | 要先定主题文件格式与安全审查 |
| 字号缩放（用户选大中小） | 不确定 | 与自定义色值同类，属于「用户改尺度」 |
