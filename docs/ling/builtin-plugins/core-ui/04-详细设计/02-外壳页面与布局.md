# core-ui 04 详细设计 02 外壳页面与布局

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 依据：`docs/ling/builtin-plugins/core-ui/03-架构设计.md` §3

本文回答：外壳的 DOM 怎么搭、侧边栏与功能区怎么排、面板怎么装进去、设置二级界面由什么组成。

---

## 1. 文档骨架

单页应用，一份 HTML 三块区域。主题属性挂在 `<html>` 上（`document.documentElement`），不挂在 `#app` 上：令牌定义用的是 `:root` 选择器，挂在别的元素上匹配不到。

```html
<div id="app">
  <aside id="sidebar">
    <div id="sidebar-head">ling</div>
    <nav id="nav-views"></nav>
    <div id="sidebar-foot">
      <span id="host-state"></span>
      <button id="btn-settings">设置</button>
    </div>
  </aside>

  <main id="workspace">
    <div id="panel-area"></div>
    <div id="empty-state"></div>
  </main>

  <section id="settings" hidden>
    <header>设置</header>
    <nav id="settings-tabs"></nav>
    <div id="settings-body"></div>
  </section>
</div>
```

三块的关系：

| 块 | 显示条件 | 与谁互斥 |
|---|---|---|
| `#panel-area` + `#empty-state` | 平时 | 有面板时隐藏空状态 |
| `#settings` | 点「设置」后 | 显示时盖住 `#workspace`，侧边栏不消失 |
| `#sidebar` | 始终 | 无 |

`#settings` 出现时不卸载面板：面板的 iframe 留在 DOM 里但被盖住。理由见 §4.3。

## 2. 侧边栏

### 2.1 入口怎么生成

启动时调 `POST /api/panels` 拿列表，按 `id` 升序逐条生成。之后每 2 秒再调一次，用于发现别处改的插件状态（停用、崩溃），与 `CUI-REQ-030` 的 2 秒验收对齐：

```html
<button class="view-item" data-plugin="resources-manager">
  <img src="/panel/resources-manager/icon.svg" alt="">
  <span>资源管理</span>
</button>
```

| 规则 | 说明 |
|---|---|
| 排序 | 按插件 `id` 升序，不用 `title`（中文排序不稳定） |
| 图标 | 有 `icon` 显示，没有则显示插件名首字 |
| 停用的插件 | 仍显示，文字变淡，点击时面板显示「插件已停用」与「启用」按钮（`CUI-REQ-030` 的「入口消失」只针对卸载，停用是保留） |
| 没有 `[ui]` 的插件 | 不显示 |
| 数量 | 不限，超过 12 个时侧边栏内部滚动 |

### 2.2 收缩

| 项 | 规定 |
|---|---|
| 宽度 | 展开 188 像素，收起 48 像素 |
| 收起后显示 | 只显示图标（无图标时显示首字），悬停显示名称 |
| 触发 | 侧边栏底部的小箭头，或窗口宽度小于 900 像素时自动收起 |
| 记忆 | 写 `core-ui.sidebar`，重启恢复 |

### 2.3 底部

两行，固定在侧边栏底部：

```
● 宿主运行中
设置
```

宿主状态每 5 秒探一次（调 `api/panels`），断了变红显示「ling 没有响应」。这行不占一整条首栏，也因此没有「首栏」这个概念。

## 3. 功能区

### 3.1 面板外框

每个面板一层外框，外框由外壳画：

```html
<section class="panel" data-plugin="resources-manager">
  <header class="panel-bar">
    <span class="panel-title">资源管理</span>
    <button class="panel-close" aria-label="关闭">×</button>
  </header>
  <iframe src="/panel/resources-manager/index.html"
          sandbox="allow-scripts allow-popups allow-downloads"
          referrerpolicy="no-referrer"></iframe>
</section>
```

| 项 | 规定 |
|---|---|
| 标题条高度 | 32 像素 |
| 标题 | 取 `[ui].title`，过长时尾部省略号，悬停显示全名 |
| 关闭钮 | 只关面板，不卸载插件，不改插件状态；该面板的槽位记在 `core-ui.layout.order` 里，重新打开时插回原位置 |
| 边框 | 1 像素，颜色取 `--ling-border` |
| 圆角 | 取 `--ling-radius`，只在外框外层 |
| 标题条上没有拖动柄 | 布局不支持自由拖动（§3.3），留一个拖不动的把手只会误导 |

`sandbox` 的取值是安全边界的一部分：不给 `allow-same-origin`，因此面板是不透明源；`allow-downloads` 让面板能导出文件；`allow-popups` 让面板能开新窗口（例如打开外部链接）。

### 3.2 打开与关闭

| 动作 | 行为 |
|---|---|
| 点侧边栏入口，该插件未打开 | 若该插件在 `order` 里还有槽位，按槽位插回；否则追加到末尾 |
| 点侧边栏入口，该插件已打开 | 不重复打开，闪一下该面板的外框 |
| 点面板关闭钮 | 移除该面板，侧边栏入口保留 |
| 已开 4 个时再打开新的 | 关掉最早打开的那个，顶部提示「已关闭较早打开的：<名称>」 |
| 插件被停用或卸载 | 关闭该面板，见 `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §7 |

上限 4 个的理由：本机界面常见宽度 1100 至 1600 像素，5 个以上每个不足 240 像素，面板内的表格与按钮会挤到不可用。

### 3.3 宽度分配与分隔条

```
[面板 A 40%][分隔条][面板 B 60%]
```

| 项 | 规定 |
|---|---|
| 默认宽度 | 平均分配。1 个占满，2 个各 50%，3 个各 33.33%，4 个各 25% |
| 分隔条宽度 | 8 像素，中间画 1 像素竖线，悬停变宽色 |
| 拖动 | 按住移动，相邻两个面板宽度按像素互补变化，其余面板不变 |
| 最小宽度 | 每个面板 240 像素；拖到下限即停 |
| 持久化 | 释放鼠标 300 毫秒后写 `core-ui.layout`，拖动过程中不写 |
| 双击分隔条 | 恢复平均分配 |

为什么不做自由拖动窗口：见 `docs/ling/builtin-plugins/core-ui/02-技术选型.md` §6。位置只由打开顺序决定，用户能调的是宽度。

### 3.4 空状态

| 情形 | 显示 |
|---|---|
| 没有已安装插件带 `[ui]` | 「当前没有带界面的插件。可以在设置 → 插件里安装。」 |
| 有带界面的插件但都没打开 | 「从左侧选一个插件开始。」 |
| 上次会话开过面板，本次恢复失败 | 「上次打开的面板没能恢复，请重新选择。」 |

## 4. 设置二级界面

### 4.1 结构

点侧边栏底部「设置」，`#settings` 显示，盖住 `#workspace`。左侧六个页签，右侧内容：

```
┌──────────┬──────────────────────────────┐
│ 插件      │                              │
│ 日志      │        当前页签内容           │
│ 配置      │                              │
│ 任务      │                              │
│ 外观      │                              │
│ 关于      │                              │
└──────────┴──────────────────────────────┘
```

离开设置：点侧边栏任一插件入口，`#settings` 隐藏，功能区回到原来的面板集合（不改动）。

页签切换不刷新页面，用 `location.hash` 记住当前页签（`#settings/logs`），刷新后回到同一页。

### 4.2 插件页

1.0.0 的插件视图整体搬过来，行为不变：

| 列 | 内容 |
|---|---|
| 插件名 | 等宽字体 |
| 版本 | 灰色小字 |
| 状态 | 彩色圆点 + 文字：已启用 / 已停用 / 启动失败（对应内核值 `activated` / `deactivated` / `failed`，另把 `crashed` 归入「启动失败」并显示 `last_error`；四个内核值到三个中文词的映射在 `views/plugins.js` 一处定义） |
| 类型 | 进程内 / 独立进程 |
| 有面板 | 有 `[ui]` 时显示「有界面」小标签 |
| 操作 | 停用或启用、卸载 |

顶部：安装插件、筛选（全部 / 在用 / 停用 / 失败）、搜索（按名过滤，输入即筛）。

「安装插件」在浏览器里拿不到用户选的绝对路径（`<input type="file">` 只给文件名），因此做成两种入口：一个文本框贴路径，一个「从剪贴板读取」按钮。`desktop` 版额外提供「浏览…」，由 WebView2 侧弹系统目录选择器再把路径填回文本框。

危险操作的确认文案：

| 操作 | 文案 |
|---|---|
| 停用 | 「停用 demo-a？它会停止工作，数据保留。」有下游时追加：「同时会停用 demo-b、demo-c。」 |
| 卸载（保留数据） | 「卸载 demo-a？它的数据会留在 `<路径>`，以后装回来还能用。」 |
| 卸载（删数据） | 「卸载 demo-a 并删除它的全部数据？**这一步不能撤销。**」按钮文字是「卸载并删除」，不是「确定」 |

危险按钮一律放右侧、红底文字，默认焦点在主按钮上。

状态「启动失败」的行可展开，显示 `last_error` 与「看日志」按钮，点了跳到日志页并选中该插件。

### 4.3 日志页

```
[插件 ▾ demo-caller]  [级别 ▾ 全部]  [☑ 自动刷新]  [清屏]
──────────────────────────────────────────────────
2026-10-31T18:00:23 [info]  event demo-a.pinged pong
```

| 项 | 规定 |
|---|---|
| 自动刷新 | 默认开，间隔 2 秒，只拉最后 200 行 |
| 手动刷新 | 关掉自动刷新后可点 |
| 上翻加载 | 滚到顶部时用 `logs` 的 `before` 参数再拉 200 行 |
| DOM 上限 | 超过 5000 行时删掉最早的，防止越用越卡 |
| 级别着色 | 只染行首标签，不整行染色 |
| 清屏 | 只清界面里的行，不动日志文件；清完再刷新会重新拉回 |
| 空状态 | 未选插件「选一个插件看它的日志」；选了无日志「这个插件还没写过日志」 |

### 4.4 配置页

左选插件，右列键值。控件按类型给：

| 值的类型 | 控件 |
|---|---|
| 布尔 | 开关 |
| 数字 | 数字输入框 |
| 字符串 | 单行输入框；超过 80 字符用多行 |
| 对象、数组 | 多行文本框，内容是格式化后的 JSON，失焦时校验 |
| `null` | 显示「（未设置）」，可点「设置」开始填 |

改完立即保存，不需要「保存」按钮。保存失败时输入框标红、下方显示原因、**内容不清空**。成功时右上角闪一条「已保存」，2 秒后消失。

`core-settings` 没装时整页显示「配置功能需要 core-settings，它当前没有启用。」

### 4.5 任务页

| 列 | 内容 |
|---|---|
| 名字 | —— |
| 时间表 | cron 原文 + 一句人话解释（如「每天 03:00」） |
| 目标方法 | 等宽字体 |
| 上次触发 | 时间，或「还没触发过」 |
| 操作 | 启用或停用 / 删除（停用走 `jobs.setEnabled`） |

新增表单：名字、cron、目标方法、参数（JSON）、补跑开关。cron 输入框下方实时显示下次触发时间，写错时提示「『时』段取值 25 超出范围 0 至 23」。

没有任务时显示「还没有定时任务」与「新增」按钮。

### 4.6 外观页

| 项 | 控件 | 说明 |
|---|---|---|
| 主题 | 两张预览卡（亮色 / 暗色） | 点一下立即生效，写 `core-ui.theme` |
| 侧边栏默认 | 开关 | 「打开界面时展开侧边栏」，写 `core-ui.sidebar_default`（当前展开状态另存 `core-ui.sidebar`，两个键不混用） |

预览卡用令牌自身的颜色画，切到暗色时两张卡都跟着变，用户看到的是真实效果而不是图片。

### 4.7 关于页

| 项 | 控件 | 说明 |
|---|---|---|
| 版本 | 只读 | 宿主版本与界面版本各一行 |
| 界面地址 | 只读 | `location.origin`（端口顺延后自动正确），点击可复制 |
| 数据目录 | 只读 | 当前数据根，排障时报给别人用 |
| 关闭窗口时 | 单选 | 「只关界面，ling 继续在后台跑」（默认）或「关掉界面也退出 ling」 |
| 退出 ling | 按钮 | 立即停掉宿主，带二次确认 |
| 设计令牌 | 折叠区 | 列出当前主题的 26 个令牌与取值，方便插件作者对照 |

「关闭窗口时」写 `core-ui.close_behavior`，界面只负责显示与写回，不自己另存一份；关窗口时按这个值执行（`docs/ling/builtin-plugins/core-ui/04-详细设计/05-进程形态与启动.md` §7）。`webui` 版这个选项置灰：浏览器标签页没有可靠的关闭事件，理由见 `docs/ling/builtin-plugins/core-ui/04-详细设计/05-进程形态与启动.md` §7.2。

`stop-host` 的文案要写清后果：「关掉界面时同时退出 ling，正在跑的定时任务会中断」。

## 5. 通用规矩

| 规矩 | 说明 |
|---|---|
| 每个操作都有反馈 | 成功给绿色提示，失败给红色提示并说明原因 |
| 失败不吞消息 | 任何请求失败都要显示，不允许只在控制台打日志 |
| 危险操作二次确认 | 卸载、删数据必须确认；停用是否确认由 `core-ui.confirm_disable` 决定，默认 `true`。它只管「单独的停用」，**有下游时的那次连带提示不受它控制，始终出现** |
| 长操作有进度 | 安装、卸载期间按钮变灰并显示「处理中」 |
| 不用弹窗套弹窗 | 确认框只有一层，需要更强的确认时改为「输入插件名确认」 |
| 键盘可用 | Tab 能走完所有可点元素，Esc 关确认框 |
| 只显示中文 | 不做国际化 |
| 颜色只取令牌 | 样式表里除令牌定义处外，不出现十六进制颜色 |
| 插件给的文本一律 `textContent` | `title`、错误信息、日志行里常常夹着 `<img onerror=…>` 这样的东西，用 `innerHTML` 等于执行插件写的代码；要排版就自己拼 DOM，不拼字符串 |

## 6. 键盘与可访问性

| 键 | 动作 |
|---|---|
| `Tab` / `Shift+Tab` | 在侧边栏、面板外框、设置控件之间移动 |
| `Alt+1` 至 `Alt+4` | 切到第 1 至第 4 个面板的外框（焦点给外框，不进入 iframe） |
| `Esc` | 关掉当前确认框；无确认框时不做任何事 |
| `Enter` | 确认当前对话框的主按钮 |
| `Ctrl+F` | 不拦截，交给浏览器 |

焦点进入 iframe 后由面板自己管；外壳不试图劫持面板内的键盘事件（跨源也做不到）。
