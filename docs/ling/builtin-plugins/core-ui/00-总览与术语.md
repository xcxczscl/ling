# core-ui 00 总览与术语

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 依据：`docs/ling/README.md`、`docs/common/01-术语表.md`、`docs/ling/plugin-support/01-插件装载与接口.md`

本文回答：core-ui 是什么、界面上有哪几块、边界在哪、本项目用的词各指什么。

---

## 1. 一句话

**它是 ling 唯一的人机界面进程：既用鼠标把 ling 管起来，又是所有插件界面的容器。**

两件事，一个进程：

| 职责 | 说明 | 谁来填内容 |
|---|---|---|
| 管理面板 | 看装了哪些插件、装新的、停掉不用的、翻日志、改配置、管定时任务 | core-ui 自己写 |
| 插件视图台子 | 给每个带界面的插件提供一个位置，把该插件的网页装进来显示 | 各插件自己写 |

1.0.0 只有第一件事。1.1.0 起增加第二件，原有的管理视图整体退到「设置」里，成为二级界面。

## 2. 它解决什么问题

### 2.1 命令行太重

命令行能做全部事情，但要记命令、记参数、记插件名。对「偶尔用一下」的场景，成本太高：

| 命令行 | 界面 |
|---|---|
| `ling install D:\plugins\my-plugin` | 点「安装」，选目录 |
| `ling plugins` 看英文状态 | 一屏卡片，颜色区分状态 |
| `ling logs demo-a` 看纯文本 | 可筛选、可搜索、可自动刷新 |
| 改配置要手编 `settings.json` | 表单，带类型校验 |

**命令行不删。** 界面是另一条入口，两者共用同一套 `kernel.*` 方法，不各写一套逻辑。

### 2.2 插件没有地方放界面

插件能力再强，只要没有一个统一的显示位置，作者只有三条烂路：自己开端口当小网站、只做命令行、或干脆不做界面。

`core-ui` 提供第四条：插件在自己目录放一份网页、在清单里声明一段 `[ui]`，界面就出现在侧边栏里。插件作者不需要写服务端，不需要处理端口、认证、导航、主题。

## 3. 界面有哪几块

一级界面三块区域；功能区里的每个面板再分外框与内容两层：

```
┌────────┬────────────────────────────────┐
│        │ 功能区                          │
│ 侧边栏 ├──────────────┬─────────────────┤
│(可收缩)│ 面板 A 外框   │ 面板 B 外框      │
│        │ ┌──────────┐ │ ┌─────────────┐ │
│ 插件A  │ │ 插件A网页 │ │ │ 插件B网页    │ │
│ 插件B  │ └──────────┘ │ └─────────────┘ │
│        │              │                 │
│ ────── │              │                 │
│ 设置   │              │                 │
└────────┴──────────────┴─────────────────┘
```

| 块 | 职责 | 归谁 |
|---|---|---|
| 侧边栏 | 导航：列出所有带界面的插件，底部固定「设置」 | 外壳 |
| 功能区 | 同时摆多个插件的面板，横向均分，中间可拖分隔条 | 外壳 |
| 面板外框 | 每个面板头上一条 32 像素高的条：标题、关闭 | 外壳 |
| 面板内容 | 插件自己的网页，装在隔离画框里 | 插件 |

没有独立的「首栏」。全局信息（宿主状态、版本）放在侧边栏底部「设置」入口的上方，不占一整条。

二级界面是「设置」，进去后是六个页签：插件、日志、配置、任务、外观、关于。前四个是 1.0.0 原有的视图，外观与关于是 1.1.0 新增。

## 4. 两种形态

同一个插件，两种发布形态，二选一：

| | `webui` 版 | `desktop` 版 |
|---|---|---|
| 界面在哪 | 浏览器标签页 | 独立窗口 |
| 怎么打开 | 启动宿主后自动开默认浏览器 | 双击图标直接开窗口 |
| 技术 | 本地 HTTP 服务 + 浏览器 | 同一个 HTTP 服务 + WebView2 容器 |
| 平台 | 三平台 | 目前只有 Windows |
| 适合 | 已有浏览器习惯、想多开标签页对照 | 想要「像普通软件一样」的体验 |

两版**界面代码完全一样**，差别只在「谁来显示这个页面」：浏览器，或一个内嵌 WebView2 的窗口。这条决定让两种形态不必维护两套前端。

## 5. 它在插件体系里的位置

`core-ui` 是一个**侧车插件**：独立进程，不是装进宿主的动态库。理由：

- 它要跑一个 HTTP 服务，宿主不需要这个能力。
- 界面进程崩了不该拖垮宿主（`LING-REQ-116`）。
- 将来换界面技术，只换这一个可执行文件。

它与宿主的关系只有一条：**以客户端身份连管理端口**（`127.0.0.1:7900`），用 `session.json` 里的口令认证，之后调 `kernel.*` 方法。

它**不启动宿主，也不停止宿主**（唯一例外是按用户存的选项调一次 `kernel.shutdown`，见 `docs/ling/builtin-plugins/core-ui/04-详细设计/05-进程形态与启动.md` §7）。宿主先起，界面后起，界面只是它的一个客户端。

它不读 `session.json`：口令由宿主启动它时经环境变量传入，这样界面不需要知道数据根在哪。

它同时是**唯一读取其他插件目录的插件**：只有它的服务端会去读别的插件的 `ui/` 目录，把网页发给浏览器。这条读取是只读、限定目录、限定后缀的（见 `docs/ling/builtin-plugins/core-ui/06-安全设计.md` §4）。

## 6. 术语

公共词（宿主、插件、能力、侧车、上下文、热更新、外壳、面板、设计令牌、主题）的一句话定义见 `docs/common/01-术语表.md`。下表补齐本项目内的具体所指，以及只在本项目出现的词。

| 词 | 定义 |
|---|---|
| **外壳** | core-ui 自己那份页面。浏览器加载它，它负责侧边栏、功能区、面板外框、设置二级界面，并持有 token。 |
| **面板** | 插件提供的网页。一个插件最多一个，用隔离画框（iframe）加载，装在外壳的面板外框里；该插件的全部界面分区由它自己在这份网页内划分。 |
| **面板外框** | 外壳画在面板周围的那一圈：顶部 32 像素的标题条（插件名、关闭钮）与边框。插件不画它。 |
| **插件视图** | 侧边栏里的一个入口。一个插件有面板时产生一个插件视图，点它等于打开该插件的面板。 |
| **管理面板** | 设置二级界面里六个页签的合称，1.1.0 起收进「设置」。 |
| **设计令牌** | 一组 CSS 变量，名字以 `--ling-` 开头，管颜色、字号、间距、圆角、阴影。外壳与所有面板只引用它，不写死具体值。 |
| **主题** | 设计令牌的一套取值。内置 `light` 与 `dark` 两套，存在 `core-settings` 的 `core-ui.theme` 键。 |
| **消息协议** | 面板与外壳之间用 `postMessage` 收发的一组固定格式消息，见 `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §3。 |
| **代调** | 面板不直接请求服务端，而是把调用意图发给外壳，由外壳带着 token 去请求。 |

## 7. 它不做什么

| 不做 | 理由 |
|---|---|
| 局域网或远程访问 | 只绑 `127.0.0.1`。一旦能远程访问，就要做账号、权限、加密，而这是单机个人工具 |
| 多用户 | 同上 |
| 业务功能 | 界面只调别的插件与内核方法，自己不实现任何业务逻辑 |
| 插件市场、在线安装 | 项目非目标，见 `docs/ling/main/00-总览与术语.md` |
| 移动端适配 | Android 版的界面形态另议，不在这一份里 |
| 面板之间自由互发消息 | 会绕开能力校验与日志，见 `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §6 |
| 窗口自由拖拽、浮动、标签页 | 只做「横向均分 + 分隔条」，见 `docs/ling/builtin-plugins/core-ui/04-详细设计/02-外壳页面与布局.md` §4 |
| 用户自定义主题颜色 | 1.1.0 只做亮色与暗色两套预设 |
| 共享组件库（按钮、表格、弹窗） | 插件自带样式，靠设计令牌保证观感一致 |
| 国际化 | 只有中文 |

## 8. 没装它的时候

| 场景 | 行为 |
|---|---|
| 命令行 | 全部可用，不受影响 |
| `ling plugins` 的列表 | 少一个 `core-ui` 条目 |
| 宿主启动 | 不受影响 |
| 带 `[ui]` 的插件 | 装载正常，插件方法可调，界面没有入口。插件不得因此报错 |
| 已保存的界面偏好 | 存在配置里（`core-ui.*` 键），重装后还在 |

`LING-REQ-075` 要求「卸掉 core-ui 后命令行仍可用」，每条命令都必须能独立完成自己的事，这是它存在的意义——界面是便利，不是依赖。

## 9. 谁在用

| 谁 | 怎么用 |
|---|---|
| 使用者 | 日常操作的主入口：管理插件与查看插件界面 |
| 命令行 | 某些场景下给出「去界面上看」的提示 |
| 其他插件 | 通过 `[ui]` 段把面板挂进来。这是 1.1.0 新增的方向：以前不调它，现在把网页交给它显示 |

其他插件与 core-ui 的耦合只有一个清单字段和一份静态网页，不产生方法调用。core-ui 被卸载时，插件无需改动。
