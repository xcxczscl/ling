# core-ui 07 测试与验收

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 依据：`docs/ling/builtin-plugins/core-ui/01-需求规格.md`

本文回答：测什么、怎么测、什么算通过。

---

## 1. 范围

### 1.1 测什么

| 层 | 测什么 | 手段 |
|---|---|---|
| 服务端 | 路由、认证、路径检查、命名空间校验 | `curl` 与脚本 |
| 外壳 | 布局、导航、面板管理、设置页 | 手测 + DevTools |
| 面板协议 | 七种消息、来源校验、超时与并发 | 手测 + 面板控制台 |
| 安全 | 越权、跨源、路径穿越、注入 | 手测，按 §5 的用例 |
| 稳定性 | 崩溃重启、单面板故障隔离 | 强杀进程、制造异常 |

### 1.2 不测什么

| 不测 | 理由 |
|---|---|
| 宿主内核的行为 | 属 `docs/ling/main/07-测试与验收.md` |
| 插件业务逻辑 | 属各插件自己的测试 |
| 浏览器兼容性矩阵 | 只支持 WebView2 与近两年的 Chromium 内核浏览器 |
| 移动端 | 不支持 |

## 2. 环境与方法

### 2.1 环境

| 项 | 要求 |
|---|---|
| 平台 | Windows 10/11（`desktop` 版）；三平台（`webui` 版） |
| 浏览器 | Edge 或 Chrome，版本不早于 111（sandbox iframe 独立进程） |
| 数据目录 | 每次测试用新目录，如 `run/t-<日期>-<序号>` |
| 测试插件 | 一个自写的 `ui-demo`，带 `[ui]` 段，暴露 3 个方法：`echo`、`sleep`、`boom` |

`ui-demo` 的三个方法各有用途：`echo` 验证正常链路；`sleep`（睡 40 秒）验证超时；`boom`（抛错）验证错误回传。

### 2.2 启动

```bash
ling serve --data-dir run/t-001
ling open
```

### 2.3 判据写法

每条用例给「期望」，判据只写可观察的事实，不写「正常」「正确」这类词。

## 3. 管理面板（A 组）

| 编号 | 前置 | 步骤 | 期望 |
|---|---|---|---|
| CU-01 | 全新数据目录 | 启动宿主，用秒表从进程起来计时到侧边栏出现 | 不超过 1 秒 |
| CU-02 | 装 3 个插件 | 设置 → 插件页的列表与 `ling plugins` 输出逐条比对 | 名称、版本、状态三项全同 |
| CU-03 | 有一个可装目录 | 插件页点「安装」，选目录，确认 | 列表新增一行，状态「已启用」；`ling plugins` 复核一致 |
| CU-04 | 一个缺 `plugin.toml` 的目录 | 同上安装 | 显示原因（含「清单」二字），插件目录不残留 |
| CU-05 | `demo-a` 被 `demo-b` 依赖 | 停用 `demo-a` | 确认框出现「同时会停用 demo-b」 |
| CU-06 | `demo-a` 有数据目录 | 卸载时选「删除数据」 | 确认按钮文字为「卸载并删除」；确认后该目录消失 |
| CU-07 | `demo-a` 有 500 行日志 | 日志页选 `demo-a`，级别选「错误」 | 列表只剩 `[error]` 开头的行 |
| CU-08 | 造 10 万行日志 | 打开日志页，滚动到底再上翻三次 | 首次出现内容不超过 2 秒；滚动无卡顿感；上翻每次加 200 行 |
| CU-09 | 存在布尔键 | 在配置页切换开关，再用 `POST /api/config.get` 读回该键 | 返回值与界面一致 |
| CU-10 | 界面已打开 | 用任务管理器结束宿主进程，再在配置页改一个值 | 输入框内容保留，下方显示原因 |
| CU-11 | 任务页 | 新增任务，cron 填 `0 25 * * *` | 提示「『时』段取值 25 超出范围 0 至 23」 |
| CU-16 | 关闭行为设为 `stop-host` | 关闭界面窗口 | 宿主进程 3 秒内退出 |

CU-08 的日志造法：写一个脚本向该插件的日志文件追加 10 万行，重启宿主后打开日志页。

## 4. 界面骨架（B 组）

| 编号 | 前置 | 步骤 | 期望 |
|---|---|---|---|
| CU-17 | 安装 `ui-demo` | 看侧边栏 | 出现一项，文字等于 `[ui].title`；有 `icon` 时显示图标 |
| CU-18 | 同上 | 点该入口，秒表计时 | 2 秒内面板出现内容 |
| CU-19 | 已开两个面板 | 拖动中间分隔条往左 100 像素 | 左侧变窄、右侧变宽，两者之和不变 |
| CU-20 | 已开一个面板 | 点外框关闭钮，再点侧边栏入口 | 面板回到原来的位置，宽度不变 |
| CU-21 | 已开两个面板，调过宽度 | 结束界面进程后重新打开 | 两个面板都在，宽度比例与关闭前一致（误差不超过 4 像素） |
| CU-26 | 任意状态 | 设置 → 外观 → 点暗色卡 | 300 毫秒内外壳与所有已开面板变色 |
| CU-27 | 暗色主题 | 新开一个未开过的面板 | 首屏即暗色，录屏逐帧看无白色帧 |

CU-19 的判据细节：拖动时只改相邻两个面板的宽度，其余面板宽度不变。开三个面板时拖第一个分隔条，第三个面板宽度应不动。

|---|---|---|---|
| CU-33 | 侧边栏展开 | 点底部箭头收起，再重启界面 | 收起后功能区占满窗口宽度；重启后仍是收起态（`core-ui.sidebar` 为 `false`） |
| CU-34 | 任意状态 | 点「设置」，逐个点六个页签 | 插件、日志、配置、任务、外观、关于六个页签都有内容；切换时页面不刷新（DevTools Network 无文档请求） |
| CU-35 | `ui-demo` 面板已打开 | 用 DevTools 量外框标题条高度；再打开 `ui-demo` 的页面源码 | 标题条为 32 像素，含插件名与关闭钮；页面里没有同名标题条也能正常显示 |
| CU-36 | 一个面板已打开 | 在另一个面板的控制台执行 `while(true){}` | 外壳仍可操作：能切换侧边栏、能关闭卡死的面板；第三个面板仍能打开 |

## 5. 面板通信（C 组）

| 编号 | 前置 | 步骤 | 期望 |
|---|---|---|---|
| CU-22 | 面板已打开 | 点面板里的「echo」按钮 | 面板显示方法返回值 |
| CU-23 | 同上 | 面板 DevTools 执行 `parent.postMessage({type:"call",id:1,method:"kernel.shutdown"},"*")` | 收到 `E_UI_FORBIDDEN`；宿主进程仍在 |
| CU-24 | 同上 | 面板 DevTools 执行 `fetch("/api/plugins")` | 控制台报 CSP 违规（`connect-src 'none'`），无数据返回 |
| CU-25 | 同上 | 面板 DevTools 执行 `parent.sessionStorage.length` | 抛 SecurityError |
| CU-29 | 删掉 `entry` 指向的文件 | 打开该插件面板 | 预检返回后一秒内出现「面板文件不存在」与「重试」；补回文件后点重试可加载 |

CU-23 的完整检查要跑三次，分别对应三道门：

| 次 | 做法 | 期望 |
|---|---|---|
| 1 | 面板直接发 `kernel.shutdown` | 外壳拒绝 |
| 2 | 绕过外壳，直接 `curl -X POST /api/panel/call -d '{"plugin":"ui-demo","method":"kernel.shutdown"}'`（带 token） | 服务端拒绝，回 `E_UI_FORBIDDEN` |
| 3 | 面板调 `ui-demo.echo` 但插件已停用 | 服务端回 `E_UI_FORBIDDEN` |

### 5.1 声明与装载（G 组）

| 编号 | 前置 | 步骤 | 期望 |
|---|---|---|---|
| CU-37 | 一个可改坏的 `ui-demo` | 依次制造四种错误：删 `entry`、删 `title`、把 `entry` 写成 `../x.html`、把 `title` 写成 40 个字符 | 四次都装载失败，`code` 为 `E_UI_PANEL_DECL`，`message` 指名是哪一项 |

| CU-40 | 已卸载 core-ui | `ling install` 一个带 `[ui]` 的插件，再调它的 `echo` | 装载成功；方法可调；侧边栏不出现该插件（没有界面可挂） |

## 7. 安全用例（E 组）

| 编号 | 场景 | 做法 | 期望 |
|---|---|---|---|
| CU-14 | 非回环访问 | 用本机的局域网地址访问 `http://192.168.x.x:8010` | 连接被拒 |
| CU-30 | 路径穿越 | `curl http://127.0.0.1:8010/panel/ui-demo/../../plugin.toml` | 404，响应体不含 `id =` |
| CU-30b | 编码穿越 | 同上但用 `%2e%2e%2f` | 404 |
| SEC-05 | 后缀绕过 | 请求 `/panel/ui-demo/plugin.toml`（若目录内有同名文件） | 404（后缀不在白名单） |
| SEC-06 | 符号链接 | 在 `ui/` 下建一个指向 `../../` 的链接，请求它 | 404 |
| SEC-11 | 标题注入 | 把某插件 `title` 改成 `<img src=x onerror=alert(1)>` 后重启界面 | 侧边栏显示这段文本原文，无弹窗 |
| SEC-12 | 主题注入 | 用 `POST /api/config.set` 把 `core-ui.theme` 写成 `dark;}body{display:none}` 后重启界面 | 界面正常，按 `light` 渲染 |
| SEC-07 | 点击劫持 | 在一个本地 HTML 里 `<iframe src="http://127.0.0.1:8010/">` | 框架拒绝显示（控制台报 `frame-ancestors` 违规） |

SEC-06 的链接在 Windows 上要开发者模式或用 `mklink /D`，跑之前确认有权限。

## 8. 性能与降级（F 组）

| 编号 | 场景 | 做法 | 期望 |
|---|---|---|---|
| CU-32 | 四个面板 | 记录打开前面板标签页的工作集，逐个打开 4 个再记 | 增量不超过 200 MB |
| CU-32b | 单面板 1000 条并发 | 面板脚本循环发 1000 条 `call` | 超过 16 条的在途请求立即回 `E_UI_BUSY`；外壳不卡死 |
| CU-32c | 慢方法 | 面板调 `ui-demo.sleep`（40 秒） | 35 秒时收到 `E_TIMEOUT`，界面仍可操作 |
| CU-43 | 静态资源 5 秒超时 | 用测试构建把静态读取的超时常量改小到 1 秒，再让 `ui-demo/ui/` 里的文件读自一个卡住的路径（如断开的网络共享） | 到点回 504，界面显示「加载超时」并可重试，其他请求不受影响 |
| CU-44 | 管理调用 30 秒超时 | 让一次 `install` 卡在解压上超过 30 秒 | 30 秒断开该次调用并回超时错误，其他请求不受影响 |
| CU-45 | 拖拽超限 | 面板 A 发一条 9 KB 的 `drag` | 回 `result{ok:false,error.code:"E_PAYLOAD_TOO_LARGE"}`，提示改传路径 |
| CU-46 | 参数超限 | 面板调 `ui-demo.echo`，`params` 序列化后 1.1 MB | 413，`code` 为 `E_PAYLOAD_TOO_LARGE` |
| CU-15b | 无 `core-settings` | 停用 `core-settings` 后打开界面 | 界面可用；主题退化为亮色；配置页显示一行说明而不是报错 |

## 10. 验收出口条件

三条同时满足才算 1.1.0 可交付：

| 条件 | 判据 |
|---|---|
| 功能 | `CU-01` 至 `CU-46` 全部通过，无「已知但不修」的 P0 项 |
| 安全 | §7 的 8 条全过；`docs/ling/builtin-plugins/core-ui/06-安全设计.md` §9 的编码清单逐条勾完 |
| 文档 | `python tools/check_docs.py` 与 `python tools/check_refs.py` 无错误 |

「P0 项」指：能看到 `E_UI_FORBIDDEN` 没拦住、token 出现在面板可读位置、路径穿越能读到文件。任一条出现即为不通过。
