# core-ui 04 两种形态与启动

> 状态：已定稿 | 最后更新：2026-10-31
> 上级：`docs/ling/builtin-plugins/core-ui/00-总览与边界.md`

本文回答：webui 与 desktop 两种形态差在哪一步、WebView2 怎么用、发布包出几个。

---

## 1. 两种形态差在哪

差别只有一处：**页面由谁显示**。

```
共同部分（两版完全相同）
  宿主拉起进程 → 绑 8010 → 连管理端口自检 → 提供 /api/*

分叉点
  webui  版：宿主调系统默认浏览器打开 http://127.0.0.1:8010/?token=...
  desktop 版：进程自己创建 WebView2 窗口，加载同一个 URL
```

两版共用同一份服务端代码、同一份页面、同一份 API。不是两套程序，是一个程序的两个构建开关。

## 2. 构建开关

```cmake
option(LING_CORE_UI_DESKTOP "把 core-ui 编成带窗口的桌面版" ON)   # 视发布类型而定
```

| 开关 | 产物 | 额外依赖 |
|---|---|---|
| OFF | `core-ui.exe`，纯控制台程序，静默运行并开浏览器 | 无 |
| ON | `core-ui.exe`，带 WebView2 窗口 | WebView2 SDK（头文件与静态库） |

`webui` 版的进程本身不开窗口，启动后由宿主调 `ShellExecute`（Windows）或 `xdg-open`（Linux）打开浏览器。

**这里有个使用体验的细节**：`webui` 版不需要窗口，但它在 Windows 上会闪一下控制台窗口。解决办法是编成 GUI 子系统（`/SUBSYSTEM:WINDOWS`），入口用 `WinMain` 而不是 `main`。宿主拉起它时也不会弹黑框。

## 3. WebView2

### 3.1 它是什么

Windows 10/11 自带的浏览器控件（Edge 的内核）。系统里已有运行时，不需要额外装——这是选它而不是 Qt 的主要理由。

### 3.2 用它要加什么依赖

WebView2 SDK：一组头文件加一个静态库，从微软官方包取。**这一条已确认引入**（2026-10-31），按 `AGENTS.md` 的依赖规矩登记在这里：

| 项 | 内容 |
|---|---|
| 用途 | 给 `desktop` 版一个内嵌浏览器窗口 |
| 体积 | 静态链接后 exe 增加约 1 MB；运行时是系统自带的，不随包分发 |
| 影响面 | 只有 `desktop` 构建受影响，`webui` 版与宿主不链它 |
| 不引入的替代 | 只能开系统浏览器，等于放弃 `desktop` 形态 |

### 3.3 窗口行为

| 项 | 规定 |
|---|---|
| 标题 | `ling` |
| 初始大小 | 1100 × 760，最小 900 × 600 |
| 记住了窗口位置 | 存配置 `core-ui.window`，下次开在同一个地方 |
| 关闭窗口 | 只关界面，不关宿主（与浏览器版一致） |
| 托盘图标 | 不做。少一个常驻进程，也少一处要维护的状态 |
| 右键菜单 | 关掉默认菜单，只保留「复制」与「刷新」 |

关闭界面不关宿主是刻意的：`core-ui` 只是界面，关掉它宿主还得继续跑定时任务、响应命令行。

### 3.4 不用 WebView2 的降级

系统里没有 WebView2 运行时（极少见，比如某些精简版 Windows）时：

- 窗口不打开，改为调默认浏览器，退化成 `webui` 版。
- 在日志里记一条 warn，说明降级原因。

不做「请先安装 WebView2」的提示框：能用浏览器打开，就没必要拦着用户。

## 4. 启动顺序与握手

### 4.1 启动顺序

**宿主先起，界面后起。** 界面不启动宿主，也不停止宿主（唯一例外是按设置调一次 `kernel.shutdown`，见 §7）。

```
1. 用户启动 ling（serve 或双击入口）
2. 宿主预装内置插件，装载 core-ui（侧车轨道）
3. 宿主把口令与端口经环境变量传给界面进程：
     LING_UI_TOKEN / LING_UI_PORT / LING_UI_ROOT
4. 界面进程绑 127.0.0.1:8010（占用顺延到 8099），写 registry.json 的 ui_port
5. 用口令连管理端口，调一次 kernel.plugins 自检
6. 自检通过，向标准输出打 {"ready": true, "port": 8010}
7. 宿主读到这一行才算激活成功，广播 kernel.plugin.state activated
8. 界面打开：webui 版由宿主调系统默认浏览器；desktop 版自己创建窗口
```

界面进程不读 `session.json`：口令已经由宿主给了，它不需要知道数据根在哪。

### 4.2 就绪信号

第 6 步打的那行 JSON 是宿主的就绪判据。不用「等 2 秒看看能不能连」这种猜测——端口被占用顺延时，猜的时间不好定。

自检这一步不能省：绑上端口不代表能连上宿主。口令不对、宿主正在关闭，都会在这里暴露，而不是等用户点了按钮才发现。

## 5. 发布包出几个

两个维度交叉，共四个产物：

| | 便携版（解压即用） | 安装包（向导安装） |
|---|---|---|
| `webui` | `ling-0.0.3-webui-portable.zip` | `ling-0.0.3-webui-setup.exe` |
| `desktop` | `ling-0.0.3-desktop-portable.zip` | `ling-0.0.3-desktop-setup.exe` |

- **便携版**：整个目录压成一个 zip，解压后双击 `ling.exe` 就能用，不写注册表。
- **安装包**：Inno Setup 脚本，装到 `Program Files`，建开始菜单项与卸载入口。

四个包的差别只在 `core-ui` 的构建开关与安装方式，其余文件完全相同。

## 6. 双击之后发生什么

```
双击 ling（或开始菜单项）
  → 宿主起来，预装三个内置插件，绑管理端口
  → 宿装载 core-ui，界面进程绑 8010、自检
  → desktop 版：弹出界面窗口
     webui 版：打开默认浏览器
  → 界面显示插件列表
```

关掉界面窗口不关宿主，除非设置里选了「关界面时也退出 ling」（§7）。

**未定**：双击入口怎么不弹控制台窗口。`ling.exe` 是控制台程序，双击必然带一个黑框。三种做法各有代价：编成 GUI 子系统（命令行输出就没了）、另做一个 GUI 启动器（多一个 exe）、用快捷方式最小化启动（黑框还在，只是缩起来）。等打包阶段定，不在这一份里展开。

## 7. 关掉界面之后宿主怎么办

**选项存在 `core-settings` 里，界面只负责读它、按它执行，不自己另记一个默认值。**

配置键 `core-ui.close_behavior`，两项：

| 取值 | 关窗口时 | 适合 |
|---|---|---|
| `keep-host`（默认） | 只关界面，宿主继续跑，定时任务照常触发 | 把 ling 当常驻服务用 |
| `stop-host` | 关界面前先调 `kernel.shutdown`，等宿主退出 | 把 ling 当随手开随手关的工具 |

三条分工：

| 谁 | 做什么 |
|---|---|
| `core-settings` | 存这个键；第一次读到不存在时写回默认值 `keep-host` |
| 界面 | 设置页读出来显示、改了就写回；关窗口时按当前值决定要不要调 `kernel.shutdown` |
| 宿主 | 不参与判断。它不知道自己被谁启动，也不该关心 |

默认 `keep-host`：定时任务与插件的后台工作不该因为关了个窗口就停。

把选项放在 `core-settings` 而不是界面自己的 `data/` 里，是为了和其他配置一样可导出、可还原：换机器时连「关窗口要不要退宿主」一起带走。

### 7.1 界面被强杀时

设置来不及生效，宿主按「自己没被通知」处理，继续跑。这不算缺陷：强杀本来就是异常路径，宿主继续跑比突然消失安全。

重启界面后它会重新读配置，恢复原状。

### 7.2 平台差异

`desktop` 版目前只做 Windows。Linux 没有 WebView2，桌面窗口要另一套方案，等做到那一步再议。`webui` 版三平台一样——它只是开浏览器，不需要窗口库。

## 8. 实现状态

| 部分 | 状态 |
|---|---|
| 服务端（HTTP、认证、`/api/*` 转管理端口） | 已实现，冒烟 20 项全过 |
| 页面 | 只有一个占位页，能验证链路，不是界面 |
| 侧车装载（宿主拉起） | 未做，卡在 M4 的侧车轨道 |
| `desktop` 窗口（WebView2） | 未做 |

现在可以直接起一个来试接口：

```bash
ling serve --data-dir run/tmp-x                 # 一个窗口
run/win-debug/ling-ui.exe --data-dir run/tmp-x  # 另一个窗口
# 输出 {"ready":true,"port":8010}；端口看 registry.json 的 ui_port
```

页面定稿后只换 `main/src/ui_server.cpp` 里那段占位 HTML，服务端不用动。
