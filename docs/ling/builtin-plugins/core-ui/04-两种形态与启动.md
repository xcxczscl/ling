# core-ui 04 两种形态与启动

> 状态：已定稿 | 最后更新：2026-10-31
> 上级：`docs/ling/builtin-plugins/core-ui/00-总览与边界.md`

本文回答：webui 与 desktop 两种形态差在哪一步、WebView2 怎么用、发布包出几个。

---

## 1. 两种形态差在哪

差别只有一处：**页面由谁显示**。

```
共同部分（两版完全相同）
  宿主拉起进程 → 绑 8010 → 连管理端口自检 → 提供 /api/*

分叉点
  webui  版：宿主调系统默认浏览器打开 http://127.0.0.1:8010/?token=...
  desktop 版：进程自己创建 WebView2 窗口，加载同一个 URL
```

两版共用同一份服务端代码、同一份页面、同一份 API。不是两套程序，是一个程序的两个构建开关。

## 2. 构建开关

```cmake
option(LING_CORE_UI_DESKTOP "把 core-ui 编成带窗口的桌面版" ON)   # 视发布类型而定
```

| 开关 | 产物 | 额外依赖 |
|---|---|---|
| OFF | `core-ui.exe`，纯控制台程序，静默运行并开浏览器 | 无 |
| ON | `core-ui.exe`，带 WebView2 窗口 | WebView2 SDK（头文件与静态库） |

`webui` 版的进程本身不开窗口，启动后由宿主调 `ShellExecute`（Windows）或 `xdg-open`（Linux）打开浏览器。

**这里有个使用体验的细节**：`webui` 版不需要窗口，但它在 Windows 上会闪一下控制台窗口。解决办法是编成 GUI 子系统（`/SUBSYSTEM:WINDOWS`），入口用 `WinMain` 而不是 `main`。宿主拉起它时也不会弹黑框。

## 3. WebView2

### 3.1 它是什么

Windows 10/11 自带的浏览器控件（Edge 的内核）。系统里已有运行时，不需要额外装——这是选它而不是 Qt 的主要理由。

### 3.2 用它要加什么依赖

WebView2 SDK：一组头文件加一个静态库，从微软官方包取。**这一条已确认引入**（2026-10-31），按 `AGENTS.md` 的依赖规矩登记在这里：

| 项 | 内容 |
|---|---|
| 用途 | 给 `desktop` 版一个内嵌浏览器窗口 |
| 体积 | 静态链接后 exe 增加约 1 MB；运行时是系统自带的，不随包分发 |
| 影响面 | 只有 `desktop` 构建受影响，`webui` 版与宿主不链它 |
| 不引入的替代 | 只能开系统浏览器，等于放弃 `desktop` 形态 |

### 3.3 窗口行为

| 项 | 规定 |
|---|---|
| 标题 | `ling` |
| 初始大小 | 1100 × 760，最小 900 × 600 |
| 记住了窗口位置 | 存配置 `core-ui.window`，下次开在同一个地方 |
| 关闭窗口 | 只关界面，不关宿主（与浏览器版一致） |
| 托盘图标 | 不做。少一个常驻进程，也少一处要维护的状态 |
| 右键菜单 | 关掉默认菜单，只保留「复制」与「刷新」 |

关闭界面不关宿主是刻意的：`core-ui` 只是界面，关掉它宿主还得继续跑定时任务、响应命令行。

### 3.4 不用 WebView2 的降级

系统里没有 WebView2 运行时（极少见，比如某些精简版 Windows）时：

- 窗口不打开，改为调默认浏览器，退化成 `webui` 版。
- 在日志里记一条 warn，说明降级原因。

不做「请先安装 WebView2」的提示框：能用浏览器打开，就没必要拦着用户。

## 4. 启动顺序与握手

### 4.1 两种启动方式

`core-ui` 有两种被启动的方式，它靠一个环境变量区分：有没有 `LING_UI_TOKEN`。

| | 用户双击（启动器模式） | 宿主装载（插件模式） |
|---|---|---|
| 谁先起 | 界面先起，宿主后起 | 宿主先起 |
| `LING_UI_TOKEN` | 没有 | 有 |
| 宿主由谁拉起 | 界面自己拉 `ling serve` 子进程 | 已经在跑 |
| 口令从哪来 | 读 `session.json` | 环境变量 |
| 关窗口时 | 按设置决定是否退宿主 | 按设置决定是否退宿主 |

**启动器模式的顺序**：

```
1. 进程起来，没有 LING_UI_TOKEN
2. 读 <数据根>/registry.json 探测宿主是否在跑
     a. 在跑 → 直接用 session.json 里的口令连上去，第 3 步
     b. 没跑 → 起子进程 ling serve，等 registry.json 与 session.json 出现（最多 15 秒）
                超时则报「宿主起不来」，退出
3. 绑 127.0.0.1:8010（占用顺延到 8099），写 registry.json 的 ui_port
4. 用口令连管理端口，调一次 kernel.plugins 自检
5. 自检通过，开窗口
6. 记下「宿主是我起的」，退出时据此决定要不要收尾
```

**插件模式的顺序**：

```
1. 宿主装载 core-ui，起进程，传三个环境变量
2. 绑端口、写 ui_port、自检
3. 自检通过，向标准输出打 {"ready":true,"port":8010}
4. 宿主读到这一行才算激活成功，广播 activated
5. 开窗口
```

### 4.2 为什么用环境变量区分

不用命令行参数：宿主拉起它时参数由宿主决定，用户双击时没有参数，参数表在两种情形下都不由界面控制。环境变量的有无是宿主控制的，界面自己不会误加。

不用配置文件标记：那要读写一个「我是怎么被启动的」状态，多一处要维护的东西。

### 4.3 就绪信号

插件模式下，界面在自检通过后向标准输出打一行：

```json
{"ready": true, "port": 8010}
```

宿主读到这一行才判定激活成功。不用「等 2 秒看看能不能连」这种猜测——端口被占用顺延时，猜的时间不好定。

启动器模式下这行也打，只是没人读；调试时有用。

## 5. 发布包出几个

两个维度交叉，共四个产物：

| | 便携版（解压即用） | 安装包（向导安装） |
|---|---|---|
| `webui` | `ling-0.0.3-webui-portable.zip` | `ling-0.0.3-webui-setup.exe` |
| `desktop` | `ling-0.0.3-desktop-portable.zip` | `ling-0.0.3-desktop-setup.exe` |

- **便携版**：整个目录压成一个 zip，解压后双击 `ling.exe` 就能用，不写注册表。
- **安装包**：Inno Setup 脚本，装到 `Program Files`，建开始菜单项与卸载入口。

四个包的差别只在 `core-ui` 的构建开关与安装方式，其余文件完全相同。

## 6. 双击之后发生什么

这是「开箱即用」的关键路径：

```
双击 ling（或开始菜单项）
  → 没有控制台窗口弹出（界面编成 GUI 子系统）
  → 界面进程起来，发现没有 LING_UI_TOKEN，进启动器模式
  → 探测宿主：没在跑，就起 ling serve 子进程
  → 宿主预装三个内置插件，绑管理端口
  → 界面绑 8010，自检，开窗口
  → 窗口里显示插件列表
```

关掉窗口时按界面里的设置决定宿主去留（§7）。要彻底退出，也可以在界面里点「退出 ling」。

## 7. 关掉界面之后宿主怎么办

由**界面**决定，在界面的设置页里调。宿主不参与这个判断——它不知道自己是被谁启动的，也不该关心。

设置项 `core-ui.close_behavior`，存在配置里（`core-settings` 的 `core-ui.close_behavior` 键），两项：

| 取值 | 关窗口时 | 适合 |
|---|---|---|
| `keep-host`（默认） | 只关界面，宿主继续跑，定时任务照常触发 | 把 ling 当常驻服务用 |
| `stop-host` | 关界面前先调 `kernel.shutdown`，等宿主退出 | 把 ling 当随手开随手关的工具 |

默认选 `keep-host`：定时任务与插件的后台工作不该因为关了个窗口就停。

启动器模式下还有个细节：如果宿主是界面自己拉起的，选 `stop-host` 时要等子进程真正退出再关窗口，否则会留下一个孤儿进程占着端口。等不超过 10 秒，超时就强杀并记一条 warn。

### 7.1 界面被强杀时

设置来不及生效，宿主按「自己没被通知」处理，继续跑。这不算 bug：强杀本来就是异常路径，宿主继续跑比突然消失安全。

重启界面后它会重新探测：宿主在跑就直接连上，恢复原状。

### 7.2 平台差异

`desktop` 版目前只做 Windows。Linux 的桌面窗口要另一套方案（没有 WebView2），等做到那一步再议。`webui` 版三平台一样——它只是开浏览器，不需要窗口库。

## 8. 实现状态

未实现。`webui` 版是最小可行目标（服务端 + 页面 + 开浏览器），`desktop` 版在它之上加 WebView2 窗口。
