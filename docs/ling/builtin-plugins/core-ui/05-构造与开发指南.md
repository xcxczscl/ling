## 2. 代码落在哪

```
main/builtin-plugins/core-ui/
├─ plugin.toml                 清单，含 [sidecar] 段（不含 [ui]，core-ui 自己不贡献面板）
├─ CMakeLists.txt
├─ src/
│  ├─ main.cpp                 入口：读环境变量、起服务、选形态
│  ├─ ui_server.cpp/.h         HTTP 服务、路由分发、静态文件
│  ├─ panel_assets.cpp/.h      面板资源读取与五道检查
│  ├─ manifest_ui.cpp/.h       [ui] 段解析与「带面板的插件」内存表
│  ├─ api.cpp/.h               /api/* 与管理端口的翻译
│  ├─ kernel_client.cpp/.h     管理端口客户端（建连、认证、帧收发）
│  ├─ theme.cpp/.h             令牌表与 theme.css 生成
│  └─ win_main.cpp             desktop 窗口（可选编译）
├─ web/
│  ├─ shell.html               外壳骨架
│  ├─ shell.css                布局与令牌引用
│  ├─ shell.js                 导航、初始化、设置挂载
│  ├─ panels.js                面板管理与消息路由
│  ├─ theme.js                 主题应用与切换
│  └─ views/
│     ├─ plugins.js
│     ├─ logs.js
│     ├─ config.js
│     ├─ jobs.js
│     ├─ appearance.js
│     └─ about.js
└─ tests/
   └─ smoke.md                 冒烟清单
```

1.0.0 的 `page.html` 一个文件承载全部视图。1.1.0 拆成 `shell.html` 加 `views/*.js`：六个管理页签各有各的状态与请求，挤在一个文件里改一处要读 800 行。

## 3. 模块划分与依赖方向

```
main.cpp
  └─ ui_server
       ├─ panel_assets  ← manifest_ui
       ├─ theme
       └─ api  →  kernel_client
```

| 模块 | 职责 | 不允许依赖 |
|---|---|---|
| `ui_server` | 路由、请求解析、响应拼装 | 任何业务判断 |
| `panel_assets` | 路径校验、读文件、定 MIME | `api`、`kernel_client` |
| `manifest_ui` | 解析 `[ui]`、维护内存表、发变更事件 | `ui_server` |
| `theme` | 令牌表、拼 CSS | 除 `manifest_ui` 外的任何模块 |
| `api` | 动作表、参数翻译、错误码转译 | `panel_assets` |
| `kernel_client` | 管理端口协议 | 除 `api` 外的任何模块 |

依赖方向单向，不出现回路。`manifest_ui` 与 `theme` 都不碰网络，因此可以单独用单元测试跑。

前端依赖：

```
shell.js
  ├─ panels.js   →  theme.js
  ├─ theme.js
  └─ views/*.js
```

`panels.js` 与 `views/*.js` 互不引用：面板管理与设置页是两块互不相干的功能，只共享 `shell.js` 提供的 DOM 容器与 `call()` 函数。

## 4. 开发顺序

八步，每步都能独立验证。前一步没跑通不做下一步。

| 步 | 做什么 | 怎么验证 |
|---|---|---|
| 1 | 令牌表 + 外壳骨架（侧边栏、空功能区、设置容器） | 起服务打开页面，看到三块布局；手动改 `<html data-theme>` 能看到配色切换；`curl /api/ui/theme.css` 三段都在 |
| 2 | `[ui]` 解析 + `/api/panels`（只验内存表，`state` 字段留到第 5 步） | 装一个带 `[ui]` 的 demo 插件，`curl` 调 `/api/panels` 返回该插件的 `id`、`title`、`icon`；写错 `[ui]` 段时装载报 `E_UI_PANEL_DECL` |
| 3 | 面板资源路由 | 浏览器直接访问 `/panel/<id>/index.html` 拿到内容；访问 `/panel/<id>/../../plugin.toml` 返回 404 |
| 4 | 面板挂载与外框 | 点侧边栏入口出现外框与 iframe，静态页能显示；关掉后入口还在 |
| 5 | 消息路由与代调 | demo 面板点一个按钮调自己的方法，界面显示返回值；改调 `kernel.shutdown` 显示 `E_UI_FORBIDDEN` |
| 6 | 主题切换 | 外观页点暗色，外壳与已开面板一起变；`curl /api/ui/theme.css` 的 `:root` 默认块换成暗色取值 |
| 7 | 设置二级界面（六个页签） | 跑 `CU-02` 至 `CU-11`，行为与 1.0.0 一致 |
| 8 | 生命周期与错误态 | 停用、卸载、删入口文件、堵住面板加载，四种情形都有对应提示 |

第 5 步是整个 1.1.0 的关键节点：它同时验证了「面板能调自己」「面板调不了别人」「token 没进面板」三条。这一步通过之前不要动第 6 至第 8 步。

## 5. 每步的验证手段

| 步 | 手法 |
|---|---|
| 1 | 目视 + 浏览器 DevTools 改 `data-theme` |
| 2 | `curl -X POST /api/panels`（带 token） |
| 3 | `curl` 正常路径与越界路径，逐条对照 `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §5.3 的五道检查 |
| 4 | 目视 + DevTools 看 iframe 的 `src` 与 `sandbox` 属性 |
| 5 | 面板控制台手发 `postMessage`，看回包 |
| 6 | 目视 + 看响应头 |
| 7 | 逐条跑用例表 |
| 8 | 逐条制造故障 |

第 3 步的越界测试要真的建一个符号链接：只在代码里写 `..` 检查，挡不住链接。

## 6. 关键类型与函数签名

### 6.1 服务端

```cpp
enum class UiState { Running, Stopped, Failed };

struct UiPanel {
  std::string id, title, entry, icon;   // entry/icon 是相对插件目录的路径
  UiState state = UiState::Stopped;
  std::string reason;                   // 仅 Failed 时非空
};

// 解析并校验 [ui] 段；失败时 err 是给人看的一句话
bool ParseUiSection(const Toml& manifest, UiPanel& out, std::string& err);

// 读面板资源，内部完成五道检查
struct AssetResult { int status; std::string content_type; std::string body; };
AssetResult ReadPanelAsset(const std::string& plugins_root,
                           const std::string& plugin_id,
                           const std::string& rel_path);

// 生成 theme.css 全文（两套取值）
std::string BuildThemeCss(const std::string& current_theme);

// 处理一次 /api/<动作>；panel 调用时 plugin 非空，用于命名空间校验
Json HandleApi(const std::string& action, const Json& body,
               const std::string& plugin, KernelClient& kc);
```

### 6.2 前端

```js
// panels.js
export function openPanel(pluginId, { width } = {});
export function closePanel(pluginId, reason);      // reason: closed|disabled|uninstalled|evicted
export function handlePanelMessage(event);         // origin/source 校验 + 分发
export function broadcastTheme(theme, tokens);
export function restoreLayout(order, widths);

// theme.js
export function applyTheme(theme, tokens);         // 写给 <html>
export async function setTheme(theme);             // 乐观更新 + 写配置 + 失败回滚

// shell.js
export async function call(action, params);        // 外壳自己的管理动作
```

`handlePanelMessage` 是安全的关键函数，它必须在任何 DOM 操作之前完成 `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §4.1 与 §4.2 的两道校验。

## 7. 构建、运行与调试

### 7.1 构建

```bash
# 必须从仓库根配置：ling_set_* 宏、LING_PLUGIN_OUTPUT_DIR、third_party 都定义在根 CMakeLists
cmake --preset win-debug
cmake --build --preset win-debug --target core-ui
```

不能 `cmake -S main/builtin-plugins/core-ui` 单独配置：`ling_set_standard` 等宏由 `tools/cmake/LingOptions.cmake` 提供（根 `CMakeLists` 里 include），`tools/embed.py` 与 `third_party/` 的路径也按 `CMAKE_SOURCE_DIR` 取，单独配置会三条一起断。

产物落在 `run/<preset>/plugins/core-ui/core-ui.exe`：根 CMakeLists 把 `LING_PLUGIN_OUTPUT_DIR` 设为 `run/${LING_PRESET}/plugins`，core-ui 的 CMakeLists 再用它设 `RUNTIME_OUTPUT_DIRECTORY`。同目录还会自动拷一份 `plugin.toml`。宿主直接从这个目录装载，不用手动搬。

编桌面版加开关：`cmake --preset win-debug -DLING_CORE_UI_DESKTOP=ON`。

### 7.2 运行

```bash
ling serve --data-dir run/tmp-x     # 宿主自动拉起 core-ui 侧车
ling open                           # 或手动开浏览器（地址读 registry.json 的 ui_port）
```

单独调试服务端时可以不经过宿主，但要手动给三个环境变量：

```bash
LING_UI_TOKEN=dev LING_UI_PORT=8010 LING_UI_ROOT=run/tmp-x ./core-ui
```

这时自检会失败（管理端口连不上），进程按 `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §9 直接退出。

要单独看服务端行为，用宿主把侧车拉起来，再用下面的方式请求：

```bash
TOKEN=$(python -c "import json;print(json.load(open('run/tmp-x/session.json'))['token'])")
curl -H "Authorization: Bearer $TOKEN" -X POST http://127.0.0.1:$(python -c "import json;print(json.load(open('run/tmp-x/registry.json'))['ui_port'])")/api/panels
```

1.0.0 曾有「自检失败也照常服务、`/api/*` 返回 503」的调试模式，1.1.0 不做：一个连不上宿主的界面进程没有可验证的行为，留着只会让「为什么界面一片空」多一种解释。

### 7.3 调试

| 要看什么 | 怎么做 |
|---|---|
| 服务端日志 | `ling logs core-ui` |
| 前端报错 | 用 `webui` 版，浏览器 DevTools；`desktop` 版的右键菜单已关掉「检查」 |
| 面板内部 | DevTools 的 frame 选择器切到该 iframe 的上下文 |
| 令牌输出 | `curl -i http://127.0.0.1:8010/api/ui/theme.css` |
| token 是否泄露 | 在面板控制台访问 `sessionStorage`，必须抛 `SecurityError`（不透明源下取不到值，所以判据是「抛错」而不是「等于 0」） |
| 越权是否被拦 | 面板控制台发 `parent.postMessage({type:"call",id:1,method:"kernel.shutdown"},"*")`，应收到 `E_UI_FORBIDDEN` |

面板里发 `fetch("/api/plugins")` 会被 CSP 的 `connect-src 'none'` 直接拒绝，控制台报 CSP 违规（比 CORS 更早）。这是预期行为，不是缺陷。
