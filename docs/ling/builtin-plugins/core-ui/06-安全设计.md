# core-ui 06 安全设计

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 依据：`docs/ling/builtin-plugins/core-ui/02-技术选型.md` §5、`docs/ling/builtin-plugins/core-ui/03-架构设计.md` §2

本文回答：界面层有哪些资产要被保护、谁会来抢、每道门怎么守、还剩哪些风险。

---

## 1. 资产与对手

### 1.1 要保护的东西

| 资产 | 被拿走会怎样 |
|---|---|
| token | 拿到就能调管理端口，等于拿到宿主的全部管理权：卸插件、关宿主、改任意配置 |
| 宿主管理权（通过 `/api/*`） | 同上，只是绕一层 |
| 插件的前端代码与数据 | 代码不是秘密（就在磁盘上）；数据是秘密，但面板只能经自己的插件方法取，取到什么由该插件决定 |
| 界面完整性 | 被篡改的界面可以骗用户点「卸载并删除」 |

### 1.2 对手

| 对手 | 能力 | 动机 |
|---|---|---|
| 有 bug 的插件面板 | 能执行任意 JS，但拿不到 token | 无恶意，但一行写错的循环就能把界面拖死 |
| 恶意插件面板 | 同上，且会主动找漏洞 | 提权到宿主管理权，或读取别的插件的数据 |
| 本机其他进程 | 能访问 `127.0.0.1:8010`、能读磁盘上的 `session.json` | 通常不是攻击者；要考虑的是「别的软件误扫端口」 |
| 用户浏览的其他网站 | 能在浏览器里打开任意页面、能 iframe 别人的页面 | 点击劫持、诱导用户输入 |

**不设防的对手**：已经能读 `session.json` 的本机进程。它拿到的权限与 core-ui 自己相同，这是宿主层的能力边界，不是界面层能解决的。

## 2. 三道边界

```
        ┌──────────── 浏览器 ────────────┐
        │ 外壳（可信·持 token） │ 面板（不可信） │
        └───────────┬───────────┴────────┘
           token 边界 │ 源边界（在内侧两者之间）
        ┌───────────▼────────────────────┐
        │ core-ui 服务端（可信）           │
        └───────────┬────────────────────┘
           能力边界 │
        ┌───────────▼────────────────────┐
        │ 宿主 → 插件（各自的权限域）      │
        └────────────────────────────────┘
```

| 边界 | 守什么 | 手段 |
|---|---|---|
| 源边界 | 面板读不到外壳的东西、发不出请求 | iframe `sandbox` 不含 `allow-same-origin`；CSP `connect-src 'none'` |
| token 边界 | 没 token 的人调不动 `/api/*` | bearer token；面板资源与主题样式表例外（只读静态） |
| 能力边界 | 插件只能调自己命名空间的方法 | 外壳校验一次、服务端再校验一次、宿主再校验能力 |

## 3. 威胁清单

| 编号 | 威胁 | 攻击路径 | 缓解 | 落点 | 残留 |
|---|---|---|---|---|---|
| SEC-01 | 面板关掉宿主 | 面板发 `call` 调 `kernel.shutdown` | 外壳按命名空间拒绝；服务端二次校验；返回 `E_UI_FORBIDDEN` | 外壳侧 `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §4.3；服务端 `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §6.2 第 2、3 步 | 无 |
| SEC-02 | 面板冒充别的插件 | 消息里写 `pluginId:"player"` | 外壳按 `event.source` 查表认定调用方，不看消息内容 | `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §4.1 | 无 |
| SEC-03 | 面板读走 token | 面板访问 `parent.sessionStorage` | 不透明源，跨源访问抛错；token 不进消息、不进 iframe 地址，只在打开外壳时经 URL 传入一次并立刻抹除 | `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §2.2 与本文 §6 | 见 §6 的 URL 暴露面 |
| SEC-04 | 面板直接请求 `/api/*` | `fetch("/api/uninstall")` 或表单提交 | 跨源被浏览器拦；CSP `connect-src 'none'` 挡脚本请求，`form-action 'none'` 挡表单提交 | `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §5.4 的响应头；本文 §5 | 无 |
| SEC-05 | 用 `../` 读插件目录里的其他文件 | `/panel/rm/../../plugin.toml` | 五道路径检查；后缀白名单 | `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §5.2（后缀白名单）、§5.3（五道检查） | 无 |
| SEC-06 | 用符号链接逃出 `ui/` | 在 `ui/` 放一个指向 `../../` 的链接 | 解析真实路径后比对前缀 | `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §5.3 第 4 步 | 无 |
| SEC-07 | 别的网站 iframe 嵌入界面做点击劫持 | 第三方页面 `<iframe src="127.0.0.1:8010">` | 外壳页响应 `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'`；面板页不设 `X-Frame-Options`，否则自己嵌不进来 | `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §5.4 | 无 |
| SEC-08 | 面板发海量请求耗尽资源 | 循环发 1 万条 `call` | 单面板在途上限 16 条，超出回 `E_UI_BUSY` | `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §4.4 | 面板仍可占 CPU |
| SEC-09 | 伪造消息来源 | 别的窗口 `postMessage` 冒充面板 | `event.source` 查表 + `event.origin` 必须为 `"null"` | `docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §4.2 | 面板被导航到外部后仍是 `"null"` 源，此时靠命名空间校验限权 |
| SEC-10 | 插件被卸载后，残留面板继续调方法 | 卸载瞬间的竞态 | 服务端校验插件当前可用，不可用回 `E_UI_FORBIDDEN` | `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §6.2 第 2 步 | 无 |
| SEC-11 | 插件名注入 HTML | 插件把 `title` 写成 `<img onerror=...>` | 外壳一律用 `textContent` 写入标题，不用 `innerHTML` | `docs/ling/builtin-plugins/core-ui/04-详细设计/02-外壳页面与布局.md` §5 | 无 |
| SEC-12 | 主题名注入 CSS | 配置里把 `core-ui.theme` 改成 `dark;}body{display:none}` | 主题名只接受 `light` 与 `dark`，其他值按 `light` 处理 | `docs/ling/builtin-plugins/core-ui/04-详细设计/04-设计令牌与主题.md` §5.2 | 无 |
| SEC-13 | 面板用弹窗钓鱼 | 面板 `window.open` 一个假登录页 | `desktop` 版：WebView2 的新窗口事件转交系统浏览器；`webui` 版：`allow-popups` 让浏览器新开标签，仍受浏览器沙箱约束。两版弹窗里都没有 token | `desktop` 见 `docs/ling/builtin-plugins/core-ui/04-详细设计/05-进程形态与启动.md` §3.3；`webui` 见本文 §4（`allow-popups`）与 §6（token 不进面板） | 用户会被页面内容欺骗 |
| SEC-14 | 面板内容冒充系统提示 | 面板画一个「你的 ling 需要更新」的假横幅 | 无技术手段，只能靠界面约定把「系统级」与「面板内容」在位置上分开 | 本文 §8.1（约定，不是代码） | 见 §8 |

SEC-11 与 SEC-12 是容易被忽略的两条：它们都不涉及跨源，纯粹是「把数据当代码用」。前者在渲染层，后者在配置层。

## 4. iframe 隔离的具体取值

```html
<iframe src="/panel/<id>/index.html"
        sandbox="allow-scripts allow-popups allow-downloads"
        referrerpolicy="no-referrer"></iframe>
```

| 取值 | 给不给 | 理由 |
|---|---|---|
| `allow-scripts` | 给 | 面板要跑 JS，否则只能显示静态页 |
| `allow-same-origin` | **不给** | 给了等于没沙箱：面板能自己移除 sandbox 属性，还能读走 token |
| `allow-forms` | 不给 | 面板的 CSP 带 `form-action 'none'`，原生表单提交本来就被禁；给了 `allow-forms` 只会让人误以为能提交。表单交互改用 JS 加 `call` |
| `allow-popups` | 给 | 面板要能打开外部链接 |
| `allow-downloads` | 给 | 面板要能导出文件 |
| `allow-modals` | 不给 | `alert`/`confirm` 会挡住整个界面，面板该用自己的弹层 |
| `allow-top-navigation` | 不给 | 面板不能把整个页面导航走 |

不给 `allow-same-origin` 的四个连带结果，都要在文档里说清，避免后来者「顺手加上」：

| 结果 | 影响 |
|---|---|
| 面板读不到 `localStorage`、`sessionStorage`、Cookie | 面板要持久化的数据必须存插件配置 |
| 面板的 `fetch` 属于跨源请求，没有 CORS 许可就被拦 | 与「token 不进面板」形成双保险 |
| `document.domain` 访问抛错 | 无法自改同源 |
| `targetOrigin` 只能写 `"*"` | 安全性改由外壳校验 `source` 与 `origin` |

## 5. CSP

### 5.1 外壳页面

```http
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self';
  img-src 'self' data:; connect-src 'self'; frame-src 'self'; frame-ancestors 'none';
  base-uri 'none'; form-action 'none'
X-Frame-Options: DENY
```

`frame-src 'self'` 只允许嵌入同源的 iframe，挡住「某个插件把面板做成嵌入外部网站」。`frame-ancestors 'none'` 与 `X-Frame-Options` 一起挡点击劫持（老浏览器看后者）。

### 5.2 面板资源

```http
Content-Security-Policy: default-src 'self' data: blob:;
  script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
  connect-src 'none'; form-action 'none'; frame-ancestors 'self'
```

| 项 | 理由 |
|---|---|
| `'unsafe-inline'` | 面板多半没配构建链，脚本与样式写在 HTML 里 |
| `connect-src 'none'` | **第三重保险**：即使浏览器放行跨源，面板也发不出 XHR、`fetch`、WebSocket、`EventSource` |
| `form-action 'none'` | `connect-src` 不管表单提交；没有这条，`<form action="http://...">` 仍能把数据发出去 |
| `default-src 'self' data: blob:` | 允许面板加载自己的图片与 Blob（导出文件时的 `URL.createObjectURL`） |
| `frame-ancestors 'self'` | 面板本身只能被同源的页面嵌入 |

`connect-src 'none'` 是一条容易被质疑的规则（「面板将来要推送怎么办」）：推送的终点是外壳，外壳收到后经 `postMessage` 转给面板，面板不需要自己的连接。这与 `docs/ling/builtin-plugins/core-ui/02-技术选型.md` §9 的设计一致。

## 6. 认证与 token

| 规则 | 说明 |
|---|---|
| token 只在外壳内存与 `sessionStorage` | 不写 Cookie、不落盘、不进 `postMessage`、不进 iframe 地址 |
| 首次进入的 `?token=` | 这是唯一的 URL 暴露面。外壳读到后立刻 `sessionStorage` 存一份并 `history.replaceState` 抹掉地址栏；残留风险见 §8 |
| 面板任何位置都不出现 token | 不放进 iframe `src`、不放进 `postMessage` |
| 免认证地址只有四类 | 见 `docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md` §2.4 |
| 401 的处理 | 提示「口令已变，请重新从主程序打开」，不自动重试 |
| token 比对 | 定长比较，避免按字节提前返回的时间差 |

最后一条：`memcmp` 会在第一个不同的字节返回，理论上可用来逐字节猜 token。本机场景下这个攻击不现实，但改成常量时间比较只多三行代码。

## 7. 能力门禁的实现

三层，任何一层单独失效都不会导致越权：

```
面板  postMessage {type:"call", method:"kernel.shutdown"}
  ↓
第 1 层  外壳：method 必须以 <该 iframe 对应插件 id>. 开头   不符 → E_UI_FORBIDDEN
  ↓
第 2 层  服务端：/api/panel/call 里 plugin 与 method 前缀一致   不符 → E_UI_FORBIDDEN
  ↓
第 3 层  宿主：方法存在、插件具有该方法所需能力                不符 → 现有错误码
```

第 2 层看起来与第 1 层重复，但它防的是「外壳自己被绕过」：外壳有 bug 或将来某个新入口忘了校验时，服务端仍然拦得住。成本是一次字符串前缀比较。

`/api/<动作>`（外壳自己用的管理通道）不经过第 1 层，因为它没有面板来源。它的安全性靠 token。

## 8. 残留风险

以下风险 1.1.0 不解决，写在这里是为了以后不用重新发现一遍：

| 风险 | 说明 | 为什么不解决 |
|---|---|---|
| 本机进程可读面板前端代码与当前主题 | 静态资源免 token | 前端代码在磁盘上，主题不含秘密；要挡住就得给 iframe 加票据机制，复杂度远大于收益 |
| 本机进程若读到 `session.json` 就能直连管理端口 | 绕过 core-ui | 属于宿主的能力边界，界面层无权处理 |
| 面板可显示任意内容（假警告、假更新提示） | 技术手段无法区分「插件自己的界面」与「伪装成系统的界面」 | 缓解只能靠约定：外壳的系统级提示固定在侧边栏底部与页面顶部一条，不进入面板区域；见本节 §8.1 的界面约定 |
| 面板会拖垮整个标签页 | 取决于浏览器是否给 sandbox iframe 独立进程（Chrome 111 起默认隔离），WebView2 跟随 Edge 版本 | 要做进程级隔离就得放弃 iframe，回到「各自起端口」的高门槛方案 |
| 拖拽 `payload` 可夹带任意文本 | 落点面板会收到最多 8 KB 的字符串 | 接收方必须当成不可信输入自己校验，这与「插件方法要校验参数」是同一条原则 |

### 8.1 界面约定（配合上面第三条）

| 约定 | 说明 |
|---|---|
| 系统级提示只在两处 | 侧边栏底部一行、功能区顶部一条临时提示 |
| 面板区域内的一切都视为插件内容 | 用户看到的「警告」「需要更新」默认不可信 |
| 危险操作只在设置页做 | 卸载、删数据、退出 ling 的入口都在设置二级界面，不在面板里 |

## 9. 编码安全清单

写代码时逐条勾：

- [ ] `handlePanelMessage` 在任何 DOM 操作前完成 `event.source` 查表与 `event.origin` 比对
- [ ] 调用方身份只来自 iframe 映射表，从不读消息里的 `pluginId`
- [ ] 所有由插件提供的内容（`title`、错误信息、日志行）用 `textContent` 写入
- [ ] 主题名只接受 `light` 与 `dark` 两个白名单值
- [ ] 面板路径经过五道检查，第 4 道用真实路径比对
- [ ] 面板资源的后缀白名单之外一律 404
- [ ] `/api/*` 除四类免认证地址外全部校验 token
- [ ] token 比较用常量时间
- [ ] iframe 的 `sandbox` 不含 `allow-same-origin`
- [ ] 外壳页响应带 CSP 与 `X-Frame-Options: DENY`；面板资源带 CSP（含 `form-action 'none'`），不设 `X-Frame-Options`（否则把自己嵌不了）
- [ ] 面板在途请求超过 16 条时立即回 `E_UI_BUSY`
- [ ] 越权与非法消息都记 warn，日志含插件名与方法名
