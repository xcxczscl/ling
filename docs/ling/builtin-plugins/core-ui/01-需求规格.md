# core-ui 01 需求规格

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 依据：`docs/ling/builtin-plugins/core-ui/00-总览与术语.md`、`docs/ling/main/01-需求规格.md`

本文回答：界面上要能做哪些事、每件事成什么样、怎么判断做对了。

---

## 1. 需求从哪来

| 上游条目 | 本插件承担的部分 |
|---|---|
| `LING-REQ-075` | 卸掉 core-ui 后命令行仍可用——反过来说，界面不能是任何能力的唯一入口 |
| `LING-REQ-116` | 界面崩溃不影响宿主，2 秒内自动重启并可重连 |
| `LING-REQ-072` | 界面与命令行走同一条调用路由，不另开一套 |
| `LING-REQ-078` | 内置插件无特权，它调的每个方法都是普通方法 |
| `LING-REQ-115` | 只绑回环，不对外暴露 |

需求编号 `CUI-REQ-###`。`CUI` 为本插件代号，已登记在 `docs/common/01-术语表.md` 的项目代号表。

## 2. 功能需求

### 2.1 界面骨架

| 编号 | 需求 | 验收标准 |
|---|---|---|
| `CUI-REQ-001` | 侧边栏列出全部带面板的插件，底部固定「设置」入口 | 装 3 个带 `[ui]` 的插件后侧边栏出现 3 项，顺序按插件 `id` 升序；「设置」始终在最下 |
| `CUI-REQ-002` | 侧边栏可收起与展开，状态写入 `core-ui.sidebar` | 收起后功能区占满窗口宽度；重启界面后保持收起 |
| `CUI-REQ-003` | 「设置」进入二级界面，含插件、日志、配置、任务、外观、关于六个页签 | 六个页签逐个点开都有内容，切换不刷新页面 |
| `CUI-REQ-004` | 功能区同时显示最多 4 个面板，横向均分，中间可拖分隔条 | 打开 4 个面板时每个宽度为可用宽度的四分之一（误差不超过 4 像素）；拖动后相邻两个宽度互补变化 |
| `CUI-REQ-005` | 面板外框由外壳绘制，含插件名与关闭钮 | 面板顶部有 32 像素高的条；插件网页自身不含这条 bar 也能正常显示 |
| `CUI-REQ-006` | 关掉面板后插件视图仍在侧边栏，可重新打开 | 关闭后再点该视图，面板按 `core-ui.layout.order` 里的原槽位插回，宽度不变 |
| `CUI-REQ-007` | 打开的插件集合与各面板宽度写入 `core-ui.layout`，重启后恢复 | 打开 2 个面板并调宽比例，重启界面后两者与比例一致 |

### 2.2 插件面板

| 编号 | 需求 | 验收标准 |
|---|---|---|
| `CUI-REQ-010` | 面板在 `plugin.toml` 的 `[ui]` 段声明，字段为 `entry`、`title`、可选 `icon`；`entry` 必须位于 `ui/` 下且后缀为 `.html`，`icon` 若有则只接受 `.svg` 或 `.png`，`title` 长度 1 至 32 字符 | 缺任一必填字段、路径越出 `ui/`、后缀不是 `.html`、`title` 超长，四种情形都装载失败并报 `E_UI_PANEL_DECL`，错误信息写清是哪一项 |
| `CUI-REQ-011` | 声明 `[ui]` 的插件，`capabilities` 必须含 `ui` | 未声明 `ui` 却写 `[ui]` 段时装载失败，错误信息说明缺哪项 |
| `CUI-REQ-012` | 面板网页从插件目录的 `ui/` 下读取，由 core-ui 服务端统一发给浏览器 | 请求面板地址返回 `[ui].entry` 指向的那个文件的内容（`entry` 为 `ui/main.html` 时返回 `main.html`）；插件目录里 `ui/` 之外的文件取不到 |
| `CUI-REQ-013` | 面板在隔离画框（iframe）中加载，不授予同源 | 面板内 `document.domain` 访问抛出安全错误；面板读不到外壳的 `sessionStorage` |
| `CUI-REQ-014` | 面板只能调自己插件命名空间下的方法 | 面板发起 `kernel.shutdown` 时外壳回 `E_UI_FORBIDDEN`，宿主未退出 |
| `CUI-REQ-015` | 面板拿不到 token，也不能自己发 HTTP 请求 | 面板内 `fetch("/api/plugins")` 被浏览器拒绝；面板页面源码与消息中不出现 token |
| `CUI-REQ-016` | 面板与外壳按固定消息协议通信：`init`、`call`、`result`、`theme`、`event`、`drag`、`shutdown` | 逐条验：`init` 在 `load` 后到达且只到一次；`call` 必回一条 `result`；`theme` 改变面板配色；`drag` 后落点面板收到 `event`/`drop`；`shutdown` 后 300 毫秒内面板被移除 |
| `CUI-REQ-017` | 面板入口文件缺失时，预检一返回就在外框内显示错误原因与「重试」；网页注册 `load` 后 10 秒仍未完成时显示「加载超时」与「重试」 | 两件事分开验：删掉 `entry` 指向的文件后打开面板，应在一秒内出现「面板文件不存在」；让入口页故意卡住不触发 `load`，应从设置 `src` 起算 10 秒时出现「面板加载超时」 |
| `CUI-REQ-018` | 单个面板报错或卡死不拖垮外壳与其他面板 | 让一个面板死循环，另一个面板仍可操作，侧边栏可切换 |

### 2.3 主题与观感

| 编号 | 需求 | 验收标准 |
|---|---|---|
| `CUI-REQ-020` | 外壳样式只引用 `--ling-*` 设计令牌，不出现写死颜色 | 全局搜索外壳 CSS，颜色值只出现在令牌定义处 |
| `CUI-REQ-021` | 内置 `light`、`dark` 两套主题，取值存 `core-ui.theme`，切换立即生效 | 在「外观」页切换，外壳与所有已开面板在 300 毫秒内变色，无需刷新 |
| `CUI-REQ-022` | 主题变化时外壳向每个面板广播 `theme` 消息 | 面板收到消息后自身 `data-theme` 同步更新 |
| `CUI-REQ-023` | 新面板的样式表默认取当前主题，`init` 消息再带上当前主题与令牌取值 | 在暗色下新开面板，首屏即为暗色（由 `theme.css` 的 `:root` 默认块保证），不出现白闪 |

### 2.4 生命周期

| 编号 | 需求 | 验收标准 |
|---|---|---|
| `CUI-REQ-030` | 插件停用或卸载时其面板关闭并提示；停用后入口变淡保留（可点开重新启用），卸载后入口消失 | 在设置的插件页停用某插件，2 秒内其面板与外框消失、入口变淡；卸载后入口消失 |
| `CUI-REQ-031` | 插件启动失败时，面板显示失败原因与「看日志」按钮 | 让插件侧车崩溃三次，面板显示 `last_error` 原文，点按钮跳到日志页并选中该插件 |
| `CUI-REQ-032` | 插件重新启用或重装后，入口恢复，不自动打开面板 | 重装后侧边栏出现该入口，功能区没有自动新增面板 |
| `CUI-REQ-033` | 界面进程崩溃时宿主不受影响，2 秒内重启一次，连续三次后停止 | 强杀界面进程三次，第三次后 `ling plugins` 显示「启动失败」并附原因 |

### 2.5 管理面板

| 编号 | 需求 | 验收标准 |
|---|---|---|
| `CUI-REQ-040` | 插件列表的条目与状态与 `ling plugins` 一致 | 两边逐条比对，名称、版本、状态相同 |
| `CUI-REQ-041` | 支持安装、停用、启用、卸载；停用有下游时先提示连带对象；卸载时可选保留或删除数据 | 停用被依赖的插件出现连带清单；卸载删数据后目录整个消失 |
| `CUI-REQ-042` | 日志视图可按插件与级别筛选，自动刷新间隔 2 秒，单次只渲染最后 200 行 | 10 万行日志下滚动流畅，首屏渲染不影响操作 |
| `CUI-REQ-043` | 配置视图按值类型给控件，改完立即保存，失败时保留输入内容 | 断开宿主后保存，输入框内容不丢，下方显示原因 |
| `CUI-REQ-044` | 任务视图新增任务时校验 cron，错误定位到具体段 | 输入 `0 25 * * *` 时提示「『时』段取值 25 超出范围 0 至 23」 |
| `CUI-REQ-045` | 设置页提供关闭行为选项与「退出 ling」，值存 `core-ui.close_behavior` | 选 `stop-host` 后关窗口，宿主进程在 3 秒内退出 |

## 3. 非功能需求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| `CUI-REQ-050` | 只监听 `127.0.0.1`，不可配置 | `netstat` 显示监听地址只有回环 |
| `CUI-REQ-051` | 面板静态资源请求的解析结果必须落在该插件的 `ui/` 目录内 | 请求 `/panel/<id>/../../plugin.toml` 返回 404，不返回文件内容 |
| `CUI-REQ-052` | 面板静态资源与 `theme.css` 免 token，其余 `/api/*` 必须带 token | 不带 token 请求 `/api/plugins` 返回 401；请求面板入口返回 200 |
| `CUI-REQ-053` | 越权调用一律拒绝并记一条 warn 日志，日志含来源插件与方法名 | 面板调 `kernel.shutdown` 后日志出现一条带插件名的 warn |
| `CUI-REQ-054` | 打开 4 个面板时界面进程常驻内存增量不超过 200 MB | 对比打开前后的进程工作集 |
| `CUI-REQ-055` | 没装 core-ui 时，带 `[ui]` 的插件照常装载与调用 | 卸掉 core-ui 后 `ling install` 一个带 `[ui]` 的插件，装载成功且方法可调 |
| `CUI-REQ-056` | `[ui].entry` 指向的文件不存在时，装载仍成功，但面板显示错误态并记 warn | 删除入口文件后重装，装载成功；打开面板出现错误态 |

## 4. 场景

### 4.1 打开界面

装好 ling 之后，使用者想看看现在是什么状态。

要成什么样：

- `webui` 版：宿主启动后自动打开浏览器到 `127.0.0.1:8010`（端口被占时顺延，实际端口从 `registry.json` 的 `ui_port` 读）。
- `desktop` 版：双击图标直接出窗口。
- 打开后 1 秒内出现内容，不是白屏转圈。

### 4.2 打开一个插件的界面

使用者装了一个带界面的插件，想用它的功能。

要成什么样：

- 侧边栏出现该插件的一项，名字取 `[ui].title`，有 `icon` 时显示图标。
- 点它，功能区出现该插件的面板，外框标题与侧边栏一致。
- 面板 2 秒内出内容；插件没启动时显示原因，不是空白。
- 再点别的插件，两个面板并排，可以调宽。

### 4.3 在插件界面里干活

要成什么样：

- 点面板里的按钮，调用落到该插件的方法上，结果回到面板。
- 调用慢于 1 秒时，面板自己能显示「处理中」——外壳不代它做加载态。
- 调用失败时，外壳把错误码与人话原因一起回给面板，面板决定怎么显示。
- 面板想调别的插件，只能经自己的插件中转，直接调被别人拒绝。

### 4.4 换主题

要成什么样：

- 侧边栏底部「设置」→「外观」，选亮色或暗色，立即生效。
- 已打开的面板一起变色，不刷新、不白闪。
- 关掉界面再打开，还是上次选的那套。

### 4.5 管理面板的原场景

插件列表、安装、停用、卸载、翻日志、改配置、管定时任务、界面崩溃，八种场景与 1.0.0 一致，只是入口从一级界面改为「设置」二级界面，验收标准见 `CUI-REQ-040` 至 `CUI-REQ-045`、`CUI-REQ-033`。

## 6. 本期明确不做的

| 不做 | 什么时候做 | 为什么现在不做 |
|---|---|---|
| 远程访问与多用户 | 不做 | 单机个人工具，加了就要做账号与加密 |
| 面板之间自由互发消息 | 不做 | 会绕开能力校验与日志 |
| 窗口自由拖拽、浮动、标签页 | 不确定 | 一插件一面板后，均分加分隔条够用，窗口管理是另一套复杂度 |
| 用户自定义主题颜色、第三方主题包 | 不确定 | 先做两套预设，看用下来的反馈 |
| 共享组件库（按钮、表格、弹窗） | 不确定 | 靠设计令牌保证观感一致，组件库要单独维护一套版本 |
| 一个插件多个面板 | 不做 | 插件在自己的网页内部划分区域即可 |
| 面板级权限声明（白名单） | 不做 | 面板只调自己的方法已是最小权限 |
| 插件详情页（README、权限说明） | 不确定 | 需要清单里带更多字段 |
| 图表（调用量、耗时趋势） | 不确定 | 要先有指标采集，那是另一件事 |
| 国际化 | 不做 | 只有中文 |
