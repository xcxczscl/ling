# core-ui 03 页面与交互

> 状态：已定稿 | 最后更新：2026-10-31
> 上级：`docs/ling/builtin-plugins/core-ui/00-总览与边界.md`

本文回答：界面长什么样、四个视图各放什么、交互的规矩。

---

## 1. 整体结构

单页应用，左边一条固定的导航，右边是内容区。不分页跳转——所有视图在同一个页面里切换，切换不刷新。

```
┌─────────────────────────────────────────────┐
│ ling 0.0.3            ● 宿主运行中    [刷新] │
├──────────┬──────────────────────────────────┤
│ 插件     │                                  │
│ 日志     │        内容区（当前视图）         │
│ 配置     │                                  │
│ 任务     │                                  │
└──────────┴──────────────────────────────────┘
```

顶栏三个信息：版本、宿主状态、刷新按钮。宿主状态每 5 秒探一次（调 `plugins` 取条目数与状态），断了就在顶栏变红并说明「ling 没有响应」。

不用前端框架。理由：四个视图、十来个接口，用原生 DOM 与 `fetch` 就够用；引入框架要配构建链，而构建链的维护成本会超过这点收益。

## 2. 插件视图

### 2.1 列表

一行一个插件：

| 列 | 内容 |
|---|---|
| 插件名 | 等宽字体，可以点进去看详情 |
| 版本 | 灰色小字 |
| 状态 | 彩色圆点 + 文字：已启用 / 已停用 / 启动失败 |
| 类型 | 进程内 / 独立进程 |
| 操作 | 停用或启用、卸载 |

状态颜色只用在圆点上，文字始终是正常的黑字——色盲用户靠文字也能分辨。

### 2.2 顶部操作

- **安装插件**：打开目录选择，选完显示路径与「确认安装」。
- **筛选**：全部 / 在用 / 停用 / 失败。
- **搜索**：按插件名过滤，输入即筛。

### 2.3 危险操作的确认

| 操作 | 确认文案 |
|---|---|
| 停用 | 「停用 demo-a？它会停止工作，数据保留。」有下游时追加：「同时会停用 demo-b、demo-c。」 |
| 卸载（保留数据） | 「卸载 demo-a？它的数据会留在 `<路径>`，以后装回来还能用。」 |
| 卸载（删数据） | 「卸载 demo-a 并删除它的全部数据？**这一步不能撤销。**」按钮文字是「卸载并删除」，不是「确定」 |

危险按钮一律放在右侧、用红底文字，默认焦点在主按钮上——手快按回车不会误删。

### 2.4 启动失败的条目

状态「启动失败」的行展开一格，显示原因（内核给的 `last_error`）与「看日志」按钮。

## 3. 日志视图

### 3.1 布局

上面一行选择器，下面是日志区。

```
[插件 ▾ demo-caller]  [级别 ▾ 全部]  [☑ 自动刷新]  [清屏]
──────────────────────────────────────────────────
2026-10-31T18:00:23 [info]  event demo-a.pinged pong
2026-10-31T18:00:23 [info]  reply=pong
```

级别用颜色区分行首的 `[info]` / `[warn]` / `[error]` 标签，行本身不整行染色——整行染色在长日志里很吵。

### 3.2 刷新与加载

- 自动刷新默认开，间隔 2 秒，只拉最后 200 行。
- 关掉自动刷新后可以手动点刷新。
- 往上滚动到底部时加载更早的内容（每次再拉 200 行）。
- 超过 5000 行时把最早的从 DOM 里删掉，防止页面越用越卡。

### 3.3 空状态

没选插件时显示「选一个插件看它的日志」。选了但没日志时显示「这个插件还没写过日志」。

## 4. 配置视图

### 4.1 结构

左边选插件，右边列出它的键。

| 值的类型 | 控件 |
|---|---|
| 布尔 | 开关 |
| 数字 | 数字输入框 |
| 字符串 | 单行输入框；超过 80 字符用多行 |
| 对象、数组 | 多行文本框，内容是格式化后的 JSON，失焦时校验 |
| `null` | 显示「（未设置）」，可以点「设置」开始填 |

### 4.2 保存

- 改完立即保存，不需要点「保存」按钮。
- 保存失败时把输入框标红、下方显示原因，**内容不清空**——用户填的东西不该因为一次失败就没了。
- 保存成功时在右上角闪一条「已保存」，2 秒后消失。

### 4.3 只读提示

`core-settings` 没装时，整个配置视图显示一行说明：「配置功能需要 core-settings，它当前没有启用。」而不是报错或空白。

## 5. 任务视图

### 5.1 列表

| 列 | 内容 |
|---|---|
| 名字 | —— |
| 时间表 | cron 原文 + 一句人话解释（如「每天 03:00」） |
| 目标方法 | 等宽字体 |
| 上次触发 | 时间，或「还没触发过」 |
| 操作 | 停用 / 删除 |

### 5.2 新增任务

一个表单：名字、cron、目标方法、参数（JSON 文本框）、补跑开关。

cron 输入框下方实时显示「下次触发时间」，写错时显示「『时』段取值 25 超出范围 0 至 23」。这比让用户自己去查 cron 语法有用得多。

### 5.3 空状态

没有任务时显示「还没有定时任务」与一个「新增」按钮。

## 6. 通用规矩

| 规矩 | 说明 |
|---|---|
| 每个操作都有反馈 | 成功给一条绿色提示，失败给一条红色提示并说明原因 |
| 失败不吞消息 | 任何请求失败都要显示出来，不允许只在控制台打日志 |
| 危险操作二次确认 | 卸载、删数据必须确认；停用可配置成不确认 |
| 长操作有进度 | 安装、卸载期间按钮变灰并显示「处理中」 |
| 不用弹窗套弹窗 | 确认框只有一层，需要二次确认的场景改为「输入插件名确认」 |
| 键盘可用 | Tab 能走完所有可点元素，Esc 关掉确认框 |
| 只显示中文 | 不做国际化 |
