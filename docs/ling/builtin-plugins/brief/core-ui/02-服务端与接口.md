# core-ui 02 服务端与接口

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-ui/02-服务端与接口.md`

## 1. 进程与端口

独立进程，由宿主拉起；只绑 `127.0.0.1`，端口 8010 起顺延到 8099，实际端口写 `registry.json` 的 `ui_port`。它与宿主是单向客户端关系。

## 2. 认证

### 2.1 口令从哪来

宿主经环境变量传 `LING_UI_TOKEN` / `LING_UI_PORT` / `LING_UI_ROOT`。界面不读 `session.json`——读文件意味着它得知道数据根，而它不需要知道。

### 2.2 浏览器怎么通过认证

打开地址带 `?token=`，页面存进 `sessionStorage`，之后每个请求带 `Authorization: Bearer`。token 不写 Cookie、不落盘。

### 2.3 为什么不做登录页

做登录页就要有「用户」，而 ling 没有用户。口令证明的是「你在这台机器上」，不是「你是谁」。

## 3. API

`POST /api/<动作>`，响应统一 `{"ok":true,"result":...}` 或 `{"ok":false,"error":{code,message,advice}}`。十三个动作，每个转成一次管理端口调用。**界面不直连内核**，所以界面与命令行行为永远一致、错误文案只有一份。

### 3.1 静态资源

页面文件编译期嵌进 exe，运行时不读磁盘：发布只有一个文件，也不怕前端文件被删。

## 4. 启动与就绪

绑端口 → 写 `ui_port` → 用 token 自检一次 `kernel.plugins` → 通过后向标准输出打 `{"ready":true,"port":8010}`。自检很重要：只绑上端口不代表能连上宿主。

## 5. 失败处理

端口全占则退出并标失败；连不上宿主则退出、宿主 2 秒后重启；请求超时 5 秒返回 504；连续崩三次停止重启。

## 6. 界面与命令行的取舍

界面不显示内核日志。内核日志是「修宿主的工具」，不能依赖会坏掉的那个部件；界面崩了的时候命令行还在。
