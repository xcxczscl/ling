# core-ui 04 详细设计 05 进程形态与启动

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 详细版：`docs/ling/builtin-plugins/core-ui/04-详细设计/05-进程形态与启动.md`

## 1. 两种形态差在哪

```
共同：宿主拉起进程 → 绑 8010 → 连管理端口自检 → 读面板清单 → 提供 /api/*
分叉：webui 版由宿主调浏览器打开；desktop 版自己创建 WebView2 窗口
```

两版共用同一份服务端、外壳页面与 API，是一个程序的两个构建开关。

## 2. 构建开关

```cmake
option(LING_CORE_UI_DESKTOP "把 core-ui 编成带窗口的桌面版" ON)
```

| 开关 | 产物 | 额外依赖 |
|---|---|---|
| OFF | 纯控制台程序，静默运行并开浏览器 | 无 |
| ON | 带 WebView2 窗口 | WebView2 SDK |

`webui` 版保留控制台子系统：就绪行要打到标准输出，宿主靠它判断激活成功。宿主以隐藏窗口拉起，用户看不到黑框；`desktop` 版才编成 GUI 子系统。

## 3. WebView2

### 3.1 它是什么

Windows 10/11 自带的浏览器控件（Edge 内核），系统已有运行时，不需要额外装。

### 3.2 用它要加什么依赖

| 项 | 内容 |
|---|---|
| 用途 | 给 `desktop` 版内嵌窗口 |
| 体积 | 静态链接后 exe 增加约 1 MB，运行时不随包分发 |
| 影响面 | 只有 `desktop` 构建，`webui` 版与宿主不链它 |
| 不引入的替代 | 只能开系统浏览器，等于放弃 `desktop` 形态 |

### 3.3 窗口行为

标题 `ling`；初始 1100 × 760，最小 900 × 600；窗口位置存 `core-ui.window`；关闭只关界面；不做托盘图标；右键菜单只留「复制」与「刷新」；面板申请的弹窗交给系统浏览器打开。

### 3.4 不用 WebView2 的降级

没有运行时时不开窗口，改为调默认浏览器，退化成 `webui` 版，日志记一条 warn。不弹「请先安装 WebView2」。

## 4. 启动顺序与握手

### 4.1 启动顺序

```
1. 用户启动 ling
2. 宿主预装内置插件，装载 core-ui（侧车轨道）
3. 宿主传 LING_UI_TOKEN / LING_UI_PORT / LING_UI_ROOT
4. 界面绑 127.0.0.1:8010（顺延到 8099），写 registry.json 的 ui_port
5. 用口令连管理端口，调一次 kernel.plugins 自检
6. 读全部插件清单，建「带面板的插件」内存表
7. 自检通过，打 {"ready": true, "port": 8010}
8. 宿主读到这行才算激活，广播 kernel.plugin.state activated
9. webui 版由宿主开浏览器；desktop 版自己建窗口
```

界面不读 `session.json`，口令由宿主给。

### 4.2 就绪信号

第 7 步的 JSON 是宿主判据，不靠「等 2 秒试试」。自检不能省：绑上端口不代表能连上宿主。第 6 步单个清单失败不阻断就绪，去掉该插件并记 warn。

## 5. 面板什么时候加载

**按需加载，不预热。**

| 时机 | 行为 |
|---|---|
| 界面启动 | 只取清单，不建 iframe |
| 点侧边栏入口 | 预检 `HEAD` → 建 iframe → `init` |
| 重启界面 | 按 `core-ui.layout.order` 恢复上次打开的面板，最多 4 个 |

不预热：一个面板是一个完整的网页上下文，4 个常驻会让冷启动后内存高出约 150 MB；用户打开界面通常只看一个具体插件。

## 6. 发布包出几个

| | 便携版 | 安装包 |
|---|---|---|
| `webui` | `ling-<宿主版本>-webui-portable.zip` | `ling-<宿主版本>-webui-setup.exe` |
| `desktop` | `ling-<宿主版本>-desktop-portable.zip` | `ling-<宿主版本>-desktop-setup.exe` |

四个包差别只在 `core-ui` 的构建开关与安装方式。带面板的插件不改变打包：面板文件在各插件目录里，按插件自己的方式分发。

## 7. 关掉界面之后宿主怎么办

配置键 `core-ui.close_behavior`：

| 取值 | 关窗口时 | 适合 |
|---|---|---|
| `keep-host`（默认） | 只关界面，宿主继续跑 | 当常驻服务用 |
| `stop-host` | 先调 `kernel.shutdown`，等宿主退出（仅 `desktop` 版有效） | 随手开随手关 |

分工：`core-settings` 存键（不存在时写回默认值）；界面显示、写回并执行；宿主不参与判断。

默认 `keep-host`：定时任务与插件后台工作不该因为关窗口就停。

### 7.1 界面被强杀时

宿主没收到通知，继续跑。强杀是异常路径，继续跑比突然消失安全；重启界面后按配置恢复原状。

### 7.2 平台差异

`desktop` 只做 Windows。Linux 没有 WebView2。`webui` 版三平台一样，但拿不到标签页关闭事件，故 `stop-host` 只对桌面版可用。

## 8. 双击之后发生什么

宿主起来 → 装载 core-ui → 绑端口、自检、读清单 → desktop 弹窗或 webui 开浏览器 → 显示侧边栏与上次的面板。

关窗口不关宿主，除非选了 `stop-host`（仅桌面版）。已有宿主在跑时再次双击不启第二个宿主，只把界面打开。

**未定**：双击入口怎么不弹控制台窗口（GUI 子系统 / 独立启动器 / 快捷方式最小化），等打包阶段定。
