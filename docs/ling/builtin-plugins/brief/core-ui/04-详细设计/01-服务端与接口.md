# core-ui 04 详细设计 01 服务端与接口

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 详细版：`docs/ling/builtin-plugins/core-ui/04-详细设计/01-服务端与接口.md`

## 1. 进程与端口

| 项 | 规定 |
|---|---|
| 监听地址 | `127.0.0.1`，不可配置 |
| 端口 | 8010 起，占用顺延到 8099 |
| 端口记录 | `registry.json` 的 `ui_port` |
| 与宿主的关系 | 单向客户端，宿主不回调 |
| 静态资源根 | 外壳编译期嵌入；面板运行时读各插件 `ui/` |
| 并发 | 单线程事件循环，单请求不阻塞超过 20 毫秒 |

8010 至 8099 与 7900 段分开，理由见 `docs/ling/main/04-详细设计/04-管理端口与命令行.md` §2.2。

## 2. 认证

### 2.1 口令从哪来

宿主经环境变量传入 `LING_UI_TOKEN`、`LING_UI_PORT`、`LING_UI_ROOT`。界面不读 `session.json`。

### 2.2 浏览器怎么通过认证

访问 `http://127.0.0.1:8010/?token=<口令>`，外壳记在 `sessionStorage`，之后每个 `/api/*` 带 `Authorization: Bearer <token>`。无 token 显示「请从 ling 主程序打开界面」；token 错返回 401，提示「口令已变，请重新从主程序打开」。

### 2.3 为什么不做登录页

ling 没有「用户」概念，口令只证明「你能读 `session.json`」。输入框会让人以为要设密码。

### 2.4 哪些地址免认证

| 地址 | 为什么可以免 |
|---|---|
| `GET /`、`/shell.css`、`/shell.js`、`/views/*.js` | 不含口令，无口令时外壳自己显示提示 |
| `GET /panel/<插件 id>/*` | 插件前端代码本就在磁盘上 |
| `GET /api/ui/theme.css` | 只有颜色与尺寸 |

免认证的地址全是 `GET`、只返回文件或常量；有副作用的请求一律要求 token（`CUI-REQ-052`）。

## 3. 路由总表

| 方法 | 路径 | 认证 | 返回 |
|---|---|---|---|
| `GET` | `/` | 无 | `text/html` |
| `GET` | `/shell.css` | 无 | `text/css` |
| `GET` | `/shell.js` | 无 | `text/javascript` |
| `GET` | `/views/<名称>.js` | 无 | `text/javascript`，名称限六个 |
| `GET` | `/api/ui/theme.css` | 无 | `text/css` |
| `GET` | `/panel/<插件 id>/<路径>` | 无 | 按后缀定 MIME |
| `HEAD` | `/panel/<插件 id>/<路径>` | 无 | 同 GET 的检查，只回头不回正文 |
| `POST` | `/api/<动作>` | 是 | `application/json` |
| `POST` | `/api/panel/call` | 是 | `application/json` |

`/views/` 只允许 `plugins`、`logs`、`config`、`jobs`、`appearance`、`about`。

## 4. 管理动作

响应统一 `{"ok":true,"result":{}}` 或 `{"ok":false,"error":{code,message,advice,detail}}`，文案沿用命令行那套。`code` 恒有；`message` 通常有；`advice` 只在有「下一步」时出现，没有就省略字段（用 `"advice" in error` 判断，别看是不是 `null`）；`detail` 是被调方法带出的原始描述，界面折叠不显示。

| 动作 | 参数 | 转成的调用 |
|---|---|---|
| `plugins` | 无 | `kernel.plugins` |
| `install` | `path` | `kernel.install` |
| `uninstall` | `id`、`purge` | `kernel.uninstall` |
| `enable` / `disable` | `id` | `kernel.enable` / `kernel.disable` |
| `logs` | `plugin`、`level`、`lines` | `core-log.tail` |
| `config.list` / `config.get` / `config.set` | 见 1.0.0 | `core-settings` 三个方法 |
| `jobs.list` / `jobs.schedule` / `jobs.cancel` | 见 1.0.0 | `core-job` 三个方法 |
| `orphans` | 无 | `core-plugin-manager.orphans` |
| `panels` | 无 | 服务端内存表（见 §4.1） |

### 4.1 `panels` 为什么在服务端过滤

界面不解析 `plugin.toml`。服务端启动时读一遍全部清单，把 `[ui]` 有效的插件记在内存表，`panels` 直接返回：

```json
{"id":"resources-manager","title":"资源管理","icon":"/panel/resources-manager/icon.svg","state":"running"}
```

`state` 取 `running`、`stopped`、`failed`，`failed` 时附 `reason`。服务端自己的写动作（`install`、`uninstall`、`enable`、`disable`）成功后立刻重读清单；别处改了插件状态则按 2 秒 TTL 兜底——距上次重读超过 2 秒时，`panels` 先查一次内核再返回。TTL 只在有请求时触发，界面没开就不扫盘。

## 5. 面板静态资源

### 5.1 路径映射

```
GET /panel/resources-manager/style.css  →  <数据根>/plugins/resources-manager/ui/style.css
```

`[ui].entry` 与 `[ui].icon` 相对插件目录写（如 `ui/index.html`），URL 路径相对 `ui/` 目录。

### 5.2 后缀白名单

`.html` `.css` `.js` `.mjs` `.json` `.svg` `.png` `.jpg` `.jpeg` `.webp` `.gif` `.ico` `.woff` `.woff2` `.ttf`，其他一律 404，即使文件存在。

### 5.3 路径穿越防护

| 序 | 检查 |
|---|---|
| 1 | 解码一次后不含 `%` 残留 |
| 2 | 按 `/` 切段后无 `..`、无空段、无以 `.` 开头的段 |
| 3 | 不以 `/` 或 `\` 开头，不含 `:` |
| 4 | 真实路径前缀等于 `<插件目录>/ui` 的真实路径（解析符号链接） |
| 5 | 目标是普通文件 |

任一不过返回 404，不区分「不存在」与「不允许」。第 4 步是关键：字符串前缀挡不住符号链接。插件 id 按 `^[a-z0-9][a-z0-9-]*$` 校验。

### 5.4 缓存与 MIME

`Cache-Control: no-cache` + `ETag`（大小加修改时间），命中 304。`/panel/<id>/` 补 `entry` 文件名，`/panel/<id>` 301 到带斜杠形式，不列目录。

### 5.5 面板不存在

无 `[ui]` 段、`entry` 文件缺失、插件已卸载，三者都返回 404 且 `code` 为 `E_UI_PANEL_NOTFOUND`；外壳在外框内显示错误与「重试」，已卸载时直接关闭面板。

## 6. `/api/panel/call`

### 6.1 请求

```json
{"plugin":"resources-manager","method":"resources-manager.scan","params":{"path":"D:/media"}}
```

### 6.2 校验顺序

| 序 | 校验 | 失败返回 |
|---|---|---|
| 1 | 有效 token | 401 |
| 2 | `plugin` 已装载且带 `[ui]` | `E_UI_FORBIDDEN` |
| 3 | `method` 以 `<plugin>.` 开头 | `E_UI_FORBIDDEN` |
| 4 | 方法在插件方法表里存在 | `E_METHOD_MISSING` |

第 2 步要求插件当前可用：被停用后，面板即使开着也调不动。

### 6.3 与 `/api/<动作>` 的区别

| | `/api/<动作>` | `/api/panel/call` |
|---|---|---|
| 调用方 | 外壳自己 | 外壳代面板 |
| 能调什么 | 管理动作表 | 只有该插件命名空间 |
| 谁决定 `plugin` | 无此参数 | 外壳按消息来源填 |

两条通道带同一枚 token，差别只在允许的方法范围。

## 7. `theme.css` 响应

```http
Content-Type: text/css; charset=utf-8
Cache-Control: no-store
```

正文一次给三段：`:root{…}` 取当前主题，`:root[data-theme="light"]{…}` 与 `:root[data-theme="dark"]{…}` 各 26 个令牌。`no-store` 因为主题会变。

## 8. 启动与就绪

```
1. 宿主装载 core-ui，传三个环境变量
2. 绑端口，写 ui_port
3. 连管理端口，调 kernel.plugins 自检
4. 读全部清单，建「带面板的插件」内存表
5. 自检通过，打 {"ready": true, "port": 8010}
6. webui 开浏览器；desktop 自己建窗口
```

第 4 步单个清单读失败不阻断就绪：去掉该插件，记 warn。

## 9. 失败处理

| 情形 | 行为 |
|---|---|
| 8010 至 8099 全被占 | 进程退出，标记启动失败，日志说明端口段占满 |
| 连不上管理端口 / token 不对 | 退出并说明，宿主 2 秒后重启 |
| 页面请求超时 5 秒 | 504，提示「ling 没有响应，正在忙或已卡住」 |
| 界面崩溃 | `restart = on-crash`，最多 3 次 |
| 面板文件读失败 | 500，外框内显示「读不到面板文件」与路径 |
| 单次管理调用超过 30 秒 | 断开该次调用，不阻塞其他请求 |

## 10. 界面与命令行的取舍

装插件、看状态、看日志、改配置，界面更省事；批量操作命令行有 `apply`；内核日志只有命令行能看（界面是会坏掉的那个部件）；插件功能命令行能调任何插件的方法，面板只能调自己那个。
