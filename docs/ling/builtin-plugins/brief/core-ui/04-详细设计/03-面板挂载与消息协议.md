# core-ui 04 详细设计 03 面板挂载与消息协议

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 详细版：`docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md`

## 1. 清单声明

### 1.1 `[ui]` 段

```toml
capabilities = ["fs", "ui"]

[ui]
entry = "ui/index.html"
title = "资源管理"
icon = "ui/icon.svg"
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `entry` | 是 | 相对插件目录，必须位于 `ui/` 下，后缀 `.html` |
| `title` | 是 | 1 至 32 字符，显示在侧边栏与外框 |
| `icon` | 否 | 位于 `ui/` 下，后缀 `.svg` 或 `.png` |

一个插件最多一个面板，`[ui]` 是单段不是数组。

### 1.2 校验

| 序 | 校验 | 失败 |
|---|---|---|
| 1 | 有 `[ui]` 时 `capabilities` 含 `ui` | `E_UI_PANEL_DECL` |
| 2 | `entry` 与 `title` 存在且非空 | `E_UI_PANEL_DECL` |
| 3 | 路径不含 `..`、不以 `/` 或 `\` 开头、不含 `:` | `E_UI_PANEL_DECL` |
| 4 | 真实路径在 `ui/` 目录内 | `E_UI_PANEL_DECL` |
| 5 | `entry` 后缀 `.html`，`icon` 后缀 `.svg` 或 `.png` | `E_UI_PANEL_DECL` |
| 6 | `title` 长度 1 至 32 | `E_UI_PANEL_DECL` |

`entry` 文件不存在不在装载期检查，装载成功，打开面板时才报错（`CUI-REQ-056`）。

### 1.3 与 capability 的关系

`capabilities` 里的 `ui` 声明才允许贡献面板。没有它却写 `[ui]` 段，装载失败，让错误在装载期暴露。

## 2. 加载流程

```
HEAD /panel/<id>/<entry> → 200
建外框 + iframe(src)
等 load（上限 10 秒）
postMessage {type:"init", …}
面板开始发 call
```

### 2.1 为什么先 HEAD 预检

iframe 加载 404 也会触发 `load`，外壳从跨源文档里读不到东西，分不清「空白」与「文件不存在」。

| 结果 | 处理 |
|---|---|
| 200 | 建 iframe |
| 404 | 不建 iframe，显示「面板文件不存在：`<路径>`」+「重试」 |
| 5 秒无响应 | 显示「面板文件读取超时」+「重试」 |
| 其他状态码 | 显示状态码与「看日志」 |

服务端对 `HEAD /panel/*` 返回与 `GET` 相同的头，不带正文。

### 2.2 10 秒加载上限

从设置 `src` 起算 10 秒没有 `load`，显示「面板加载超时」+「重试」。

## 3. 消息格式

### 3.1 信封

| 字段 | 出现于 | 说明 |
|---|---|---|
| `type` | 全部 | 七种之一 |
| `id` | `call`、`drag`、`result` | 正整数，面板自增，外壳原样回带 |
| `v` | `init` | 协议版本，当前 `1` |

### 3.2 七种消息

| 种类 | 方向 | 字段 | 何时发 |
|---|---|---|---|
| `init` | 外壳 → 面板 | `pluginId`、`title`、`theme`、`tokens`、`v` | `load` 后立即发，只发一次 |
| `call` | 面板 → 外壳 | `id`、`method`、`params` | 要调方法时 |
| `result` | 外壳 → 面板 | `id`、`ok`、`result` 或 `error` | 每次 `call` 或 `drag` 必有且仅有一条 |
| `theme` | 外壳 → 面板 | `theme`、`tokens` | 主题变化时广播 |
| `event` | 外壳 → 面板 | `name`、`data` | 外壳手势与将来推送共用 |
| `drag` | 面板 → 外壳 | `id`、`kind`、`payload` | 面板内开始拖动时 |
| `shutdown` | 外壳 → 面板 | `reason` | 移除前 300 毫秒 |

### 3.3 各消息的正文

```json
{"type":"init","v":1,"pluginId":"rm","title":"资源管理","theme":"dark","tokens":{"--ling-bg":"#1b1b1d"}}
{"type":"call","id":7,"method":"rm.scan","params":{"path":"D:/media"}}
{"type":"result","id":7,"ok":false,"error":{"code":"E_UI_FORBIDDEN","message":"…","advice":"…"}}
{"type":"theme","theme":"light","tokens":{"--ling-bg":"#ffffff"}}
{"type":"event","name":"drop","data":{"kind":"files","payload":{"paths":["D:/media/a.jpg"]},"from":"resources-manager"}}
{"type":"drag","id":8,"kind":"files","payload":{"paths":["D:/media/a.jpg"]}}
{"type":"shutdown","reason":"disabled"}
```

`shutdown.reason` 取 `closed`、`disabled`、`uninstalled`、`evicted`。

## 4. 外壳侧处理

### 4.1 来源识别

外壳维护 `iframe.contentWindow → 插件 id` 的表，收到消息先查表：

| 情形 | 处理 |
|---|---|
| 不在表里 | 丢弃不回复 |
| 在表里，`type` 不是 `call` 或 `drag` | 丢弃并记 warn |
| 是 `call` | 见 §4.3 |
| 是 `drag` | 见 §6.2 |

**永远不读消息里的 `pluginId` 认定调用方**，面子挡不住冒充。

### 4.2 `event.origin` 只放行「不透明源」

面板的 `sandbox` 不含 `allow-same-origin`，所以面板页面是不透明源，它发出的消息 `event.origin` 一律是字符串 `"null"`。

| 收到的 `event.origin` | 处理 |
|---|---|
| `"null"` | 通过（来自隔离画框） |
| 等于外壳自己的 `location.origin` | 丢弃并记 warn（同源页面不该冒充面板） |
| 其它 | 丢弃并记 warn |

**不能写成「与 `location.origin` 相等才放行」**——那会把面板自己的消息全挡掉。身份认定最终仍靠 §4.1 的 `event.source` 对照表，`origin` 只是第一道筛子。

### 4.3 命名空间校验

`method` 必须以 `<pluginId>.` 开头，否则回 `E_UI_FORBIDDEN` 并记 warn（含插件名与方法名）。

### 4.4 并发与超时

| 项 | 规定 |
|---|---|
| 单面板在途请求上限 | 16 条 |
| 超过上限 | 立即回 `E_UI_BUSY`，不排队 |
| 单条超时 | 35 秒（服务端 30 秒 + 5 秒余量），超时回 `E_TIMEOUT` |
| `id` 重复 | 后者覆盖前者，前者按超时处理 |

### 4.5 面板发来非法结构

不是对象或 `type` 不是字符串：丢弃。`call` 缺 `id` 或 `id` 非正整数：丢弃并记 warn。`method` 非字符串：回 `E_UI_FORBIDDEN`。`params` 非对象：当 `{}`。外壳不深校验 `params`。

## 5. 面板侧接入

### 5.1 最小样板

```js
window.addEventListener("message", (e) => {
  if (e.source !== window.parent) return;   // 只认外壳
  const m = e.data;
  if (!m || typeof m.type !== "string") return;
  if (m.type === "init") { pluginId = m.pluginId; applyTheme(m.theme, m.tokens); render(); }
  else if (m.type === "theme") applyTheme(m.theme, m.tokens);
  else if (m.type === "result") { const cb = pending.get(m.id); if (cb) { pending.delete(m.id); cb(m); } }
  else if (m.type === "event") onEvent(m.name, m.data);
  else if (m.type === "shutdown") cleanup();
});

function call(method, params = {}) {
  return new Promise((resolve, reject) => {
    const id = ++seq;
    pending.set(id, (m) => (m.ok ? resolve(m.result) : reject(m.error)));
    parent.postMessage({ type: "call", id, method, params }, "*");
  });
}
```

### 5.2 三条硬要求

| 要求 | 理由 |
|---|---|
| 等 `init` 再渲染 | 之前拿不到 `pluginId` 与主题，会白闪 |
| 只接受 `e.source === window.parent` 的消息 | 面板发出的消息 `e.origin` 恒为 `"null"`，收到的消息带的是外壳的源；拿 `e.origin` 做白名单会把外壳的消息挡掉 |
| 颜色与尺寸只取 `--ling-*` | 否则切主题不跟随 |

### 5.3 面板不该做的事

不用 `localStorage`（不透明源不可用）；不 `fetch("/api/...")`（跨源无 token 被拦）；不设 `document.domain`；除 `call` 与 `drag` 外没有别的通道。

## 6. 事件通道

### 6.1 现在只有一个来源

`event` 目前只由外壳在一处产生：它接管的拖放手势（`name:"drop"`）。

面板被挤掉、被关闭、被停用都不走 `event`，统一用 `shutdown` 加 `reason`。`event` 的位置留给将来的推送。面板的数据变化（例如资源库多了文件）也不走 `event`，自己用 `call` 轮询。

### 6.2 拖放怎么发生

原生拖拽跨 iframe 会被吞掉，所以是「消息式拖拽」：

| 步骤 | 谁 | 动作 |
|---|---|---|
| 1 | 面板 A | 按下并移动超过 5 像素，发 `{type:"drag", id, kind, payload}` |
| 2 | 外壳 | 校验来源与字段，盖透明遮罩，显示跟随光标的提示条 |
| 3 | 外壳 | 松手时算落点；不在任何面板上则丢弃 |
| 4 | 外壳 | 给落点发 `event{name:"drop", data:{kind, payload, from}}`；给 A 回 `result` |
| 5 | 面板 B | 收到 `drop`，调自己的方法处理 |

`drag` 字段：`id` 正整数、`kind` 取 `files` 或 `text`、`payload` 为 `{paths:[...]}` 或 `{text:"..."}`。

- 手势由外壳接管，执行由目标面板自己调自己的方法。
- 外壳不搬运数据，只传路径或文本；读文件由目标插件的插件本体做，过宿主能力校验。
- `payload` 上限 8 KB，超过时回失败并提示「拖拽内容过大，请传路径而不是内容」。

### 6.3 将来接推送

外壳内部有 `EventHub`，面板只认「收到 `event`」。将来加「服务端 → 外壳」的 SSE 或 WebSocket，收到后调 `EventHub.emit(pluginId, name, data)`，面板代码不改。

## 7. 生命周期

### 7.1 打开

预检 HEAD → 建外框 → 建 iframe → load → init。

### 7.2 关闭

发 `shutdown{reason:"closed"}`，300 毫秒后移除。到期无论如何都移除。

### 7.3 插件停用

`shutdown{reason:"disabled"}`，300 毫秒后移除；侧边栏入口变淡保留，点开显示「插件已停用」与「启用」。

### 7.4 插件卸载

`shutdown{reason:"uninstalled"}`，300 毫秒后移除；入口消失；顶部提示。

### 7.5 重启恢复

读 `core-ui.layout.order` 逐个预检并按 `widths` 恢复：

| 情形 | 处理 |
|---|---|
| 插件在、预检通过 | 打开 |
| 插件已卸载 | 跳过并从 `order` 删掉，不提示 |
| 插件已停用 | 不打开，入口变淡 |
| 预检 404 | 跳过，提示「`<名称>` 的面板文件不在了」 |

最多恢复 4 个。

### 7.6 面板卡死

不提供「重启单个面板」按钮；关掉再打开即重载。不做自动重启：无法区分卡死与「正在算一个大目录」。

## 8. 失败处理

| 情形 | 显示 | 后续 |
|---|---|---|
| 没有 `[ui]` | 不出现在侧边栏 | —— |
| 预检 404 | 「面板文件不存在：`<路径>`」+「重试」 | 修文件后重试 |
| 预检超时 5 秒 | 「面板文件读取超时」+「重试」 | —— |
| 加载超时 10 秒 | 「面板加载超时」+「重试」 | —— |
| 面板脚本抛错 | 面板白屏，外壳不显示错误 | 用户点重试 |
| `init` 前发 `call` | 回 `result` 失败（`E_UI_NOT_READY`）并记 warn | 面板应等 `init` |
| 插件已卸载但面板开着 | 关闭并提示 | —— |
| 面板发 1000 条 `call` | 超 16 条的立即回 `E_UI_BUSY` | 面板应降并发 |
