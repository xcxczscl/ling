# core-ui 04 两种形态与启动

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-ui/04-两种形态与启动.md`

## 1. 两种形态差在哪

差别只有一处：页面由谁显示。服务端、页面、API 三样两版完全相同。

## 2. 构建开关

`LING_CORE_UI_DESKTOP` 一个选项决定产物。`webui` 版也要编成 GUI 子系统（`/SUBSYSTEM:WINDOWS`），否则宿主拉起时会闪黑框。

## 3. WebView2

### 3.1 它是什么

Windows 10/11 自带的浏览器控件，系统里已有运行时，不用额外装。

### 3.2 用它要加什么依赖

WebView2 SDK（头文件加静态库），**已确认引入**。exe 增加约 1 MB，运行时是系统自带的，不随包分发；只有 `desktop` 构建受它影响。

### 3.3 窗口行为

标题 `ling`，初始 1100×760，记住上次位置（存配置），关闭窗口只关界面、宿主去留看设置，不做托盘图标，关掉右键菜单只留复制与刷新。

### 3.4 不用 WebView2 的降级

系统里没有运行时时退化成用默认浏览器打开，记一条 warn，不弹「请先安装」的提示框。

## 4. 启动顺序与握手

### 4.1 启动顺序

宿主先起，界面后起。宿主装载 core-ui 并传三个环境变量，界面绑 8010、写 `ui_port`、自检一次，通过后开窗口（`webui` 版由宿主开浏览器）。界面不启动宿主，也不停止宿主。

### 4.2 就绪信号

自检通过后向标准输出打 `{"ready":true,"port":8010}`，宿主读到才算激活成功。自检不能省：绑上端口不代表能连上宿主。

## 5. 发布包出几个

四个：`webui` / `desktop` 两个形态各出便携 zip 与安装包。

## 6. 双击之后发生什么

双击 → 宿主起来、预装插件 → 装载界面、绑端口、自检 → 出窗口或开浏览器 → 显示插件列表。关窗口不关宿主，除非设置里选了「关界面时也退出 ling」。

**未定**：双击入口怎么不弹控制台窗口，三种做法各有代价，等打包阶段定。

## 7. 关掉界面之后宿主怎么办

选项存在 `core-settings`（键 `core-ui.close_behavior`），界面只读它、按它执行，不另记默认值。`keep-host`（默认，只关界面）或 `stop-host`（先调 `kernel.shutdown` 再关）。放配置里是为了可导出、可还原。

### 7.1 界面被强杀时

设置来不及生效，宿主继续跑。这不是缺陷：强杀是异常路径，继续跑比突然消失安全。

### 7.2 平台差异

`desktop` 版目前只做 Windows，Linux 的桌面窗口另议；`webui` 版三平台一样。

## 8. 实现状态

服务端（HTTP、认证、`/api/*` 转管理端口）已实现并冒烟通过；页面只有占位页；侧车装载要到 M4；`desktop` 窗口未做。页面定稿后只换占位 HTML，服务端不动。
