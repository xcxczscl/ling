# core-ui 04 两种形态与启动

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-ui/04-两种形态与启动.md`

## 1. 两种形态差在哪

差别只有一处：页面由谁显示。服务端、页面、API 三样两版完全相同。

## 2. 构建开关

`LING_CORE_UI_DESKTOP` 一个选项决定产物。`webui` 版也要编成 GUI 子系统（`/SUBSYSTEM:WINDOWS`），否则宿主拉起时会闪黑框。

## 3. WebView2

### 3.1 它是什么

Windows 10/11 自带的浏览器控件，系统里已有运行时，不用额外装。

### 3.2 用它要加什么依赖

WebView2 SDK（头文件加静态库），**已确认引入**。exe 增加约 1 MB，运行时是系统自带的，不随包分发；只有 `desktop` 构建受它影响。

### 3.3 窗口行为

标题 `ling`，初始 1100×760，记住上次位置（存配置），关闭窗口只关界面、宿主去留看设置，不做托盘图标，关掉右键菜单只留复制与刷新。

### 3.4 不用 WebView2 的降级

系统里没有运行时时退化成用默认浏览器打开，记一条 warn，不弹「请先安装」的提示框。

## 4. 启动顺序与握手

### 4.1 两种启动方式

靠有没有 `LING_UI_TOKEN` 环境变量区分：没有 = 用户双击的启动器模式（界面先起、自己拉 `ling serve`、口令读 `session.json`）；有 = 宿主装载的插件模式（宿主先起、传口令、界面自检后打就绪信号）。

### 4.2 为什么用环境变量区分

命令行参数在两种情形下都不由界面控制；配置文件标记要额外维护一个状态。环境变量的有无是宿主决定的，界面不会误加。

### 4.3 就绪信号

插件模式下自检通过后向标准输出打 `{"ready":true,"port":8010}`，宿主读到才算激活成功。不用「等 2 秒试试」这种猜测。

## 5. 发布包出几个

四个：`webui` / `desktop` 两个形态各出便携 zip 与安装包。

## 6. 双击之后发生什么

双击 → 无控制台窗口 → 界面进启动器模式 → 探测宿主、没跑就起子进程 → 宿主预装插件 → 界面绑端口、自检、开窗口 → 显示插件列表。

## 7. 关掉界面之后宿主怎么办

由界面决定，在界面设置页里调。设置项 `core-ui.close_behavior`：`keep-host`（默认，只关界面）或 `stop-host`（先调 `kernel.shutdown` 再关）。默认选 `keep-host`——定时任务不该因为关了个窗口就停。

### 7.1 界面被强杀时

设置来不及生效，宿主继续跑。这不是 bug：强杀是异常路径，继续跑比突然消失安全。重启界面会重新探测并恢复。

### 7.2 平台差异

`desktop` 版目前只做 Windows，Linux 的桌面窗口另议；`webui` 版三平台一样，只是开浏览器。

## 8. 实现状态

未实现。`webui` 版是最小可行目标，`desktop` 版在它之上加窗口。
