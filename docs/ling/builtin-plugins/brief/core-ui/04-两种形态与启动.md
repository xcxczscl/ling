# core-ui 04 两种形态与启动

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-ui/04-两种形态与启动.md`

## 1. 两种形态差在哪

差别只有一处：页面由谁显示。服务端、页面、API 三样两版完全相同。

## 2. 构建开关

`LING_CORE_UI_DESKTOP` 一个选项决定产物。`webui` 版也要编成 GUI 子系统（`/SUBSYSTEM:WINDOWS`），否则宿主拉起时会闪黑框。

## 3. WebView2

### 3.1 它是什么

Windows 10/11 自带的浏览器控件，系统里已有运行时，不用额外装——这是选它而不是 Qt 的主要理由。

### 3.2 用它要加什么依赖

WebView2 SDK（头文件加静态库）。按项目规矩新增依赖要先问，动手前再确认一次。exe 增加约 1 MB。

### 3.3 窗口行为

标题 `ling`，初始 1100×760，记住上次位置（存配置），关闭窗口只关界面不关宿主，不做托盘图标，关掉右键菜单只留复制与刷新。

### 3.4 不用 WebView2 的降级

系统里没有运行时时退化成用默认浏览器打开，记一条 warn，不弹「请先安装」的提示框。

## 4. 启动顺序与握手

宿主传三个环境变量 → 界面绑端口、写 `ui_port`、自检一次 → 向标准输出打 `{"ready":true,...}` → 宿主据此判定激活成功 → 开浏览器或开窗口。不用「等 2 秒试试」这种猜测。

## 5. 发布包出几个

四个：`webui` / `desktop` 两个形态，各自出便携 zip 与安装包。差别只在构建开关与安装方式。

## 6. 双击之后发生什么

双击 → 无控制台窗口 → 后台起宿主、预装插件 → 拉起界面 → 出窗口或开浏览器 → 显示插件列表。关界面不关宿主。

## 7. 未定事项

关掉界面后宿主怎么退，三个选项：一直在后台跑 / 关界面即退 / 加托盘图标。倾向托盘图标，等 desktop 版开工时定。

## 8. 实现状态

未实现。`webui` 版是最小可行目标，`desktop` 版在它之上加窗口。
