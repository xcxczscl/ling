# core-ui 02 技术选型

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 详细版：`docs/ling/builtin-plugins/core-ui/02-技术选型.md`

## 1. 这份文档定什么

1.1.0 新增的每条技术选择，结论在 §2，理由与被否决方案在 §3 至 §12。

## 2. 决策总表

| # | 决策 | 结论 | 主要理由 |
|---|---|---|---|
| 1 | 插件界面形态 | iframe 整页挂载 | 隔离干净、作者门槛低、能装复杂界面 |
| 2 | 面板资源由谁 serve | core-ui 服务端统一 serve | 保住同源，主题机制才成立 |
| 3 | token 位置 | 不进面板，只在外壳 | 面板被攻破也拿不到宿主权限 |
| 4 | 面板能力边界 | 只能调自己命名空间的方法 | 最小权限；跨插件走插件本体中转 |
| 5 | 面板粒度 | 一插件一面板 | 避开窗口管理器复杂度 |
| 6 | 面板操作入口 | 面板自带工具栏，无独立首栏 | 不需要维护「焦点面板」 |
| 7 | 面板与外壳通信 | `postMessage` 固定七种消息 | 同浏览器内唯一的跨源通道 |
| 8 | 实时刷新 | 轮询，抽象出事件通道 | 本机开销可忽略；推送要新增常驻连接 |
| 9 | 样式一致 | 设计令牌 `--ling-*` | 只靠变量，不靠共享代码 |
| 10 | 主题可调 | 令牌的一套取值，亮/暗两套 | 换主题等于换值 |
| 11 | 外壳前端 | 原生 DOM + `fetch` | 视图数量有限，构建链成本高于收益 |
| 12 | 面板前端 | 不限，作者自选 | 面板是独立网页 |

## 3. 插件界面用哪种形态

| 方案 | 能装的界面 | 隔离 | 作者门槛 | 结论 |
|---|---|---|---|---|
| **A. iframe 整页挂载** | 任意，含进度条、拖拽、图表 | 浏览器强制 | 会写网页即可 | **采用** |
| B. 声明式描述 | 只能表单、列表 | 无代码进外壳 | 最低 | 否决：装不下播放器与目录树 |
| C. 微前端组件 | 任意 | 需自己画边界，同源即同权 | 需要构建链 | 否决：能直接读走 token |
| D. 各自起端口 | 任意 | 跨源，外壳够不着 | 要写服务端 | 否决：破同源 |

A 的代价：拖拽是「松手后发一条消息」，不是跟手拖拽（§12）。

## 4. 面板资源为什么必须由 core-ui 统一 serve

| 由谁 serve | 关系 | 后果 |
|---|---|---|
| core-ui（8010） | 默认同源；再由 `sandbox` 主动降为不透明源 | 主题样式表同源提供；读取、缓存、失败处理集中一处 |
| 插件自己（各自端口） | 跨源，随插件数量失控 | 每个插件都要处理 CORS 与鉴权；外壳无法统一处理加载失败 |

更硬的理由：插件是运行时安装的，网页无法编译期嵌进 exe，只能从 `<插件目录>/ui/` 运行时读。由已存在的服务统一读，比让每个插件各起一个 HTTP 服务省事。

1.0.0 的「编译期嵌入」只保留给外壳自己。

## 5. token 为什么不进面板

### 5.1 面板是不可信代码

面板内容不受 core-ui 控制。只要面板与外壳同源，面板里任意一行 JS 都能读走 `sessionStorage` 里的 token。

规则：token 只在外壳内存中，不放进 iframe 的 URL、不放进 `postMessage`、不写进面板可读的任何存储。

### 5.2 面板也无法自己发请求

iframe 不授予同源（`sandbox` 不含 `allow-same-origin`），浏览器把它的源视为不透明源：

| 结果 | 表现 |
|---|---|
| 请求 `127.0.0.1:8010` 属跨源 | 无 CORS 许可即被浏览器拦下 |
| 读不到外壳的 `sessionStorage`、`localStorage`、Cookie | 写进去也拿不到 |
| `document.domain` 访问抛错 | 无法自改同源 |

这三条由浏览器强制，不依赖 core-ui 的代码正确性。

### 5.3 能力边界怎么落地

```
面板 → postMessage{"type":"call","method":"rm.scan"} → 外壳
外壳 → 按 iframe 来源查 pluginId，校验 method 前缀 → 不符回 E_UI_FORBIDDEN
外壳 → POST /api/panel/call {plugin:"rm", method:"rm.scan"} + token → 服务端
服务端 → 再校验 method 属于该命名空间 → kernel.call
```

调用方身份来自消息来源，不来自面板自报。服务端再校验一次，防外壳自身 bug。

| 被否决的方案 | 理由 |
|---|---|
| 面板与外壳同权 | 等于把宿主管理权交给任意插件 |
| 清单白名单声明 | 比最小权限更宽松；真实需求没有「面板必须调别人」的场景 |
| 只靠外壳校验 | 单点失效 |

## 6. 为什么一插件一面板

多面板要求外壳实现面板注册表、格子布局、拖拽重排、跨插件拖放、焦点管理、布局持久化，是一套窗口管理器；而这些能力插件在自己的网页里就能给。

**选一插件一面板。** 「两个插件同屏」不受影响：功能区摆的是多个插件的面板，不是一个插件的多个面板。

## 7. 为什么不要独立首栏

- 首栏放焦点面板的按钮：要维护「谁是焦点面板」，用户点面板内任意位置都会改变焦点，状态链比省下的垂直空间贵。
- 首栏只放全局信息：1.1.0 的全局信息只有宿主状态与版本号，放得进侧边栏底部两行。

结论：面板的操作按钮画在面板自己的网页里，外壳只画 32 像素高的外框标题条。外框跟着面板走，不需要同步焦点状态。

## 8. 为什么用 postMessage

外壳与面板是两个文档，唯一的合法通道是 `postMessage`：跨源可用、单向投递、可传结构化对象。

| 被否决的通道 | 理由 |
|---|---|
| 面板直接调 HTTP | 面板没有 token 且被浏览器拦 |
| `BroadcastChannel` | 按源隔离，不透明源用不了，且无法定向单个面板 |
| `SharedWorker` | 同源才能共享 |
| URL 参数回传 | 每次传值都要导航，面板状态会丢 |

## 9. 实时刷新为什么先轮询

| | 轮询 | 推送（SSE/WebSocket） |
|---|---|---|
| 实时性 | 最多迟一个间隔 | 毫秒级 |
| 实现 | 面板定时发一条 `call` | 常驻连接、断线重连、事件补发 |
| 本机开销 | 每 2 秒一次空查询 | 长连接常驻 |

单用户、面板不超过 4 个，2 秒一次空查询的开销测不出来，差别在实现复杂度。**选轮询，但把「事件通道」抽象出来**：面板侧统一「订阅事件名 + 收 `event` 消息」，现在用轮询实现，将来换推送只改外壳与服务端之间那段。

推送将来只能加在服务端与外壳之间：面板是不透明源，`EventSource` 与 `WebSocket` 都要跨源许可且没有 token 可带。所以推送终点是外壳，再由外壳转发，消息协议形状不变。

## 10. 样式与主题

### 10.1 问题

插件写死颜色会导致插件之间观感不统一，且切暗色时外壳变暗而面板仍白。

### 10.2 设计令牌

外壳与所有面板只引用变量，不写死具体值。

| 类别 | 令牌举例 | 数量 |
|---|---|---|
| 背景 | `--ling-bg`、`--ling-bg-raised`、`--ling-bg-sunken` | 3 |
| 文字 | `--ling-text`、`--ling-text-dim`、`--ling-text-invert` | 3 |
| 线条 | `--ling-border`、`--ling-border-strong` | 2 |
| 强调与语义 | `--ling-accent`、`--ling-accent-hover`、`--ling-ok`、`--ling-warn`、`--ling-danger` | 5 |
| 字号 | `--ling-fs-sm`、`--ling-fs-md`、`--ling-fs-lg`、`--ling-fs-xl` | 4 |
| 间距 | `--ling-sp-1` 至 `--ling-sp-5` | 5 |
| 形状 | `--ling-radius`、`--ling-radius-sm`、`--ling-shadow` | 3 |

用变量而不是共享 CSS 类：变量只约束色值与尺度，不约束结构；共享组件库会把插件锁死在 core-ui 的 DOM 结构上。

### 10.3 主题 = 一套取值

```css
:root { --ling-bg:#ffffff; --ling-text:#1a1a1a; ... }
:root[data-theme="dark"] { --ling-bg:#1b1b1d; --ling-text:#e6e6e6; ... }
```

主题名存 `core-ui.theme`，由 `core-settings` 保管。面板通过 `<link rel="stylesheet" href="/api/ui/theme.css">` 取当前令牌，该地址免 token，响应头 `Cache-Control: no-store`。

不把令牌塞进 `postMessage`：样式要在首屏渲染前到位，等消息会白闪（`CUI-REQ-023`）。

### 10.4 被否决的主题方案

| 方案 | 理由 |
|---|---|
| 只支持固定主题 | 暗环境刺眼，插件写死颜色的问题仍在 |
| 用户自定义每个色值 | 配置项从 1 个变 20 多个，还要取色器与对比度校验 |
| 插件各自维护主题 | 切主题要通知所有插件改常量，必然不一致 |
| 用 `@import` 从插件目录带主题 | 面板样式被插件控制，无法统一切换 |

## 11. 前端技术

### 11.1 外壳不用框架

视图为一级界面 3 块加设置 6 个页签，接口十来个，交互是列表、表单、确认框、拖分隔条。引入框架要配构建链，构建链本身要维护。**结论：原生 DOM 加 `fetch`。**

### 11.2 面板不限技术

面板是独立网页，作者可用任意框架。core-ui 只要求两件事：入口是一个 HTML 文件，路径写在 `[ui].entry`；通过 `postMessage` 遵守七种消息格式。

## 12. 代价与已知不足

| 代价 | 表现 | 缓解 |
|---|---|---|
| 拖拽不跟手 | 松手后才生效 | 外壳接管手势转成 `event`；将来换渲染方式时协议不变 |
| 面板不能用浏览器存储 | 不透明源下 `localStorage` 不可用 | 面板要持久化的数据应存插件配置 |
| 首屏多一次请求 | 主题样式表一次 | 本机请求，耗时可忽略 |
| 外壳代码量增长 | 新增侧边栏、面板管理、消息路由、主题 | 按 `04-详细设计` 分层切开 |
