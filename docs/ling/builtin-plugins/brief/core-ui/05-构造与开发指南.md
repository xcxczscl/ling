## 2. 代码落在哪

```
main/builtin-plugins/core-ui/
├─ plugin.toml                 含 [sidecar]，不含 [ui]
├─ CMakeLists.txt
├─ src/
│  ├─ main.cpp                 入口：读环境变量、起服务、选形态
│  ├─ ui_server.cpp/.h         HTTP 服务、路由、静态文件
│  ├─ panel_assets.cpp/.h      面板资源读取与五道检查
│  ├─ manifest_ui.cpp/.h       [ui] 解析与内存表
│  ├─ api.cpp/.h               /api/* 与管理端口的翻译
│  ├─ kernel_client.cpp/.h     管理端口客户端
│  ├─ theme.cpp/.h             令牌表与 theme.css
│  └─ win_main.cpp             desktop 窗口（可选编译）
├─ web/
│  ├─ shell.html / shell.css / shell.js
│  ├─ panels.js                面板管理与消息路由
│  ├─ theme.js                 主题应用与切换
│  └─ views/{plugins,logs,config,jobs,appearance,about}.js
└─ tests/smoke.md
```

1.0.0 的 `page.html` 一个文件承载全部，1.1.0 拆成 `shell.html` 加 `views/*.js`。

## 3. 模块划分与依赖方向

```
main.cpp → ui_server → { panel_assets ← manifest_ui, theme, api → kernel_client }
```

| 模块 | 职责 | 不允许依赖 |
|---|---|---|
| `ui_server` | 路由、解析、响应拼装 | 任何业务判断 |
| `panel_assets` | 路径校验、读文件、MIME | `api`、`kernel_client` |
| `manifest_ui` | 解析 `[ui]`、维护内存表、发变更事件 | `ui_server` |
| `theme` | 令牌表、拼 CSS | 除 `manifest_ui` 外 |
| `api` | 动作表、参数翻译、错误码转译 | `panel_assets` |
| `kernel_client` | 管理端口协议 | 除 `api` 外 |

前端：`shell.js` → {`panels.js` → `theme.js`, `theme.js`, `views/*.js`}。`panels.js` 与 `views/*.js` 互不引用。

## 4. 开发顺序

| 步 | 做什么 | 怎么验证 |
|---|---|---|
| 1 | 令牌表 + 外壳骨架 | 看到三块布局；手动改 `data-theme` 能切配色 |
| 2 | `[ui]` 解析 + `/api/panels` | `curl` 返回该插件；写错时 `E_UI_PANEL_DECL` |
| 3 | 面板资源路由 | 正常路径 200；`../` 与符号链接 404 |
| 4 | 面板挂载与外框 | 点入口出外框与 iframe；关掉后入口还在 |
| 5 | 消息路由与代调 | 调自己的方法成功；调 `kernel.shutdown` 回 `E_UI_FORBIDDEN` |
| 6 | 主题切换 | 外观页切暗色，外壳与面板一起变 |
| 7 | 设置二级界面迁移 | 跑 `CU-02` 至 `CU-11` |
| 8 | 生命周期与错误态 | 停用、卸载、缺文件、加载超时四种提示 |

第 5 步是关键节点：它同时验证「能调自己」「调不了别人」「token 没进面板」。通过前不动第 6 至第 8 步。

## 5. 每步的验证手段

| 步 | 手法 |
|---|---|
| 1 | 目视 + DevTools 改 `data-theme` |
| 2 | `curl -X POST /api/panels`（带 token） |
| 3 | `curl` 四条越界路径（`..`、绝对路径、盘符、符号链接） |
| 4 | DevTools 看 iframe 的 `src` 与 `sandbox` |
| 5 | 面板控制台手发 `postMessage` |
| 6 | 目视 + 看响应头 |
| 7 | 逐条跑用例表 |
| 8 | 逐条制造故障 |

第 3 步要真的建一个符号链接：只写 `..` 检查挡不住链接。

## 6. 关键类型与函数签名

### 6.1 服务端

```cpp
enum class UiState { Running, Stopped, Failed };

struct UiPanel {
  std::string id, title, entry, icon;
  UiState state = UiState::Stopped;
  std::string reason;
};

bool ParseUiSection(const Toml& manifest, UiPanel& out, std::string& err);

struct AssetResult { int status; std::string content_type; std::string body; };
AssetResult ReadPanelAsset(const std::string& plugins_root,
                           const std::string& plugin_id,
                           const std::string& rel_path);

std::string BuildThemeCss(const std::string& current_theme);

Json HandleApi(const std::string& action, const Json& body,
               const std::string& plugin, KernelClient& kc);
```

### 6.2 前端

```js
export function openPanel(pluginId, { width } = {});
export function closePanel(pluginId, reason);   // closed|disabled|uninstalled|evicted
export function handlePanelMessage(event);
export function broadcastTheme(theme, tokens);
export function restoreLayout(order, widths);

export function applyTheme(theme, tokens);
export async function setTheme(theme);          // 乐观更新 + 写配置 + 失败回滚
export async function call(action, params);
```

`handlePanelMessage` 必须在任何 DOM 操作之前完成 origin 与 source 两道校验。

## 7. 构建、运行与调试

### 7.1 构建

```bash
# 必须从仓库根配置（ling_set_* 宏与 third_party 路径都定义在根 CMakeLists）
cmake --preset win-debug
cmake --build --preset win-debug --target core-ui
```

产物在 `run/<preset>/plugins/core-ui/`，同目录自动带上 `plugin.toml`。

### 7.2 运行

```bash
ling serve --data-dir run/tmp-x
ling open
```

单独调试服务端：

```bash
LING_UI_TOKEN=dev LING_UI_PORT=8010 LING_UI_ROOT=run/tmp-x ./core-ui
```

此时自检失败，进程按 04/01 §9 直接退出。1.1.0 不做「自检失败照常服务」的调试模式。

### 7.3 调试

| 要看什么 | 怎么做 |
|---|---|
| 服务端日志 | `ling logs core-ui` |
| 前端报错 | 用 `webui` 版 + 浏览器 DevTools |
| 面板内部 | DevTools 的 frame 选择器切到该 iframe |
| 令牌输出 | `curl -i /api/ui/theme.css` |
| token 是否泄露 | 面板控制台执行 `sessionStorage.length`，不透明源下直接抛错 |
| 越权是否被拦 | 面板发 `{type:"call",method:"kernel.shutdown"}`，应回 `E_UI_FORBIDDEN` |

面板里 `fetch("/api/plugins")` 被浏览器拒绝是预期行为。
