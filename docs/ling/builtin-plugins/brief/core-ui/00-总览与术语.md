# core-ui 00 总览与术语

> 状态：初定 | 版本：1.1.0-b1 | 最后更新：2026-11-02
> 详细版：`docs/ling/builtin-plugins/core-ui/00-总览与术语.md`

## 1. 一句话

它是 ling 唯一的人机界面进程：既用鼠标把 ling 管起来，又是所有插件界面的容器。

| 职责 | 说明 | 谁来填内容 |
|---|---|---|
| 管理面板 | 看插件、装卸启停、翻日志、改配置、管定时任务 | core-ui 自己写 |
| 插件视图台子 | 给每个带界面的插件一个显示位置 | 各插件自己写 |

1.0.0 只有第一件事。1.1.0 起增加第二件，原有的管理视图整体退到「设置」二级界面。

## 2. 它解决什么问题

### 2.1 命令行太重

命令行能做全部事情，但要记命令与参数。界面把「装插件、看状态、翻日志、改配置」变成点击与表单。命令行不删，两者共用同一套 `kernel.*` 方法。

### 2.2 插件没有地方放界面

插件不做界面就只能靠命令行；自己做界面就得自己写服务端、端口、认证、导航、主题。core-ui 提供第四条：插件放一份网页、清单声明一段 `[ui]`，界面就出现在侧边栏。

## 3. 界面有哪几块

| 块 | 职责 | 归谁 |
|---|---|---|
| 侧边栏 | 列出所有带界面的插件，底部固定「设置」 | 外壳 |
| 功能区 | 同时摆多个面板，横向均分，可拖分隔条 | 外壳 |
| 面板外框 | 面板头上 32 像素的条：标题、关闭 | 外壳 |
| 面板内容 | 插件自己的网页，装在隔离画框里 | 插件 |

没有独立首栏。全局信息放在侧边栏底部「设置」入口上方。二级界面是「设置」，含六个页签：插件、日志、配置、任务、外观、关于。

## 4. 两种形态

`webui` 版开浏览器标签页，三平台可用；`desktop` 版开独立窗口，目前只 Windows。两版界面代码完全相同，差别只在谁来显示页面。

## 5. 它在插件体系里的位置

侧车插件，独立进程。理由：它要跑 HTTP 服务、崩了不该拖垮宿主、将来换界面技术只换一个 exe。它只以客户端身份连管理端口，不读 `session.json`。它同时是唯一读取其他插件 `ui/` 目录的插件，该读取只读、限定目录、限定后缀。

## 6. 术语

| 词 | 定义 |
|---|---|
| 外壳 | core-ui 自己那份页面，负责导航、面板外框、设置二级界面，并持有 token |
| 面板 | 插件提供的网页，一个插件最多一个，用 iframe 加载 |
| 面板外框 | 外壳画在面板周围的那一圈，含标题条与边框 |
| 插件视图 | 侧边栏里的一个入口，一个带面板的插件对应一个 |
| 管理面板 | 设置二级界面六个页签的合称 |
| 设计令牌 | `--ling-` 开头的 CSS 变量，管颜色、字号、间距、圆角、阴影 |
| 主题 | 设计令牌的一套取值，内置 `light` 与 `dark`，存 `core-ui.theme` |
| 消息协议 | 面板与外壳之间 `postMessage` 的固定消息格式 |
| 代调 | 面板把调用意图发给外壳，由外壳带 token 请求服务端 |

## 7. 它不做什么

不做远程访问与多用户、不做业务功能、不做插件市场、不做移动端适配、不做面板间自由互发消息、不做窗口自由拖拽与标签页、不做自定义主题颜色、不做共享组件库、不做国际化。

## 8. 没装它的时候

命令行全部可用；列表少一个条目；宿主启动不受影响；带 `[ui]` 的插件装载正常、方法可调、只是界面没有入口，插件不得因此报错；界面偏好仍在配置里。

## 9. 谁在用

使用者（日常主入口）、命令行（提示「去界面上看」）、其他插件（通过 `[ui]` 挂面板）。耦合只有一个清单字段与一份静态网页，不产生方法调用；core-ui 被卸载时插件无需改动。
