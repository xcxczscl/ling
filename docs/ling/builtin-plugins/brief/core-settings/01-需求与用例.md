# core-settings 01 需求与用例

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-settings/01-需求与用例.md`

## 1. 需求从哪来

挂在 `LING-REQ-028` 至 `038`（上下文与账本里的配置写入）、`031`（改共享状态才入账）、`047`（卸载还原）、`081`（可卸载）、`078`（无特权）之下。

## 2. 场景

### 2.1 插件存一个设置

写完立即可读，值可以是任何 JSON，键必须以自己插件名开头，这次写入进账本。

### 2.2 两个插件的键名撞了

互不影响：实际落在 `demo-a.timeout` 与 `demo-b.timeout` 两个键上。

### 2.3 插件读回自己的设置

键不存在时返回「没找到」而不是错误；类型原样带回，数字不会变成字符串。

### 2.4 用户想备份设置

`export` 导出全部；`import` 只补不覆盖——误导入旧备份不该冲掉当前配置。

### 2.5 卸载插件后配置自动还原

按账本倒序撤销，回到写入前的值；原本不存在的键撤销后消失，不是变成空串。

### 2.6 `core-settings` 自己被卸掉

宿主照常启动，此后 `write_config` 一律返回 `E_PLUGIN_MISSING`，配置文件原地保留。

### 2.7 配置文件读不出来

不因此起不来；日志记 warn；**不覆盖原文件**——自动写回空配置等于把用户的配置弄丢。

## 3. 用例与验收标准

`CS-01` 至 `CS-12`：写读一致、越权前缀、同名键隔离、读不存在的键、卸载还原、导出导入、只补不覆盖、坏文件不改写、超限、卸掉后写入、并发写、版本过高拒绝装载。

## 4. 本期明确不做的

配置界面、配置迁移、按值查询、加密、配置变更事件。
