# core-settings 02 设计与接口

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-settings/02-设计与接口.md`

## 1. 文件

### 1.1 位置与结构

`<数据根>/settings.json`，顶层 `schema_version` 与 `entries`；`entries` 的键是 `<插件名>.<键名>`，值是 `{"v": 任意 JSON, "updated_at": 本地时间}`。

### 1.2 为什么整份重写

几十 KB 的文件，重写以微秒计；不会出现改到一半的中间状态；不需要维护偏移。代价是成本与文件大小成正比，4 MB 上限就是为这条设的。

### 1.3 原子替换

序列化 → 写 `.tmp` → 刷盘 → 替换。Windows 用 `MoveFileEx`（`rename` 不覆盖已存在目标），其他平台用 `rename`。崩溃时要么旧文件要么新文件，不会半个。

## 2. 五个方法

### 2.1 `core-settings.write`

`plugin`（内核填，不由调用方自报）、`key`、`value`。值 `null` 表示删除这个键。`plugin` 由内核填是键空间隔离能成立的关键。

### 2.2 `core-settings.get`

只有 `key`。返回 `value` 与 `found`；不存在时 `found=false`，仍算成功。

### 2.3 `core-settings.list`

可选 `prefix`，返回字典序的键列表。

### 2.4 `core-settings.export`

无参数，返回整份文件内容，供备份。

### 2.5 `core-settings.import`

只补不覆盖，返回新增条数。

## 3. 键空间

必须以 `<调用方插件名>.` 开头，总长不超过 128 字节，只允许字母数字与 `_` `-` `.`。本插件自己的前缀是 `core-settings.`。

## 4. 与账本的配合

账本在内核手里，不在本插件手里。顺序：读旧值 → 内核记 `ConfigWritten` → 落盘；撤销 = 写回旧值（旧值为空则删键）。账本放插件里的话，插件一卸载就失去了撤销依据。

## 5. 失败处理

参数错报错误码；超限与写盘失败返回 `E_IO` 且文件不变；读到时语法错按空配置继续但**不改写原文件**，日志记 warn。

## 6. 版本与迁移

`schema_version` 只有一个用途：防旧版本覆盖新格式。读到高于当前的版本就拒绝装载本插件，原文件不动。这保证了降级回去时用户能看到「版本不兼容」，而不是配置被悄悄改写。

## 7. 代码位置与实现状态

`main/builtin-plugins/core-settings/`，产物进 `run/<preset>/plugins/core-settings/`。四处曾与实现不符，已改齐并实测：版本过高拒绝装载、`value` 为 `null` 删键、坏文件记一行且不改写、键加字符集与长度校验。
