# core-log 01 需求与用例

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-log/01-需求与用例.md`

## 1. 需求从哪来

不单独立编号，挂在 `LING-REQ-077`（`logs` 子命令）、`117` 至 `126`（日志字段）、`081`（可卸载）、`078`（无特权）下面。

## 2. 场景

### 2.1 插件写一条日志

给插件名、级别、正文，存进文件。写失败也返回成功——日志写不进去不该让业务失败，但要在 stderr 留一句。

### 2.2 看某个插件最近的日志

`ling logs <插件名>` 返回最近 40 行，最早在上，每行带时间与级别。从没写过时给一句人话而不是空白。

### 2.3 按日期与级别查

按日期取那天那份文件；按级别只留匹配的行。

### 2.4 没装 `core-log`

宿主照常启动；写入报 `E_PLUGIN_MISSING`；`logs` 退回读 `data/`；重新装回来继续追加旧文件。

### 2.5 一天的日志涨到很大

本期不轮转、不删除，文件一直追加。查询只读需要的部分，不把整份文件读进内存。风险写在文档里：不做轮转，长期运行会把磁盘写满。

## 3. 用例与验收标准

十条 `CL-01` 至 `CL-10`：写一条、连写两条、非法插件名、查最近 N 行、查从没写过的插件、按级别过滤、按日期查、卸掉后重启、目录不可写、50 MB 文件下 tail 要快。

## 4. 本期明确不做的

轮转、实时跟随、结构化字段、跨插件检索。每条都写了什么时候做、为什么现在不做。
