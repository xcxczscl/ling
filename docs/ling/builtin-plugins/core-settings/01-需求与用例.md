# core-settings 01 需求与用例

> 状态：已定稿 | 最后更新：2026-10-31
> 上级：`docs/ling/builtin-plugins/core-settings/00-总览与边界.md`

本文回答：哪些情况下会用到它、每种要成什么样、怎么判断做对了。

## 1. 需求从哪来

| 条目 | 本插件承担的部分 |
|---|---|
| `LING-REQ-028` 至 `LING-REQ-038` | 上下文与账本里「配置写入」这一类的落点 |
| `LING-REQ-031` | 只有改共享状态才入账，配置写入属于要入账的那一类 |
| `LING-REQ-047` | 卸载时把配置还原到写入前 |
| `LING-REQ-081` | 内置插件可卸载，卸掉后宿主仍能启动 |
| `LING-REQ-078` | 内置插件无特权，方法同样经路由与门禁 |

## 2. 场景

### 2.1 插件存一个设置

插件想让用户选「扫描时是否跟着符号链接」。它调用 `Context::write_config("demo-a.follow_symlinks", "true")`。

要成什么样：

- 写完立刻可读，不用重启。
- 值可以是任何 JSON：字符串、数字、布尔、数组、对象。
- 键必须以 `demo-a.` 开头，写别人的前缀被拒。
- 这次写入进账本，卸载 `demo-a` 时这个键回到写入前的状态。

### 2.2 两个插件的键名撞了

`demo-a` 和 `demo-b` 都想用 `timeout` 这个名字。

要成什么样：互不影响。它们实际写到 `demo-a.timeout` 与 `demo-b.timeout` 两个键上。前缀隔离就是为这件事。

### 2.3 插件读回自己的设置

启动时读回上次存的值；从没存过时给一个默认值。

要成什么样：

- 键不存在时返回「没找到」，不是错误码。调用方据此决定用不用默认值。
- 返回值原样带回类型：存的是数字，读回来还是数字，不是字符串 `"5"`。

### 2.4 用户想备份设置

换机器之前把配置导出来。

要成什么样：

- `core-settings.export` 返回整个文件的内容，含所有插件的键。
- 导入时**只补不覆盖**：目标里已有的键保持不动，新键才写进去。

「只补不覆盖」是刻意的：误导入一份旧备份，不该把当前配置冲掉。

### 2.5 卸载插件后配置自动还原

`demo-a` 把 `demo-a.theme` 从 `light` 改成 `dark`，之后卸载。

要成什么样：

- 卸载时按账本倒序撤销，`demo-a.theme` 回到 `light`。
- 如果这个键原本不存在，撤销后它应该消失，不是变成空字符串。

### 2.6 `core-settings` 自己被卸掉

要成什么样：宿主照常启动；此后任何插件的 `write_config` 都返回 `E_PLUGIN_MISSING`；已写的配置文件原地保留，重装回来还能读。

### 2.7 配置文件读不出来

用户手工编辑 `settings.json` 时多打了个逗号。

要成什么样：

- 宿主不因此起不来。
- 内核日志记一条 warn，说明配置文件坏了、按空配置继续。
- **不覆盖原文件**：坏文件留着让人修，不要用空配置把它冲掉。

这条比「自动修复」重要：自动写回空配置，用户的配置就真的没了。

## 3. 用例与验收标准

编号 `CS-` 开头。

| 编号 | 场景 | 期望 | 怎么判 |
|---|---|---|---|
| CS-01 | 写一个键再读回 | 值相同、类型相同 | `get` 返回的 JSON 与写入的等价 |
| CS-02 | 写别人的前缀（`demo-b.x` 由 `demo-a` 写） | `E_NAMESPACE_VIOLATION` | 配置文件里没有这个键 |
| CS-03 | 两个插件写同名键 | 各自独立 | 两个键都在，值不同 |
| CS-04 | 读不存在的键 | 成功，`found=false` | 返回体里 `found` 为 false |
| CS-05 | 写入后卸载插件 | 键回到写入前；原本不存在则消失 | 对比卸载前后文件 |
| CS-06 | 导出再导入到空环境 | 全部键都在 | 键集合相等 |
| CS-07 | 导入到已有配置 | 已有键不变，只新增 | 已有键的值保持原样 |
| CS-08 | 配置文件语法错误 | 宿主启动成功，日志有 warn，文件未被改写 | 文件内容与改动前逐字节相同 |
| CS-09 | 文件超过 4 MB | 写入返回 `E_IO`，文件不变 | 文件大小不变 |
| CS-10 | 卸掉 `core-settings` 后写配置 | `E_PLUGIN_MISSING` | 返回值与日志 |
| CS-11 | 并发写同一个键 | 后写的覆盖先写的，不出现半截内容 | 文件始终能被 JSON 解析 |
| CS-12 | 配置文件版本高于当前 | 拒绝装载本插件，原文件不动 | 插件状态为失败，文件未变 |

## 4. 本期明确不做的

| 不做 | 什么时候做 | 为什么现在不做 |
|---|---|---|
| 配置界面 | `core-ui` | 界面归界面 |
| 配置迁移 | M6 之前 | 现在只有一个格式版本，没有「旧版」可迁 |
| 按值查询（找出所有值为 `true` 的键） | 不确定 | 现在的规模用不上，加了反而要维护索引 |
| 加密 | 不做 | 敏感信息不该进配置，见 `00-总览与边界.md` §3 |
| 配置变更通知（事件） | 不确定 | 插件读配置是拉取式的，没有订阅的需求 |
