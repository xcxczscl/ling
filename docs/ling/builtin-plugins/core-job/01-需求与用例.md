# core-job 01 需求与用例

> 状态：已定稿 | 最后更新：2026-10-31
> 上级：`docs/ling/builtin-plugins/core-job/00-总览与边界.md`

本文回答：什么情况下会用到它、每种要成什么样、怎么判断做对了。

---

## 1. 需求从哪来

| 条目 | 本插件承担的部分 |
|---|---|
| `LING-REQ-078` | 内置插件无特权，任务触发也是一次普通的方法调用 |
| `LING-REQ-081` | 可卸载，卸掉后宿主仍能启动，任务定义留在配置里 |
| `LING-REQ-017` | 调用超时 30 秒，任务执行同样受这条约束 |
| `LING-REQ-031` | 登记任务是一次配置写入，要入账 |

## 2. 场景

### 2.1 登记一个每天凌晨三点跑的任务

```
core-job.schedule(name="cleanup", cron="0 3 * * *", method="demo-a.cleanup")
```

要成什么样：

- 登记成功立即可查（`core-job.list` 里有它）。
- 登记是一次配置写入，进账本；卸载调用方时任务一并消失。
- 任务定义存在 `<数据根>/settings.json` 的 `core-job.cleanup` 键下，能导出、能随配置还原。

### 2.2 到点了触发

宿主运行中，时间到 03:00。

要成什么样：

- 调一次 `demo-a.cleanup`，参数为空。
- 调用失败（目标没激活、方法不存在、超时）只记 warn，不影响下一次。
- 调用的超时与普通调用一致（30 秒）。

### 2.3 到点时宿主没在运行

03:00 时宿主没开，09:00 才开。

要成什么样：

- 默认**不补跑**：错过就错过，等下一个时间点。
- 任务声明 `catch_up = true` 时，启动后补跑一次。
- 补跑只补最近一次，不补一周的量。

### 2.4 上一次还没跑完，下一次又到点

一个任务每次要跑五分钟，而 cron 写的是每分钟一次。

要成什么样：

- 跳过一次，记一条 warn，说明「上一次还在跑」。
- **不排队**。排队会在慢任务上累积，最后变成「重启后一口气跑三百次」。

### 2.5 目标插件在触发时没激活

`demo-a` 因为依赖缺失处于停用状态。

要成什么样：

- 跳过本次，记 warn，带插件名与任务名。
- 不尝试激活目标，也不重试。让插件可用是调和的事，不是定时任务的事。

### 2.6 取消一个任务

要成什么样：

- 任务从列表消失，配置里的键被删（写 `null`）。
- 这次删除进账本，卸载调用方时按旧值还原。

### 2.7 时间表达式写错了

```
core-job.schedule(name="x", cron="0 25 * * *", ...)
```

要成什么样：

- 拒绝登记，返回错误码，说明哪一段不合法（这里是「小时」段超过了 23）。
- 错误信息里给出合法范围，不要只说「非法」。

## 3. 用例与验收标准

编号 `CJ-` 开头。

| 编号 | 场景 | 期望 | 怎么判 |
|---|---|---|---|
| CJ-01 | 登记一个任务 | 列表里有它，配置文件里出现 `core-job.<名字>` | 两处都对得上 |
| CJ-02 | 登记同名任务两次 | 第二次拒绝，`E_PLUGIN_EXISTS` 那一类 | 只有一条定义 |
| CJ-03 | cron 表达式非法 | 拒绝并指出是哪一段 | 错误信息含段名与范围 |
| CJ-04 | 取消任务 | 列表与配置里都没了 | 两处都对得上 |
| CJ-05 | 到点触发 | 目标方法被调用一次 | 目标插件日志里有记录 |
| CJ-06 | 目标未激活 | 跳过并记 warn | 内核日志有对应行 |
| CJ-07 | 上次未结束又到点 | 跳过本次，记 warn | 目标方法只被调用一次 |
| CJ-08 | 宿主停机期间错过 | 默认不补跑 | 启动后目标方法没被调用 |
| CJ-09 | `catch_up = true` 且错过 | 启动后补跑一次 | 目标方法被调用一次 |
| CJ-10 | 任务执行超时 | 30 秒后放弃，记 warn | 下一次照常触发 |
| CJ-11 | 卸掉 `core-job` 再装回 | 任务定义仍在，继续触发 | 配置文件未变，触发恢复 |
| CJ-12 | 卸载调用方插件 | 它的任务一并消失（账本撤销） | 列表里没有该任务 |

`CJ-05` 至 `CJ-10` 依赖内核的定期回调机制（`02-设计与接口.md` §4），该机制落地前无法验证。

## 4. 本期明确不做的

| 不做 | 什么时候做 | 为什么现在不做 |
|---|---|---|
| 秒级定时 | 不做 | 五段 cron 最短一分钟，需要更密的走事件 |
| 任务依赖（A 跑完再跑 B） | 不确定 | 那是工作流引擎，不是定时器 |
| 执行历史与结果 | 不确定 | 要看结果让目标插件自己记日志，本插件只负责触发 |
| 手动立即执行一次 | 界面有需求时再加 | `core-ui` 的任务页会需要「立刻跑一次」按钮，届时加到 `02` 的方法表里 |
| 时区处理 | 不做 | 单机个人工具，用本地时间 |
