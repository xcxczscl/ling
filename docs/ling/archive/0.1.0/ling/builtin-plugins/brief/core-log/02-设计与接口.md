# core-log 02 设计与接口

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-log/02-设计与接口.md`

## 1. 三个方法

`core-log.write`（插件名、级别、正文）、`core-log.tail`（插件名、行数）、`core-log.query`（插件名、日期、级别）。参数与返回都是 JSON。

### 1.1 `core-log.write`

必填 `plugin` 与 `message`，`level` 默认 `info`，返回 `{"written": true}`。

### 1.2 `core-log.tail`

默认取最后 40 行，返回 `plugin`、`path`、`lines` 三个字段。跨天有多份文件时取最新那份。

### 1.3 `core-log.query`

默认今天，给了 `level` 就只返回该级别。返回同构的 `lines`。

## 2. 文件布局与行格式

落在 `<数据根>/logs/<插件名>-日期.log`，行格式 `<ISO 时间> [级别] <正文>`，UTF-8。文件名带日期，查某一天不用先过滤大文件。

## 3. 插件名必须校验

插件名直接拼进文件名，不校验就是目录穿越。只允许字母、数字、连字符，长度 1 至 64。

## 4. 失败处理

参数错误报错误码；环境错误（目录建不了、磁盘满）返回成功并往 stderr 留一句。区别在于：参数错调用方能改，环境错它改不了。

## 5. 并发

宿主单线程，同一时刻只有一个写入。不需要文件锁；写完即关，进程被强杀最多丢最后一行。

## 6. 大文件

`tail` 从文件尾按 64 KB 块往前读，凑够行数就停；`query` 逐行读、命中的才留。两者内存都不随文件大小增长。本期不做轮转。

## 7. 代码位置

`main/builtin-plugins/core-log/`，产物进 `run/<preset>/plugins/core-log/`。只依赖标准库与 nlohmann/json，不引第三方日志库。

## 8. 已知不足

没有轮转、`query` 不支持跨天、单行封顶 8 KB、时间不带时区偏移。
