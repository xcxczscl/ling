# core-job 00 总览与边界

> 状态：已定稿 | 最后更新：2026-10-31
> 详细版：`docs/ling/builtin-plugins/core-job/00-总览与边界.md`

## 1. 一句话

按时间表自动调别的插件的方法：到点调一次，没到就等着。

## 2. 它解决什么问题

每个业务插件自己起线程做定时，会有五种写法、十个线程、任务定义散在各自 `data/` 里。收成一处之后，任务定义存进配置（可导出、可还原），触发由一处统一调度。

## 3. 它不做什么

不做秒级定时、不保证一次不漏、不负责让目标插件变得可用、不排队执行、不汇总执行结果。

## 4. 为什么不起自己的线程

宿主是单线程内核，路由表由内核线程写。插件线程调 `call` 就是读写并发，出错现象随机且难复现。所以改为内核每 200 毫秒广播一次 `kernel.tick`，本插件在回调里检查并执行，全程在内核线程上。代价是精度受节拍限制，对分钟级 cron 可以忽略。

## 5. 没装它的时候

任务定义还在配置里但没人触发；重装回来继续生效——因为定义在配置里，不在插件的 `data/` 里。

## 6. 谁在用

主要是 `core-ui` 的任务页；其他插件也可以调 `core-job.schedule` 给自己登记任务。
