# core-plugin-manager 00 总览与边界

> 状态：已定稿 | 最后更新：2026-10-31
> 上级：`docs/ling/04-详细设计/07-内置插件.md`

本文回答：命令行已经能装卸了，这个插件还补什么、不碰什么。

---

## 1. 一句话

**补命令行不做的四件事：看清依赖关系、找出白占空间的数据、一次操作一组插件、动手前先算会连带什么。**

## 2. 它解决什么问题

装卸、启停、查状态，内核的 `kernel.*` 方法已经做了（`docs/ling/04-详细设计/06-管理端口与命令行.md` §4）。剩下的四类问题命令行答不上来：

| 问题 | 命令行为什么答不上 |
|---|---|
| 「我卸了 `demo-a`，哪些插件会跟着停？」 | 要算依赖图的传递闭包，不是单条命令 |
| 「这些只剩 `data/` 的目录是谁留下的，占了多少？」 | 要扫目录并累加大小，`plugins` 只报装载状态 |
| 「把这五个插件一起停掉」 | 要按拓扑序执行，反了会半路失败 |
| 「先别动，告诉我这一下会影响哪些插件」 | 要能只算不做 |

这四件事都不是「没有宿主就不成立」的能力，所以归插件；装卸本身归内核，卸掉这个插件也能用。

## 3. 它不做什么

| 不做 | 谁做 | 理由 |
|---|---|---|
| 装载、卸载、启停的实际动作 | 内核 `kernel.*` | 内置插件不该有特权，也不该绕过管理通道 |
| 依赖解析与调和 | 内核（M3） | 那是宿主的核心机制，插件只读它的结果 |
| 图形界面 | `core-ui` | 界面归界面 |
| 删除孤儿数据 | 使用者 | 这个插件只**列出**，删不删由人决定。自动删是危险的默认值 |

**最后一条要强调**：孤儿数据是「只剩 `data/` 的目录」，里面是用户的数据。扫描可以自动，删除必须手动确认。`--purge` 那种「一条命令连数据一起删」的做法，在这里不提供。

## 4. 四项能力的成熟度

| 能力 | 依赖 | 现在能不能用 |
|---|---|---|
| 孤儿数据扫描 | 无 | 能用，已实现 |
| 目录占用统计 | 无 | 能用，已实现 |
| 依赖树 | M3 的依赖图 | 设计已写，实现等依赖落地 |
| 变更预演 | M3 的调和计算 | 同上 |
| 批量启停 | 内核允许插件调写方法 | 同上 |

三项要等 M3，原因不是懒：MVP 没有依赖声明，算不出树；内核的写方法只对管理端口开放，插件调不到。这两条都是 M3 要改的东西。

## 5. 没装它的时候

| 场景 | 行为 |
|---|---|
| 命令行装卸 | 不受影响，那是内核的事 |
| 找孤儿数据 | 只能自己翻 `plugins/` 目录 |
| 宿主启动 | 不受影响 |

这个插件是纯粹的「便利功能」，卸掉不损失任何核心能力。

## 6. 谁在用

- **使用者**：命令行没有对应子命令，所以主要是 `core-ui` 的插件页在调。
- **`core-ui`**：插件页的「依赖关系」「清理建议」两块由它提供数据。
