# core-log 01 需求与用例

> 状态：已定稿 | 最后更新：2026-10-31
> 上级：`docs/ling/builtin-plugins/core-log/00-总览与边界.md`

本文回答：什么情况下会用到它、每种情况要成什么样、怎么判断做对了。

---

## 1. 需求从哪来

内置插件的需求不单独立编号，直接挂在 `docs/ling/01-需求规格.md` 的条目下：

| 条目 | 与本插件的关系 |
|---|---|
| `LING-REQ-077` | `logs <插件名>` 走 `kernel.logs` → `core-log`，这是本插件存在的主要理由 |
| `LING-REQ-117` 至 `LING-REQ-126` | 日志行的字段与级别，本插件必须照同一套写 |
| `LING-REQ-081` | 内置插件均可卸载，卸掉后宿主仍能启动 |
| `LING-REQ-078` | 内置插件不获得特权，方法同样经路由与门禁 |

## 2. 场景

### 2.1 插件写一条日志

插件在激活时或处理请求时想把一件事记下来。它把插件名、级别、正文交给 `core-log.write`，不关心存哪、怎么存。

要成什么样：

- 写成功时返回成功，调用方不必检查。
- **写失败也返回成功。** 日志写不进去（磁盘满、权限不对）不该让业务逻辑失败——日志是诊断手段，不是流程的一环。
- 落盘失败要在内核日志里留一条 warn，否则「日志没写进去」这件事本身没人知道。

### 2.2 看某个插件最近的日志

使用者在命令行敲 `ling logs demo-caller`，想看到这个插件最近写了什么。

要成什么样：

- 返回最近 40 行，按时间正序（最早在上）。
- 每行带时间戳与级别，能直接看出什么时候发生了什么。
- 插件从没写过日志时，输出一句人话，不是空白。

### 2.3 按日期与级别查

排查昨天的问题，只想看 error。

要成什么样：

- 按日期取对应那天的文件。
- 按级别过滤时只保留匹配的行。

### 2.4 没装 `core-log`

```bash
ling uninstall core-log
```

要成什么样：

- 宿主照常启动，其他插件照常工作。
- 插件调 `core-log.write` 得到 `E_PLUGIN_MISSING`，插件自己决定要不要处理。
- `ling logs <插件名>` 退回读插件 `data/` 下的日志文件；没有就报「还没有写过日志」。
- 重新装回来之后，之前写过的文件还在，继续追加。

### 2.5 一天的日志涨到很大

一个插件不停地写日志，文件越来越长。

要成什么样（本期）：

- 不做轮转、不做删除。文件一直追加。
- 查询只读最后 N 行，不把整个文件读进内存——`tail` 与 `query` 的实现要能处理几十 MB 的文件。

风险写在这里而不是藏起来：长时间运行且日志量大的插件会把磁盘写满。`docs/ling/builtin-plugins/core-log/02-设计与接口.md` 第 6 节说明了为什么现在不做轮转。

## 3. 用例与验收标准

编号 `CL-` 开头，与 `docs/ling/07-测试与验收.md` 的 `TC-` 分开：`TC-` 是宿主行为的用例，`CL-` 是本插件的。

| 编号 | 场景 | 前置 | 期望 | 怎么判 |
|---|---|---|---|---|
| CL-01 | 写一条日志 | 宿主在跑，`core-log` 已启用 | 返回成功；`<数据根>/logs/<插件名>-日期.log` 多一行，格式为 `<时间> [级别] <正文>` | 读文件末行，正则匹配 |
| CL-02 | 连续写两条 | 同上 | 两行都在，顺序与写入顺序一致 | 读末两行 |
| CL-03 | 插件名带非法字符（如 `../x`） | 同上 | 拒绝，返回错误码，不产生文件 | 目录里没有新文件 |
| CL-04 | 查最近 N 行 | 已有 100 行 | 返回 40 行（默认），最早在上 | 比较行数与首行时间 |
| CL-05 | 查一个从没写过日志的插件 | 同上 | 返回空列表，不报错 | `lines` 为空数组 |
| CL-06 | 按级别过滤 | 文件里 info 与 error 混排 | 只返回 error 行 | 每行都含 `[error]` |
| CL-07 | 按日期查 | 有两天的文件 | 取指定那天的那份 | 返回内容的日期与请求一致 |
| CL-08 | 卸掉 `core-log` 后重启 | 已卸 | 宿主正常启动；`ling logs <插件名>` 不报「内部错误」 | 退出码 0 或提示「还没有写过日志」 |
| CL-09 | 日志目录不可写 | 把 `logs/` 设为只读 | `core-log.write` 仍返回成功；内核日志里有一条 warn | 查内核日志 |
| CL-10 | 文件很大时 tail | 造一个 50 MB 的文件 | 在 1 秒内返回，内存占用不随文件线性增长 | 计时与观察 |

## 4. 本期明确不做的

| 不做 | 什么时候做 | 为什么现在不做 |
|---|---|---|
| 日志轮转（按大小或按天删除） | 有真实的大日志需求时 | 现在没有数据支撑阈值，拍一个数字没意义 |
| 实时跟随（`logs --follow`） | M5 之后 | 需要推送通道，`04/06` §5.5 已定为只对内核日志生效 |
| 结构化字段（额外 JSON 字段） | 不确定 | 插件日志是自由文本，先保持简单 |
| 跨插件的统一检索 | 不确定 | `query` 已能按插件名取，跨插件检索是 `core-ui` 的事 |
