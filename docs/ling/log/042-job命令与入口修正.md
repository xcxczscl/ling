# log 042 `ling job` 与两处入口修正

> 日期：2026-10-31
> 关联：`docs/ling/04-详细设计/06-管理端口与命令行.md` §5.7、`docs/ling/builtin-plugins/core-job/02-设计与接口.md` §1.1.1

## 1. 为什么现在做

上一轮做完界面服务端，暴露出一个空洞：**没有任何一条命令能建定时任务**，只能手改 `settings.json`。`kernel.call` 通后，补三条命令是几十行的事，顺手把库里那个「命令行要全面」的账还上。

`ling job` 不是 core-job 的命令，是它的命令行入口：任务定义存在 `core-settings`，由 `core-job` 解释，命令行只把参数整理成一次 `kernel.call`。

| 命令 | 实际调用 |
|---|---|
| `job list` | `core-job.list` |
| `job add` | `core-job.validate` → `core-job.schedule` |
| `job remove` | `core-job.cancel` |

## 2. 为什么 `add` 要调两次

第一版只调 `core-job.schedule`，实测写错时间表时用户看到的是：

```
ling 内部出错：调用 core-job.schedule 失败（E_INTERNAL）
```

原因在接口层：插件方法失败只带回一个整数错误码，`2` 说不出「「时」段取值 25 超出范围 0 至 23」。这句细节原本只打到宿主 stderr，而用户在另一个窗口里看不到。

不加字段、不改插件 ABI 的做法：把「校验」单独做成一个返回正文的方法 `core-job.validate`，返回 `{"ok":false,"reason":"…"}`。命令行先校验再落盘，错了当场指出哪一段超范围；界面以后做 cron 输入框时用同一个方法做实时提示。

这条也顺手记进 `core-job/02` 与 `04/06 §5.7`，避免下次有人问「为什么不用一个方法搞定」。

## 3. 顺手修的真 bug：中文参数变乱码

测试里 `--args '{"message":"到点了"}'` 一直报「只收 JSON 对象」。查下来不是 JSON 解析的错：**Windows 把命令行参数按系统代码页（936）交给程序**，程序内部按 UTF-8 解析，中文已经是坏字节，JSON 自然不合法。

这个 bug 影响所有带中文的参数——插件目录里有中文、`--args` 里有中文、以后 `ling job add 每天备份` 这种任务名也全废。

修法：入口处把 `argv` 从 ANSI 代码页转成 UTF-8 再进后续逻辑（`MultiByteToWideChar` + `WideCharToMultiByte`），程序自身路径也走同一条转换（`u8path`），否则插件目录带中文时 `serve` 找不到 `plugins/`。

顺带一句：`--help` 里的示例现在敢写中文任务名了，之前写中文任务名会存成乱码。

## 4. 验收

`tests/acceptance/job_cli.py`，13 项：空列表人话、缺 `--cron` / `--call` 的提示、建任务、列表含表头与内容、`--json` 可解析、非法 cron 当场指出哪一段、`--args` 非对象被拒、删任务、删完为空、未知动作、不带动作打用法、`--help` 里有入口。

实测回显：

```
$ ling job add probe --cron "0 3 * * *" --call core-log.write --args '{"message":"到点了"}'
已建任务 probe：0 3 * * * 调用 core-log.write。
想确认：ling job list。想删掉：ling job remove probe。

$ ling job list
任务名            时间表        到点调用             上次触发
probe             0 3 * * *     core-log.write       还没跑过

$ ling job add bad --cron "0 25 * * *" --call core-log.write
时间表写错了：cron 的「时」段取值 25 超出范围 0 至 23
格式是五段：分 时 日 月 周。例："0 3 * * *" 每天 03:00，"*/10 * * * *" 每 10 分钟。
```

## 5. 没做的

- `lang job show <名字>`：`list` 里已经能看到全部字段，暂时不需要。
- `job add --disabled`：`schedule` 支持 `enabled=false`，但命令行没暴露。现在停用一条任务的现实办法是删掉，等界面做开关时一起补。
- 任务执行历史：`core-job` 本来就不记（`01` 的「本期明确不做的」）。
