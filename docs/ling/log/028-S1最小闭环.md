## 二、依赖改成随仓库走

`05` §3.3 原定 vcpkg，本机装不下去（`vcpkg.exe` 首运行要写 `%LOCALAPPDATA%\vcpkg`，被沙箱拒绝）。三个库都有官方单文件发行版，改成取下来随仓库走：

| 依赖 | 版本 | 说明 |
|---|---|---|
| toml++ | v3.4.0 | 单个 `toml.hpp` |
| nlohmann/json | v3.11.3 | 单个 `json.hpp`，S5 协议帧才用 |
| Catch2 | v3.7.1 | `catch_amalgamated.hpp` + `.cpp` |

版本与 sha256 记在 `third_party/README.md`，升级要同时改三处。这比 vcpkg 更硬地锁住了版本——文件名即版本，不依赖远端基线。

## 三、写代码时撞到的四个真问题

**① 方法名字符集把插件编号排除在外。** `04/01` §5.1 第 4 条写「只含字母、数字、下划线、点」，而插件编号允许连字符（`^[a-z0-9][a-z0-9-]*$`）。方法名必须以 `<编号>.` 开头，于是 `demo-a.ping` 永远注册不了。已放宽字符集，两版文档同步。

这条是文档内部矛盾，不是实现问题。测试第一次跑就撞上，说明用例写得值。

**② 首字符校验写松了。** `-demo` 被判为合法。规则是 `^[a-z0-9]...`，连字符不能打头。已修。

**③ ASan 与 MSVC STL 注解冲突。** 测试链接报 `LNK2038 annotate_string/annotate_vector 不匹配`。原因是 ASan 会关掉 STL 的容器注解，而 Catch2 静态库没开 ASan，两侧取值不同。解法是让 Catch2 也开同一个消毒器开关。

**④ `getenv` 在 MSVC 下是 C4996。** `/WX` 把它变成错误。改用 `_dupenv_s`，非 Windows 仍用 `getenv`。

## 四、实现上做的三个判断

**入口即激活点。** C ABI 只有一个导出符号（`04/02` §4.1），没有单独的 activate 函数。所以 `ling_plugin_entry` 返回即视为激活完成，插件在入口里登记方法；停用时宿主批量注销并卸载库。这条要在 S3 引入依赖与调和时重新审视——那时激活与装载要分开。

**缓冲区统一 malloc/free。** `04/02` §4.2 写「谁申请谁释放，插件用插件自己的释放函数」，但单符号约束下宿主拿不到插件的释放函数。进程内轨道两侧共用一个 `/MD` 运行时，统一用 `malloc`/`free` 最省事，也已写进 `plugin_api.h`。侧车轨道（S5）走协议帧，不受这条影响。

**MVP 阶段两条临时限制写成常量。** `requires` 非空、含 `[sidecar]` 段一律拒绝装载，并给出「M3/M4 起支持」的说明。参考 `docs/ling/11-MVP 范围.md` §4.2：宁可拒绝，不静默忽略。
