## 五、定稿之后的改动规则

状态由「初定」转「已定稿」不是流程终点，它改的是**改动的代价**：

| 想改什么 | 该怎么做 |
|---|---|
| 措辞、举例、表述不清 | 直接改，记变更记录 |
| 某个取值、某个字段名 | 直接改，但要 grep 全部引用点同步 |
| 需求条目增删、接口语义变化 | 先算影响面（`01` 是源头，牵动 03 至 07），改完重跑三个校验脚本 |
| 架构级结论（语言、插件形态、进程模型） | 回到对应文档改，并重写受影响的下游章节；这是 `10` §5 说的「核心判断被证伪」才允许的返工 |

代码与文档不一致时，**先判断哪边错了**：文档写错了改文档，代码写错了改代码。不允许「代码这样更顺手」就放着不动（`05` §5.2 出口条件第 4 条）。
