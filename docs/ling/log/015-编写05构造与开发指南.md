## 五个决定

### 一、命令全部标 `[未验证]`

代码还没写，第 7 节与第 9 节里的构建、运行、测试、打包命令一条都没跑过。

标法：每条命令后加 `[未验证]`，并在文档开头写明「S0 跑通后逐条去掉标注，跑不通的按实际改写」。

这是本文唯一允许「写着但没验证」的部分。其他内容都是推理得出的，不依赖运行结果。

### 二、Catch2 v3 作为测试框架

对比过四选项：GoogleTest、Catch2 v3、doctest、自写断言。

选 Catch2 v3 的理由是**文档丰富度**而不是功能：它最大的优势（mock 框架）本项目用不上，因为被测对象是真实的动态库与真实的协议帧，不需要假装。而编译速度比 doctest 慢的那部分，在增量场景只有一秒左右。

### 三、测试与生产代码零耦合

用户明确要求「测试和代码本身不要绑定」，落成三条硬规则：

| 规则 | 具体要求 |
|---|---|
| 生产代码不含测试框架 | `main/src/`、`main/include/` 里不出现 `catch2/` |
| 测试不进生产目录 | 全部放 `tests/` |
| 不为测试改可见性 | 不用 `friend`、不用 `#define private public`、不加 `#ifdef TESTING` |

代价也写进文档了：内部函数（例如不变式校验）只能通过公开行为间接测。这个代价接受——为可测性暴露私有实现，会让测试反过来主导设计。

例外是四个纯函数（版本匹配、主题匹配、环检测、清单 id 校验）：它们放在独立头文件直接暴露，不存在「暴露私有实现」的问题。这四个在 S0 阶段就能写完测试，是那时唯一有实际逻辑的代码。

### 四、七个模块

`kernel`（骨架与快照）+ `route`、`event`、`gate`、`depend`、`loader`、`log`。

骨架单列的理由：它被其余六个依赖。若混在某个业务模块里，那个模块会变成「所有人都要 include 的模块」，实际上退化成一个环。

依赖方向定为单向，额外只允许两条边：`depend → loader`、`loader → route/event/gate`。由 CMake 在配置阶段检查成环，不靠人看目录。

### 五、S0 至 S6 纵向切片

每片都能跑起来验证。S1 就打通「装插件 → 注册方法 → 调用」这条最小闭环，之后逐层加。

反面做法是「先横后纵」——把路由做完做透再做事件，很久看不到能跑的东西。对个人项目，看不到东西就无法判断方向对不对。

## 三个新增依赖

按 `AGENTS.md` §4 的规则，新增依赖要说明用途、体积、维护影响：

| 依赖 | 用途 | 体积 | 说明 |
|---|---|---|---|
| Catch2 v3 | 测试框架 | 只链接测试目标，不进产物 | 社区活跃，vcpkg 维护良好 |
| toml++ | 解析 `plugin.toml` | header-only，编译期展开，无运行时体积 | 支持 TOML 1.0，无第三方依赖 |
| nlohmann/json | 协议帧、错误结构、日志行 | header-only | 最常用的 C++ JSON 库，源码可读 |

三项已写入本文 §3.3，并配 `vcpkg-configuration.json` 的 baseline 锁版本。不锁版本会导致不同时间构建出不同依赖，出了问题无法复现。

`core-ui` 的 HTTP 依赖不在本期定：它在 S6 才动，届时按同一流程引入。候选是 cpp-httplib（header-only）与 Boost.Beast（重）。

## 顺带修了校验脚本的一个 bug

`check_docs.py` 把 bash 与 PowerShell 代码块里的 `# 注释` 当成了 Markdown 标题，导致两版标题比对出现十几条假差异。

修法：新增 `content_lines()`，遍历时标记「这一行在代码块内」，标题比对、表格检查、措辞检查都跳过这些行。代码块里的注释本来就不该参与文档结构判断。
