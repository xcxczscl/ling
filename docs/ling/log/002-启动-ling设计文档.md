# 002 启动 ling 设计文档

> 日期：2026-10-27
> 类型：阶段开始

## 发生了什么

ling 项目的设计文档开始编写，第一份 `docs/ling/00-总览与术语.md` 出草案。

## 定了什么

| 事项 | 结论 |
|---|---|
| 项目定位 | 插件宿主 + 功能插件：ling 只做宿主，全部实用功能由插件提供 |
| 目标 | 个人使用、当工具用、插件可独立演进、装插件和改插件都不重启宿主 |
| 非目标 | 不做大型系统（几十个插件、单机、单用户）；不做多人协作；不做插件市场；不做通用开发框架 |
| 术语分级 | 公共术语进 `docs/common/01-术语表.md`；项目专属术语留在各项目 `00-总览与术语.md` |
| 文档拆分 | ling 沿用 old 的主题序列，只把 old 的 `01-宿主设计`（417 行）拆成三份 |
| 篇幅上限 | 详细版参考 500 行（上下 50）；拆完会破坏连贯性的不强拆，无硬上限 |
| 许可 | 不采用开源许可，保留所有权利 |

## 为什么

- old 的 `01-宿主设计` 把目标、原则、总体结构、进程模型、安全、配置调和、里程碑、风险、决策记录九件事塞进一份，读者要跳读。拆开后每份只回答一类问题。
- 术语分两级是因为公共词跨项目复用，而清单、效应账本这类词出了 ling 就没人用，放公共表会稀释它。

## 影响

- 新增：`docs/ling/00-总览与术语.md`、`docs/ling/brief/00-总览与术语.md`
- 修改：`README.md` 补齐定位、目标、非目标、许可；`docs/common/00-文档编写规范.md` §6.4 改为术语两级登记、新增 §4.5 篇幅规则、审查清单 C 同步
