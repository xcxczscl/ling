# log 034 面向使用者文案整理

> 日期：2026-10-31
> 触发：实际使用中发现四处「不像给用户看的」输出

## 一、四个问题

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | `ling plugins` 只有数据行，没有表头 | 早期图省事，直接 `printf` 了三列 | 加表头，状态与类型翻中文 |
| 2 | `--help` 里「`--data-dir <路径>`」「`--purge 连 data/ 一起删`」「`logs [编号]`」看不懂 | 写帮助时站在实现者视角；「编号」尤其误导，会让人以为是一串数字 | 重写帮助，参数名改「插件名」，进阶选项单列 |
| 3 | 卸载带不带 `--purge` 都回「uninstall 成功」 | 只有内核日志区分了，命令回显没区分 | 回显里说明数据去了哪、怎么彻底删 |
| 4 | 要一个开箱即用的安装包，界面里能开关命令行 | 属 M5 的 `core-ui` 与 M6 的打包，MVP 外 | 未做，见 §四 |

## 二、文案对照

| 位置 | 改前 | 改后 |
|---|---|---|
| 帮助首行 | `ling 0.0.3-b1` | `ling 0.0.3-b1 —— 插件宿主。装插件、用插件，自己不带功能。` |
| 参数名 | `uninstall <编号>` | `uninstall <插件名>` |
| 参数名 | `logs [编号]` | `logs [插件名]` |
| 选项说明 | `--purge 连 data/ 一起删` | `--purge 卸载时连插件的数据一起删除` |
| 进阶选项 | 与常用选项混在一起 | 单独一节，注明 `--data-dir` 默认 `%APPDATA%\ling` |
| 帮助结尾 | 无 | 三步上手流程 + 「插件名就是 `ling plugins` 第一列」 |
| 列表输出 | 无表头，`activated` `process` | `插件名 版本 状态 类型` / `已启用` `进程内` |
| 列表为空 | 什么都不打印 | `还没有安装任何插件。用 ling install <插件目录> 装一个。` |
| 安装成功 | `install 成功` | `已安装 demo-a 1.0.0，现在可以用。` |
| 卸载（保留数据） | `uninstall 成功` | `已卸载 demo-a，它的数据还留在：<绝对路径>` + `下次装回来会用上这份数据。要连它一起删，加 --purge。` |
| 卸载（`--purge`） | `uninstall 成功` | `已卸载 demo-caller，插件和它的数据都删掉了。` |
| 启用 / 停用 | `enable 成功` | `已启用 demo-a。` / `已停用 demo-a，数据还在，随时能再启用。` |
| 插件不存在 | `E_PLUGIN_MISSING nope` | `找不到这个插件：nope（E_PLUGIN_MISSING）` + `提示：用 ling plugins 看看装了哪些插件，第一列就是插件名。` |
| 宿主没起 | `宿主未运行（找不到 registry.json）` | 同上，再加 `提示：先在另一个窗口运行 ling serve 启动 ling。` |
| 启动成功 | 一行塞满端口与数据根 | 分行列出数据目录与端口，标「本机内部通信，不用管」，并说明怎么停 |
| 停止 | `宿主已退出` | `ling 已停止。` |

错误码没有取消，只是退到括号里。理由：出问题时贴日志、搜报错都要那个码，但它不该是使用者第一眼看到的东西。

## 三、规则落到文档

- `docs/ling/04-详细设计/06-管理端口与命令行.md` 新增 §4.4「面向使用者的文案规则」，六条配反例与正例：多列必须有表头、只显示看得懂的状态、参数用使用者会说的词、错误先人话再码再下一步、改变数据范围的选项要回显后果、内部量标「不用管」。
- `docs/common/01-术语表.md` 新增「插件名」词条：命令行与界面上的称呼，等于设计文档的「插件编号」、清单里的 `id`。
- `docs/ling/09-运行时预案.md` 里 6 处「插件编号」改为「插件名」——这份是排障时给人看的。
- 简版同步。

## 四、没做的

安装包与图形界面（第 4 条的后半）。它属于 `core-ui`（M5）与打包（M6），要动的东西是：不弹控制台的启动器、本地网页界面、界面里的「显示命令行窗口」开关、安装包。范围与顺序需要单独定，不在这次文案整理里顺手做。
