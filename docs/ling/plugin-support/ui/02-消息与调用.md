# ling plugin-support/ui 02 消息与调用

> 状态：初定 | 最后更新：2026-11-02
> 依据：`docs/ling/plugin-support/ui/00-总览与约定.md` §3；`docs/ling/builtin-plugins/core-ui/04-详细设计/03-面板挂载与消息协议.md` §3 至 §7

本文回答：面板与外壳之间发哪些消息、每条消息长什么样、调用受哪些限制、面板侧最少要写多少代码。

---

## 1. 消息概览

面板与外壳之间只有七种消息，全部是一个 JSON 对象，`type` 字段区分种类。

| 种类 | 方向 | 什么时候 | 关键字段 |
|---|---|---|---|
| `init` | 外壳 → 面板 | 网页加载完成后，只发一次 | `v`、`pluginId`、`title`、`theme`、`tokens` |
| `call` | 面板 → 外壳 | 要调自己的方法 | `id`、`method`、`params` |
| `result` | 外壳 → 面板 | 每条 `call` 与 `drag` 的回复 | `id`、`ok`、`result` 或 `error` |
| `theme` | 外壳 → 面板 | 用户换主题 | `theme`、`tokens` |
| `event` | 外壳 → 面板 | 外壳级手势与将来的推送 | `name`、`data` |
| `drag` | 面板 → 外壳 | 面板内开始一次拖动 | `id`、`kind`、`payload` |
| `shutdown` | 外壳 → 面板 | 面板即将被移除 | `reason` |

**面板只能发 `call` 与 `drag` 两种。** 其余五种都由外壳发。发别的种类会被丢弃并记一条 warn。

面板发消息的目标固定写 `"*"`：不透明源下拿不到外壳的确切来源，安全性由外壳侧校验消息来源保证，不靠这里。

## 2. `init`

```json
{"type":"init","v":1,"pluginId":"resources-manager","title":"资源管理",
 "theme":"dark","tokens":{"--ling-bg":"#1b1b1d","--ling-text":"#e6e6e6"}}
```

| 字段 | 用处 |
|---|---|
| `v` | 协议版本，当前为 `1`。面板拿到不认识的值时按自己支持的最高版本工作 |
| `pluginId` | 本插件 id。用于拼方法前缀，也用于调试输出 |
| `title` | 与清单 `[ui].title` 相同 |
| `theme` | 当前主题名，`light` 或 `dark` |
| `tokens` | 当前主题的令牌取值，可以直接写到 `<html>` 的 `style` 上 |

三条要求：

1. **`init` 之前不要渲染内容。** 此时既没有 `pluginId` 也没有主题，先渲染会白闪，且早发的 `call` 会被回 `E_UI_NOT_READY`。
2. **`init` 只来一次。** 主题变化用 `theme` 消息，不重复发 `init`。
3. **`init` 之前就可以先画骨架**（背景色用 `var(--ling-bg)` 的默认值），避免长时间空白。

## 3. `call` 与 `result`

```json
{"type":"call","id":7,"method":"resources-manager.scan","params":{"path":"D:/media"}}
```

```json
{"type":"result","id":7,"ok":true,"result":{"files":12}}
{"type":"result","id":7,"ok":false,"error":{"code":"E_UI_FORBIDDEN","message":"面板不能调用其他插件的方法","advice":"改为调用本插件的方法"}}
```

| 字段 | 规则 |
|---|---|
| `id` | 正整数，面板自己递增，外壳原样回带。同一个 `id` 不能有两条在途 |
| `method` | 完整方法名，必须带 `<pluginId>.` 前缀 |
| `params` | JSON 对象。不是对象时按 `{}` 处理 |
| `result` | 方法成功时的返回值，类型由方法决定 |
| `error` | 失败时的结构。`code` 恒有；`message` 通常有；`advice` 只在有「下一步」时出现，没有就整条省略（不要按 `null` 判断，用 `"advice" in error`）；`detail` 只在被调方法给出结构化补充时出现（如缺的字段名、越界的路径），是 JSON 值不是句子。主文案取 `message`，第二行取 `advice`，`detail` 收进「详情」里默认不展开 |

四件事要知道：

| 项 | 规定 |
|---|---|
| 回复条数 | 每条 `call` 必有一条且仅有一条 `result` |
| 在途上限 | 单个面板 16 条。第 17 条立即回 `E_UI_BUSY`，不排队 |
| 超时 | 35 秒（服务端 30 秒加 5 秒余量），超时回 `E_TIMEOUT` |
| 参数校验 | 外壳不校验 `params` 的内容，插件方法自己校验 |
| `params` 大小 | 序列化后不超过 1 MB，超过回 `E_PAYLOAD_TOO_LARGE` |

在途上限 16 条对正常面板够用：列表、详情、计数这类并发在 3 至 5 条。超限多半是循环里发了请求，应当改成一次批量调用。

## 4. `theme`

```json
{"type":"theme","theme":"light","tokens":{"--ling-bg":"#ffffff"}}
```

外壳在用户切换主题时广播给每个已打开的面板。面板收到后把 `tokens` 里的键写到 `<html>` 上，或改 `<html data-theme>`。两条路都行，做法见 `docs/ling/plugin-support/ui/03-风格与主题.md` §4。

要求：300 毫秒内完成。超时不会报错，只是用户看到外壳变了、面板没变。

## 5. `event`

```json
{"type":"event","name":"drop","data":{"kind":"files","payload":{"paths":["D:/media/a.jpg"]},"from":"resources-manager"}}
```

当前只有一个来源：别的面板拖东西到本面板上，外壳转发一条 `drop`。`data` 的形状由外壳统一组装成 `{kind, payload, from}`，`from` 是拖出方的插件 id，不要期待别的形状，见本文 §6。

将来的推送也走这条消息，`name` 会是别的取值。**面板遇到不认识的 `name` 要忽略，不要报错**，否则新增一种事件就会打坏老面板。

## 6. `drag`

原生拖拽跨 iframe 会被 iframe 吞掉：从面板 A 拖到面板 B，事件只落在 A 的文档里。所以拖拽由外壳接管：

| 步骤 | 谁做 | 动作 |
|---|---|---|
| 1 | 面板 A | 用户按下并移动超过 5 像素时发 `{"type":"drag","id":3,"kind":"files","payload":{"paths":["D:/media/a.jpg"]}}` |
| 2 | 外壳 | 进入拖拽模式，在所有面板上盖一层透明遮罩，显示跟随光标的提示 |
| 3 | 外壳 | 用户松手时按坐标找到落点面板 B，给 B 发 `event`，`name` 为 `drop`，`data` 组装成 `{kind, payload, from}`：`payload` 原样搬运，`from` 填拖出方的插件 id |
| 4 | 外壳 | 给 A 回 `result`，`ok` 为 `true` |
| 5 | 面板 B | 收到 `drop`，调自己的方法处理，例如 `player.play(data.payload.paths[0])` |

落点不在任何面板上时，外壳丢弃这次拖拽，给 A 回 `ok` 为 `false`。面板应当据此恢复自己的状态（例如取消选中态）。

`kind` 只有两个合法取值，外壳会校验，其余取值整条 `drag` 被拒：

| `kind` | `payload` 形状 | 用途 |
|---|---|---|
| `files` | `{paths:["D:/a.jpg", ...]}` | 拖文件或目录，只传路径 |
| `text` | `{text:"..."}` | 拖一段文字 |

`payload` 序列化后不得超过 8 KB。超限时外壳回 `result{ok:false}`，`error.code` 为 `E_PAYLOAD_TOO_LARGE`，此时应改为传路径而不是传内容。

`ok` 只表示**壳有没有把 `drop` 投给某个面板**，不表示对方处理成功。对方处理失败不会回头通知拖出方。

## 7. `shutdown`

```json
{"type":"shutdown","reason":"disabled"}
```

面板被移除前 300 毫秒发来，`reason` 四种取值：

| `reason` | 场景 |
|---|---|
| `closed` | 用户点了面板上的关闭钮 |
| `disabled` | 插件被停用 |
| `uninstalled` | 插件被卸载 |
| `evicted` | 功能区最多 4 个面板，被新打开的面板挤掉 |

面板收到后要做的：清掉 `setInterval`、`setTimeout`，移除 `window` 上的监听，取消在途请求的回调。不做也不会报错，但定时器会继续跑，白占 CPU。

300 毫秒是留给面板收尾的时间，不要在这段时间里发新的 `call`。

## 8. 调用规则

### 8.1 只能调自己的方法

`method` 必须以 `<pluginId>.` 开头，否则外壳直接回 `E_UI_FORBIDDEN`，请求不会到达服务端。

要拿别的插件的数据，正确做法是**经自己的插件中转**：

```
面板调 resources-manager.export-to-player(path)
   → 该方法的实现里调 player.open(path)      ← 插件之间调，走宿主路由与能力校验
   → 结果返回给面板
```

不要试图从面板直接调 `player.open`：调不到，而且这是设计上刻意堵死的路。跨插件的调用收在插件本体一层，那里有完整的能力校验、日志与账本。

### 8.2 身份由来源决定，不由消息内容决定

外壳靠「消息从哪个 iframe 发来」认定调用方，**永远不读消息里的 `pluginId` 或 `plugin` 字段**。

所以：面板写什么名字都不影响判定；想冒充别的插件、调别人的方法，从机制上无从下手。面板也不需要报自己是谁。

### 8.3 面板侧校验来源

外壳侧会校验消息来源，面板侧也要做对称的一件事：**只接受 `e.source === window.parent` 的消息**。

不能用 `e.origin` 判断：面板向外发消息时源恒为 `"null"`，而它收到的消息带的是外壳的源——拿 `e.origin` 做白名单，会把外壳发来的消息全挡掉。用 `e.source` 比父窗口引用，才是真正「只认外壳」。

### 8.4 拿不到 token

token 只在外壳手里。面板发的每条 `call` 都由外壳带上 token 转发，面板既不需要、也无法接触它。

因此不要在面板里找 token、不要尝试直接请求 `/api/*`，那条路在浏览器层面就是断的。

## 9. 面板侧最小实现

一份能跑的最小骨架，直接用，不要另造协议：

```js
let pluginId = null, seq = 0;
const pending = new Map();

window.addEventListener("message", (e) => {
  if (e.source !== window.parent) return;   // 只认外壳
  const m = e.data;
  if (!m || typeof m.type !== "string") return;

  switch (m.type) {
    case "init":
      pluginId = m.pluginId;
      applyTheme(m.theme, m.tokens);
      render();
      break;
    case "theme":
      applyTheme(m.theme, m.tokens);
      break;
    case "result": {
      const cb = pending.get(m.id);
      if (cb) { pending.delete(m.id); cb(m); }
      break;
    }
    case "event":
      if (m.name === "drop") onDrop(m.data);
      break;
    case "shutdown":
      cleanup();
      break;
  }
});

function call(method, params = {}) {
  if (!pluginId) return Promise.reject({ code: "E_UI_NOT_READY", message: "还没收到 init" });
  return new Promise((resolve, reject) => {
    const id = ++seq;
    pending.set(id, (m) => (m.ok ? resolve(m.result) : reject(m.error)));
    parent.postMessage({ type: "call", id, method, params }, "*");
  });
}

function drag(kind, payload) {
  if (!pluginId) return Promise.reject({ code: "E_UI_NOT_READY", message: "还没收到 init" });
  return new Promise((resolve, reject) => {
    const id = ++seq;
    pending.set(id, (m) => (m.ok ? resolve(m.result) : reject(m.error)));
    parent.postMessage({ type: "drag", id, kind, payload }, "*");
  });
}
```

`applyTheme`、`render`、`onDrop`、`cleanup` 四处由插件实现。`cleanup` 里要清掉所有定时器与监听。

## 10. 常见错误

| 现象 | 原因 |
|---|---|
| 首次调用回 `E_UI_NOT_READY` | 在 `init` 之前发了 `call`，等收到 `init` 再调 |
| 一直 `E_UI_FORBIDDEN` | `method` 没带 `<pluginId>.` 前缀，或想调别的插件的方法 |
| 偶发 `E_UI_BUSY` | 并发超过 16 条，检查是否在循环里发请求 |
| 调用 35 秒后 `E_TIMEOUT` | 方法本身慢。协议里没有「取消调用」这条消息，超时后该 `id` 作废、不要复用；界面上给用户一个「重新执行」的入口 |
| 收不到 `result` | `id` 不是正整数，或同一个 `id` 被复用 |
| 拖拽到另一个面板没反应 | 对方没监听 `event` 的 `drop`，或落点不在任何面板上 |
| 消息里带了 `pluginId` 却仍被拒 | 外壳不看这个字段，身份按 iframe 来源算 |
| 面板一片白，控制台没报错 | 面板脚本抛的错外壳不会显示出来。先按 F12 看 Console；外壳只在「文件不存在 / 加载超时」两种情形给提示，脚本错误得自己查 |
| 拖拽回 `E_PAYLOAD_TOO_LARGE` | `payload` 超过 8 KB，改传路径 |
