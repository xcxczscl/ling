# ling plugin-support/ui 01 面板声明与资源

## 1. 清单声明

### 1.1 最小写法

```toml
id = "my-panel"            # 必须等于插件目录名，别照抄示例
version = "0.1.0"
api = "1"
name = "我的面板"
capabilities = ["ui"]

[ui]
entry = "ui/index.html"
title = "资源管理"
icon = "ui/icon.svg"
```

`[ui]` 段三个字段：

| 字段 | 必填 | 规则 | 用在哪 |
|---|---|---|---|
| `entry` | 是 | 相对插件目录的路径，必须位于 `ui/` 下，后缀必须 `.html` | 面板里加载的那个网页 |
| `title` | 是 | 1 至 32 字符 | 侧边栏条目与面板顶部标题条 |
| `icon` | 否 | 相对插件目录的路径，必须位于 `ui/` 下，后缀 `.svg` 或 `.png` | 侧边栏条目左侧 |

`title` 与清单顶层的 `name` 是两件事：`name` 给 `ling plugins` 与日志用，`title` 给界面用。两者可以不同，例如 `name = "资源管理插件"`、`title = "资源管理"`。

### 1.2 一个插件一个面板

`[ui]` 是单段，不是数组。一个插件最多贡献一个面板，侧边栏里一个插件对应一条。

面板内部想分几块（左边目录树、右边文件列表）由插件自己在这份网页里划分布局，外壳不参与。外壳只提供一个矩形区域和一条标题条。

### 1.3 为什么必须同时声明 `ui` 能力

`capabilities` 里没有 `ui` 却写了 `[ui]` 段时，装载直接失败，报 `E_UI_PANEL_DECL`。

这条挡的是「复制清单时忘了改能力」：错在装载期暴露，信息写着缺哪一项；若不拦，错要等到用户点开面板才变成一片白屏。

## 2. 装载期校验

`[ui]` 段的校验接在清单校验的第 10 步之后，六项按顺序执行，遇第一个失败即停：

| 序 | 校验 | 失败 |
|---|---|---|
| 1 | `capabilities` 含 `ui` | `E_UI_PANEL_DECL`，信息写明「声明了 [ui] 但缺少 ui 能力」 |
| 2 | `entry` 与 `title` 都存在且非空 | `E_UI_PANEL_DECL`，写明缺哪个字段 |
| 3 | `entry`、`icon` 不含 `..`、不以 `/` 或 `\` 开头、不含 `:` | `E_UI_PANEL_DECL`，信息回显原文 |
| 4 | `entry`、`icon` 解析后的真实路径在 `ui/` 目录内 | `E_UI_PANEL_DECL` |
| 5 | `entry` 后缀 `.html`，`icon` 后缀 `.svg` 或 `.png` | `E_UI_PANEL_DECL` |
| 6 | `title` 长度在 1 至 32 | `E_UI_PANEL_DECL` |

**`entry` 指向的文件在装载期不检查存在性。** 插件可以先装、后补文件，也可以把网页放在压缩包里按需解压。文件不存在不影响装载，打开面板时才显示错误（本文 §7，`CUI-REQ-056`）。

## 3. `ui/` 目录规则

### 3.1 URL 与磁盘的对应

请求面板时，URL 里的路径相对该插件的 `ui/` 目录：

| `[ui].entry` | 面板地址 | 磁盘位置 |
|---|---|---|
| `ui/index.html` | `/panel/<id>/index.html` | `<插件目录>/ui/index.html` |
| `ui/main.html` | `/panel/<id>/main.html` | `<插件目录>/ui/main.html` |
| `ui/sub/index.html` | `/panel/<id>/sub/index.html` | `<插件目录>/ui/sub/index.html` |

换算规则：URL 路径等于 `entry` 去掉开头的 `ui/`。外壳用这条规则拼地址，插件不需要自己拼。

### 3.2 后缀白名单

只有下列后缀会被返回，其他一律 404，即使文件存在：

`.html` `.css` `.js` `.mjs` `.json` `.svg` `.png` `.jpg` `.jpeg` `.webp` `.gif` `.ico` `.woff` `.woff2` `.ttf`

白名单之外的文件读不到，包括 `plugin.toml`、数据文件、日志。所以**不要把运行时数据放进 `ui/`**：既读不到，也容易被下一次升级覆盖。

### 3.3 网页里的引用一律写相对路径

面板地址带子目录时（例如 `ui/sub/index.html`），写死的 `/style.css` 会指到 `/panel/<id>/style.css` 之外的地方。规则两条：

| 规则 | 说明 |
|---|---|
| 引用同目录资源写相对路径 | `href="style.css"`、`src="./app.js"` |
| 引用 `ui/` 之外的东西一律取不到 | 兄弟目录、插件数据目录、`../` 全部 404 |

### 3.4 目录样例

```
plugins/resources-manager/
├── plugin.toml
├── resources_manager.dll        ← 插件本体，ui/ 之外
├── data/                         ← 运行时数据，ui/ 之外
└── ui/                           ← 只有这里会被发给浏览器
    ├── index.html
    ├── icon.svg
    ├── style.css
    └── app.js
```

`ui/` 是不是自包含，决定面板能不能打开。建议把前端构建产物全部输出到这一个目录，不要引用仓库里其他位置的源码。

## 4. 谁来把这些文件发给浏览器

### 4.1 由 core-ui 统一发

面板的 HTTP 请求由 core-ui 的服务端（监听 `127.0.0.1` 的回环端口，默认 8010）处理，它去磁盘读 `<插件目录>/ui/` 下的文件再返回。

```
浏览器 ──GET /panel/resources-manager/index.html──▶ core-ui 服务端
                                                     │ 读文件
                                                     ▼
                                    <插件目录>/ui/index.html
```

插件因此不需要写服务端，不需要挑端口，不需要处理认证与跨域。

### 4.2 不能自己起端口的原因

**注意：面板在 sandbox 里是不透明源，它与外壳并不共享 DOM 与存储**，这是刻意设计的（见 `docs/ling/plugin-support/ui/00-总览与约定.md` §3 第 9 条）。所以「由 core-ui 统一发」的理由不是「让它们同源」，而是下面三条：

| 理由 | 说明 |
|---|---|
| 主题能统一下发 | `theme.css` 与面板由同一个服务提供，面板一个 `<link>` 就拿到令牌，不必自己拼一份 |
| 加载失败能被外壳接管 | 外壳预检同一个服务上的文件，404、超时都能提前发现并显示原因；插件自建服务时外壳只能看到一个加载不出来的画框 |
| 插件不必写服务端 | 不用挑端口、不用处理认证、不用管静态文件的 MIME |

若改成每个插件自建服务：外壳仍能 `postMessage`（跨源也能发），但每个插件都要自己处理 CORS、自己的端口、自己的静态文件，门槛抬到「先写一个 HTTP 服务」；而且外壳无法预检，面板打不开时只能显示一句「加载失败」。

所以「由 core-ui 统一 serve」是硬要求，不是便利。插件自建服务的面板不会被装进功能区。

### 4.3 缓存

| 项 | 行为 |
|---|---|
| `Cache-Control` | `no-cache`，允许缓存但每次回源校验 |
| `ETag` | 按文件大小与修改时间生成，未变则返回 304 |

插件升级换了前端文件，用户下次打开面板就能拿到新版本，不会看到旧界面。

## 5. 面板里不能做的事

面板在不透明源下运行，且响应带 `connect-src 'none'` 的 CSP。下面这些做不了，写代码时不要依赖：

| 不做 | 实际表现 | 替代做法 |
|---|---|---|
| `localStorage`、`sessionStorage`、`IndexedDB` | 抛安全错误 | 状态存在插件自己的配置里，经方法读写 |
| `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource` | 跨源被拦，CSP 再拦一层 | 要数据就发 `call` 让插件方法去取 |
| `document.domain` | 抛安全错误 | 不需要，也不该用 |
| 引入外部 CDN 的脚本或样式 | 被 `script-src 'self'` 拦 | 把依赖打包进 `ui/` |
| 用 `iframe` 嵌外部网站 | 被 `default-src 'self'` 拦 | 需要展示外部内容时在自己的方法里取回来 |
| Service Worker | 不透明源下不可用 | 不需要 |
| 读父页面的 DOM 或存储 | 跨源，被浏览器拦 | 一切经消息协议 |
| 原生表单提交 | `sandbox` 没有 `allow-forms`，CSP 又带 `form-action 'none'`，双击提交无效 | 用 JS 收值后发 `call`，提交动作交给插件方法 |

## 6. 图标与观感约定

| 项 | 建议 |
|---|---|
| `icon` 尺寸 | 画在 `viewBox="0 0 24 24"` 里，按矢量缩放；不要假设显示尺寸写死像素 |
| `icon` 颜色 | 单色。外壳用 `<img>` 加载它，`currentColor` 在内联 SVG 之外取不到父级颜色，因此不要依赖它随主题变色；深浅两套主题下都要能看清 |
| 字体 | 不指定 `font-family`，沿用宿主的系统栈 |
| 品牌色 | 允许有，但只用于强调与图标；背景、文字、边框必须取令牌，见 `docs/ling/plugin-support/ui/03-风格与主题.md` §5 |

## 7. 打开面板失败时用户看到什么

| 情形 | 用户看到 | 作者要做的 |
|---|---|---|
| `entry` 文件不存在 | 外框内显示「面板文件不存在：`<路径>`」与「重试」 | 检查 `entry` 是否写错、构建产物是否漏拷 |
| 预检 5 秒无响应 | 显示「面板文件读取超时」与「重试」 | 文件在慢速盘或被独占打开；先确认磁盘与权限 |
| 文件在，10 秒内没加载完 | 显示「面板加载超时」与「重试」 | 检查首屏是否在等一个拿不到的网络请求 |
| 插件启动失败 | 显示失败原因与「看日志」 | 修插件的启动问题；面板代码不背这个锅 |
| 插件被停用或卸载 | 面板被关闭，提示「插件已停用」或「插件已卸载」 | 无需处理，不会调用到面板 |

重试由用户点按钮触发，外壳不自动重试。

## 8. 自检清单

提交带面板的插件前逐条打勾：

- [ ] `[ui]` 三字段齐全，`capabilities` 含 `ui`
- [ ] `entry` 在 `ui/` 下，后缀 `.html`
- [ ] 网页里的资源引用都是相对路径，没有指向 `ui/` 之外；唯一例外是 `/api/ui/theme.css`（绝对路径，见 `docs/ling/plugin-support/ui/03-风格与主题.md` §3.1）
- [ ] 没有 `fetch`、`localStorage`、外链脚本
- [ ] `icon` 是单色 SVG 或 PNG，颜色用 `currentColor`
- [ ] 面板能显示的前提下，插件的方法仍可独立工作（没装 core-ui 时不受影响）
