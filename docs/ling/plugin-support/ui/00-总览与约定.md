## 1. 这套文档管什么

### 1.1 覆盖什么

插件如何把一份网页交给人机界面显示。四件事：

| 件事 | 落在哪份 | 一句话 |
|---|---|---|
| 声明 | `docs/ling/plugin-support/ui/01-面板声明与资源.md` | 清单里写 `[ui]` 段，声明 `ui` 能力 |
| 资源 | 同上 | 网页放在插件目录的 `ui/` 下，由 core-ui 统一发给浏览器 |
| 通信 | `docs/ling/plugin-support/ui/02-消息与调用.md` | 面板与外壳按七种固定消息收发 |
| 观感 | `docs/ling/plugin-support/ui/03-风格与主题.md` | 颜色与尺度只引用 `--ling-*` 令牌 |

这四件事之外，还有一条贯穿全篇的前提：**面板是不可信代码**。它拿不到 token，也不能自己发 HTTP 请求，一切需要宿主配合的动作都交给外壳代办。这条决定了下面所有「必须」与「禁止」。

### 1.2 不覆盖什么

| 内容 | 去哪 |
|---|---|
| core-ui 自己怎么实现、界面怎么排、安全模型 | `docs/ling/builtin-plugins/core-ui/00-总览与术语.md` 起的整组文档 |
| 清单其他字段、C ABI 函数表、错误码总表 | `docs/ling/plugin-support/01-插件装载与接口.md` §3、§4、§5 |
| 安装、停用、卸载、热更新 | `docs/ling/plugin-support/01-插件装载与接口.md` §6、§7 |
| `Context` 方法与效应账本 | `docs/ling/plugin-support/02-上下文与效应账本.md` |
| 方法怎么注册、怎么被路由 | `docs/ling/main/04-详细设计/01-内核四服务.md` §3 |

本文与三份细则只写「插件作者要做什么」。同一件事的完整设计与理由在 core-ui 文档里，本文引用不重复。

## 2. 谁要读

| 角色 | 读哪几节 |
|---|---|
| 给插件加界面的作者 | 全篇。动手顺序：按 `docs/ling/plugin-support/ui/01-面板声明与资源.md` §1 写清单与 `ui/index.html`，按 `docs/ling/plugin-support/ui/02-消息与调用.md` §9 抄那段 JS，按 `docs/ling/plugin-support/ui/03-风格与主题.md` §3 引主题。三份拼起来才是一个能跑的面板 |
| 只写方法、不写界面的作者 | 本文 §3 的第 1、2 条与 `docs/ling/plugin-support/ui/01-面板声明与资源.md` §1，避免误声明 `ui` 能力 |
| 维护 core-ui 的人 | 本文 §3 是三份细则的约束清单，改任何一条都要回头核对这里 |

## 3. 契约总览

十条，前七条是必须做到，后三条是禁止做。违反后果写在「不遵守会怎样」一列。

| # | 要求 | 不遵守会怎样 | 细则 |
|---|---|---|---|
| 1 | 清单带 `[ui]` 段，且 `capabilities` 含 `ui` | 装载失败，报 `E_UI_PANEL_DECL` | `docs/ling/plugin-support/ui/01-面板声明与资源.md` §1 |
| 2 | `entry` 指向 `ui/` 下的 `.html` 文件 | 装载失败，或打开面板时报 `E_UI_PANEL_NOTFOUND` | `docs/ling/plugin-support/ui/01-面板声明与资源.md` §1、§2 |
| 3 | 面板只调自己插件命名空间下的方法 | 外壳回 `E_UI_FORBIDDEN`，调用不生效 | `docs/ling/plugin-support/ui/02-消息与调用.md` §8 |
| 4 | 收到 `init` 之后再渲染、再发 `call` | 拿不到插件 id 与主题，首屏白闪；早发的调用回 `E_UI_NOT_READY` | `docs/ling/plugin-support/ui/02-消息与调用.md` §2 |
| 5 | 颜色、字号、间距、圆角只取 `--ling-*` 令牌 | 切主题时面板不跟着变，出现半亮半暗 | `docs/ling/plugin-support/ui/03-风格与主题.md` §1 |
| 6 | 收到 `theme` 后 300 毫秒内完成切换 | 外壳已变、面板未变 | `docs/ling/plugin-support/ui/03-风格与主题.md` §4 |
| 7 | 收到 `shutdown` 后停掉定时器、清掉事件监听 | 面板被移除后定时器继续跑，白耗 CPU | `docs/ling/plugin-support/ui/02-消息与调用.md` §7 |
| 8 | 禁止自己起 HTTP 服务来提供面板 | 外壳无法预检、无法统一注入主题样式 | `docs/ling/plugin-support/ui/01-面板声明与资源.md` §4 |
| 9 | 禁止在面板里发 `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`，禁用 `localStorage`；`alert`、`confirm`、`prompt` 也无效 | 浏览器直接拦或抛错，功能不可用；调 `alert` 没有任何反应 | `docs/ling/plugin-support/ui/01-面板声明与资源.md` §5 |
| 10 | 禁止依赖 token，禁止靠自报 `pluginId` 取得权限 | 外壳只按消息来源认调用方，自报无效 | `docs/ling/plugin-support/ui/02-消息与调用.md` §8 |

第 3 条与第 10 条是同一件事的两面：面板能调什么由「这个 iframe 属于哪个插件」决定，不由消息内容决定。所以面板既不需要、也无法声明自己是谁。

## 4. 版本与兼容

| 项 | 规定 |
|---|---|
| 契约适用版本 | core-ui 1.1.0 及以后，当前文档对应 1.1.0-b1 |
| 消息协议版本 | `init` 里的 `v` 为 `1` |
| 宿主没装 core-ui | 插件照常装载、方法照常可调，只是没有界面（`CUI-REQ-055`）。插件不得因为「面板没被显示」而报错或拒绝工作 |
| 宿主版本较旧 | 旧装载器只读已知键，多出的 `[ui]` 段被忽略，装载成功、没有界面【待验证：1.0.0 的 `manifest.cpp` 只读已知键、不拒绝未知段，代码结论如此，但未在旧宿主上实测，替换宿主前应跑一次】 |
| core-ui 被卸载后重装 | 面板不自动打开，侧边栏入口恢复，用户点了才打开（`CUI-REQ-032`） |

最后两行的意思是：**`[ui]` 段是可选增强，不是运行前提**。插件不该把核心功能只放在面板里，方法层要能独立工作。
