## 1. `Context` 从哪来

`Context` 由内核在激活前创建，经 `context_alloc` 注入，是不透明句柄。不能自己造，不能拿别人的 `ctx`；停用后再用会返回 `E_PLUGIN_MISSING`。

## 2. 方法表

十个方法中，产生账本条目的是 `register_method`、`unregister_method`、`subscribe`、`unsubscribe`、`write_config`。`call`、`emit`、`data_dir`、`ledger`、`last_error` 不入账。核心规则：只有改共享状态的方法入账。

## 3. 哪些操作会被记账

方法注册、事件订阅、配置写入、侧车启动、停用回调五类。前四类由宿主撤销，停用回调由插件自己执行。线程与文件句柄不入账，插件要在 `on_deactivate` 里自己停、自己关。

## 4. 撤销规则

倒序撤销，后建立的先拆。单条失败不中断，记 `E_UNDO_FAILED`；全部结束后返回 `E_UNINSTALL_INCOMPLETE`。重复撤销是安全的。停用保留数据文件；卸载删工件、默认保留 `data/`；重载先撤销再开新一代。

## 5. 撤销函数怎么写

进程内插件注册方法与订阅时交 `undo_fn`；侧车交不出函数指针，由宿主代撤。侧车仍要在收到 `deactivated` 后清理自己的线程、文件与子进程。

## 6. 数据目录与配置

`data_dir()` 返回 `plugins/<编号>/data/` 的绝对路径，激活前已存在。跨调用状态放文件，连接与线程放内存。`write_config` 的键必须以 `<编号>.` 开头，撤销时恢复旧值。

## 7. 命名空间与边界

方法名、事件主题、配置键都必须以 `<编号>.` 开头，`kernel.` 保留。宿主不检测也不还原绕开 `Context` 的修改：直接写文件、改全局变量、起子进程。ling 不是沙箱。

## 8. 常见错误

| 现象 | 原因 |
|---|---|
| 停用后调用返回 `E_PLUGIN_MISSING` | 用了旧 `ctx`，或异步回调在停用后才触发 |
| 注册返回 `E_NAMESPACE_VIOLATION` | 名字没带 `<编号>.` 前缀 |
| 卸载后配置还在 | 没走 `write_config`，直接改了文件 |
| 侧车卸载后线程还在 | 没在 `deactivated` 里停自己的线程 |
| 以为 `call` 或 `emit` 会被撤销 | 这两类不入账 |
