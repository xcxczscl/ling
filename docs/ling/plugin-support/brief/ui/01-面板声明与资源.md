## 1. 清单声明

### 1.1 最小写法

```toml
id = "resources-manager"
version = "1.2.0"
api = "1"
name = "资源管理"
capabilities = ["fs", "ui"]

[ui]
entry = "ui/index.html"
title = "资源管理"
icon = "ui/icon.svg"
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `entry` | 是 | 相对插件目录，在 `ui/` 下，后缀 `.html` |
| `title` | 是 | 1 至 32 字符，显示在侧边栏与面板标题条 |
| `icon` | 否 | 相对插件目录，在 `ui/` 下，后缀 `.svg` 或 `.png` |

`name` 给 `ling plugins` 与日志用，`title` 给界面用，两者可以不同。

### 1.2 一个插件一个面板

`[ui]` 是单段，不是数组。面板内部的分栏布局由插件自己在这份网页里划分，外壳不参与。

### 1.3 为什么必须同时声明 `ui` 能力

`capabilities` 缺 `ui` 而写了 `[ui]` 时装载失败，报 `E_UI_PANEL_DECL`。拦在装载期，错误信息写明缺哪项，不必等用户点开面板看到白屏。

## 2. 装载期校验

接在清单校验第 10 步之后，六项按序执行，遇第一个失败即停：

| 序 | 校验 | 失败 |
|---|---|---|
| 1 | `capabilities` 含 `ui` | `E_UI_PANEL_DECL` |
| 2 | `entry` 与 `title` 存在且非空 | `E_UI_PANEL_DECL` |
| 3 | `entry`、`icon` 不含 `..`、不以 `/` 或 `\` 开头、不含 `:` | `E_UI_PANEL_DECL` |
| 4 | 真实路径在 `ui/` 内 | `E_UI_PANEL_DECL` |
| 5 | `entry` 后缀 `.html`，`icon` 后缀 `.svg` 或 `.png` | `E_UI_PANEL_DECL` |
| 6 | `title` 长度 1 至 32 | `E_UI_PANEL_DECL` |

`entry` 指向的文件装载期不检查存在性；文件缺失不影响装载，打开面板时才报错（`CUI-REQ-056`）。

## 3. `ui/` 目录规则

### 3.1 URL 与磁盘的对应

URL 路径 = `entry` 去掉开头的 `ui/`。

| `[ui].entry` | 面板地址 |
|---|---|
| `ui/index.html` | `/panel/<id>/index.html` |
| `ui/sub/index.html` | `/panel/<id>/sub/index.html` |

### 3.2 后缀白名单

`.html` `.css` `.js` `.mjs` `.json` `.svg` `.png` `.jpg` `.jpeg` `.webp` `.gif` `.ico` `.woff` `.woff2` `.ttf`

白名单外一律 404，包括 `plugin.toml`、数据文件与日志。运行时数据不要放 `ui/`。

### 3.3 网页里的引用一律写相对路径

写 `/style.css` 这类绝对路径会指到 `ui/` 之外；`../` 与兄弟目录一律 404。构建产物全部输出到 `ui/`，保持自包含。

### 3.4 目录样例

```
plugins/resources-manager/
├── plugin.toml
├── resources_manager.dll        ← 插件本体，ui/ 之外
├── data/                         ← 运行时数据，ui/ 之外
└── ui/                           ← 只有这里会被发给浏览器
    ├── index.html
    ├── icon.svg
    ├── style.css
    └── app.js
```

## 4. 谁来把这些文件发给浏览器

### 4.1 由 core-ui 统一发

core-ui 的服务端（`127.0.0.1` 回环端口，默认 8010）读 `<插件目录>/ui/` 下的文件并返回。插件不写服务端、不挑端口、不处理认证与跨域。

### 4.2 不能自己起端口的原因

| 后果 | 说明 |
|---|---|
| 主题换不动 | 跨源读不到外壳的令牌，界面半亮半暗 |
| 加载失败无法统一控制 | 外壳够不到别的源 |
| 每个插件都要处理 CORS 与认证 | 门槛抬到「先写一个 HTTP 服务」 |

插件自建服务的面板不会被装进功能区。

### 4.3 缓存

`Cache-Control: no-cache` 加 `ETag`。升级换了前端文件，下次打开面板即取到新版本。

## 5. 面板里不能做的事

| 不做 | 实际表现 | 替代做法 |
|---|---|---|
| `localStorage`、`sessionStorage`、`IndexedDB` | 抛安全错误 | 状态存插件配置，经方法读写 |
| `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource` | 跨源被拦，CSP 再拦一层 | 发 `call` 让方法去取 |
| `document.domain` | 抛安全错误 | 不需要 |
| 引入外部 CDN 的脚本或样式 | 被 `script-src 'self'` 拦 | 依赖打包进 `ui/` |
| `iframe` 嵌外部网站 | 被 `default-src 'self'` 拦 | 由方法取回内容再展示 |
| Service Worker | 不透明源下不可用 | 不需要 |
| 读父页面 DOM 或存储 | 跨源被拦 | 一切经消息协议 |

## 6. 图标与观感约定

| 项 | 建议 |
|---|---|
| `icon` 尺寸 | `viewBox="0 0 24 24"`，按矢量缩放，不假设显示尺寸 |
| `icon` 颜色 | 单色，用 `currentColor` |
| 字体 | 不指定 `font-family` |
| 品牌色 | 只用于强调与图标；背景、文字、边框取令牌，见 `docs/ling/plugin-support/ui/03-风格与主题.md` §5 |

## 7. 打开面板失败时用户看到什么

| 情形 | 用户看到 | 作者要做的 |
|---|---|---|
| `entry` 文件不存在 | 「面板文件不存在：`<路径>`」与「重试」 | 检查 `entry` 与构建产物 |
| 10 秒内没加载完 | 「面板加载超时」与「重试」 | 排查首屏是否在等网络请求 |
| 插件启动失败 | 失败原因与「看日志」 | 修插件启动问题 |
| 插件被停用或卸载 | 面板关闭并提示 | 无需处理 |

外壳不自动重试，只由用户点「重试」。

## 8. 自检清单

- [ ] `[ui]` 三字段齐全，`capabilities` 含 `ui`
- [ ] `entry` 在 `ui/` 下且后缀 `.html`
- [ ] 资源引用都是相对路径，没有指向 `ui/` 之外
- [ ] 没有 `fetch`、`localStorage`、外链脚本
- [ ] `icon` 是单色 SVG 或 PNG
- [ ] 没装 core-ui 时，插件方法仍可独立工作
