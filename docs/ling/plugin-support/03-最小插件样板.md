# ling 插件支持 03 最小插件样板

> 状态：已定稿 | 最后更新：2026-11-02
> 依据：`docs/ling/plugin-support/01-插件装载与接口.md` §3、§4；`docs/ling/plugin-support/02-上下文与效应账本.md` §2

这一篇是给人照抄的样板，从空目录到一个能调用的插件。只讲「怎么写」；清单字段、C ABI 函数表、错误码的完整定义在 `01`，`Context` 与撤销在 `02`，这里只引用不重复。

---

## 1. 目录与清单

```
plugins/demo-a/
├── plugin.toml
└── demo_a.cpp
```

`plugin.toml`：

```toml
id = "demo-a"
version = "1.0.0"
api = "1"
name = "示例插件 A"
description = "最小可运行插件"
capabilities = []
```

字段含义见 `01` §3。这里 `capabilities` 留空：这个插件只提供一个方法，不碰文件、网络、界面。

## 2. 入口函数

插件唯一导出的符号是 `ling_plugin_entry`（`LING_PLUGIN_EXPORT` 宏在 `plugin_api.h` 里按平台展开成 `__declspec(dllexport)` 或可见性属性）。没有 `sdk.hpp` 之类的封装，直接手写：

```cpp
#include <cstdlib>
#include <cstring>

#include "ling/plugin_api.h"

namespace {

const char* kReply = "pong";

// 处理函数：签名由 01 §4.1 的函数表决定。
int32_t on_ping(void* handler_ctx, const uint8_t* args, size_t args_len, uint8_t** out,
                size_t* out_len) {
    (void)handler_ctx;
    (void)args;
    (void)args_len;
    const size_t len = std::strlen(kReply);
    auto* buffer = static_cast<uint8_t*>(std::malloc(len));
    if (buffer == nullptr) return 1;
    std::memcpy(buffer, kReply, len);
    *out = buffer;      // 插件申请，宿主拷走后调 free_buffer 释放
    *out_len = len;
    return 0;
}

}  // namespace

LING_PLUGIN_EXPORT int32_t ling_plugin_entry(const ling_host_api* host,
                                             ling_plugin_descriptor* out_desc,
                                             void** out_plugin) {
    void* ctx = host->context_alloc("demo-a", 0);   // 分配本次激活的上下文
    if (ctx == nullptr) return 2;

    const int32_t code = host->register_method(ctx, "demo-a.ping",
                                               reinterpret_cast<void*>(&on_ping), nullptr, 0);
    if (code != 0) return 3;

    out_desc->abi_version = LING_ABI_VERSION;
    out_desc->plugin_id = "demo-a";
    out_desc->plugin_version = "1.0.0";
    out_desc->api = "1";
    *out_plugin = ctx;
    return 0;
}
```

三个要点：

| 要点 | 说明 |
|---|---|
| 方法名必须带 `demo-a.` 前缀 | 不带则注册返回命名空间违规（`docs/ling/main/04-详细设计/01-内核四服务.md` §5.1 第 3 步） |
| 返回缓冲区 | 插件用 `malloc` 申请，宿主拷走后调 `free_buffer` 释放；两边共用 `/MD` 运行时，`malloc`/`free` 对得上 |
| 撤销函数可传 `nullptr` | 方法没有副作用需要撤销时就传空；宿主对「没有撤销动作」的方法直接跳过撤销步骤 |

## 3. 构建

在 `plugins/CMakeLists.txt` 里加一行：

```cmake
add_ling_plugin(demo-a SOURCES demo_a.cpp)
```

`add_ling_plugin` 由 `tools/cmake/LingPlugin.cmake` 提供，自动做四件事：套用统一编译选项、把产物命名为 `<编号>.dll` 或 `.so`、复制到 `run/<preset>/plugins/demo-a/`、同时复制 `plugin.toml`。

插件作者不写编译选项——这是 `docs/ling/main/02-技术选型.md` §5.4「插件作者不自己写编译选项」的落地方式。

```bash
# 调用  [未验证]

```

## 5. 常见错误

| 现象 | 原因 |
|---|---|
| `E_MANIFEST_INVALID`，message 说缺字段 | 清单少写 `name` 或 `api`（`01` §3.1 四个必填） |
| `E_API_MISMATCH` | `api` 写成 `"2"`，而宿主支持 `"1"` |
| `E_NAMESPACE_VIOLATION` | 方法名写成 `ping` 而不是 `demo-a.ping` |
| 装载成功但 `call` 找不到方法 | 注册写在 activate 之后，或注册失败但没检查返回值 |
| Windows 上装载报「不是有效的 Win32 程序」 | 插件与宿主位数不一致（x64 对 arm64） |
| 崩溃在 `register_method` 里 | 传进去的 `ctx` 不是宿主给的，或用了别的插件的 `ctx` |

最后一条对应 `02` §2.4：`ctx` 不能自己造，也不能拿别人的。`context_alloc` 只返回本次激活注入的那个句柄，插件自己保存、原样回传。
