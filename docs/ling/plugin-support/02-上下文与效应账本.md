# ling plugin-support/02 上下文与效应账本

> 状态：已定稿 | 最后更新：2026-11-03
> 依据：`docs/ling/main/04-详细设计/05-上下文与效应账本.md`

这一篇只讲插件作者要用的接口：`Context` 有哪些方法、哪些操作会被记账、撤销时宿主会做什么。条目结构、按激活代分段、容量与并发这些实现细节在 `docs/ling/main/04-详细设计/05-上下文与效应账本.md`。

## 1. `Context` 从哪来

`Context` 由内核在激活前创建，经函数表的 `context_alloc` 交给插件。插件拿到的是一个不透明句柄（`void* ctx`），只能保存和原样回传：

- 不能自己造，结构体不对外公开。
- 不能拿别人的 `ctx` 调方法，内核按 `ctx` 反查插件编号，越权返回 `E_CAPABILITY_DENIED`。
- 停用后再用同一个 `ctx` 调用，返回 `E_PLUGIN_MISSING`，也不会再写账本。

## 2. 方法表

| 方法 | 返回 | 产生账本条目 |
|---|---|---|
| `register_method(name, fn, undo_fn, requires_mask)` | 错误码 | 是 |
| `unregister_method(name)` | 错误码 | 是（撤销上面那条） |
| `subscribe(pattern, fn, undo_fn, out_sub_id)` | 错误码 | 是 |
| `unsubscribe(sub_id)` | 错误码 | 是（撤销上面那条） |
| `call(method, args, out)` | 错误码 | 否 |
| `emit(topic, payload)` | 错误码 | 否 |
| `write_config(key, value)` | 错误码 | 是 |
| `data_dir()` | 路径字符串 | 否 |
| `ledger()` | 只读视图 | 否 |
| `last_error(out_message, out_detail)` | 错误码 | 否 |

核心规则：**只有改共享状态的方法入账，调用与广播不入账。**

## 3. 哪些操作会被记账

| 类别 | 什么时候产生 | 撤销时谁做 |
|---|---|---|
| 方法注册 | `register_method` 成功 | 宿主从路由表删条目 |
| 事件订阅 | `subscribe` 成功 | 宿主从订阅表删 `sub_id` |
| 配置写入 | `write_config` 成功 | 宿主调 core-settings 恢复旧值；原本不存在则删键 |
| 侧车启动 | 侧车进程起来 | 宿主结束进程 |
| 停用回调 | 插件登记 `on_deactivate` | 插件自己的回调 |

线程与文件句柄不单独入账：它们随进程或动态库的生命周期结束，宿主无法代为管理。插件要在 `on_deactivate` 里自己停线程、关句柄。

## 4. 撤销规则

- 按登记顺序的倒序执行：后建立的先拆除。
- 某一条撤销失败时，记 `E_UNDO_FAILED`，继续撤其余条目；全部结束后返回 `E_UNINSTALL_INCOMPLETE`，`detail` 列出没撤掉的条目。
- 同一条目重复撤销是安全的：已完成的直接返回成功。
- 撤销期间 `ctx` 已失效，再登记新效应会被拒绝。

| 操作 | 撤销范围 | 之后 |
|---|---|---|
| 停用 | 当前这一代的全部效应 | 数据文件保留，装载表保留 |
| 卸载 | 当前这一代的全部效应 | 删安装工件，默认保留 `data/` |
| 重载 | 先按停用撤销，新版本装好后开新一代 | 旧段丢弃，新段新建 |

## 5. 撤销函数怎么写

- 进程内插件：注册方法与订阅时一并交出 `undo_fn`，宿主在撤销时回调它。
- 侧车插件：跨进程交不出函数指针，只做语义声明，宿主代为注销方法与退订事件。
- 侧车插件仍要在收到 `deactivated` 后清理自己的线程、文件与子进程；宿主代撤的只是路由表与订阅表里的登记。

## 6. 数据目录与配置

- `data_dir()` 返回 `plugins/<编号>/data/` 的绝对路径，UTF-8 编码；内核保证目录在 `activate` 前已存在。
- 跨调用状态放 `data/` 下的文件；连接、句柄、线程只放内存，随激活创建、随停用释放。
- `write_config` 的键必须以 `<插件编号>.` 开头，否则返回 `E_NAMESPACE_VIOLATION`。写入前宿主会记下旧值，撤销时恢复；原本不存在则删键。
- 需要别的组件看到、或需要可撤销的，走配置；只属于自己的中间状态，走文件。

## 7. 命名空间与边界

| 对象 | 约束 | 违反时 |
|---|---|---|
| 方法名 | 以 `<编号>.` 开头 | `E_NAMESPACE_VIOLATION` |
| 事件主题 | 以 `<编号>.` 开头，`kernel.` 保留 | `E_NAMESPACE_VIOLATION` |
| 配置键 | 以 `<编号>.` 开头 | `E_NAMESPACE_VIOLATION` |
| 注销他人的方法 | 归属校验 | `E_CAPABILITY_DENIED` |

宿主不检测、也不还原插件绕开 `Context` 做的修改：直接写文件、改全局变量、起子进程、在 `data/` 之外建目录。ling 不是沙箱，插件是可信代码；宿主能做的是拒绝、记录、报告。

## 8. 常见错误

| 现象 | 原因 |
|---|---|
| 停用后调用返回 `E_PLUGIN_MISSING` | 用了旧的 `ctx`，或异步回调在停用后才触发 |
| 注册返回 `E_NAMESPACE_VIOLATION` | 方法名、主题或配置键没带 `<编号>.` 前缀 |
| 卸载后配置还在 | 写配置没走 `write_config`，而是直接改了文件 |
| 侧车卸载后线程还在 | 只在宿主侧注销了方法，没在 `deactivated` 里停自己的线程 |
| 以为 `call` 或 `emit` 会被撤销 | 这两类不是共享状态，不入账 |
