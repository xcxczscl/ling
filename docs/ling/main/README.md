# ling 主体文档导航

本目录是 ling **宿主自身**的设计文档，给宿主开发与维护者看。写插件看 [`../plugin-support/`](../plugin-support/)，内置插件看 [`../builtin-plugins/`](../builtin-plugins/)，用户操作看 [`12-用户手册.md`](12-用户手册.md)。

## 文档清单

| 文档 | 回答什么 |
|---|---|
| `00-总览与术语.md` | ling 是什么、边界在哪、名词什么意思 |
| `01-需求规格.md` | 宿主必须做到什么（127 条需求） |
| `02-技术选型.md` | 为什么选 C++、为什么这样搭技术栈 |
| `03-架构设计.md` | 分成哪几层、依赖方向、关键决策 |
| `04-详细设计/` | 内核四服务、依赖解析、热更新、管理端口的细节 |
| `05-构造与开发指南.md` | 代码放哪、怎么编、怎么测、怎么调试 |
| `06-安全设计.md` | 防什么、不防什么、信任边界 |
| `07-测试与验收.md` | 测什么、什么算通过 |
| `08-部署与发布.md` | 怎么打包、升级、回滚、卸载 |
| `09-运行时预案.md` | 出问题怎么办（一页处置表） |
| `10-路线图与里程碑.md` | 分几段做、每段什么标准 |
| `11-MVP 范围.md` | 最早能用的版本包含什么 |
| `12-用户手册.md` | 最终用户怎么装怎么用 |
| `M0-提审包.md` | 设计定稿评审材料（一次性） |

每份文档都有简版，在同目录 `brief/` 下，章节结构与详细版对应。

## 按你想做的事读

| 你想做 | 按这个顺序 |
|---|---|
| 第一次了解 ling | `00` → `03` §2 → 仓库根 `README.md` |
| 改宿主代码 | `03` §2（架构）→ `05` §2、§6（文件与类型落点）→ 对应 `04` 详细设计 |
| 排一个故障 | `09` §7 一页处置表 → 按现象找对应节 |
| 发布一版 | `08` §2、§3 → `05` §7 打包命令 |
| 看项目进度 | `10` §3 → 仓库 `docs/ling/log/` |

## 跨目录的事实索引

端口、路径、数量上限这些常查取值的唯一定义位置汇总在 `docs/common/03-常用取值速查.md`。改一个取值时，改那里的定义处，再回来更新索引。按问题找文档看 `docs/README.md`。

## 目录外还有什么

- `../builtin-plugins/`：五个内置插件的文档；共同规则与版本在 `docs/ling/README.md`。
- `../plugin-support/`：写插件的契约（清单、C ABI、Context、侧车、样板）。
- `../log/`：开发日志与决策记录（只增不改）。
- `../archive/`：版本归档，`main/<宿主版本>/` 与 `builtin-plugins/<插件名>/<插件版本>/`，说明见 `docs/ling/archive/README.md`。
- `../../common/`：跨项目公共文档（编写规范、术语、版本约定、导航）。
