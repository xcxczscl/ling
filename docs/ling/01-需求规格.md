## 1. 目的与范围

### 1.1 管什么

- 只写 ling 宿主（代号 `LING`）的需求。插件自身的功能需求归各插件文档，如 `docs/plugins/resources-manager/01-需求规格.md`（待编写）。
- 只写"必须做到什么"，不写"怎么做"。实现方案见 `docs/ling/03-架构设计.md` 与 `docs/ling/04-详细设计/`。
- 编号从 `LING-REQ-001` 起连续分配，全文唯一，不复用。需求作废时保留编号并标注"作废"，新需求取下一个号。后补需求追加在其所属组的末尾，不按编号插进中间，避免全表重排——所以 §4.3 末尾是 116、§4.4 末尾是 117 至 126。

### 1.2 不管什么

| 不做                | 归属                                     |
| ----------------- | -------------------------------------- |
| 用户界面、导航栏、设置页      | core-ui 与 core-settings 插件             |
| 配置存储、作业调度 | core-settings、core-job 两个内置插件 |
| 插件日志的收集与查询 | core-log 内置插件；内核自身日志由宿主内置，不依赖它（见 §4.4） |
| 具体业务功能（文件整理、内容播放） | resources-manager、player 插件            |
| 插件市场、在线分发、评分付费    | 非目标，见 `docs/ling/00-总览与术语.md` §2.3     |
| 进程内安全沙箱           | 非目标：插件是第一方代码；内存隔离只存在于侧车轨道              |
| 形式化验证             | 非目标：采纳论文的工程机制，不做数学演算                   |
| 多用户、账号体系、权限分级     | 非目标：单机、单用户                             |

### 1.3 与里程碑、MVP 的关系

本文只回答"必须有什么"，不标优先级，不标实现阶段。

先做哪些、MVP 包含哪些，由 `docs/ling/10-路线图与里程碑.md` 与 `docs/ling/11-MVP 范围.md` 决定。那两份文档从本文挑条目，反过来不改本文。

### 1.4 条目格式

每条需求四个字段：

| 字段   | 含义                                                        |
| ---- | --------------------------------------------------------- |
| 编号   | `LING-REQ-xxx`                                            |
| 需求   | 必须成立的行为，一句话说清                                             |
| 验收标准 | 能判真假的检查方式：观测值、测试文件、命令输出                                   |
| 平台   | `三平台` = 三个平台都要求；`W L` = Windows 与 Linux 要求，Android 见第 5 节 |

验收标准里的测试文件名为集成测试命名约定（`l1_*` 到 `l6_*`），具体用例在 `docs/ling/07-测试与验收.md` 展开。

数字型需求（第 4 节）一律写上限，不是平均值。测量前提写在 4.1 开头。

### 1.5 运行时目录与源码目录

需求里出现的路径分两类，不要混：

| 类别 | 例子 | 现在存在吗 | 谁创建 | 进版本库吗 |
|---|---|---|---|---|
| 源码目录 | `main/`、`plugins/`、`docs/` | 存在，代码目录为空 | 手工创建 | 是 |
| 运行时数据目录 | `<数据根>`、`plugins/<编号>/`、`data/`、`logs/` | **不存在**，首次运行才出现 | 宿主自己创建 | 否 |

`<数据根>` 是宿主存数据的地方：Windows 上是 `%APPDATA%\ling`，Linux 上是 `~/.local/share/ling`，Android 上是应用私有目录；取值与切换方式见 `docs/ling/03-架构设计.md` §6.3。

**需求里写的目录是「跑起来之后应该长什么样」，不是「仓库里已经建好的文件夹」。** 源码目录现在为空，是因为设计文档未定稿前不写代码。

## 3. 功能需求

### 3.1 装载与卸载

| 编号           | 需求                                                                     | 验收标准                                                                   | 平台  |
| ------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- | --- |
| LING-REQ-001 | 已安装插件从 `<数据根>/plugins/<编号>/` 读取，目录名必须与清单 `id` 完全一致                     | 目录名 `Foo` 与 id `foo` 不一致时装载被拒，返回 `E_MANIFEST_INVALID`；`l1_manifest` 断言 | 三平台 |
| LING-REQ-002 | 清单必填 `id`、`version`、`api`；缺任一项拒绝装载并指出缺哪项                               | 逐个删字段各跑一次，返回 `E_MANIFEST_INVALID` 且 message 含字段名                       | 三平台 |
| LING-REQ-003 | `id` 满足 `^[a-z0-9][a-z0-9-]*$` 且长度 ≤ 64，违反则拒绝装载                        | 表驱动四种非法输入（含大写、下划线、首字符短横线、65 字符）全部被拒                                    | 三平台 |
| LING-REQ-004 | `version` 为三段式 `主.次.修`，每段 0–65535，违反则拒绝装载；宿主只校验格式，不限制插件作者如何递增 | 输入 `1.0`、`1.0.0.0`、`70000.0.0` 三种写法全部被拒 | 三平台 |
| LING-REQ-005 | `api` 必须落在宿主支持范围（当前主版本及其前一版本）；不符拒绝装载并返回 `E_API_MISMATCH`，其他插件状态不变      | api=99 的插件装载失败时，同时在装的其他插件仍为 activated                                  | 三平台 |
| LING-REQ-006 | 清单出现绝对路径或 `..` 一律拒绝；`sidecar.executable` 必须位于插件目录内且可执行                 | 三种非法写法各一次，全部拒绝并返回 `E_MANIFEST_INVALID`                                 | 三平台 |
| LING-REQ-007 | 安装来源支持插件目录与 zip 包；安装时一律拷贝到 `plugins/<编号>/`，删除原位置不影响已装插件                | 从临时目录安装后删掉临时目录，`ling plugins` 仍显示 activated，调用其方法成功                    | 三平台 |
| LING-REQ-008 | 一个插件只能有一种产物：动态库或侧车；两者并存或都缺时拒绝装载                                        | 两种非法组合各一次，返回 `E_MANIFEST_INVALID`                                      | 三平台 |
| LING-REQ-009 | 安装已存在的编号时拒绝，并提示先卸载或升级                                                  | 连续两次安装同一插件，第二次返回错误且原插件状态不变                                             | 三平台 |
| LING-REQ-010 | 卸载默认移除安装工件（`plugin.toml`、动态库、侧车目录），保留 `data/`；`--purge` 连 `data/` 一起删除 | 卸载后目录只剩 `data/`；带 `--purge` 卸载后目录不存在                                   | 三平台 |
| LING-REQ-011 | "已安装"的判定依据是 `plugin.toml` 存在；只剩 `data/` 的目录视为未安装，可重装并沿用原数据             | 删掉 `plugin.toml` 后 `ling plugins` 不列出该插件；重装后读到的 data 内容与卸载前一致          | 三平台 |
| LING-REQ-012 | 卸载顺序固定：先停用依赖它的下游插件 → 调 `on_deactivate` → 账本倒序撤销 → 移出装载表 → 触发一次调和       | `l2_uninstall` 断言四类动作的先后顺序，以及账本序号严格递减                                  | 三平台 |
| LING-REQ-013 | 某条撤销失败时记录 `E_UNDO_FAILED`、继续执行其余条目，最后返回"卸载不完整 + 未撤销条目清单"               | 故障注入：让第 2 条撤销报错，最终报告含该条描述，且第 1、3 条已执行                                  | 三平台 |

### 3.2 调用路由与事件广播

| 编号           | 需求                                                                                                            | 验收标准                                                   | 平台  |
| ------------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | --- |
| LING-REQ-014 | 方法名必须带本插件编号前缀（`<编号>.` 开头），内核校验；未带前缀拒绝注册并返回 `E_NAMESPACE_VIOLATION`                                            | 注册 `scan.start` 被拒；注册 `demo-a.scan.start` 成功           | 三平台 |
| LING-REQ-015 | `call(plugin, method, args)` 按（编号，方法名）路由到目标插件；同进程插件之间为直接函数调用，不经过序列化                                           | `l1_bench_call` 测得 P95 ≤ 1 微秒（见 LING-REQ-089）          | 三平台 |
| LING-REQ-016 | 目标插件未安装或未激活返回 `E_PLUGIN_MISSING`；方法未注册返回 `E_METHOD_MISSING`；两者都不影响路由表中其他条目                                    | 两个用例分别断言错误码，随后调用其他插件方法仍成功                              | 三平台 |
| LING-REQ-017 | 同步调用默认超时 30 秒，超时返回 `E_TIMEOUT`；`call_async` 不设宿主超时，由调用方控制                                                     | 处理函数睡 31 秒时同步调用返回 `E_TIMEOUT`；异步调用在 31 秒后正常返回结果        | 三平台 |
| LING-REQ-018 | 事件订阅支持前缀通配：`demo-b.*` 匹配 `demo-b.scan.done`，`*` 匹配全部主题                                                        | 三种模式各订阅一次，广播后断言收到条数                                    | 三平台 |
| LING-REQ-019 | 广播主题必须以本插件编号开头；`kernel.` 前缀只允许内核使用；越权返回 `E_NAMESPACE_VIOLATION` 并记录一条越权记录                                     | demo-a 广播 `demo-b.x` 被拒，且记录中出现该条                       | 三平台 |
| LING-REQ-020 | 广播本身不产生效应记录；订阅产生一条 EventSubscribed 效应                                                                         | 广播 100 次后账本条目数不变；订阅 1 次后条目数加 1                         | 三平台 |
| LING-REQ-021 | 广播为同步派发：按订阅登记顺序逐个调用，不落盘、不重投；单个回调执行超过 5 秒则跳过该订阅者并记录，其他订阅者照常收到                                                  | 3 个订阅者中第 2 个睡 6 秒，断言第 1、3 个在 6 秒内收到，第 2 个留下一条超时记录      | 三平台 |
| LING-REQ-022 | 内核至少广播两类事件：`kernel.plugin.state`（activated / deactivated / uninstalled / failed / crashed）与 `kernel.plan.step`（调和每步一条） | 装一个插件后录制事件，断言 state 事件含 activated，且 plan.step 条数等于计划步数 | 三平台 |

### 3.3 能力门禁

| 编号           | 需求                                                                                          | 验收标准                                                   | 平台  |
| ------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------ | --- |
| LING-REQ-023 | 宿主维护固定能力集，首版为 `fs`、`network`、`ui`、`shell`；清单出现集合外取值时拒绝装载并返回 `E_CAPABILITY_UNKNOWN`，提示宿主版本过旧 | 清单写 `["gpu"]` 装载失败，message 含"宿主版本过旧"                   | 三平台 |
| LING-REQ-024 | 注册方法时可声明该方法的 `requires`，取值必须 ⊆ 本插件清单 `capabilities`，否则拒绝注册                                  | 清单只有 `fs`、方法声明 `network` 时注册失败，该方法不可调用                 | 三平台 |
| LING-REQ-025 | 调用瞬间核对目标插件的生效能力（清单声明 − 用户撤销黑名单）是否覆盖方法 `requires`，不覆盖返回 `E_CAPABILITY_DENIED`                | 撤销 demo-b 的 `fs` 后调用其 `fs` 方法，返回 `E_CAPABILITY_DENIED` | 三平台 |
| LING-REQ-026 | 用户撤销某能力后插件保持激活，只有依赖该能力的方法调用被拒；撤销状态持久化，重启后仍生效                                                | 撤销后重启宿主，`ling plugins` 显示该插件 activated，调用其依赖能力的方法仍被拒   | 三平台 |
| LING-REQ-027 | 能力门禁只判定"有没有资格"，不限制具体文件路径或网络地址                                                               | 声明 `fs` 的插件可读写任意用户可访问路径，宿主不产生拒绝记录                      | 三平台 |

### 3.4 上下文与效应账本

| LING-REQ-030 | `subscribe` 必须同时提交撤销函数，同样为必填参数，空函数拒绝注册 | 省略撤销参数编译失败；传空函数返回 `E_LEDGER_INVALID` | 三平台 |

| LING-REQ-033 | 账本不落盘；宿主启动时装载表从空开始，账本随插件激活重建                                            | 重启前后 `plugins/<编号>/` 下不出现账本文件                     | 三平台 |
| LING-REQ-034 | 插件只能读自己的账本用于调试；读不到其他插件的账本                                               | `ledger()` 条目数等于自身效应数；接口不提供按编号查询他人账本的入口           | 三平台 |

| LING-REQ-101 | 100 次连续 reload 后内存增长 | ≤ 50 MB；达到 30 MB 时 `doctor` 提示重启 | 私有副本方案每次重载留下一个映射，10 MB 达不到；50 MB 是"明显泄漏"的判定线，30 MB 处提前提示 | 前后 RSS 差值 |
| LING-REQ-102 | 管理端口并发连接 | 同时保持 32 条连接不拒绝 | 界面占 1–2 条，命令行每次 1 条；每条连接约 16 KB，32 条约 0.5 MB | 32 条连接各自执行一条命令 |

4.3 至 4.5 的数字是判定阈值，不是性能目标，依据：2 秒（侧车恢复）= 进程创建 50–200 毫秒的十倍余量；5%（24 小时内存增长）= 无泄漏时 RSS 波动通常低于 2%；30 秒（1000 次调用完成）= 每次 1 毫秒的 30 倍余量；20 毫秒（200 插件调和）= 建图与排序约 2 毫秒的十倍；30 秒（调用超时）= 人愿意为单次操作花的时间上限，超过即视为卡死；64 MB 与 7 天（日志）= 每天约 10 万行、每行 200 字节的 3 倍。
