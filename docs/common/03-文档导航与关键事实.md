# 文档导航与关键事实

> 状态：初定 | 最后更新：2026-10-29
> 性质：**索引，不是正文**

这份文档只有一个用途：**你想查一件事时，不用一份份翻，直接知道该看哪一节。**

它不解释设计理由，也不复制表格。每个格子只放「取值 + 唯一定义在哪」。正文与本文冲突时，以正文为准，并以修好正文为结果——本文跟着改。

> 本文不设简版。索引没有「详细论证」可压缩，做两版只会立刻互相漂移。规范里的例外条款见 `docs/common/00-文档编写规范.md` §4.6。

## 3. 关键事实

每张表的最后一列是**唯一定义位置**。要改一个值，改那里，再回来改本表。

### 3.1 地址与端口

| 项 | 取值 | 定义在哪 |
|---|---|---|
| 管理端口 | 默认 7900；被占用时在 7900 至 7999 内顺延 | `docs/ling/04-详细设计/06-管理端口与命令行.md` §2.2 |
| 管理端口绑定 | 只绑 `127.0.0.1`，不监听 `0.0.0.0` | 同上 §2.1 |
| 界面端口 | 从 8010 起选空闲端口，避开 7900 至 7999 整段 | `docs/ling/04-详细设计/07-内置插件.md` §3.2 |
| 侧车端点 | 动态选空闲回环端口，以 `tcp:127.0.0.1:<端口>` 经 `LING_SOCKET` 传给侧车 | `docs/ling/04-详细设计/02-插件装载与接口.md` §6.2 |

## 4. 十条常见误解

这些是读文档时最容易想反的地方。每条给「容易以为的」与「实际」。

| 容易以为 | 实际 | 出处 |
|---|---|---|
| 仓库里的 `data/` 是已经建好的目录 | `data/` 是运行期目录，首次启动才出现；仓库里 `main/`、`plugins/` 是空的 | `docs/ling/01-需求规格.md` §1.5 |
| 命令行能调任意插件的方法 | 只能调 `kernel.*` 方法；业务方法由插件之间调用，所以没有 `call` 子命令 | `docs/ling/04-详细设计/06-管理端口与命令行.md` §3.1 |
| 能力门禁是沙箱 | 只是审计与误用拦截：不管路径、不管频率，也拦不住绕过 `Context` 直接调系统 API | `docs/ling/06-安全设计.md` §4 |
| 卸载会把插件数据一起删掉 | 默认只删安装文件，`data/` 保留；加 `--purge` 才连数据删 | `docs/ling/01-需求规格.md` §3.1 |
| 热更新会卸载旧动态库 | 不卸载：复制到新文件名再加载，旧映射留在内存，因此重载次数多了会涨内存 | `docs/ling/04-详细设计/05-热更新.md` §2 |
| 侧车就是指 Python 插件 | 侧车指独立进程，C++ 也能写；`core-ui` 就是 C++ 侧车 | `docs/ling/03-架构设计.md` A-8 |
| 界面是宿主的一部分，界面崩了宿主也崩 | `core-ui` 是侧车，崩了只死自己，2 秒内重启 | `docs/ling/01-需求规格.md` 116 |
| 「单线程内核」意味着所有调用都排队 | 只有写串行；读走不可变快照，任意线程无锁读 | `docs/ling/03-架构设计.md` §5.3 |
| 插件版本由宿主按语义化版本管 | 宿主只校验三段式格式，不限制怎么递增 | `docs/common/02-版本号与兼容约定.md` §3 |
| MVP 不能升级宿主 | 能，手工替换二进制并重启；不含的只有侧车协议版本字段 | `docs/ling/11-MVP 范围.md` §4.1 |

## 6. 怎么知道一份文档是不是最新

三处一起看：

| 看什么 | 在哪 | 说明 |
|---|---|---|
| 状态 | 每份文档第 2 行 | 初定 / 已定稿；定稿前一律可改 |
| 最后更新 | 同一行 | 与变更记录末行一致 |
| 变更记录 | 每份文末 | 一行一次改动，写清改了什么、为什么 |

三处不一致时，以变更记录为准，并顺手修另外两处。
