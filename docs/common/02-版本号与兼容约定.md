# 02 版本号与兼容约定

> 状态：初定 | 最后更新：2026-10-28
> 适用范围：ling 宿主自身的版本、插件清单里的 `version` 与 `min_host`、内核与插件的兼容判定

本文定两件事：**版本号怎么递增**、**哪些东西能改、哪些改了就是破坏兼容**。

## 1 版本号格式

`大版本.首要版本.次版本`，发布前追加 `-bN`：

```
0.0.1-b3
│ │ │  └─ N：第几次构建，从 1 开始
│ │ └──── 次版本：功能变化
│ └────── 首要版本：阶段推进，由项目负责人决定
└──────── 大版本：几乎等于另一套软件
```

每段 0–65535，纯数字，不带前导零。`bN` 只在项目完成前出现，完成后去掉。

## 2 ling 宿主怎么递增

| 动作 | 版本变化 | 例子 |
|---|---|---|
| 修 bug | 只加 `bN` | `0.0.1-b3` → `0.0.1-b4` |
| 重新打包测试 | 只加 `bN` | `0.0.1-b4` → `0.0.1-b5` |
| 功能变化（新增或改动功能） | 次版本 +1，`bN` 归 1 | `0.0.1-b9` → `0.0.2-b1` |
| 阶段推进，含不兼容 | 首要版本 +1，由项目负责人决定 | `0.0.2-b5` → `0.1.0-b1` |
| 大改，接近另一套软件 | 大版本 +1，默认不兼容 | `0.1.0-b3` → `1.0.0-b1` |
| 项目完成 | 去掉 `-bN` | `0.1.0-b7` → `0.1.0` |

两条容易误解的地方，写清楚：

- **`bN` 是构建序号，不是 beta 版本**。修 bug 与纯重测都会让它加一，因为它记录的是「这个包被构建了几次」。
- **首要版本不由技术规则自动决定**，由项目负责人判断是否够一个阶段。次版本才按「有没有功能变化」机械递增。

## 3 插件的版本

宿主**只校验格式**，不限制插件作者如何递增，不强制语义。

| 项 | 规则 |
|---|---|
| 格式 | 三段式，每段 0–65535，与宿主同格式 |
| 递增方式 | 由插件作者自己决定，宿主不校验、不警告 |
| 用途 | 依赖匹配（`@1`、`@1.2`、`@1.2.3` 三种写法） |
| 格式非法 | 拒绝装载，返回 `E_MANIFEST_INVALID` |

不限制的理由：插件是自有的、数量有限，强制语义版本只会增加记账负担；真正决定能不能装的是 `api` 与 `min_host` 两个字段。

## 4 兼容判定：谁说了算

插件能否在一个宿主上运行，由两条独立规则共同决定，两条都满足才装得上：

| 规则 | 字段 | 判定 | 失败错误码 |
|---|---|---|---|
| 接口兼容 | 清单 `api` | 宿主支持 api 主版本 N 与其前一版 N-1 | `E_API_MISMATCH` |
| 宿主够新 | 清单 `min_host`（选填） | 当前宿主版本 ≥ `min_host`；不写视为不限制 | `E_HOST_TOO_OLD` |

两者的分工：`api` 管「接口长什么样」，`min_host` 管「宿主够不够新」。一个插件的接口没变、但依赖宿主新增的某个行为时，只升 `min_host`，不动 `api`。

## 5 什么能改，什么改了就破坏兼容

### 5.1 可以直接改，只升次版本

| 改动 | 为什么安全 |
|---|---|
| 新增方法、新增事件主题 | 旧插件不调用它，不受影响 |
| 新增清单可选字段 | 旧清单不写该字段时按默认值处理 |
| 新增能力取值 | 旧插件不声明它，不受影响 |
| 新增 `ling` 子命令 | 旧用法仍然有效 |
| 修改日志内容与格式（字段不变） | 日志不是接口 |

### 5.2 不加版本号也能改

| 改动 | 说明 |
|---|---|
| 修 bug | 只加 `bN` |
| 改内部实现、重构、改文档 | 外部行为不变 |
| 改 `data/` 之外的目录布局 | 运行时会重建 |

### 5.3 改了必须升 api 主版本

这些是插件能观察到的接口，改动会让已发布插件行为变化：

| 改动 | 后果 |
|---|---|
| 删除或重命名已发布的方法、事件主题 | 旧插件调用失败 |
| 改变已发布方法的参数或返回值语义 | 旧插件按旧语义写出错误数据 |
| 改变 `Context` 已有方法的签名或语义 | 旧插件编译不过或行为错 |
| 把可选清单字段改成必填 | 旧清单装载被拒 |
| 改变侧车 jsonl 帧的字段名或含义 | 旧侧车握手失败 |
| 改变管理端口的请求或应答结构 | 旧命令行无法连接 |

### 5.4 永远不能改的

| 项 | 原因 | 代价 |
|---|---|---|
| 已发布 api 主版本的接口语义 | 已发布插件依赖它 | 只能升 api 主版本 |
| `data/` 目录的格式 | 内核不替插件迁移数据（`LING-REQ-088`） | 要改格式只能由插件自己在启动时迁移 |
| 插件编号的含义 | 编号是依赖与目录名的依据 | 改编号等于换一个插件 |

## 6 兼容窗口

| 维度 | 承诺 |
|---|---|
| api 主版本 | 宿主同时支持 N 与 N-1，跨两个主版本不做兼容 |
| 宿主版本 | 不承诺向前兼容，插件用 `min_host` 自己声明下限 |
| 协议版本 | 侧车协议与管理端口协议都带版本字段，不匹配时只拒绝该连接或该插件，不影响其他插件 |
| 数据格式 | 跨宿主版本保持，升级不转换 `data/` |
