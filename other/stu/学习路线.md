# 学习路线

> 位置：`other/stu/`。这份文件是**个人学习用**，不属于项目设计文档。
>
> 它不编号、不做简版、不进评审流程，也不登记在 `docs/ling/00-总览与术语.md` 的文档地图里。
> `docs/` 里的规矩（编号、两种粒度、写-审-问-改）对它不适用。

## 1 这份文件解决什么

上一版失败不是因为代码写得差，是因为**没有判断对错的依据**——不懂 Rust，找不到问题，只能全权交给 AI。换语言把门槛降低了，但门槛降低不等于有了判断力。

所以这份文件只做一件事：把「跟着项目学」拆成有止境的阶段，每个阶段给出「读什么、要会什么、怎么算学会了」。学完一个阶段就打勾，不追进度，也不跳阶段。

## 2 起点

客观记录，用于判断哪一步可以省：

| 项 | 现状 | 影响 |
|---|---|---|
| Rust | 完全没学过 | 上一版读不懂的直接原因；新项目不用它，不必补 |
| C++ | 有基础，不算深 | 新项目的主语言；需要补的是「指针与对象生命周期」这类基本功 |
| 插件、动态库、ABI | 没接触过 | 这是本项目的核心概念，必须专门学，不能靠读代码悟 |
| 多平台构建 | 没接触过 | 阶段 5 再碰，现在不影响 |

**不必学会写 C++ 内核。** 目标是能读懂 300 行胶水代码、能判断「这段在做危险的事」、能自己写一个小插件。内核由 AI 写，你负责审。

## 3 三条学习原则

| 原则 | 做法 | 为什么 |
|---|---|---|
| 先问「为什么存在」，再看「怎么实现」 | 每个概念先回答「没有它会出现什么问题」，再去读代码或设计 | 直接读实现，记住的是写法；知道问题，记住的是目的 |
| 每阶段有可验证的产出 | 每个阶段末尾列了自检问题，能答上来才算过 | 没有验收就会产生「好像懂了」的错觉，和上一版一样 |
| 不懂就记，不硬啃 | 想不通的记进 §7，不打断当前阶段 | 一个词卡三天是最常见的放弃方式 |

### 阶段 0 说清这个项目是什么

- **读什么**：`docs/ling/00-总览与术语.md` 的 §1（是什么）、§2（定位与目标）、§5（术语表，只查不背）；`docs/ling/02-技术选型.md` 的 §1、§2、§3。
- **要会**：零内容边界是什么意思；为什么宿主不能有业务功能；两种插件形态的区别；为什么可读性是权重最高的维度。
- **不必会**：语言评分表的每一项细节、C# 与 Python 的排除理由。那些是决策依据，读结论就够。
- **自检**：
  1. 用三句话说明 ling 是什么，不用「插件」「宿主」以外的专有词
  2. 有人问「为什么不直接把功能写在主程序里」，能答上来
  3. 说明「进程内插件」和「侧车插件」各适合什么场景
  4. 说明上一版失败的四条原因里，哪两条换语言解决不了

### 阶段 1 宿主的七项职责与五个核心概念

- **读什么**：`docs/ling/01-需求规格.md` §3.1 装载与卸载、§3.2 路由与事件、§3.3 能力门禁、§3.4 上下文与账本。
- **要会**：清单是什么；方法名为什么必须带插件编号前缀；能力门禁在拦什么；`Context` 为什么必须由内核注入；账本为什么必须能倒着撤销。
- **不必会**：清单校验的正则、错误码的具体取值。那些是查表的事。
- **自检**：
  1. 说明「停用」和「卸载」的区别
  2. 说明为什么插件不能自己造一个 `Context`
  3. 一个插件卸载时，它注册过的方法、订阅过的事件会怎样
  4. 说明能力门禁只管「有没有资格」、不管「能碰哪些文件」的理由

### 阶段 2 插件怎么被装进来、怎么被调用

- **读什么**：`docs/ling/02-技术选型.md` §5（C ABI、唯一入口点、类型禁区、编译器一致性）；`docs/ling/01-需求规格.md` §3.2、§3.7。
- **要会**：动态库是什么；为什么跨动态库不能直接传 C++ 的对象；函数指针表怎么顶替「对象」；为什么整个系统只有一个跨边界函数；侧车为什么用 JSON 传消息。
- **不必会**：`dlopen` 的返回值细节、句柄管理的写法。
- **自检**：
  1. 说明为什么插件和宿主必须用同一个编译器、同一个 `/MD` 选项
  2. 说明为什么 `std::string` 不能直接跨动态库传
  3. 说明侧车插件为什么不需要关心 ABI
  4. 一次调用的开销在进程内轨道和侧车轨道上差多少，这个差距在什么场景下重要

### 阶段 3 依赖与调和

- **读什么**：`docs/ling/01-需求规格.md` §3.5。
- **要会**：依赖图是什么；拓扑序为什么能保证「被依赖的先启动」；三态判定（该激活、该停用、不动）；成环为什么必须拒绝；为什么整次要能回滚。
- **不必会**：版本约束的四种写法的全部组合。
- **自检**：
  1. 装一个被别的插件依赖的插件时，会牵连哪几个插件
  2. 说明「成环就拒绝安装」而不是「挑一个先装」的理由
  3. 说明为什么连续操作要合并成一次调和

### 阶段 4 架构与模块划分

- **读什么**：`docs/ling/03-架构设计.md`（未编写）。
- **要会**：四个内核服务各管什么、边界在哪；进程与线程怎么分；哪些状态在内存、哪些落盘。
- **自检**：给定一个新功能需求，能说出它该落在内核、内置插件还是业务插件。

### 阶段 5 动手

- **读什么**：`docs/ling/05-构造与开发指南.md`、`docs/ling/12-用户手册.md`（均未编写）。
- **要会**：怎么编译、怎么装、怎么看日志、怎么改一行代码再重载。
- **自检**：能独立完成「写一个只提供 `hello.ping` 方法的插件、装上、调用成功」这一整套流程。

## 5 概念分级

同一个词在不同阶段的重要性差别很大，混在一起学会被劝退。按下面分级安排精力。

| 级别 | 概念 | 什么时候必须懂 |
|---|---|---|
| 现在必须懂 | 进程、动态库、函数调用与跨库调用、回调、撤销 | 阶段 0–1 |
| 阶段 2 必须懂 | ABI、C ABI、函数指针表、不透明句柄、编译器运行时一致性 | 阶段 2 |
| 阶段 3 必须懂 | 有向图、拓扑排序、环、原子回滚 | 阶段 3 |
| 只需知道名字 | RAII、虚表、SEH、GIL、AOT、JIT、GC | 读到相关文档时查一次即可，不背 |

「只需知道名字」里最容易被过度投入的是 RAII 和 GIL：前者在「不耍花招」写法里已经限定了用法，后者只影响纯 Python 侧车能不能并行，与你要读的代码无关。
