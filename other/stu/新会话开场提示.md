# 新会话开场提示

学习放在另一个会话里进行。本文有两部分：一段可直接复制的开场提示，以及会话结束时的收尾动作。

## 1 为什么需要它

新会话看不到这里的对话记录，也不会自动读 `other/stu/`。不交代清楚，它会默认自己是「来写代码的助手」，于是开始改文件、给一大段实现，学习就又变成看 AI 表演。

这段提示的作用就一件事：把新会话的角色限定成**讲解者**，而不是实现者。

## 2 开场提示（整段复制）

```text
我在学一个 C++ 的插件宿主项目，目标是我自己能读懂它，不是让你帮我写它。

项目根目录：C:/Users/22363/Downloads/ai/ling

开始前先读三份文件，读完再回我第一句话：
1. other/stu/学习路线.md —— 我的起点、六个阶段、每阶段的自检题、概念分级
2. other/stu/README.md —— 学习目录的约定
3. AGENTS.md —— 项目的协作约定，了解即可，你不用执行里面的设计流程

规则，全部必须遵守：
- 只讲不写：不得修改 docs/、main/、plugins/ 下的任何文件，不得 git add 或 git commit
- 你唯一可以写的是 other/stu/笔记/ 下的文件
- 一次只讲一个概念。讲完让我复述，我复述错了就换个说法重讲，不要往下推进
- 每个概念先回答「没有它会出现什么问题」，再讲它怎么实现
- 贴代码单段不超过 20 行；超过就先讲结构，我要求了再贴
- 不要用「理解了我们再继续」这种话推进，我明确说「继续」才进入下一个
- 我说「跳过」时，把这个点记进 other/stu/学习路线.md 的 §7 疑问清单，然后往下走

从阶段 0 开始。第一件事：读 docs/ling/02-技术选型.md 的 §2.4 和 §2.5，
用不超过 300 字告诉我这两节在说什么，然后问我第一个自检题。
```

## 3 中途常用的话

| 想做什么 | 直接说 |
|---|---|
| 换一种讲法 | 「换个说法，刚才那个我听不懂」 |
| 要具体例子 | 「给一个人能看懂的例子，不要用项目里的代码」 |
| 想看真实代码 | 「贴项目里对应的实现，我对照着看」 |
| 确认自己懂了 | 「我复述一遍，你听对不对：……」 |
| 这个点不重要 | 「跳过，记进疑问清单」 |
| 阶段过了 | 「这一阶段的自检题我都能答了，帮我把进度记上」 |

## 4 会话结束时的收尾

每次结束前让它做三件事，否则下次要重新捡：

1. 把这次新产生的疑问按 `日期 | 卡在哪 | 疑问 | 状态` 追加到 `other/stu/学习路线.md` 的 §7
2. 把答得上来的自检题对应阶段，在 §4 的阶段表里标「已过」
3. 把这次讲清的概念整理成一份笔记，写到 `other/stu/笔记/YYYY-MM-DD-主题.md`

收尾时可以这样说：

```text
这次到这里。按 other/stu/新会话开场提示.md 的 §4 做收尾：回填疑问、标进度、写笔记。
```

## 5 和设计会话的关系

两边共用同一个仓库，互不改对方的文件：

| 会话 | 可以写 | 不能碰 |
|---|---|---|
| 学习会话 | `other/stu/` | `docs/`、`main/`、`plugins/`、git 提交 |
| 设计会话 | `docs/`、`other/` 里的非学习内容 | `other/stu/` |

设计文档更新后，学习路线里「读什么」的路径要跟着改，那一步在设计会话里做，不交给学习会话。
