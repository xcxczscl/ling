## 1. 这套文档是什么、怎么读

本项目叫 **player**（中文名：内容执行器插件），是跑在 [ling 宿主](../../ling/README.md) 上的一个**业务插件**。它把 [resources-manager](../../resources-manager/README.md) 登记的内容（视频、音频、图片、PDF、应用程序……）**用起来**——播放、查看、运行，必要时把画面串流到局域网里的另一台设备。

**它不是文件管理器。** 归纳、整理、分类、去重、备份、同步都是 resources-manager 的职责；player 只负责「拿来内容字节 → 变成画面/声音/进程 → 送到某个输出端」。

**本项目共 2 份文档**（设计阶段；编码后随里程碑增补 02/03/04）：

| 顺序 | 文档 | 回答什么问题 | 什么时候读 |

| ① | `00-总览与术语`（本文） | 名词解释、现在做到哪了 | 先读；之后随时查术语 |
| ② | `01-总体设计` | 项目解决什么、为什么这么设计、各部分怎么配合、分几步做完 | 立项与评审时通读 |

## 2. player 是什么（一句话 + 边界）

**一句话**：player 是内容执行器——从 resources-manager 要字节，解码成画面/声音，送到本机屏幕或局域网另一台设备。

**它做什么**：

| 能力 | 白话 | 举例 |
|---|---|---|
| 音视频播放 | 解码视频/音频文件，输出到屏幕和扬声器 | 看《深空旅人》4K 版 |
| 图片/PDF 查看 | 只读展示图片和文档 | 翻看旅行照片、阅读说明书 PDF |
| 程序运行 | 在沙箱里启动 exe/apk，显示其窗口 | 运行一个游戏安装包 |
| 串流输出 | 把画面/声音送到局域网另一台设备 | 把 PC 上正在播的电影推到客厅电视 |

**它不做什么（硬边界）**：

| 不做 | 归谁 | 说明 |
|---|---|---|
| 扫描、去重、备份、同步 | resources-manager | player 是纯消费方 |
| 插件加载、依赖解析、热更新 | ling | player 只是普通插件 |
| 文件传输本身 | resources-manager 的流接口 | player 只是流 URL 的 HTTP 客户端 |

## 3. 贯穿示例（全文档统一使用）

后面所有章节、所有示例数据，都基于这一个场景：

**用户**：一位拥有多台设备的个人用户（下文直接称"用户"）。

> 示例中的作品名（《深空旅人》《旧港疑云》）**均为虚构**，仅作演示，不影射任何真实作品。

**三台设备**：

| 设备 | 系统 | 在 player 里的角色 |
|---|---|---|
| 台式机 | Linux | 播放源（有 4K 显示器 + 环绕声） |
| 客厅电视盒子 | Android（lite 接收器） | 接收端（只有解码 + 显示，无完整 player） |
| 笔记本 | Windows | 完整 player（既能本地播，也能被远程执行画面） |

**贯穿场景**：

1. 用户在台式机上用 player 打开《深空旅人》4K 版（rm 已登记，`asset_type=video`）。
2. 台式机解码播放，画面出现在 4K 显示器上，比例正确（21:9 电影在 16:9 屏上左右留黑边，无裁切）。
3. 用户想在客厅电视上看，但电视解码器不认识这个 HEVC 文件 → player 自动选择「重编码推流」，电视盒子上的 lite 接收器收流解码显示。
4. 用户暂停，走到卧室笔记本打开同一内容 → 从暂停点继续（会话接力）。
5. 用户在笔记本上点「运行安装包」→ exe 实际跑在笔记本沙箱里，画面本机显示。

## 4. 名词表（按首次出现顺序）

### 4.1 基础名词

| 名词 | 白话定义 | 例子 | 它不是什么 |
|---|---|---|---|
| **插件（Plugin）** | 跑在 ling 宿主里的一个功能模块，用 `.so`/`.dll` 动态库加载 | player 本身、resources-manager 本身 | 不是独立可执行程序；不能脱离 ling 单独运行 |
| **宿主（Host / ling）** | 提供插件加载、方法路由、事件广播的「空壳」程序 | `ling` 二进制 | 不是业务程序；自己不做事 |
| **资源管理插件（resources-manager）** | 管文件清单、去重、备份、同步的插件；player 的数据来源 | rm 的 `stream.open` 接口 | 不负责播放 |
| **流交付接口（stream.open）** | rm 提供的方法：给一个 placement_id，返回带 token 的 HTTP URL，player 对该 URL 发请求拿字节 | `http://127.0.0.1:7913/s/st_xxx/token` | 不是文件路径；token 可收回 |
| **placement（放置）** | rm 里表示「某内容存放在某台设备的某个位置」的记录 | 《深空旅人》4K 版在台式机 `/data/media` 的一条放置记录 | 不是文件本身；是元数据 |

### 4.2 player 内部模块名词

| 名词 | 白话定义 | 例子 | 它不是什么 |
|---|---|---|---|
| **传输区（Source）** | 「从哪拿字节」。向 rm 要流 URL，然后发 HTTP 请求 | 视频 40 GB，Source 拿到 URL 后按需请求字节段 | 不是播放器；不负责解码 |
| **功能区（Capability）** | 「能把字节变成什么」。解码视频成画面帧、把图片渲染成位图、把 exe 变成运行中的进程 | 音视频解码器、图片渲染器、PDF 渲染器、进程运行器 | 不负责决定画面送到哪 |
| **输出区（Sink）** | 「画面/声音送到哪」。本机屏幕、本机声卡、局域网另一台设备、电视投屏协议 | 本机 Sink = 直接显示；网络 Sink = 编码后推给接收器 | 不负责解码 |
| **会话区（Session）** | 「当前播到哪了」。进度、音量、字幕轨、播放列表——跨设备接力的载体 | 书房 PC 看到 32:15 暂停，客厅电视从 32:15 继续 | 不是 rm 的内容元数据；是 player 自己的状态 |
| **发现区（Discovery）** | 「本机能干什么、对端有谁」。枚举本机解码器/显示器；枚局域网可接收设备 | 手机上列出「客厅电视」「书房 PC」作为可输出目标 | 不是网络扫描器；只发现已配对/已知设备 |

### 4.3 串流与接收名词

| 名词 | 白话定义 | 例子 | 它不是什么 |
|---|---|---|---|
| **接收器（Receiver）** | 对端设备上「收流 + 解码 + 显示」的轻量程序 | 旧电视盒子上的 lite player，打开就等投屏 | 不是完整 player；没有传输区/运行区 |
| **lite 接收器** | 同一 player 代码库的裁剪构建，只含输出区 + 解码器 | 电视盒子装的构建 | 不是独立项目；是 player 的一种构建目标 |
| **字节转发（模式 A）** | 原文件字节直接给对端，对端自己解码播放 | 电影是 H.264，电视支持硬解 → 直接把 rm 流 URL 转给电视 | 不涉及重编码 |
| **重编码（模式 B）** | 本机解码成帧 → 重新编码（如 H.264）→ 传输 | Windows 程序画面必须先渲染再编码才能给手机 | 不是简单转发字节 |
| **帧流（模式 C）** | 解码帧经轻量压缩（如 JPEG）直接推，延迟最低 | 远程桌面、看文档 | 带宽占用大 |
| **屏幕镜像（模式 D）** | 捕获本机屏幕 + 硬件编码，系统级协议 | AirPlay / Miracast / Moonlight | 需要系统权限或专有协议 |
| **远程执行** | 程序实际跑在局域网另一台机器上，画面串流回来 | Android 上点「运行 setup.exe」→ 实际跑在书房 Windows → 画面投到手机 | 不是本地虚拟机；不是翻译层 |

### 4.4 其他名词

| 名词 | 白话定义 | 例子 | 它不是什么 |
|---|---|---|---|
| **沙箱（Sandbox）** | 运行任意代码时的隔离环境：独立目录、限制网络、限制文件访问 | 运行 exe 时，它只能看到沙箱目录，不能读整个硬盘 | 不是虚拟机；是进程级隔离 |
| **四边黑边** | 画面比例不匹配时，上下左右同时出现黑边（错误显示） | 21:9 电影在 16:9 屏上如果既缩放又居中，就会四边黑边 | 正确做法是只留左右黑边（pillarbox）或上下黑边（letterbox） |
| **pillarbox** | 画面比屏幕宽时，左右留黑边 | 宽银幕电影在普通屏幕上 | 不是裁切 |
| **letterbox** | 画面比屏幕高时，上下留黑边 | 竖版视频在横屏上 | 不是拉伸 |
| **会话接力（Handoff）** | 在 A 设备暂停，到 B 设备从同一点继续 | 书房 PC 看到 32:15，客厅电视继续从 32:15 | 不是文件同步；只是状态同步 |
