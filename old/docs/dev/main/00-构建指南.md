# 00 构建指南

> 本文档只讲 **main 宿主 + 内置插件** 的构建。player 和 resources-manager 各有自己的构建脚本，分别在它们各自的开发手册里说明。

---

## 1. Rust 工具链准备

| 项 | 要求 |
|---|---|
| Rust 版本 | stable，edition 2021（当前 1.85+ 可） |
| 安装方式 | `rustup`（https://rustup.rs） |
| Windows 构建目标 | **MSVC 工具链**（默认 `x86_64-pc-windows-msvc`，GNU 工具链在 sqlite3 上有已知问题） |
| Linux 构建目标 | `x86_64-unknown-linux-musl`（静态链接，便于分发） |

验证安装：

```powershell
cargo --version
rustc --version
rustup target list --installed
```

Windows 需额外安装 MSVC 工具链（Visual Studio 安装器里的 "C++ 桌面开发" 工作负载，或 `rustup target add x86_64-pc-windows-msvc`）。

## 2. 工作区结构

### 2.1 main 的 Cargo workspace

```
main/
├── Cargo.toml                     # workspace 根（resolver=2）
├── crates/
│   ├── ling-sdk/                  # 插件开发套件（插件唯一依赖的 crate）
│   ├── ling-kernel/               # 宿主内核
│   └── ling-cli/                  # ling 命令行入口
└── builtin-plugins/               # 内置插件（从属关系，不在 workspace 成员里！）
    ├── core-ui/
    ├── core-settings/
    ├── core-plugin-manager/
    ├── core-job/
    └── core-log/
```

**注意**：内置插件有自己独立的 `Cargo.toml`（因为它们是独立的 cdylib），不跟 main 的 workspace 合并。但它们都依赖同一个 `ling-sdk` crate。

### 2.2 编译产物统一输出到 run/

所有项目的 `.cargo/config.toml` 都设置了 `target-dir` 指向 `run/target/<项目名>`，源码目录不会生成 `target/`：

```toml
# main/.cargo/config.toml
[build]
target-dir = "../run/target/ling"
```

### 2.3 统一构建脚本

`run/build.ps1` 是整个项目的一键构建入口，支持参数：

```powershell
# 构建全部（默认本机目标）
powershell -File run\build.ps1

# 只构建 main + resources-manager
powershell -File run\build.ps1 -Only host

# 只构建 player
powershell -File run\build.ps1 -Only player

# 指定目标平台交叉编译
powershell -File run\build.ps1 -Target linux

# 清理后重建
powershell -File run\build.ps1 -Clean
```

脚本会自动把构建产物拷贝到 `run/dist/<triple>/`，形成可分发的目录：

```
run/dist/windows-x86_64-msvc/
├── ling.exe                        ← 命令行入口
├── rmgr.exe                        ← resources-manager 独立 CLI
├── core-ui/core-ui.dll
├── core-ui/plugin.toml
├── core-settings/core-settings.dll
├── core-settings/plugin.toml
├── ... (其他内置插件)
├── player/player.dll
├── player/mpv-2.dll                ← player 依赖的 MPV 动态库
├── player/plugin.toml
├── resources-manager/resources-manager.dll
└── resources-manager/plugin.toml
```

## 3. 单独构建 main

### 3.1 只构建内核 + CLI + SDK

```powershell
cd main
cargo build                          # debug
cargo build --release                # release
cargo build --release -p ling-cli    # 只构建 CLI（会连带 kernel 和 SDK）
```

产物位置：`run/target/ling/{debug,release}/ling.exe`

### 3.2 构建内置插件

内置插件是独立的 cdylib，需要单独构建：

```powershell
cd plugins/builtin-plugins/core-ui
cargo build --release
# 产物：run/target/ling/release/libcore_ui.dll → 复制到 dist/core-ui/core-ui.dll
```

所有五个内置插件都要这样构建。`build.ps1` 会自动处理复制。

### 3.3 构建 demo 插件（可选）

```powershell
cd plugins/demo/demo-a
cargo build --release
```

demo-a 和 demo-b 主要用于集成测试（L1-L6 的测试代码会在运行时装载它们），正常使用不需要。

## 4. 运行与测试

### 4.1 启动宿主

```powershell
# 方式一：cargo run
cargo run -p ling-cli -- serve

# 方式二：用编译好的 exe
run\dist\windows-x86_64-msvc\ling.exe serve

# 指定内置插件目录
ling serve --builtin-dir D:\my-builtin

# 自定义数据目录
$env:LING_HOME = "D:\ling-data"; ling serve
```

启动后会显示：

```
ling 已启动：管理端口 127.0.0.1:7900
内置插件目录：C:\...\run\dist\windows-x86_64-msvc
数据根目录：C:\Users\...\AppData\Local\ling
首启自动安装内置三件套... 完成
```

### 4.2 CLI 命令

所有除 `serve` 外的命令都需要宿主已经在运行（连管理端口 7900）：

```powershell
ling plugins                    # 列出所有插件
ling install D:\my-plugin       # 安装新插件
ling uninstall demo-a           # 卸载（保留数据）
ling uninstall demo-a --purge   # 卸载（删除数据）
ling disable core-job           # 停用
ling enable core-job            # 启用
ling reload core-ui             # 热更新
ling logs core-ui 100           # 读日志（需 core-log）
ling shutdown                   # 停止宿主
```

### 4.3 运行测试

```powershell
cd main

# 全部测试
cargo test

# 只跑内核集成测试（L1-L6）
cargo test -p ling-kernel

# 只跑 CLI 端到端测试
cargo test -p ling-cli

# 只跑某个里程碑的测试
cargo test -p ling-kernel l1_
cargo test -p ling-kernel l3_
```

里程碑与测试文件的对应关系：

| 里程碑 | 测试文件 | 覆盖内容 |
|---|---|---|
| L1 | `l1_acceptance.rs` | 安装、路由、事件、门禁、命名空间（5 条） |
| L2 | `l2_uninstall.rs` | 卸载干净还原（4 条 + 故障注入） |
| L3 | `l3_reconcile.rs` | 依赖图、调和、自动激活/停用（6 条） |
| L4 | `l4_reload.rs` | 热更新、回滚（5 条） |
| L5 | `l5_builtin.rs` | 内置插件默认安装、界面贡献（6 条） |
| L6 | `l6_sidecar.rs` | 侧车插件双轨、崩溃隔离（4 条） |

## 5. Windows vs Linux 差异

| 方面 | Windows (MSVC) | Linux (musl) |
|---|---|---|
| 动态库后缀 | `.dll` | `.so`（前缀 `lib`） |
| 链接工具链 | MSVC 的 `lib.exe` | GNU `ld` |
| sqlite3 | 用 bundled feature 直接编译 | 同 |
| 进程管理 | `tasklist` / `taskkill`（降级方案） | Landlock + seccomp（原生沙箱） |
| 文件权限 | NTFS 权限，无 unix 权限位 | unix 权限（0600 等） |
| 管理端口 | `127.0.0.1:7900`（同样） | 同样 |
| 测试 | 全部通过 | 全部通过（沙箱功能更完整） |

## 6. 常见构建问题

### Q: Windows 上 MSVC 链接 sqlite3 报段错误？
A: 本项目 `.cargo/config.toml` 已强制 MSVC 工具链。如果你手动用 GNU 工具链（`x86_64-pc-windows-gnu`），会撞上 sqlite3 已知问题。保持默认即可。

### Q: 内置插件的 dll 找不到？
A: 确认已经 `cargo build --release` 每个内置插件。kernel 启动时会从 `target/release/lib<编号下划线化>.dll` 查找，缺失会被静默跳过。可以检查 `run/target/ling/release/` 下有没有对应文件。

### Q: `libloading::Error` 找不到 ling_plugin_create 符号？
A: 插件的 `Cargo.toml` 必须是 `crate-type = ["cdylib"]`，且插件的 `src/lib.rs` 必须导出 `ling_plugin_create`：
```rust
#[no_mangle]
pub extern "C" fn ling_plugin_create() -> *mut dyn Plugin {
    Box::into_raw(Box::new(MyPlugin))
}
```

### Q: serve 启动后报"管理端口 7900 被占用"？
A: 端口占用会自动顺延到下一个可用端口（7901、7902...），以启动输出为准。也可以改 registry.json 手动指定。
