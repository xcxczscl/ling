# 04 扩展与调试

> 本文档回答：**怎么写一个新插件、怎么让它跑起来、遇到问题怎么排查**。

---

## 1. 从零写一个新插件（step by step）

### Step 1：创建目录

```
plugins/my-plugin/
├── Cargo.toml
├── src/
│   └── lib.rs
└── plugin.toml
```

### Step 2：写 Cargo.toml

```toml
[package]
name = "my-plugin"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
ling-sdk = { path = "../../main/crates/ling-sdk" }
serde_json = "1"
```

### Step 3：写 plugin.toml

```toml
[plugin]
id = "my-plugin"
name = "我的插件"
version = "0.1.0"
api = "1"

[requires]
capabilities = ["ui"]
plugins = ["core-ui@1"]
```

### Step 4：写 src/lib.rs

参考 [02-SDK与插件API参考](02-SDK与插件API参考.md) §1 的最小模板。关键点：

1. `Plugin` trait 三个方法：`id()` / `activate()` / `deactivate()`
2. `activate` 里所有注册经 `ctx`，**必须同时提供撤销闭包**
3. 导出 `ling_plugin_create` 函数（`#[no_mangle] pub extern "C"`）

### Step 5：构建

```powershell
cd plugins/my-plugin
cargo build --release
# 产物：target/release/libmy_plugin.dll
```

### Step 6：安装到 ling

```powershell
# 方式一：直接拷贝
mkdir "$env:LING_HOME\plugins\my-plugin"
copy target\release\libmy_plugin.dll "$env:LING_HOME\plugins\my-plugin\my-plugin.dll"
copy plugin.toml "$env:LING_HOME\plugins\my-plugin\"

# 方式二：用 ling 命令（需要宿主已运行）
ling install plugins/my-plugin
```

### Step 7：调和与激活

安装后宿主自动触发调和：
- 如果 `my-plugin` 的依赖（`core-ui@1`）已装 → **自动激活**
- 如果依赖未装 → 保持"未激活"，依赖装上后自动激活

查看状态：

```powershell
ling plugins
# my-plugin  activated
```

调用方法：

```powershell
# 通过界面 /rpc 网关
curl -X POST http://127.0.0.1:7910/rpc ^
  -H "X-Ling-Token: $(Get-Content $env:LING_HOME\session.json | ConvertFrom-Json).token" ^
  -d "{\"id\":\"1\",\"plugin\":\"my-plugin\",\"method\":\"my-plugin.hello\",\"params\":{}}"
```

或者写一个 demo（参考 demo-a/demo-b）来测试。

## 2. 插件开发常见模式

### 2.1 注册方法同时记账

```rust
ctx.register_method(
    "my-plugin.do_something",
    |args| {
        // 处理业务逻辑
        Ok(json!({"result": "done"}))
    },
    || {
        // 撤销闭包：清理插件私有状态
        // 内核会先从方法表移除这个方法，然后调用这个闭包
    },
    Some(Capability::Fs),  // 需要文件系统能力
).map_err(|e| ActivateError::new(e.message()))?;
```

### 2.2 订阅事件后调其他插件

```rust
// 订阅 core-job 的进度事件
ctx.subscribe(
    "core-job.progress",
    |payload| {
        // 拿到 JSON Value，解析需要的字段
        let job_id = payload.get("job_id").and_then(|v| v.as_u64());
        println!("job {:?} progress: {:?}", job_id, payload);
    },
    || { /* 撤销 */ },
)?;
```

### 2.3 贡献界面到 core-ui

```rust
// activate 里
ctx.call(
    "core-ui",
    "ui.contribute",
    json!({
        "plugin": "my-plugin",
        "type": "page",
        "path": "/my-plugin",
        "title": "我的插件",
        "icon": "✨",
        "asset_dir": ctx.data_dir().join("assets").to_string_lossy(),
    }),
)?;
```

**注意**：贡献的撤下**不需要**你自己管。core-ui 订阅了 `kernel.plugin.state`，插件停用时会自动撤回。

### 2.4 用 data_dir 存持久状态

```rust
use std::fs;
use std::path::PathBuf;

let db_path = ctx.data_dir().join("data.db");
let data_root: PathBuf = ctx.data_dir();

fn save_state(ctx: &Context, state: &State) {
    let json = serde_json::to_string(state).unwrap();
    fs::write(ctx.data_dir().join("state.json"), json).unwrap();
}

fn load_state(ctx: &Context) -> Option<State> {
    let bytes = fs::read(ctx.data_dir().join("state.json")).ok()?;
    serde_json::from_slice(&bytes).ok()
}
```

**纪律**：**所有持久状态放 data_dir**。热更新会丢弃旧动态库的全部内存，所以不要让"重启还要重新初始化的东西"只在内存里。

## 3. 调试方法

### 3.1 看日志

如果装了 core-log：

```powershell
ling logs my-plugin 100        # 最近 100 条
ling logs core-ui               # 全部
```

如果没装 core-log，看 stderr 输出（`ling serve` 前台运行时直接打印到控制台）。

### 3.2 看插件状态

```powershell
ling plugins
# 输出：
# core-ui              activated
# core-settings        activated
# my-plugin            pending (依赖未满足: core-ui)
```

状态含义：

| 状态 | 含义 | 怎么变 |
|---|---|---|
| `installed` | 已拷贝到 plugins/ 目录，但还没装载 | `ling install` 后 |
| `pending` | 依赖未满足，等待中 | 调和时依赖不齐 |
| `activated` | 已装载且已激活 | 调和时依赖齐 + activate 成功 |
| `deactivated` | 被用户停用 | `ling disable` |
| `crashed` | 侧车崩溃 | 侧车连接断开 |

### 3.3 看账本

在插件代码里临时加：

```rust
// activate 结束前
println!("my ledger: {:#?}", ctx.ledger());
```

### 3.4 直接 curl /rpc 测试

```powershell
# 认证
$token = (Get-Content "$env:LING_HOME\session.json" | ConvertFrom-Json).token

# 调用
curl -s -X POST http://127.0.0.1:7910/rpc `
  -H "X-Ling-Token: $token" `
  -H "Content-Type: application/json" `
  -d "{\"id\":\"1\",\"plugin\":\"core-ui\",\"method\":\"core-ui.ui.list\",\"params\":{}}"
```

### 3.5 跑集成测试看流程

```powershell
cd main
cargo test -p ling-kernel l1_
# 或具体某条测试
cargo test -p ling-kernel test_l1_broker_router
```

### 3.6 用 demo-a/demo-b 试验

demo-a 和 demo-b 是最完整的示例：

| demo-a 方法 | 说明 |
|---|---|
| `demo-a.ping` | 返回 `{"pong": true}` |
| `demo-a.echo` | `{"msg": "..."}` → `{"echo": "..."}` |
| `demo-a.forward` | 转发调用：`{"plugin":"demo-b","method":"demo-b.add","args":{...}}` |
| `demo-a.probe` | 命名空间/能力探针 |

| demo-b 方法 | 说明 |
|---|---|
| `demo-b.add` | `{"a":1,"b":2}` → `{"sum":3}` |
| `demo-b.dup.delete` | 需要 `fs` 能力才能调用 |

## 4. 常见问题排查

### Q: 插件装了但显示"pending"？

依赖未满足。`ling plugins` 会告诉缺什么。装上依赖插件后自动调和激活。

### Q: `ling_plugin_create` 符号找不到？

1. 确认 `Cargo.toml` 里 `crate-type = ["cdylib"]`
2. 确认 `src/lib.rs` 里导出了 `#[no_mangle] pub extern "C" fn ling_plugin_create() -> *mut dyn Plugin`
3. 确认编译产物后缀对：Windows `.dll`、Linux `.so`（带 `lib` 前缀）

### Q: 插件 activate 失败？

看 stderr 输出。常见原因：
1. 清单版本号和 Plugin::id() 不一致 → 内核核对失败
2. api 字段 ≠ 1 → 装载拒绝
3. 撤销闭包 panic → 账本倒序撤销时某个 undo panic

### Q: 卸载插件后发现有残留？

1. 查 `ctx.ledger()` 看账本有没有全部撤销
2. 查违规效应：插件有没有绕过 ctx 直接 `std::fs::write` / `std::thread::spawn`
3. 卸载失败后 `ling plugins` 会显示"卸载不完整 + 清单"

### Q: 热更新后旧插件还在跑？

热更新流程：停旧版 → 装新版 → 激活新版。如果激活新版失败，会**自动回滚**到旧版，旧版继续服务。检查 stderr 里的 reload 日志确认。

### Q: 跨插件调用报 E_CAPABILITY_DENIED？

两种可能：
1. 调用目标插件的方法声明了 `requires: Some(Capability::X)`，但目标插件**当前生效能力**里没有 X（被用户撤销了）
2. 目标插件清单声明了 X，但用户在插件管理页撤销了

### Q: emit 报 E_NAMESPACE_VIOLATION？

你广播的事件主题没以自己插件编号开头。比如 `emit("scan.progress", ...)` → 错。应该 `emit("my-plugin.scan.progress", ...)`。

### Q: 找不到 core-ui.ui.contribute 方法？

core-ui 没装或没激活。先 `ling install core-ui` 并等它 activated。或者你的插件清单里应该写 `plugins = ["core-ui@1"]` 声明依赖。

## 5. 给内核（而非插件）贡献代码

### 5.1 改内核模块

`main/crates/ling-kernel/src/` 里每个文件职责单一，修改时：

1. **加新能力**：改 `ling-sdk/src/lib.rs` 的 `Capability` 枚举 + `manifest.rs` 的校验
2. **加新内核方法**：改 `admin.rs` 的 dispatch + `kernel.rs` 的公开 API
3. **加新事件主题**：在对应模块 emit，约定好前缀（`kernel.*`）

### 5.2 加新的集成测试

`main/crates/ling-kernel/tests/` 下每个里程碑一个文件，common/mod.rs 提供辅助函数。新测试函数命名 `test_Lx_描述`。

### 5.3 内核错误码

新增错误先在 `ling-sdk/src/lib.rs` 的 `codes` 模块加常量，再在 `ling-kernel/src/error.rs` 的 `KernelError` 加变体并映射 code()。
