# 01 内核模块详解

> 本文档按 **源码文件** 组织，每个文件讲清楚：**一句话做什么**、**关键结构体/枚举**、**公开 API**、**它依赖谁 / 谁依赖它**。
> 
> 架构层面的决策（为什么这样分文件）见 `docs/ling/01-宿主设计.md` §3。

---

## 总体依赖图

```
ling-cli ──→ Kernel ──→ Shared (状态中心)
                │          │
                │          ├── broker (路由)
                │          ├── bus (广播)
                │          ├── caps (门禁)
                │          ├── deps (依赖图)
                │          ├── sidecars (侧车句柄)
                │          └── violations (越权记录)
                │
                ├── loader (装载通道)
                ├── manifest (清单解析)
                ├── registry (registry.json 读写)
                ├── ledger (效应账本)
                ├── context (ContextCore 实现)
                ├── admin (管理端口)
                ├── builtin (内置插件目录发现)
                └── sidecar (侧车运行时)
```

**数据流向**：所有跨插件调用/事件/注册最终都落到 `Shared` 的几张大表上；`broker`/`bus`/`caps` 是读写这些表的"专职管家"；`loader`/`sidecar` 是代码装载通道；`admin` 是对外命令行通道。

## 1. kernel.rs — 内核门面

**一句话**：`Kernel` 类把 broker/bus/caps/deps/loader 等模块组织起来，对外暴露 install/uninstall/load/reload/call/emit 等公开 API。

```rust
pub struct Kernel {
    pub shared: Arc<Shared>,
    pub core: Arc<KernelCore>,  // ContextCore 实现
    // ...
}
```

| 公开方法 | 说明 |
|---|---|
| `new(data_root: PathBuf)` | 创建内核、准备数据根、载入 registry.json |
| `install(source: &str)` | 安装目录或 zip，校验清单→拷贝→环拒绝→调和 |
| `uninstall(id: &str, purge: bool)` | 卸载：级联停依赖方→停用→撤销账本→清理工件→调和 |
| `load(id: &str)` / `load_all()` | 装载插件（原语，不校验依赖） |
| `call(plugin, method, args)` | 跨插件调用（broker 路由 + caps 门禁） |
| `emit(topic, payload)` | 内核侧广播（`kernel.*` 主题） |
| `subscribe(pattern, callback)` | 宿主侧订阅（不入插件账本） |
| `reload(id)` | 热更新：校验→备份→停下游→装新版→调和；失败回滚 |
| `restart(id)` | 重启插件（先停再装） |
| `shutdown()` | 优雅停机（逆向拓扑序停用所有插件） |
| `enable/disable(id)` | 启用/停用并调和 |
| `revoke_capability/grant_capability(id, cap)` | 撤销/恢复能力 |
| 查询类 | `installed_plugins()` / `activated_plugins()` / `plugin_list()` / `ledger_of(id)` / `manifest_of(id)` |

**关键流程**：`config_gate: Mutex<()>` 保证所有配置变更（install/uninstall/enable/disable/reload）串行执行，防止并发调和。

## 2. state.rs — 共享状态中心

**一句话**：`Shared` 是所有模块共同操作的**状态大仓库**，里面存方法表、订阅表、能力表、插件记录等，各模块都持有 `Arc<Shared>`。

```rust
pub struct Shared {
    pub data_root: PathBuf,
    pub methods: RwLock<HashMap<String, MethodEntry>>,      // 方法表：全名→条目
    pub subs: RwLock<Vec<SubEntry>>,                        // 订阅表
    pub caps: RwLock<HashMap<String, CapEntry>>,           // 能力表
    pub plugins: RwLock<HashMap<String, PluginRecord>>,     // 插件记录表
    pub violations: Mutex<Vec<Violation>>,                  // 命名空间越权记录
    pub disabled: RwLock<BTreeSet<String>>,                 // 停用名单
    pub revoked: RwLock<BTreeMap<String, BTreeSet<Capability>>>, // 撤销黑名单
    pub config_gate: Mutex<()>,                             // 配置变更串行闸
    pub lib_seq: AtomicU64,                                 // 私有库序号（热更新用）
    pub plan_seq: AtomicU64,                                // 调和计划序号
    pub sidecars: Mutex<BTreeMap<String, Arc<SidecarHandle>>>,  // 侧车句柄表
}
```

| 方法/字段 | 说明 |
|---|---|
| `plugins_dir()` / `plugin_dir(id)` | 计算路径：`<data_root>/plugins/` 和 `<data_root>/plugins/<id>/` |
| `full_method_name(plugin, method)` | 拼全名并校验 method 以 plugin 开头（越权则记 violation） |
| `record_violation(...)` | 命名空间违规时记录，供 doctor 检查 |
| `dispatch(topic, payload)` | **事件分发核心**：遍历 subs，topic_matches(pattern, topic) 匹配，执行回调 |
| `topic_matches(pattern, topic)` | 通配符匹配：`*` 匹配任意子串 |

**`PluginRecord` 装载记录**：

```rust
pub struct PluginRecord {
    pub manifest: Manifest,
    pub manifest_text: String,
    pub state: PluginState,       // Activating / Activated
    pub library: Option<Library>, // libloading 句柄（dlclose 时 drop）
    pub library_file: PathBuf,    // 私有库副本路径
    pub ledger: Vec<LedgerEntry>, // 效应账本
    pub next_seq: u64,            // 账本序号递增器
    pub deactivate_cbs: Vec<UndoFn>,
    pub sidecar: Option<Arc<SidecarHandle>>,
}
```

| 方法 | 说明 |
|---|---|
| `push_effect(kind, desc, undo)` | 登记效应（append 到 ledger） |
| `push_deactivate_cb(cb)` | 登记停用回调 |
| `take_deactivate_cbs()` | 取出所有停用回调（停用时执行） |

## 3. broker.rs — 接口方法路由（服务①）

**一句话**：管"谁提供什么方法"。`register` 把方法名→处理函数+撤销闭包写入方法表；`call` 查方法表、校验激活状态和能力、执行 handler。

| 函数 | 说明 |
|---|---|
| `register(shared, plugin, name, handler, unregister, requires)` | ① 校验 name 以 plugin 开头 ② 若 requires 存在，校验 ⊆ plugin 清单声明能力 ③ 写 methods 表 ④ 记账：UNDO 移除方法 + 调用 unregister |
| `call(shared, plugin, method, args)` | ① `full_method_name` 拼全名 ② 查 methods 表（E_METHOD_MISSING） ③ 校验 owner.state==Activated（E_PLUGIN_MISSING） ④ 校验生效能力（E_CAPABILITY_DENIED） ⑤ handler(args) |

**为什么"撤销闭包"要 plugin 自己提供**：因为内核不知道 handler 里做了什么插件私有的注册（比如插件自己内部的方法分发），plugin 自己的 unregister 才知道怎么完整撤掉。

---

## 4. bus.rs — 事件广播（服务②）

**一句话**：管"谁订阅了什么事件"。`subscribe` 写入订阅表；`emit` 遍历订阅表、通配匹配、执行回调。

| 函数 | 说明 |
|---|---|
| `subscribe(shared, plugin, pattern, callback, unsubscribe)` | ① 不限命名空间（任何插件可以订阅任何主题） ② 写 subs 表 ③ 记账 |
| `emit(shared, plugin, topic, payload)` | ① 校验 topic 以 plugin 开头（E_NAMESPACE_VIOLATION） ② `Shared::dispatch` 分发 |
| `kernel_subscribe(shared, pattern, callback)` | 宿主侧订阅，owner=`kernel`，不入任何插件账本 |
| `wrap_plugin_callback(plugin_id, plugin_callback)` | 适配器：SDK 侧回调 `Fn(Value)` → 内核侧回调 `Fn(&str, Value)`（后者带主题） |

**事件回调签名差异**：
- **插件 SDK 侧**：`EventCallback = Box<dyn Fn(Value) + Send + Sync>` — 只见载荷，主题由内核固定知道
- **内核侧**：`Arc<dyn Fn(&str, Value) + Send + Sync>` — 带主题（sidecar 转发需要）
- bus.rs 的 `wrap_plugin_callback` 在订阅时做适配

## 5. caps.rs — 能力门禁（服务③）

**一句话**：管"某个插件当前**生效**的能力是什么"。生效 = 清单声明的 − 用户撤销的。

| 函数 | 说明 |
|---|---|
| `set_declared(shared, plugin, caps)` | 装载时把清单声明能力写入 caps 表 |
| `effective(shared, plugin, cap)` | 判定某能力是否生效：`declared.contains(cap) && !revoked[plugin].contains(cap)` |
| `revoke(shared, plugin, cap)` | 撤销（拒绝未声明能力）→ 写入 registry.json |
| `grant(shared, plugin, cap)` | 恢复撤销 → 写入 registry.json |

**四个能力**（`Capability` 枚举，见 SDK）：`Fs` / `Network` / `Ui` / `Shell`。

**门禁时机**：broker 注册时校验 `requires ⊆ declared`；broker 调用时校验 `requires ⊆ effective`。注册时是"声明够不够"，调用时是"当前还能不能用"。

## 6. deps.rs — 依赖图与配置调和（服务④）

**一句话**：管"装了这些插件之后应该谁先激活谁先停"。建依赖图、环检测、版本匹配、拓扑序排、调和执行。

| 函数 | 说明 |
|---|---|
| `version_satisfied(declared, constraint)` | 按段前缀匹配：`@1` / `@1.2` / `@1.2.3` 分别比较前 1/2/3 段 |
| `find_cycle(nodes)` | DFS 检测有向环，返回带路径的环（如 `core-job → core-ui → core-job`） |
| `active_dependents(shared, id)` | 找出"因 id 存在才激活"的所有下游插件（递归） |
| `shutdown_order(shared)` | 逆向拓扑序（先停叶子） |
| `reconcile(shared, core)` | **调和主流程**：重建依赖图 → 环检测 → satisfiable 判定 → 拓扑序 → 逐步执行 activate/deactivate |

**调和触发时机**：任何配置变更（install/uninstall/enable/disable/reload）后自动同步执行。

**`PlanStep`**：调和的单步记录（`id` + `action=activate/deactivate` + `result`），每步执行完广播 `kernel.plan.step`，core-plugin-manager 订阅用来展示进度。

**`ReconcileReport`**：调和结果（成功/失败 + 每步结果 + 失败原因）。

## 7. loader.rs — 装载通道

**一句话**：把"磁盘上的插件"变成"内存里的 Plugin 实例"。支持目录或 zip 包安装、私有动态库副本装载、热更新备份/还原、卸载文件语义。

| 函数 | 说明 |
|---|---|
| `install(source)` | 目录/zip → 暂存 → 校验 manifest → 拷贝进 plugins/<id>/ |
| `load(shared, core, id)` | 核心装载流程（见下方） |
| `create_instance(library)` | 取 `ling_plugin_create` 符号 → 调用 → 核对 `id()` 与清单一致 |
| `backup_install_artifacts` / `restore_install_artifacts` | 热更新用：备份运行版本的清单原文 + 私有库；失败时还原 |
| `remove_install_files(dir, purge)` | **非 purge**：删 `plugin.toml` + `.so`，保留 `data/`；**purge**：连 `data/` 一起删 |

**核心装载流程**（Rust cdylib 插件）：

```
loader::load(shared, core, id)
 ├─ 校验目录存在 + 读取并校验 manifest
 ├─ 拷贝 {id}.so → {id}.{lib_seq++}.so   // 私有副本，热更新时不会碰原件
 ├─ libloading 打开私有副本 → 取 ling_plugin_create → create_instance
 ├─ caps::set_declared                    // 声明能力写入
 ├─ 插入 PluginRecord(state=Activating)
 ├─ instance.activate(ctx)                // ★ 插件在此注册方法/订阅
 │    └─ 每步都经 broker/bus，同步记入账本
 ├─ 成功 → state=Activated → 广播 kernel.plugin.state:activated
 └─ 失败 → 账本倒序撤销 → dlclose → 清理 → 返回 E_ACTIVATE_FAILED
```

**侧车插件**：loader::load 识别清单里有 `sidecar` 字段后，转给 `sidecar::start`（见 §10）。

## 8. manifest.rs — 清单解析与校验

**一句话**：解析 `plugin.toml`，校验全部字段合法性，产出 `Manifest` 结构体。

```rust
pub struct Manifest {
    pub plugin: PluginMeta,   // id, name, version, api
    pub requires: Requires,   // capabilities + plugins + sidecar
    pub sidecar: Option<SidecarMeta>,
}
```

**校验规则**（硬编码在 `parse_and_validate`）：

| 字段 | 规则 |
|---|---|
| `id` | 小写字母/数字/短横线，首字符不能是 `-`，长度 ≤ 64 |
| `version` | 三段式 `X.Y.Z`，各段 ≤ 65535 |
| `api` | 必须等于 `HOST_API`（当前 1），接受字符串或整数 |
| `capabilities` | 必须是 `Capability::parse` 能认得的（fs/network/ui/shell） |
| `plugins` | `id[@版本约束]`，版本约束 1–3 段 |
| `sidecar.executable` | 相对路径不含 `..` 且文件存在 |
| `sidecar.protocol` | 必须是 `"jsonl"` |
| `sidecar.restart` | `on-crash` 或 `never` |

## 9. ledger.rs — 效应账本

**一句话**：管"插件装进来后做了什么事"。`take_ledger` 在停用时取出账本，`run_reverse` 倒序执行撤销闭包。

| 函数 | 说明 |
|---|---|
| `take_ledger(record)` | `mem::take(&mut record.ledger)` — 取出账本，record 自己清空 |
| `run_reverse(entries)` | 倒序遍历，每条 `catch_unwind` 隔离执行 undo；返回失败清单（seq + desc + reason），单条失败不阻断后续 |

**为什么要 `catch_unwind`**：undo 是插件自己写的，如果插件的撤销函数 panic 了，不能让整个宿主崩掉。每条撤销独立执行，最终报告"卸载不完整 + 清单"。

## 10. sidecar.rs — 侧车运行时

**一句话**：管进程外侧车插件的生命周期。启动进程、JSONL 控制面握手、转发注册/调用/事件、优雅停用、崩溃善后。

| 函数/类型 | 说明 |
|---|---|
| `start(shared, core, id, manifest)` | 起子进程（env `LING_SOCKET` + `LING_PLUGIN`）→ TCP 握手 → 发 activate → 起 monitor 线程 |
| `SidecarHandle` | 持有 endpoint、child、writer、stopping、pending 请求表等 |
| `graceful_stop(handle)` | deactivate → 等 deactivated（5s）→ shutdown → 等退出（5s）→ 强杀 |
| `crash_cleanup(handle, shared)` | 注销效应 → 广播 crashed → restart=on-crash 时自动重装 |

**控制面协议**（行式 JSON，每行一条）：

| 方向 | 消息 |
|---|---|
| 内核→侧车 | `{"op":"activate"}` / `{"op":"deactivate"}` / `{"op":"invoke", "req_id", "plugin", "method", "args"}` |
| 侧车→内核 | `{"op":"register_method", "name", "requires"}` / `{"op":"subscribe", "pattern"}` / `{"op":"emit", "topic", "payload"}` / `{"op":"result", "req_id", "result"}` / `{"op":"error", "req_id", "code", "message"}` |

**30 秒调用超时**：内核侧侧车 invoke 有 tokio time::timeout，超时返回 `E_TIMEOUT`。

## 12. context.rs — ContextCore 实现

**一句话**：把 SDK 层 `ContextCore` trait 的每个方法映射到内核的 broker/bus/loader，是插件 Context 句柄与内核服务之间的桥接层。

```rust
pub struct KernelCore {
    shared: Arc<Shared>,
    // ...
}

impl ContextCore for KernelCore {
    fn register_method(&self, plugin, name, handler, unregister, requires) {
        broker::register(&self.shared, plugin, name, handler, unregister, requires);
    }
    fn call(&self, plugin, method, args) {
        broker::call(&self.shared, plugin, method, args)
    }
    fn subscribe(&self, plugin, pattern, callback, unsubscribe) {
        bus::subscribe(&self.shared, plugin, pattern, callback, unsubscribe)
    }
    fn emit(&self, plugin, topic, payload) {
        bus::emit(&self.shared, plugin, topic, payload)
    }
    fn data_dir(&self, plugin) {
        self.shared.plugin_dir(plugin).join("data")  // 内核保证目录存在
    }
    fn on_deactivate(&self, plugin, callback) {
        self.shared.plugins.lock()[plugin].push_deactivate_cb(callback)
    }
    fn ledger_info(&self, plugin) {
        // 只返回快照（seq, kind, desc），撤销闭包不外泄
    }
}
```

**职责边界**：KernelCore 不做任何业务逻辑，只做"转发 + 记账"。业务规则（命名空间校验、能力校验）全在 broker/bus 里。

## 15. error.rs — 统一错误类型

**一句话**：`KernelError` 把各模块的错误统一映射到 SDK 层的 `codes` 错误码。

```rust
pub enum KernelError {
    ManifestError(...),        // E_MANIFEST_INVALID
    ApiMismatch(...),          // E_API_MISMATCH
    CapabilityDenied(...),     // E_CAPABILITY_DENIED
    // ...
}
```

每个变体都有 `code()` 返回对应的 SDK 错误码字符串，CLI 和 admin 用它生成统一的错误 JSON。
