# 03 内置插件开发模式

> 五个内置插件是学习插件开发的最佳范例。本文档逐个拆解：**声明了什么能力、依赖谁、注册了什么方法、发了什么事件、贡献了什么界面**。

---

## 内置插件总览

| 插件 | 能力声明 | 依赖 | 默认安装 | 一句话职责 |
|---|---|---|---|---|
| **core-ui** | network, fs, ui | 无 | ✅ | 本机网页服务 + `/rpc` 网关 + 界面贡献管理 |
| **core-settings** | fs, ui | core-ui@1 | ✅ | 设置存储（SQLite）+ 设置页 |
| **core-plugin-manager** | network, fs, ui | core-ui@1 | ✅ | 插件管理页 + 管理端口转发 |
| **core-job** | ui | 无 | ❌ | 长任务登记/进度广播 + 作业页 |
| **core-log** | fs, ui | 无 | ❌ | 日志写入/读取/轮转 + 日志页 |

## 1. core-ui — 界面壳

**plugin.toml**：
```toml
[plugin]
id = "core-ui"
name = "界面壳"
version = "1.0.0"
api = "1"

[requires]
capabilities = ["network", "fs", "ui"]
```

### 1.1 激活时做了什么

1. 启动 HTTP 服务监听 `127.0.0.1:7910`（占用顺延），实际端口写入 `registry.json` 的 `ui_port` 字段
2. 注册 3 个方法 + 1 个事件订阅
3. 订阅 `kernel.plugin.state`，插件停用/卸载时自动撤下其界面贡献

### 1.2 注册的方法

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `core-ui.ui.contribute` | `{ plugin, path, title, icon?, asset_dir? }` | `{ ok: true }` | 其他插件调这个来贡献页面和菜单 |
| `core-ui.ui.retract` | `{ plugin, path }` | `{ ok: true }` | 撤下某贡献 |
| `core-ui.ui.list` | `{}` | `{ pages: [...], menus: [...] }` | 列出当前所有贡献 |

### 1.3 界面贡献模型

```json
{
  "type": "page",              // page 或 menu
  "plugin": "resources-manager",
  "path": "/resources-manager",
  "title": "资源管理",
  "icon": "📁",
  "asset_dir": "/abs/path/to/assets"
}
```

- `asset_dir` 是插件自己的 HTML/JS/CSS 资源目录，core-ui 托管在 `/assets/<plugin>/` 下
- 页面通过 `/rpc` 网关调用其他插件方法：`POST /rpc` body = `{"id":1,"plugin":"xxx","method":"yyy","params":{...}}`
- 认证：`X-Ling-Token` 头 / `?token=` 查询参数 / cookie，token 来自 `session.json`

### 1.4 `/rpc` 网关流程

```
浏览器 POST http://127.0.0.1:7910/rpc
  body: {"id":"1","plugin":"resources-manager","method":"scan.start","params":{"path":"/data"}}
  │
  ├─ 校验 token
  ├─ ctx.call("resources-manager", "scan.start", json!({"path":"/data"}))
  │    → broker → resources-manager 的 handler
  │    → 返回 Ok(json!({"job_id": 42}))
  │
  └─ 浏览器收到: {"id":"1","ok":true,"result":{"job_id":42}}
```

### 1.5 订阅的事件

| 主题 | 行为 |
|---|---|
| `kernel.plugin.state` | state=deactivated/uninstalled → 遍历 contributions，撤回该插件的全部贡献 |

## 2. core-settings — 设置存储

**plugin.toml**：
```toml
[plugin]
id = "core-settings"
name = "设置存储"
version = "1.0.0"
api = "1"

[requires]
capabilities = ["fs", "ui"]
plugins = ["core-ui@1"]
```

### 2.1 激活时做了什么

1. 打开 SQLite 数据库 `ling/plugins/core-settings/data/settings.db`
2. 创建 `schema` 表（存设置项定义：类型、默认值、取值范围）和 `values` 表（存实际值）
3. 注册 4 个方法
4. 调 `ctx.call("core-ui", "ui.contribute", ...)` 贡献设置页面

### 2.2 注册的方法

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `core-settings.define` | `{ plugin, key, schema: {type, default, range?} }` | `{ ok: true }` | 插件声明自己有什么设置项（带模式校验） |
| `core-settings.get` | `{ plugin, key }` | `{ value, exists }` | 读某个设置 |
| `core-settings.set` | `{ plugin, key, value }` | `{ ok: true }` | 写某个设置（按 schema 校验） |
| `core-settings.list` | `{ plugin }` | `[{ key, value, schema }]` | 列出某插件全部设置 |

### 2.3 与内核配置的分界

| | 内核配置（Context 级） | core-settings 的设置 |
|---|---|---|
| 谁拥有 | ling 内核 | core-settings 插件 |
| 存什么 | 宿主级登记（停用名单、撤销黑名单） | 插件业务设置（扫描超时、默认主题） |
| 卸载时 | 随内核自动维护 | 保留在 settings.db 里 |
| 谁读 | 内核自己 | 插件通过 `ctx.call("core-settings", "get", ...)` |

## 3. core-plugin-manager — 插件管理界面

**plugin.toml**：
```toml
[plugin]
id = "core-plugin-manager"
name = "插件管理"
version = "1.0.0"
api = "1"

[requires]
capabilities = ["network", "fs", "ui"]
plugins = ["core-ui@1"]
```

### 3.1 激活时做了什么

1. 调 `ctx.call("core-ui", "ui.contribute", ...)` 贡献插件管理页面
2. 注册 12+ 个方法（大部分经管理端口转发内核 API）
3. 订阅 `kernel.plan.step`，保存最近 50 步用于调和进度展示

### 3.2 经管理端口与内核通信

core-plugin-manager 自己就是一个插件，但它需要操作**宿主内核**（安装/卸载/启停/授权）。这些内核级操作用"管理端口 + session 口令"来做：

```rust
// 连接管理端口（127.0.0.1:7900），读 session.json 获取 token
// 发 {"op":"auth","token":"xxx"} 认证
// 再发 {"method":"kernel.plugins.install","params":{...}}
// 收到 {"ok":true,"result":{...}}
```

### 3.3 注册的方法

| 方法 | 对应内核 API |
|---|---|
| `core-plugin-manager.list` | `kernel.plugins.list` |
| `core-plugin-manager.install` | `kernel.plugins.install` |
| `core-plugin-manager.uninstall` | `kernel.plugins.uninstall` |
| `core-plugin-manager.enable` | `kernel.plugins.enable` |
| `core-plugin-manager.disable` | `kernel.plugins.disable` |
| `core-plugin-manager.reload` | `kernel.plugins.reload` |
| `core-plugin-manager.restart` | `kernel.plugins.restart` |
| `core-plugin-manager.revoke_capability` | `kernel.plugins.revoke_capability` |
| `core-plugin-manager.grant_capability` | `kernel.plugins.grant_capability` |
| `core-plugin-manager.builtin.available` | 内核内置插件可安装列表 |
| `core-plugin-manager.builtin.install` | 内核安装内置插件 |
| `core-plugin-manager.plan.recent` | 自己保存的最近调和步骤（非内核 API） |

### 3.4 能力授权模型

- **默认**：插件清单声明的能力**全部允许**（装了就算同意）
- **撤销**：界面撤销某项能力 → 内核写入 `registry.json` 的 `revoked` 字段
- **生效判定**：`effective = declared - revoked`，broker 调用时校验

## 4. core-job — 作业调度（可选）

**plugin.toml**：
```toml
[plugin]
id = "core-job"
name = "作业调度"
version = "1.0.0"
api = "1"

[requires]
capabilities = ["ui"]
```

### 4.1 激活时做了什么

1. 打开自己的 data 目录（存作业历史，保留 30 天）
2. 注册 5 个方法
3. 贡献作业页面到 core-ui

### 4.2 注册的方法 + 事件

| 方法 | 说明 |
|---|---|
| `core-job.register` | 登记作业，返回 job_id：`{ plugin, name, total? }` |
| `core-job.progress` | 上报进度：`{ job_id, current, total? }` |
| `core-job.cancel` | 取消作业 |
| `core-job.list` | 列出某插件的全部作业 |
| `core-job.get` | 查询单个作业详情 |

**广播事件**：

| 主题 | 载荷 |
|---|---|
| `core-job.progress` | `{ job_id, plugin, current, total, percent }` |
| `core-job.done` | `{ job_id, plugin, status, result? }` |

### 4.3 降级路径

core-job **未安装**时：
- 插件可以自己管理作业（进度只在自己的界面可见）
- 如果插件清单写了 `requires core-job@1`，则 core-job 未装时该插件保持"待激活"

## 5. core-log — 日志收集（可选）

**plugin.toml**：
```toml
[plugin]
id = "core-log"
name = "日志收集"
version = "1.0.0"
api = "1"

[requires]
capabilities = ["fs", "ui"]
```

### 5.1 激活时做了什么

1. 扫描已安装插件，为每个插件创建日志文件：`ling/plugins/<编号>/logs/plugin.log`
2. 注册 3 个方法
3. 贡献日志查看页面到 core-ui

### 5.2 注册的方法

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `core-log.write` | `{ plugin, level, message }` | `{ ok: true }` | 插件写日志 |
| `core-log.read` | `{ plugin, lines?, since? }` | `{ entries: [...] }` | 读日志 |
| `core-log.rotate` | `{ plugin }` | `{ ok: true }` | 手动轮转 |

**日志轮转规则**：单插件日志文件上限 10 MB，保留最近 5 个文件。

### 5.3 降级路径

core-log **未安装**时：
- `ling logs` 命令会报错（经管理端口走不到 core-log）
- 插件侧日志桩（`ctx` 暂未提供统一日志 API）写 stderr

## 6. 内置插件之间的协作关系图

```
core-ui ────────────────────────────────────────────────┐
  │ 提供 ui.contribute / ui.retract / ui.list          │
  │ 订阅 kernel.plugin.state                            │
  ▼                                                     ▼
core-settings ── requires ──▶ core-ui        core-plugin-manager ── requires ──▶ core-ui
  │                                                 │
  │ 定义/读写设置                                   │ 经管理端口操作内核
  ▼                                                 ▼
  (被 core-settings 插件消耗)                   kernel (broker/bus/caps/deps)


core-job (独立)          core-log (独立)
  │                        │
  │ 进度事件               │ 日志写入
  ▼                        ▼
  (被 resources-manager    (被所有插件消耗)
   等插件消耗)
```

## 7. 内置插件与普通插件的唯一区别

| 方面 | 内置插件 | 普通插件 |
|---|---|---|
| 源码位置 | `ling/builtin-plugins/` | 任意目录 |
| 构建方式 | 和普通插件一样（cdylib） | 一样 |
| 插件规范 | 完全相同的 `plugin.toml` + `Plugin` trait | 一样 |
| 首次安装 | **自动**装三件套 | 用户手动装 |
| 后续新增 | **不自动**，用户按需装 | 用户手动装 |
| 可卸载 | **可以**（卸掉只剩命令行） | 可以 |
| 热更新 | 可以（走 reload 流程） | 可以 |

**唯一的"特权"**：发行包里自带、首启自动安装。内核里没有任何"如果 id==core-ui 就特殊处理"的分支。
