# 00 构建指南

> resources-manager（简称 **rm**）是一个**独立 Cargo workspace**，内部有一个 cdylib 插件（给 ling 装）和一个独立 CLI（`rmgr.exe`，可脱离 ling 运行）。

---

## 1. 工作区结构

```
plugins/resources-manager/
├── Cargo.toml                     # workspace 根
├── crates/
│   ├── rm-plugin/                 # ★ 插件壳（cdylib）：组装所有 rm-* crate、注册方法、广播事件
│   ├── rm-catalog/                # SQLite 目录库：打开/迁移/仓储层
│   ├── rm-proto/                  # 协议层：错误码、消息结构、事件主题常量
│   ├── rm-scan/                   # 扫描：分层哈希、walker、增量判断
│   ├── rm-fs/                     # 文件系统适配：跨平台元数据（大小/mtime/inode）
│   ├── rm-dedup/                  # 去重：按内容哈希分组
│   ├── rm-store/                  # 存储与压缩：zstd 试压、池路径布局、三档迁移
│   ├── rm-sync/                   # 同步：op-log、冲突解决、墓碑
│   ├── rm-transfer/               # 传输：局域网 HTTP 传输、配对、身份
│   ├── rm-ai/                     # AI 功能：provider、suggest、extract、cache
│   ├── rm-classify/               # 分类：基于规则的自动打标签
│   └── rm-semantic/               # 语义层：词条/版本/标签/关系的业务逻辑
├── apps/
│   └── cli/                       # rmgr.exe 独立 CLI
├── plugins/
│   └── resources-manager/
│       ├── src/lib.rs             # 插件 entry（目前只是 re-export rm-plugin）
│       ├── plugin.toml            # ling 插件清单
│       └── Cargo.toml             # crate-type = ["cdylib"]
└── packaging/                     # 打包脚本
```

### 依赖关系（简化）

```
rm-plugin ──→ rm-catalog ──→ rusqlite (bundled)
     │              └── rm-proto
     ├── rm-scan ──→ rm-fs ──→ rm-proto
     ├── rm-store
     ├── rm-dedup
     ├── rm-sync ──→ rm-proto
     ├── rm-transfer ──→ rm-proto
     ├── rm-ai ──→ rm-proto
     └── rm-classify

apps/cli ──→ rm-plugin + rm-proto
```

## 2. 构建

### 2.1 构建整个 workspace（包含插件 + CLI）

```powershell
cd plugins/resources-manager
cargo build --release
```

产物位置（`.cargo/config.toml` 设置 target-dir 到 `run/target/ling`，和 main 共用缓存）：

| 产物 | 路径 |
|---|---|
| `rmgr.exe` | `run/target/ling/release/rmgr.exe` |
| 插件 dll | `run/target/ling/release/resources_manager.dll` |

### 2.2 只构建插件（给 ling 用）

```powershell
cargo build --release -p resources-manager  # 或 rm-plugin
```

### 2.3 只构建 CLI

```powershell
cargo build --release -p rmgr
```

### 2.4 用 run/build.ps1 一键构建

```powershell
powershell -File run\build.ps1 -Only rm
```

脚本会自动：
1. 构建 rm workspace
2. 拷贝 `rmgr.exe` 到 `run/dist/<triple>/`
3. 拷贝 `resources-manager.dll` + `plugin.toml` 到 `run/dist/<triple>/resources-manager/`

## 3. 两种运行方式

### 3.1 作为 ling 插件（推荐）

```powershell
# 确保插件已安装
ling install run/dist/windows-x86_64-msvc/resources-manager

# 启动宿主（如果还没启动）
ling serve

# 查看状态
ling plugins
# resources-manager    activated
```

插件激活后会：
1. 打开 SQLite 目录库（`ling/plugins/resources-manager/data/catalog.db`）
2. 启动 LAN 同步服务（端口 7913）
3. 启动流交付服务（从 rm 给 player 提供文件流）
4. 注册所有 `resources-manager.*` 方法

### 3.2 独立运行（rmgr CLI）

```powershell
# 独立运行需要指定数据库路径
.\rmgr.exe --standalone --db D:\my-catalog.db

# 或用默认路径（$HOME/.local/share/rmgr/catalog.db）
.\rmgr.exe --standalone
```

CLI 提供的业务命令：

```powershell
rmgr --standalone location add D:\media
rmgr --standalone scan start 1          # 扫描 location id=1
rmgr --standalone browse query "tag:科幻"
rmgr --standalone dup list
```

## 6. 常见构建问题

### Q: rmgr.exe 报"找不到 rusqlite 符号"？
A: rm workspace 和 main workspace 共用 `run/target/ling/` 作为 target-dir。如果先构建 rmgr 再构建 main，或反过来，都不会有冲突——但如果单独构建某个时可能缺 crate 缓存。在 rm 根目录执行一次 `cargo build --release` 即可。

### Q: 插件 dll 装到 ling 后激活失败？
A: 检查 stderr 输出。常见原因：
1. `plugin.toml` 里 `api` 字段 ≠ 1
2. 清单声明了不存在的 `requires.plugins`（如 `player@1` 但 player 还没装）
3. rm-catalog 打开 catalog.db 时权限问题（目录应已由内核创建）

### Q: rmgr 独立运行报"数据目录不存在"？
A: 独立模式下 rmgr 自己不创建目录。先手动 `mkdir $env:USERPROFILE\.local\share\rmgr`，或用 `--db` 指定一个已存在路径。
