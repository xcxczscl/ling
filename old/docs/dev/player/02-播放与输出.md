> 本文档聚焦 player 最核心的功能：**怎么从 rm 拿到字节 → 解码成画面 → 送到某个输出端**。

## 1. 管道模型总览

```
rm (resources-manager)              player
    │                                 │
    │  placement_id = 42              │
    ├────────────────────────────────▶│
    │                                 │
    │  stream.get_local_path          │  优先：同设备直接拿路径
    │  返回 D:\media\深空旅人.mkv      │  如果有本地路径
    │                                 │
    │  否则 stream.open               │  否则：返回带 token 的流 URL
    │  返回 http://127.0.0.1:7913/... │  player 自己发 HTTP Range 请求
    │                                 │
    │                                 ▼
    │                          MpvBackend.load(url_or_path)
    │                                 │
    │                                 ├─ 视频 → mpv 解码 → vo=libmpv → player.ui 展示
    │                                 ├─ 音频 → mpv 解码 → ao 输出到扬声器
    │                                 │
    │                                 └─ 画面比例 aspect.rs 计算
    │                                    (pillarbox / letterbox)
```

## 2. player.play 完整流程

```rust
// methods.rs 里
fn play(state: &PlayerState, args: Value) -> Result<Value, CallError> {
    // Step 1: 解析目标
    let placement_id = args["placement_id"].as_i64().ok_or(...)?;

    // Step 2: 先问 rm 有没有本地路径
    let local_path = state.ctx.call(
        "resources-manager",
        "stream.get_local_path",
        json!({ "placement_id": placement_id })
    );

    let (load_url, content_hash) = match local_path {
        Ok(v) if v["local_path"].is_string() => {
            let path = v["local_path"].as_str().unwrap().to_string();
            (format!("file:///{}", path.replace('\\', "/")), v["content_hash"].clone())
        }
        _ => {
            // 没有本地路径（内容在另一台设备上）
            let stream_info = state.ctx.call(
                "resources-manager",
                "stream.open",
                json!({ "placement_id": placement_id })
            )?;
            let url = stream_info["url"].as_str().unwrap().to_string();
            (url, stream_info["content_hash"].clone())
        }
    };

    // Step 3: 确定 asset_type（从 rm 的 content 表查）
    let asset_type = detect_asset_type(&content_hash)?;

    // Step 4: 创建 Session
    let session = state.sessions.create(
        asset_type,
        &load_url,
        Some(placement_id),
        content_hash.as_str(),
    );

    // Step 5: 根据 asset_type 加载
    match asset_type {
        AssetType::Video | AssetType::Audio => {
            let backend = MpvBackend::start()?;
            backend.load_at(&load_url, session.position)?;  // 续播
            session.backend = Some(Arc::new(backend));
        }
        AssetType::Image => { image_cap::load(&session)?; }
        AssetType::Pdf => { pdf_cap::load(&session)?; }
        AssetType::Application => { ... }  // 不进 play，进 run
    }

    // Step 6: 持久化
    state.store.store_session(&session)?;

    Ok(json!({ "session_id": session.id }))
}
```

## 3. MpvBackend 详解

### 3.1 生命周期

```
MpvBackend::start()
  │
  ├─ mpv_create()
  ├─ mpv_initialize()
  ├─ mpv_set_property_string("vo", "libmpv")  ← 关键：走 libmpv GPU 渲染
  ├─ mpv_set_property_string("ao", "auto")
  ├─ mpv_set_property_string("wid", "<player UI window id>")
  └─ spawn event_pump thread

backend.load("file:///path/to/file.mkv")
  │
  └─ mpv_command_string("loadfile", ["file:///path/to/file.mkv", "replace"])

backend.pause()
  │
  └─ mpv_set_property_flag("pause", true)

backend.seek(32.0)
  │
  └─ mpv_command_string("seek", ["32.0", "absolute"])

drop(backend)  // 析构
  │
  ├─ stop_flag = true → event_pump 退出
  ├─ mpv_command_string("stop", [])
  ├─ mpv_destroy(ctx)
  └─ join event_pump thread
```

### 3.2 event_pump 事件映射

```rust
fn event_pump(ctx: *mut mpv_handle, on_event: impl Fn(BackendEvent)) {
    loop {
        if stop_flag.load(Ordering::Relaxed) { break; }

        let event = unsafe { mpv_wait_event(ctx, 0.1) };
        match event.event_id {
            MPV_EVENT_TIME_POSITION => {
                let pos: f64 = read_property("time-pos")?;
                let dur: f64 = read_property("duration")?;
                on_event(BackendEvent::Progress { position: pos, duration: dur });
            }
            MPV_EVENT_PAUSE => { on_event(BackendEvent::Paused); }
            MPV_EVENT_UNPAUSE => { on_event(BackendEvent::Resumed); }
            MPV_EVENT_END_FILE => {
                let reason: &str = read_property("end-file")?;
                if reason == "eof" { on_event(BackendEvent::Finished); }
                else { on_event(BackendEvent::Failed { reason: reason.to_string() }); }
            }
            MPV_EVENT_FILE_LOADED => {
                // 等 duration ready（load_at 里用来续播 seek）
            }
            _ => {}  // 其他事件忽略
        }
    }
}
```

### 3.3 续播（load_at）

```rust
fn load_at(&self, url: &str, start_sec: f64) -> Result<(), PlayerError> {
    self.load(url)?;

    // 等文件加载完成
    self.wait_for_event(MPV_EVENT_FILE_LOADED, Duration::from_secs(10))?;

    // 再等 duration 属性就绪（有些容器要解完 header 才知道时长）
    loop {
        if let Ok(dur) = self.get_property::<f64>("duration") {
            if dur > 0.0 { break; }
        }
        std::thread::sleep(Duration::from_millis(50));
    }

    // seek 到续播点
    self.seek(start_sec)?;
    Ok(())
}
```

## 4. 画面比例计算

`aspect.rs` 处理"画面宽高比 ≠ 屏幕宽高比"时的正确黑边。

```rust
// 21:9 电影在 16:9 屏幕上
// 正确：左右黑边（pillarbox）
// 错误：四边黑边（同时缩放居中）

pub struct AspectResult {
    pub target_x: f32,    // 绘制区域 x 偏移
    pub target_y: f32,    // 绘制区域 y 偏移
    pub target_w: f32,    // 绘制宽度
    pub target_h: f32,    // 绘制高度
    pub padding_left: f32,
    pub padding_right: f32,
    pub padding_top: f32,
    pub padding_bottom: f32,
}

pub fn compute_aspect(
    content_w: f32, content_h: f32,   // 原始视频分辨率
    screen_w: f32, screen_h: f32,     // 目标屏幕分辨率
) -> AspectResult
```

| 条件 | 结果 |
|---|---|
| content aspect > screen aspect | **pillarbox**（左右留黑） |
| content aspect < screen aspect | **letterbox**（上下留黑） |
| aspect 相等 | 撑满，无黑边 |

fn outputs_set(state: &PlayerState, args: Value) -> Result<Value, CallError> {
    let session_id = args["session_id"].as_u64().ok_or(...)?;
    let output_id = args["output_id"].as_str().ok_or(...)?;

    let session = state.sessions.get(session_id)?;

        // 告诉 mpv 切输出：--vo=libmpv:wid=新窗口 或 --ao=新音频设备

    }
    Ok(json!({ "ok": true }))
}

## 6. 串流模式详解（router.rs）

### 6.1 三种模式

```
模式 A — 字节转发：
  player ─── HTTP Range ──▶ rm 流端点 ──▶ 原始字节 ──▶ 接收器解码
  条件：接收器支持内容编码（如视频是 H.264，接收器硬解 H.264）
  优点：最省 player 资源（不解码不重编码）
  缺点：接收器必须支持内容编码

模式 B — 重编码：
  player ─── libmpv 解码 ─── ffmpeg/libavcodec 重编码 ──▶ 推给接收器
  条件：接收器不支持内容编码，但带宽足够
  优点：接收器可以"弱"
  缺点：player CPU 负担重（解码+重编码）

模式 C — 帧流：
  player ─── libmpv 解码帧 ─── JPEG 压缩 ──▶ 高帧率推帧 ──▶ 接收器显示
  条件：带宽不足但接收器有网络
  优点：延迟最低（远低于模式 B）
  缺点：带宽占用大（每帧都是 JPEG）
```

### 6.2 auto_select_mode 决策树

```
auto_select_mode(receiver_codecs, content_codec, bandwidth_mbps)
  │
  ├─ receiver_codecs 包含 content_codec？
  │   └─ YES → CastMode::A（字节转发）
  │
  ├─ bandwidth_mbps > MIN_B_FOR_BANDWIDTH (10 Mbps) 且
  │   receiver_codecs 包含 "h264" 或 player 能重编码？
  │   └─ YES → CastMode::B（重编码）
  │
  └─ 否则 → CastMode::C（帧流）
```

### 6.3 投屏流程

```
player.cast.start(session_id, receiver_id, mode?)
  │
  ├─ 1. player.remote.caps(receiver_id) → 拿到接收器的 codecs
  │
  ├─ 2. 内容 codec 从 rm 查
  │     (ctx.call("resources-manager", "content.get", ...))
  │
  ├─ 3. auto_select_mode → 决定 A/B/C
  │
  ├─ 4. 按模式启动：
  │     A: player 自己 HTTP GET rm 流 URL → 转发给接收器
  │        (proxy.rs)
  │     B: player decode → re-encode → push to receiver
  │     C: player decode → jpeg compress → push frames
  │
  └─ 5. 广播 player.cast.started { session_id, receiver_id, mode }
```

## 8. 远程续播（Session Handoff）

### 场景

用户在书房 PC 上看《深空旅人》，暂停在 32:15。走到客厅拿起电视盒子，打开同一个内容 → 自动从 32:15 继续。

### 实现

```
书房 PC（player A）                    电视盒子（player B）
    │                                    │
    │ pause(32.15)                       │
    │                                    │
    │ push_sync → 发现新 peer            │
    │ POST http://客厅电视:7917/sync      │
    │ { session_id, pos: 32.15, ... }    │
    │ ──────────────────────────────▶  │
    │                                    │
    │                                    │ 收到 sync
    │                                    │ session.create
    │                                    │ load_at(32.15)
    │                                    │ 从暂停点继续 ✅
```

### 同步推送时机（SyncMode）

| 模式 | 推送时机 | 节流 |
|---|---|---|
| `Manual` | 用户点了"接力"按钮 | 无 |
| `OnPlay` | 新播放开始时 | 只推一次 |
| `OnPauseSeek` | 暂停/跳转时 | pause 时推，seek 时推 |

### 节流实现

```rust
fn should_sync(prev_sent: Instant, threshold_secs: f64) -> bool {
    prev_sent.elapsed().as_secs_f64() >= threshold_secs
}
```

防止网络好时用户疯狂 seek，把局域网打爆。
