# 00 构建指南

> player 是一个**独立 Cargo workspace**，核心是一个 cdylib 插件，另外还有一个可选的 `player_lite` 子二进制（接收器）。player 依赖 MPV SDK（libmpv），需要在构建前准备好。

## 2. MPV SDK 准备

player 依赖 `libmpv2-sys`（绑定 libmpv C 接口），需要在 `run/mpv-sdk/` 目录下有：

```
run/mpv-sdk/
├── include/mpv/
│   ├── client.h          ← libmpv 头文件
│   ├── render.h
│   ├── render_gl.h
│   └── stream_cb.h
├── libmpv-2.dll           ← 运行时动态库
└── mpv.lib                ← MSVC 链接库（build.rs 会自动定位）
```

### 2.1 Windows MSVC 下的 mpv.lib 生成（一次性）

MPV 官方发布的 dev 包里是 MinGW 格式的 `libmpv.dll.a`，MSVC 不认。需要手动生成：

```powershell
# 1. 用 dumpbin 从 dll 导出符号
dumpbin /exports libmpv-2.dll > mpv.def

# 2. 生成 .def 文件（需要手动格式化：EXPORTS 节 + 每行一个符号）
#    或者用 libmpv2-sys 自带的工具自动生成

# 3. 用 MSVC lib.exe 生成 mpv.lib
lib /def:mpv.def /out:mpv.lib /machine:x64
```

本项目已经生成好，放在 `run/mpv-sdk/` 下。

### 2.2 build.rs 做了什么

```rust
// build.rs 伪代码
fn main() {
    let sdk_path = find_mpv_sdk();  // 优先 run/mpv-sdk，其次 MPV_SDK 环境变量

    // 告诉 cargo 去哪里找 mpv.lib 和 libmpv-2.dll
    println!("cargo:rustc-link-search=native={}\\lib", sdk_path);
    println!("cargo:rustc-link-lib=mpv");

    // 告诉 libmpv2-sys 头文件在哪
    let mut build = cc::Build::new();
    build.include(format!("{}\\include", sdk_path));
    // ... 编译生成绑定
}
```

### 2.3 运行时

分发时需要**把 `libmpv-2.dll` 和 `player.dll` 放同一目录**。`build.ps1` 会自动拷贝。

## 3. 构建

### 3.1 构建插件（给 ling 用）

```powershell
cd plugins/player
cargo build --release -p player
# 产物：run/target/player/release/player.dll
```

### 3.2 构建 lite 接收器（可选）

```powershell
cargo build --release --bin player_lite
# 产物：run/target/player/release/player_lite.exe
```

### 3.3 用 run/build.ps1 一键构建

```powershell
powershell -File run\build.ps1 -Only player
```

脚本会：
1. 构建 player 插件 dll
2. 拷贝 `mpv-2.dll` 到 dist
3. 拷贝 `player.dll` + `plugin.toml` + `mpv-2.dll` 到 `run/dist/<triple>/player/`
4. 如果有 player_lite.exe，拷贝到 dist 根目录

## 4. 运行

### 4.1 作为 ling 插件

```powershell
# 先确保 player 已安装
ling install run/dist/windows-x86_64-msvc/player

# 启动宿主
ling serve

# 调用方法
# 先问 rm 拿流 URL / 本地路径
# player.play → 从 rm 拿字节 → 用 libmpv 播放
```

### 4.2 player 插件激活流程

```
Plugin::activate(ctx)
  │
  ├─ 1. 初始化 PlayerState
  │     打开 SQLite player.db（会话持久化）
  │     初始化 SessionManager
  │     启动 UDP 发现监听（7916）
  │     启动控制平面 HTTP（7917-7920 起）
  │
  ├─ 2. register_methods(ctx, &state)
  │     注册所有 player.* 方法
  │
  ├─ 3. 订阅事件
  │     kernel.plugin.state → rm 停用时清理会话
  │
  └─ 4. 贡献 UI 页面
        ctx.call("core-ui", "ui.contribute", json!({...}))
```

### 4.3 端口分配

| 功能 | 默认端口 | 占用顺延 |
|---|---|---|
| 发现（UDP） | 7916 | 临时端口 |
| 控制平面（HTTP） | 7917–7920 | 顺序顺延 |

## 6. 运行时依赖

| 工具 | 用途 | 缺失时降级行为 |
|---|---|---|
| ffmpeg | P0 e2e 夹具、ffprobe 轨枚举 | ffprobe 缺失 → 返回空轨列表；ffmpeg 缺失 → e2e 跳过 |
| poppler-utils | P1 PDF 渲染（pdftoppm/pdfinfo） | 缺失 → PDF 查看器显示降级提示 |
| DRM sysfs (`/sys/class/drm`) | P2 输出设备枚举（Linux） | 缺失 → 兜底 `local-0` 虚拟输出 |
| libmpv | 所有音视频播放 | 缺失 → player 根本无法链接 |
| Landlock + seccomp | P5 沙箱隔离（Linux） | 缺失 → sandbox 如实降级，`isolation=degraded` |

## 7. 常见构建问题

### Q: Windows 上找不到 mpv.lib？
A: 确认 `run/mpv-sdk/` 里有 `mpv.lib`。如果用了新的 MPV dev 包，需要重新 dumpbin + lib.exe 生成。详见 §2.1。

### Q: link.exe 报 "unresolved external symbol mpv_*"？
A: mpv.lib 版本不匹配。确认 libmpv-2.dll 和 mpv.lib 是从同一个 dev 包来的（符号导出表必须一致）。

### Q: Linux 上报 libmpv.so 找不到？
A: 先 `sudo apt install libmpv-dev`，然后构建时设置 `MPV_SDK=/usr` 环境变量。

### Q: player 激活后报 "E_PLUGIN_MISSING: resources-manager"？
A: player 清单声明了 `requires.plugins = ["resources-manager@1"]`。先装 rm，再装 player。或者先装 player 它会保持 pending，等 rm 装上后自动激活。
