# 03 沙箱与远程执行

> 本文档聚焦 player 最"重"的两个功能：P5 **沙箱运行**（隔离执行任意 exe/apk）和 P7 **远程执行**（让对端跑程序、远程控制、会话接力）。
> 
> 设计层面的沙箱安全模型见 `docs/player/01-总体设计.md` §6。

## Part A：P5 沙箱运行

### 1. 为什么需要沙箱？

player 的设计目标是"内容执行器"——不仅播放媒体，还要能运行 exe/apk 等应用。但执行不受信任的程序有风险：

| 风险 | 例子 |
|---|---|
| 文件系统越权 | setup.exe 偷偷读 Documents |
| 网络越权 | 安装回连 C2 |
| 后台存活 | 程序退出但子进程还在跑 |

沙箱的目标：**让被执行的程序以为自己在完整系统里，但实际上只能接触指定目录、不能联网、退出后不留余孽**。

### 2. SandboxOpts — 权限配置入口

```rust
pub struct SandboxOpts {
    /// 允许程序访问的目录（默认只有沙箱自身目录）
    pub allow_dirs: Vec<PathBuf>,

    /// 是否允许程序联网（默认 false）
    pub allow_network: bool,

    /// 程序退出后是否留后台进程（默认 false）
    pub allow_background: bool,
}
```

### 典型配置

```rust
// 场景 1：安全运行安装包
SandboxOpts {
    allow_dirs: vec![temp_dir.join("install_source")],
    allow_network: false,
    allow_background: false,
}

// 场景 2：运行需要联网的游戏
SandboxOpts {
    allow_dirs: vec![game_install_dir],
    allow_network: true,
    allow_background: false,
}
```

### 3. player.run 完整流程

```
player.run(target, sandbox_opts)
  │
  ├─ 1. 解析 target
  │     ├─ 有 placement_id → call rm.stream.get_local_path
  │     │       └─ 拿到 exe 本地路径
  │     └─ 有 app_path → 直接用
  │
  ├─ 2. sandbox::prepare(&sandbox_opts)
  │     ├─ 创建隔离目录 `<data_dir>/sandbox/<run_id>/`
  │     ├─ 写入 allowed list 文件
  │     └─ 平台特定的隔离准备
  │
  ├─ 3. std::process::Command::new(app_path)
  │     ├─ 设置 cwd = sandbox_dir
  │     ├─ sandbox::install(&mut cmd, &sandbox)   ← 关键！
  │     ├─ spawn() → 拿到 child
  │     └─ 登记 RunRow { pid, state=Running, ... }
  │
  ├─ 4. spawn monitor 线程
  │     ├─ child.wait() → 等进程退出
  │     ├─ 更新 RunRow.state → Stopped / Crashed
  │     ├─ sandbox::process_alive 检查残留子进程
  │     │   └─ 有残留 → sandbox::kill_process_group
  │     └─ 广播 player.run.done
  │
  └─ 5. 返回 { run_id, pid }
```

### 4. 跨平台实现：Unix vs Windows

#### 4.1 Unix（Linux）— 真正的隔离

```rust
#[cfg(unix)]
pub fn install(cmd: &mut Command, opts: &SandboxOpts) -> Result<InstallResult> {
    // Level 1: 文件系统 — Landlock
    landlock::restrict_paths(&opts.allow_dirs)?;
    // 进程只能访问 allow_dirs 里的文件 + 系统库目录

    // Level 2: 网络 — seccomp
    if !opts.allow_network {
        seccomp::deny_syscalls(&["connect", "sendto", "sendmsg"])?;
        // connect 等 syscall 返回 EPERM
    }

    // Level 3: 进程组 — 清理残留
    unsafe { cmd.pre_exec(move || {
        libc::setsid();  // 新建 session，方便 kill process group
        Ok(())
    }); }

    Ok(InstallResult { isolation: IsolationLevel::Full, sandbox_dir })
}
```

#### 4.2 Windows — 降级方案

```rust
#[cfg(not(unix))]
pub fn install(cmd: &mut Command, opts: &SandboxOpts) -> Result<InstallResult> {
    // Windows 没有 Landlock/seccomp 的等价方案
    // 降级为：
    // 1. 进程组标记（job object）方便后续 kill
    // 2. cwd 隔离（程序默认只在沙箱目录里）
    // 3. 没有真正的文件系统权限限制

    // 警告日志
    eprintln!("sandbox isolation degraded on Windows; no filesystem/network enforcement");

    Ok(InstallResult { isolation: IsolationLevel::Degraded, sandbox_dir })
}
```

#### 4.3 能力检测

```rust
pub fn check_capabilities() -> SandboxCapabilities {
    SandboxCapabilities {
        landlock_available: cfg!(unix) && landlock_supported(),
        seccomp_available: cfg!(unix),
        isolation_level: if cfg!(unix) { Full } else { Degraded },
    }
}
```

激活时 player 会检查并记录日志：

```
sandbox: Landlock=available, seccomp=available, isolation=full    (Linux)
sandbox: Landlock=N/A, seccomp=N/A, isolation=degraded            (Windows)
```

### 5. 进程存活检查与终止

#### 跨平台 API

```rust
pub fn process_alive(pid: u32) -> bool {
    #[cfg(unix)] {
        // 发信号 0，检查进程是否还在
        unsafe { libc::kill(pid as i32, 0) == 0 }
    }
    #[cfg(not(unix))] {
        // Windows: tasklist | find pid
        let output = Command::new("tasklist")
            .args(["/FI", &format!("PID eq {}", pid)])
            .output();
        output.map(|o| o.stdout.contains(&pid.to_string())).unwrap_or(false)
    }
}

pub fn kill_process_group(pid: u32) -> Result<()> {
    #[cfg(unix)] {
        // 杀整个进程组
        unsafe { libc::kill(-(pid as i32), libc::SIGKILL) };
    }
    #[cfg(not(unix))] {
        // Windows: taskkill /T /F /PID pid
        Command::new("taskkill")
            .args(["/T", "/F", "/PID", &pid.to_string()])
            .output()?;
    }
    Ok(())
}
```

## Part B：P7 远程执行

### 1. 远程执行是什么

player 作为"内容执行器"，不仅能在**本机**运行程序/播放媒体，还能让**局域网另一台设备**替你运行。

| 场景 | 例子 |
|---|---|
| 远程运行程序 | 在笔记本上点"运行 setup.exe" → 实际跑在书房 Windows → 画面投到手机 |
| 远程查看 | 客厅电视盒子只有 lite player → 书房 PC 的 player 解码 → 帧流推给电视 |
| 会话接力 | 在书房看到 32:15 暂停 → 走到客厅打开同一个内容 → 从 32:15 继续 |

### 2. 控制平面架构

### 3. 远程方法处理（control.rs）

```rust
fn remote_run(state: &PlayerState, args: Value) -> Result<Value, CallError> {
    let peer_id = args["peer_id"].as_str().ok_or(...)?;
    let target = args["target"].clone();
    let sandbox = args.get("sandbox").cloned();

    // 1. 解析 peer → HTTP 地址
    //    优先从 rm pairing 拿；其次从 discovery 拿
    let peer_url = resolve_peer(state, peer_id)?;

    // 2. POST /remote/run { target, sandbox }
    let url = format!("{}/remote/run", peer_url);
    let resp = http_post(&url, &json!({
        "target": target,
        "sandbox": sandbox,
    })).map_err(|e| CallError::new("E_PLAYER_REMOTE", e.to_string()))?;

    Ok(resp)  // { run_id, pid }
}
```

### 4. 控制平面 HTTP 服务

```rust
pub fn start(preferred_port: Option<u16>) -> Result<ControlHandle> {
    // 监听 7917（被占用就顺延 7918/7919/7920）
    let port = preferred_port.unwrap_or(7917);
    let listener = TcpListener::bind(format!("127.0.0.1:{}", port))?;
    // 或者 0.0.0.0（局域网可达）

    // spawn accept 循环
    tokio::spawn(async move {
        loop {
            let (stream, _addr) = listener.accept().await;
            tokio::spawn(handle_connection(stream, state.clone()));
        }
    });

    Ok(ControlHandle { port, listener })
}
```

### 7. 会话接力（LWW 跨机）

接力的核心是"两边对同一 session_id 做最后写入者赢"（LWW）合并：

```
player A 的 session 状态: pos=32.15, volume=80, track=2
player B 的 session 状态: pos=31.00, volume=100, track=1

sync 推送后合并（LWW，按 timestamp）：
  pos      → A 的 32.15 更新（时间戳新）
  volume   → B 的 100 更新（B 最近调过音量）
  track    → A 的 2 更新（A 最近切过轨）

结果 B 从 pos=32.15 继续，volume=100，track=2
```

### 8. 控制平面与 discovery 的关系

| 功能 | 端口 | 协议 | 用途 |
|---|---|---|---|
| discovery | 7916 | UDP | player B 定期发心跳到局域网，player A 发现有哪些接收器 |
| control | 7917–7920 | HTTP | player A 主动连 player B 的控制平面，发远程执行请求 |

player B 启动时：
1. `DiscoveryState::ensure_listener()` → UDP 7916 监听
2. `control::start(Some(7917))` → HTTP 7917 监听
3. 心跳里同时带上自己的 control port：`{"id":"xxx", "control_port":7917}`

player A 发 remote.run 时：
1. `resolve_peer(peer_id)` → 先查 rm pairing（权威），没有查 discovery 表
2. 拿到 ip + control_port → `http://{ip}:{port}/remote/run`

### 9. 安全考虑

| 措施 | 说明 |
|---|---|
| 控制平面绑 `127.0.0.1`（默认） | 局域网其他设备不能直接发远程执行请求 |
| 或者绑 `0.0.0.0` + rm pairing 认证 | 只有已配对设备能互发 remote.run |
| 远程 run 目标也走沙箱 | 即使远程执行，目标进程也被 SandboxOpts 限制 |
