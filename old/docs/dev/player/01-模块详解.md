# 01 模块详解

> player 按"五区模型"组织源码：**传输区（Source）**、**功能区（Capability）**、**输出区（Sink）**、**会话区（Session）**、**发现区（Discovery）**。每个区对应一组源文件。
> 
> 设计层面的五区模型详解见 `docs/player/01-总体设计.md` §3。

## 1. lib.rs — 插件入口 + PlayerState

### PlayerState — 核心运行时状态

```rust
pub struct PlayerState {
    pub ctx: Context,
    pub sessions: SessionManager,
    pub selected_output: Mutex<Option<Selected>>,      // P2：当前选中的输出设备
    pub casts: Mutex<HashMap<String, CastState>>,       // P3：进行中的投屏（session_id → CastState）
    pub runs: Arc<RunRegistry>,                         // P5：运行表（监控线程与停用即杀共享）
    pub store: Option<Store>,                           // P6：player.db（打开失败 → 降级纯内存）
    pub control: Mutex<Option<ControlHandle>>,          // P7：控制平面 HTTP 句柄
    pub sync_marks: Mutex<HashMap<String, (f64, u64)>>, // P7：同步节流 mark（content_id → (pos, timestamp)）
    pub sync_applied: AtomicU64,                        // P7：接收侧合入计数
    pub sync_ignored: AtomicU64,                        // P7：接收侧丢弃计数
}
```

### 激活流程

```rust
fn activate(&mut self, ctx: Context) -> Result<(), ActivateError> {
    // 1. 打开 player.db（打开失败降级为纯内存）
    let store = Store::open(ctx.data_dir().join("player.db")).ok();
    let sessions = SessionManager::restore(&store);

    // 2. 启动 UDP 发现监听（进程级 DiscoveryState）
    DiscoveryState::ensure_listener();

    // 3. 启动控制平面 HTTP（P7，端口全忙 → Mutex<Option<None>> 降级）
    let control = control::start(Some(7917)).ok();

    // 4. 注册所有 player.* 方法
    register_methods(&ctx, &state)?;

    // 5. 订阅 kernel.plugin.state，rm 停用时清理会话
    // ...

    // 6. 贡献 UI 页面（shell.html, control.html, viewer.html）
    ctx.call("core-ui", "ui.contribute", json!({...}))?;

    Ok(())
}
```

## 2. backend.rs — MpvBackend

**一句话**：封装 libmpv C 接口，向上层暴露 `start` / `load` / `load_at` / event 回调。是音视频播放的唯一后端。

```rust
pub struct MpvBackend {
    ctx: *mut mpv_handle,
    stop_flag: Arc<AtomicBool>,
    event_handle: Option<JoinHandle<()>>,
}

pub enum BackendEvent {
    Progress { position: f64, duration: f64 },
    Paused,
    Resumed,
    Finished,
    Failed { reason: String },
}
```

### 关键方法

| 方法 | 说明 |
|---|---|
| `start() -> Self` | 创建 mpv 实例，设置 OSD、vo=libmpv、起事件线程 |
| `load(&self, url: &str)` | `mpv_command_string("loadfile", [url])` |
| `load_at(&self, url: &str, start_sec: f64)` | 续播：load → 等 duration ready → `mpv_command_string("seek", [start_sec, "absolute"])` |
| `pause/resume` | `mpv_command_string("cycle", ["pause"])` 或直接 set property |
| `seek(seconds)` | `mpv_command_string("seek", [seconds, "absolute"])` |
| `set_volume(v)` | `mpv_set_property_double("volume", v)` |
| `set_subtitle_track(index)` | `mpv_set_property_int("aid", index)` |
| `event_pump` | 线程循环 `mpv_wait_event` → 把 libmpv 事件转成 BackendEvent → 回调上层 |

### 事件线程

```
event_pump() 循环：
  ├─ mpv_wait_event(timeout)
  ├─ 匹配 event_id：
  │   ├─ MPV_EVENT_TIME_POSITION → BackendEvent::Progress
  │   ├─ MPV_EVENT_PAUSE → BackendEvent::Paused
  │   ├─ MPV_EVENT_UNPAUSE → BackendEvent::Resumed
  │   ├─ MPV_EVENT_END_FILE → BackendEvent::Finished (正常) / Failed (错误)
  │   └─ MPV_EVENT_FILE_LOADED → 等待 duration ready 后报告
  └─ stop_flag 置位 → 退出循环
```

## 4. run.rs — player.run 执行

**一句话**：`player.run` 的完整实现。启动子进程（exe/apk），用沙箱隔离，登记运行表，监控生命周期。

### 主流程

```
player.run(target, sandbox_opts)
  │
  ├─ 1. 解析 target
  │     ├─ 有 placement_id → call rm.get_local_path / stream.open → 得到本地路径或 URL
  │     └─ 有 app_path → 直接用
  │
  ├─ 2. sandbox::prepare(&sandbox_opts)
  │     准备隔离目录（Unix Landlock / Windows 降级）
  │
  ├─ 3. Command::new(app_path)
  │     sandbox::install(cmd, &sandbox)  ← 把隔离策略安装到 Command
  │     spawn()
  │
  ├─ 4. 登记 RunRow 到 RunRegistry
  │     { run_id, pid, state=Running, stdin_pipe, ... }
  │
  └─ 5. spawn monitor 线程
        等进程退出 → 更新 state → 广播 player.run.done
```

### RunRow + RunRegistry

```rust
pub struct RunRow {
    pub run_id: u64,
    pub pid: u32,
    pub state: RunState,    // Running / Stopped / Crashed
    pub sandbox_dir: PathBuf,
    pub input_tx: Option<Sender<InputEvent>>,  // 远程输入管道
    pub log: Vec<String>,                       // 进程 stdout/stderr
}

pub struct RunRegistry {
    rows: HashMap<u64, RunRow>,
}
```

| 方法 | 说明 |
|---|---|
| `register(pid, sandbox_dir)` | 登记运行中的进程 |
| `get(run_id)` | 查找 |
| `stop(run_id)` | 发 SIGTERM → 等 5s → SIGKILL |
| `kill_non_background()` | 退出时清理所有非后台进程 |

## 5. sandbox.rs — 跨平台沙箱

**一句话**：P5 沙箱的跨平台实现。Unix 用 Landlock + seccomp 做真正的隔离；Windows 没有等价方案，降级为"进程存活检查 + 终止能力"。

### 降级策略

```rust
pub struct SandboxOpts {
    pub allow_dirs: Vec<PathBuf>,         // 进程能访问的目录（Unix 有效）
    pub allow_network: bool,              // Unix seccomp 网络系统调用拦截
    pub allow_background: bool,           // 进程退出后是否留后台
}

pub struct InstallResult {
    pub isolation: IsolationLevel,  // Full / Partial / Degraded
    pub sandbox_dir: PathBuf,
}
```

### 跨平台公开 API

| 函数 | Unix 实现 | Windows 实现 |
|---|---|---|
| `prepare(opts)` | 创建空目录 + 写入 allowed list | 同（目录还是要建） |
| `install(cmd, opts)` | Landlock restrict_paths + seccomp filter | 无操作（降级） |
| `process_alive(pid)` | 信号 0 / /proc | `tasklist` 查进程 |
| `kill_process_group(pid)` | kill(-pgid, SIGKILL) | `taskkill /F /T /PID pid` |

### 平台条件编译

```rust
#[cfg(unix)]
fn landlock_install(cmd: &mut Command, opts: &SandboxOpts) -> Result<()> {
    landlock::restrict_paths(&opts.allow_dirs)?;
    seccomp::filter_network()?;
    Ok(())
}

#[cfg(not(unix))]
fn landlock_install(_cmd: &mut Command, _opts: &SandboxOpts) -> Result<()> {
    Ok(())  // 降级
}
```

## 6. router.rs — 自动路由

**一句话**：P4 自动路由策略 `auto_select_mode`，按接收器 codec、内容编码、带宽选择最佳串流模式。

```rust
pub enum CastMode {
    A,  // 字节转发：原文件给对端，对端自己解码（接收器必须支持内容编码）
    B,  // 重编码：本机解码 → 重新编码（如 H.264） → 推流
    C,  // 帧流：解码帧经 JPEG 压缩直接推（延迟最低但带宽大）
}

pub fn auto_select_mode(
    receiver_codecs: &[String],
    content_codec: &str,
    bandwidth_mbps: u32,
) -> CastMode
```

| 条件 | 选模式 |
|---|---|
| receiver_codecs 包含 content_codec | A（字节转发，最省资源） |
| receiver_codecs 不包含，但带宽足够 + 对端支持 | B（重编码） |
| 带宽不足 + 对端是 lite 接收器 | C（帧流） |

## 7. discovery.rs — UDP 接收器发现

**一句话**：P3 局域网发现。UDP 7916 监听，接收器定期发心跳入表，超时清理。

```rust
pub const DISCOVERY_PORT: u16 = 7916;
pub const TTL_SECS: u64 = 10;

pub struct ReceiverInfo {
    pub id: String,
    pub name: String,
    pub ip: String,
    pub port: u16,
    pub state: ReceiverState,   // Online / Offline
    pub codecs: Vec<String>,    // 接收器支持的编码
    pub last_seen: Instant,
}

pub struct DiscoveryState {
    receivers: Mutex<HashMap<String, ReceiverInfo>>,

```

### 协议

```
接收器 → player: UDP 7916
Body: {"op":"heartbeat", "id":"xxx", "name":"客厅电视", "port":7917, "codecs":["h264","aac"], "control_port":7917}

player 定期清理：last_seen > TTL_MS (3秒) → 标记 Offline → 从表移除
```

### 常量


## 8. control.rs — 控制平面 + 远程执行

**一句话**：P7 同步推送 + 远程执行 + 控制平面 HTTP 服务。是 player 跨设备接力/远程跑程序的核心。

### 同步推送

```rust
pub enum SyncMode {
    Manual,          // 用户显式触发
    OnPlay,          // 开始播放时自动推
    OnPauseSeek,     // 暂停/跳转时推
}

pub fn push_sync(ctx: &Context, session: &Session, peer_id: &str) -> Result<()> {
    // 1. 解析 peer 的 HTTP 地址（通过 rm pairing 或 discovery）
    let peer_url = resolve_peer(peer_id)?;

    // 2. POST /sync { session_id, position, volume, subtitle_track, ... }
    let resp = http_post(&format!("{}/sync", peer_url), &payload)?;

    // 3. 广播 player.sync.pushed
    ctx.emit("player.sync.pushed", json!({...}))?;
}
```

### 远程执行（remote.run）

```rust
// player.remote.run 处理函数
fn remote_run(state: &PlayerState, args: Value) -> Result<Value, CallError> {
    let peer_id = args["peer_id"].as_str().ok_or(...)?;
    let target = args["target"].clone();
    let sandbox = args.get("sandbox").cloned();

    // 1. 解析 peer → HTTP 地址
    let peer_url = resolve_peer(state, peer_id)?;

    // 2. POST {peer_url}/remote/run { target, sandbox }
    //    对端 player 收到后会调自己的 player.run 流程
    let resp = http_post(&format!("{}/remote/run", peer_url), &payload)?;

    Ok(json!({ "run_id": resp["run_id"] }))
}
```

### 控制平面 HTTP 服务

```
player control plane 监听端口 7917-7920（启动时自动选可用端口）

路由：
  POST /sync              ← 同步推送目标
  POST /remote/run        ← 远程执行发起
  POST /remote/run/{id}/stop
  POST /remote/run/{id}/input
  GET  /remote/run/{id}/log
  GET  /remote/caps
```

### SyncMode 节流

同步推送不盲目每次都发——有节流逻辑：
- `OnPlay`：只在 `is_playing` 时推送，位置变化超过阈值才发
- `OnPauseSeek`：暂停/跳转动作立即发，播放过程只在 seek 后发一次
- 节流防止局域网被连续同步打爆

## 10. image_cap.rs / pdf_cap.rs — 非 mpv 功能

图片和 PDF 不走 mpv，用各自的渲染器：

| 模块 | 功能 | 依赖 |
|---|---|---|
| `image_cap.rs` | 打开图片 → `image` crate 解码 → 写入临时目录 → viewer 展示 | image crate |
| `pdf_cap.rs` | 打开 PDF → `poppler-utils` 转 ppm → viewer 展示 | pdftoppm / pdfinfo |

### P1 降级

如果 pdftoppm 找不到 → `isolation=degraded` → PDF 查看器只显示"安装 poppler-utils"提示。
