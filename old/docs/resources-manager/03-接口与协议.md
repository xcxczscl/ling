# 03 接口、协议与代码规矩

> 版本：v0.12 ｜ 状态：已封档（终审通过；M1–M6 编码完成）
> 本文回答：**resources-manager 对外提供哪些接口、用什么命令、遵守什么传输协议、代码按什么规矩写。**
> 数据含义见 `02-数据字典.md`；设计理由见 `01-总体设计.md`；插件怎么装载、怎么注册方法见 `../../ling/docs/04-插件接口规范.md`。

## 1. 接口总览

本插件有**四种入口**，全部汇聚到 **ling 宿主**（本插件不自己开服务器）：

| # | 入口 | 谁在用 | 走什么通道 |
|---|---|---|---|
| 1 | 图形界面 / 网页 | 人 | core-ui 网关的本机回环 HTTP 接口（见 §2） |
| 2 | 命令行 `rmgr` | 人、脚本 | 同一套 HTTP 接口，或 `--standalone` 直跑本插件代码（见 §3） |
| 3 | 事件推送 | 图形界面刷新用 | WebSocket `/events`，由 core-ui 托管（见 §4） |
| 4 | 插件内互调 | 其他插件（如记账插件） | ling 内核的接口方法路由，进程内直接调用，不过网络（见 §2.4） |

**端口**：core-ui 网关默认 `7910`。被占用时自动顺延（7911、7913…；`7912` 留给局域网传输面，见下）。实际端口写入 `ling/registry.json`，窗口壳和命令行自动读取。

**鉴权**：ling 启动时生成随机口令写入 `ling/session.json`（文件权限 0600）。所有 HTTP 请求必须带请求头 `X-Ling-Token: <口令>`。窗口壳和命令行自动读取该文件；浏览器首次访问时需粘贴口令。

**例外只有两个**（其余一律走 core-ui 网关，本插件不再开别的服务器）：

| 例外 | 承载什么 | 端口 | 鉴权 | 出处 |
|---|---|---|---|---|
| 流数据面 | `stream.open` 返回 URL 的内容字节 | 本机回环，动态端口，URL 自带 | URL 内 128-bit token | §2.6、01 附录 A-17 |
| 局域网传输面（M3） | `/hello` `/pair` `/blob` `/op/*`（配对、按需取回文件本体、记录同步） | LAN 可达，默认 `7912`，占用自动顺延，实际端口写入 `ling/registry.json` 与 `data_dir/transfer.json` | Ed25519 签名头 + 配对码（§5.2） | §5.2、01 §7.6 |

业务 API（上表 1–4）**仍 100% 走 core-ui 网关**；两个例外只承载字节与配对握手，不承载业务方法。

## 2. 本机 HTTP 接口

### 2.1 请求格式

- 地址：`POST http://127.0.0.1:7910/rpc`
- 请求头：`Content-Type: application/json`、`X-Ling-Token: <口令>`
- 请求体（JSON）：

```json
{
  "id": "请求编号，客户端生成，用于对应响应",
  "plugin": "resources-manager",
  "method": "scan.start",
  "params": { "location_id": "lc_home", "full": false }
}
```

core-ui 网关收到后转给 ling 内核的接口方法路由，路由把调用转给 resources-manager 插件（整条链路见 `../../ling/docs/06-内置插件设计.md` §4.1）。

### 2.2 响应格式

成功：
```json
{ "id": "同上", "ok": true, "result": { "job_id": "jb_scan_001" } }
```
失败：
```json
{ "id": "同上", "ok": false,
  "error": { "code": "F101", "message": "位置不存在：lc_home" } }
```

> 业务错误码 `F###` 归 resources-manager；`E_*`（如 `E_CAPABILITY_DENIED`）是 ling 内核错误码，清单见 `../../ling/docs/04` §8。

### 2.5 安全删除的行为约定（接口层面）

调用 `dup.delete` 时：
1. 后端先跑 `01-总体设计.md` §7.3 的四道检查。
2. 全部通过 → 返回 `{deleted: n}`。
3. 任一不通过 → 返回 `{blocked: {reason, detail}}`，HTTP 状态仍是 200（这是业务结果不是网络错误），但**结果里带 `blocked` 字段**；命令行据此返回退出码 3。
4. `force=true` 可跳过部分检查，但会在结果里返回 `risk_record_id`（写入一条风险记录，可审计）。

### 2.6 流交付契约（stream.open / get_local_path）

**定位**：把池中内容以**逻辑字节流**交付给消费插件（播放/运行/文档渲染）。逻辑流 = resources-manager 读池、按需解压，压缩（`enc=zstd`）对消费者透明；磁盘上的物理字节不是契约对象。设计决策见 01 附录 A-17；A-12 的"预留接口"以此为准升格为正式契约。

**消费场景对照**：

| 场景 | 用法 |
|---|---|
| 音视频 seek、图片整读、PDF 页读 | `stream.open` → 对返回 URL 发 HTTP 请求（Range 语义） |
| 运行 exe/apk（必须交给操作系统执行） | `get_local_path` → 消费插件自行沙箱执行 |
| M3 局域网传输 | **不走本契约**——走既有 `/blob` 配对鉴权协议（§5.2）；本契约 v1 仅限本机回环 |

#### 2.6.1 `stream.open`

```jsonc
// 请求
{ "placement_id": "10241", "purpose": "play" }
// purpose 可选：play / render / copy，仅作审计与统计，不影响权限
// 响应
{
  "stream_id": "st_7c3f…",
  "url": "http://127.0.0.1:7913/s/st_7c3f…/<token>",
  "content_len": 42949672960,   // 逻辑长度（解压后）
  "seekable": true,
  "idle_ttl_sec": 600           // 空闲 10 分钟自动过期
}
```

#### 2.6.2 HTTP 语义（对 `url` 直接请求，无需网关口令——鉴权靠 URL 中的 token）

| 请求 | 响应 |
|---|---|
| `GET` + `Range: bytes=a-b` | `206 Partial Content` + `Content-Range`；**seek 靠它** |
| `GET`（无 Range） | `200 OK` 整流（整读也支持，推荐大文件带 Range 分段） |
| `HEAD` | 返回 `Content-Length` 等响应头 |
| 每次成功请求 | **刷新空闲计时**（活跃即续期） |
| token 无效 / 过期 / 放置已离线或删除 | `403`，固定文案不泄露放置信息；放置状态**每次请求实时查**，离线立即断流 |

#### 2.6.3 token 机制（最小授权、可收回）

| 规则 | 理由 |
|---|---|
| 128 位随机数，拼在 URL 路径中 | 无状态校验，不查库 |
| **内存态，不落盘**：插件重启 / 热更新后全部失效，消费者重新 `stream.open` | 与"内存不留状态"原则一致（01 A-5）；失效重开代价极小 |
| 一个 token 只绑**一个 placement** | 最小授权：不能借一个 token 读整个池 |
| 只绑 `127.0.0.1`；访问日志只记 `stream_id` 不记完整 token | 本机限定 + 防日志泄漏 |
| token 与路径的区别 | **token 收得回，路径给出去收不回**——所以默认交付是流，路径仅限"必须执行"场景 |

#### 2.6.4 `get_local_path`（仅运行/外调场景）

| 检查 | 结果 |
|---|---|
| `state=online` 且 `enc=plain` | 返回 `{path}` |
| 离线 / 冷 / 丢失 | `F501 数据当前不可用` |
| 内容已压缩（`enc=zstd`） | `F503 当前形态不支持路径交付`（未来的"物化临时文件"接口再说） |

**消费者责任**：拿到路径 = 拿到无期限读权，插件无法收回；沙箱与生命周期责任在消费插件（A-12：运行 exe/apk 绝不能与本插件同进程）。

#### 2.6.5 错误码（F5xx 族）

| 码 | 含义 |
|---|---|
| `F501` | 数据当前不可用（离线/冷/丢失） |
| `F502` | stream token 无效或过期（HTTP 层表现为 403） |
| `F503` | 当前形态不支持该交付方式（如压缩内容要求路径） |
| `F504` | 流服务未启动 / 端口分配失败（提示重试 `stream.open`） |

> 池与归纳相关业务错误码：`F801` 池非空 / `F802` 目标空间不足 / `F803` 源端离线（排队） / `F804` 校验失败已回滚——在 `pool.*` 方法中返回，HTTP 状态仍是 200（业务结果不是网络错误，同 §2.5 惯例）。

### 2.7 业务错误码总表（F 族）

> 内核错误码 `E_*` 见 ling/docs/04 §8；本表只登记 resources-manager 的业务错误码 `F###`。
> **编码族规约**：`F1xx` 位置与设备 / `F2xx` 词条与版本 / `F3xx` 通用业务（含安全删除拦截） / `F4xx` 局域网传输与配对（M3） / `F5xx` 流交付 / `F6xx` 备份与压缩（M4） / `F7xx` AI 建议（M5） / `F8xx` 池与归纳。新增错误码必须先入本表再进代码。

| 码 | 含义 | 首次出现 |
|---|---|---|
| `F101` | 位置不存在（如 `lc_home`） | §2.2 示例 |
| `F301` | 通用业务错误占位示例（具体错误按族在实现期登记于此） | §6.3 |
| `F401` | 配对码无效或已过期 | §2.3 `device.pair` |
| `F402` | 身份指纹不匹配（证书被更换，防中间人；已 pin 的对端拒绝连接） | §2.3 `device.pair` |
| `F403` | 冷备份副本不作为数据源 / 策略禁止取回（`local_only`、`record_only`） | §5.2 |
| `F404` | 对端不可达（连接超时、端口未开） | §2.3 `transfer.fetch` |
| `F405` | 传输块或整文件校验失败（已写入的数据不可信，任务标记失败） | §5.2 |
| `F501` | 流交付：数据当前不可用（离线/冷/丢失） | §2.6 |
| `F502` | 流交付：token 无效或过期（HTTP 层 403） | §2.6 |

## 5. 协议（§5.1–§5.4 已冻结）

> §5.1 记录同步（M2 起）、§5.2 局域网传输（M3）、§5.3 备份段格式（M4）、§5.4 AI 与刮削（M5）均已实现并冻结格式；真实 Ollama/云端 Provider 与资料站插件接口已冻结，占位实现待环境具备后接入。

### 5.1 记录同步协议（M2 实现，M3 换传输）

**目标**：两台设备交换"文件清单"，只同步记录，不同步文件数据。

**流程**：
```
第 1 步  A → B：{类型:"你好", 设备号, 身份指纹, 我知道你已同步到第几号}
第 2 步  B → A：{类型:"流水", 从你缺的那号开始, 最多 1000 条操作}
第 3 步  A 逐条应用（按操作全局编号去重，重复的直接跳过），更新进度
第 4 步  换方向重复 1–3；循环直到双方都没有新操作
```

**传输通道**：M2 走文件桥（`sync.export`/`sync.import` JSON 包）；**M3 起改走局域网面的 `/op/export` 与 `/op/import`**（报文与文件桥完全相同，只换通道；鉴权与配对见 §5.2）。对端无 `addr`（未真握手）时 `sync.run` 仍返回 bridge 提示。

**合并规则**：见 `01-总体设计.md` §7.5（内容不可变、位置状态只由所属设备改写、删除走墓碑）。

### 5.2 局域网配对与数据传输协议（M3）

| 项目 | 规定 |
|---|---|
| 身份 | 首次运行生成 Ed25519 密钥 + 自签证书；指纹 = 公钥的 SHA-256 前 16 字节，RFC 4648 Base32（大写、无填充，26 字符），前缀 `sha256:` |
| 密钥存放 | `data_dir/identity.key`，32 字节种子，文件权限 0600；公钥与指纹登记进本机 `device` 表 |
| 配对 | 输入 8 位配对码或扫二维码 → 交换指纹 → 写入对端表；此后证书固定，**更换即拒绝（F402）** |
| 传输 | `GET /blob/{内容指纹}?offset=&len=`；每 4 MB 一块附校验值；8 条并行连接 |
| 断点续传 | 从最后一次确认的偏移继续（未验校验的字节不计入确认偏移） |
| 限制 | 状态为 `cold` 的位置**永远不作为数据源**（服务端直接 F403） |
| 端口 | LAN 监听默认 `7912`，占用自动顺延；实际端口写 `ling/registry.json` 与 `data_dir/transfer.json` |

**端点一览**（HTTP/1.1，JSON 报文体；`/blob` 为二进制帧）：

| 端点 | 鉴权 | 说明 |
|---|---|---|
| `GET /hello` | 无 | `{device_id, fingerprint, proto}`，供配对前核对身份 |
| `POST /pair` | 配对码 | 双向 Ed25519 握手，见下 |
| `GET /blob/{blake3}?offset=&len=` | 签名头 | 按需取回内容字节，见下 |
| `GET /op/export?after=&limit=` | 签名头 | 导出 op 流水（报文同 §5.1） |
| `POST /op/import` | 签名头 | 导入 op 流水（报文同 §5.1） |

**配对握手（`POST /pair`）**：

```
请求体：{code, device_id, name, platform, pubkey, ts, sig}
  sig = Ed25519(我方私钥, "rm-pair|code|device_id|pubkey|ts")
响应体：{device_id, name, platform, pubkey, fingerprint, ts, sig}
  sig = Ed25519(对端私钥, "rm-pair|peer_device_id|peer_pubkey|ts")
```

- 配对码由**监听端**经 `device.pairing_code` 生成，内存态、10 分钟过期、一次性（用过即失效）；码错或过期 → F401。
- 发起端核对响应中的 `fingerprint`，写入 `peer` 表；监听端同样写入发起端。**若 `peer` 表已有该 `device_id` 而指纹不同 → F402 拒绝**（防中间人/换证书）。

**传输鉴权头**（`/blob` 与 `/op/*` 全部携带）：

```
X-Rm-Device: <device_id>
X-Rm-Ts: <Unix 秒>
X-Rm-Sig: <Base64(Ed25519 签名)>
  签名串 = "rm-blob|<blake3>|<offset>|<len>|<ts>"   （/blob）
  签名串 = "rm-op|<method>|<body 的 SHA-256>|<ts>"   （/op/*，method ∈ export|import）
```

服务端校验：签名有效、ts 偏差 ≤300 秒、`X-Rm-Device` 在 `peer` 表且指纹 pin 一致；任一不通过 → 403（固定文案，不泄露内容信息）。

**`/blob` 响应体块帧**（二进制，重复到 `len` 字节发完为止）：

```
[u32 块长 N（小端）][32 字节 该块的 BLAKE3][N 字节块数据]
```

- 默认块长 4 MB（`4194304`），最后一块可短。
- 客户端**逐块验校验**：通过才把确认偏移推进 N 字节并落盘；失败 → 整个任务标记 F405，保留 `.part` 供人工处理。
- 传输完成后客户端对整文件再算一次 BLAKE3，与请求的 `blake3` 不符 → F405，不登记 placement。

### 5.3 备份段格式（M4）

```
<备份目标>/
  manifest.json        清单（见下方字段）
  segments/000001.seg  数据段，定长 128 MB（最后一段可短）
  segments.idx         索引（见下方行格式）
  CHECKSUM             清单与索引文件的校验值
```

**`manifest.json` 字段**：

| 字段 | 类型 | 含义 |
|---|---|---|
| `snapshot_id` | 文本 | 快照号（与 `snapshot.id` 一致，形如 `sn_20261017_a1b2`） |
| `created` | 整数 | 生成时间（Unix 秒） |
| `device_id` | 文本 | 发起备份的设备 |
| `location_id` | 文本 | 被备份的位置 |
| `entry_count` | 整数 | 内容条数（去重后） |
| `total_bytes` | 整数 | 原始字节总和 |
| `seg_size` | 整数 | 段长（当前固定 `134217728` = 128 MB） |
| `enc` | 文本 | 整池加密形态：`none` / `placeholder`（见下） |

**`segments.idx` 行格式**：按 `blake3` 升序的 **JSON Lines**（每行一个 JSON 对象，行尾 `\n`）：

```
{"blake3":"<64位十六进制>","seg":3,"off":1048576,"len":4194304,"zstd":true}
```

- `seg` 段号（`segments/%06d.seg`）；`off` 段内偏移；`len` 该内容在段中占的字节（压缩后长度）；`zstd` 是否 zstd 压缩存储。
- **排序的意义**：恢复/校验按指纹二分定位，不必读整个索引。
- 压缩内容的**原始长度**不进索引——恢复时解压到自然结束即可；内容本身的正确性由整文件 BLAKE3 复核保证。

**`CHECKSUM` 行格式**（两行文本）：

```
manifest <manifest.json 的 BLAKE3 十六进制>
index    <segments.idx 的 BLAKE3 十六进制>
```

- 校验顺序：先比 `CHECKSUM` 两个值（清单/索引未被篡改），再按索引抽样或全量核对段内数据。
- **索引与清单都以文件形式落在备份目标上，不进 catalog.db**——备份目标必须能脱离本机打开（灾难恢复的前提）。

- 写入前先查索引：已存在的内容**跳过不写**（天然增量备份）。
- 校验：抽样（默认 1%）或 `--full` 全量；报告"正常 / 不一致 / 缺失"。
- **离线目标**：备份目标不可达 → 作业进 `queued`，目标插上后自动续传（复用 M3 传输机制）；每池记 `last_verified`。
- **从冷备份恢复**：要恢复的内容只在长期不插的盘上时，不报错，排进"待恢复队列"，目标上线后自动继续。

#### 5.3.1 异地池加密（M4 占位，后续替换）

- `manifest.enc = "placeholder"` 表示段数据经**可逆占位加密**后落盘；`"none"` 表示明文。
- **占位算法**（明确标注为占位，禁止当作真实保密手段）：密钥 = `BLAKE3(口令, 个人化串="rm-backup-v1")` 取前 32 字节；流式 XOR，密钥流 = `BLAKE3(key ‖ 段内偏移)` 展开。口令只存用户侧（不落库、不进清单）。
- **换正式 AEAD 的路径**：将来引入 `aes-gcm`/`chacha20poly1305` 后，`enc` 增加 `"aes-gcm"`，段头加 nonce；旧 `placeholder` 数据支持读取迁移。**在换成 AEAD 之前，此加密不提供任何实质保密能力，仅满足"可逆混淆"的占位需求**（用户已确认按此降级）。

### 5.4 AI 与刮削协议（M5）

**5.4.1 数据源插件接口**（`scrape-tmdb` 等）

```
输入：{ 标题, 年份?, 类型 }
输出：{ 候选列表 [ { 资料站, 条目号, 标题, 年份, 链接, 简介?, 封面链接? } ] }
```
- 必须声明 `network` 能力才能访问网络（能力名以 ling/docs/04 §1.3 的集合为准）。
- 结果按（资料站 + 查询词指纹）缓存，默认缓存 30 天。
- 必须带 `来源地址 + 抓取时间`，写入 `entry_ext` 表。

**5.4.2 AI 插件接口**

```
输入：{ 目标对象, 我方上下文(文件名/已提取参数/已有标签), 候选列表? }
输出：{ 建议列表 [ { 种类, 内容, 置信度 } ] }
```
- 输出**只写入建议表**（`ai_suggestion`），绝不直接写业务表。
- 低风险种类（题材标签）在置信度 ≥ 阈值（默认 0.85）时可自动采纳；
- 高风险种类（关系、新建词条、拆分版本）一律 `pending` 待人工确认。

**5.4.3 确定性提取顺序（先跑代码，再跑模型）**

| 顺序 | 手段 | 工具 |
|---|---|---|
| 1 | 扩展名、MIME 类型 | 代码内查表 |
| 2 | 音视频内嵌信息（分辨率、编码、时长） | ffprobe |
| 3 | 图片内嵌信息（拍摄时间、相机型号） | exiftool |
| 4 | 文件名模式（剧集编号、版本号、书号） | 正则 |
| 5 | 目录规则 | 用户规则表 |
| 6 | 以上都搞不定的，才交给大模型 | AI 插件 |

| 数据库列名 | 蛇形 | `rel_path`、`hash_state` |
| 接口方法 | `领域.动作` | `scan.start`、`dup.delete` |
| 事件主题 | `插件.对象.动作` | `resources-manager.job.progress` |
| Rust 类型 | 大驼峰 | `PlacementRepo` |
| Rust 函数/变量 | 小驼峰或蛇形（按 Rust 惯例） | `can_delete` |

### 6.3 错误处理规矩

| 规矩 | 说明 |
|---|---|
| **禁止在业务与文件读写路径使用 `unwrap()` / `expect()`** | 这两种写法遇到错误会让程序直接崩溃。必须用 `Result<T, E>` 向上返回 |
| 一律用 `thiserror` 定义错误类型 | 每个错误带稳定错误码（如 `F301`），方便界面显示与脚本判断 |
| 错误信息用中文、写清楚上下文 | 差：`io error`；好：`无法读取 D:\media\旧港疑云.epub：文件被其他程序占用` |

### 6.4 结构规矩

| 规矩 | 说明 |
|---|---|
| 插件入口必须薄 | `lib.rs` 只做"解析参数 → 调用 commands → 返回结果"，业务全在 `commands/` |
| 同一逻辑只写一份 | 命令行和接口调用同一个 `commands/` 函数，不允许各写一套 |
| 公开函数必须写文档注释 | 说明"做什么、参数含义、可能返回什么错误" |
| 单个函数超过 80 行 | 必须拆分 |
| 接口数据结构只在 `rm-proto` 定义 | 其他地方不得重复定义；前端类型由脚本自动生成 |

### 7.2 端到端测试的固定剧本

```
1. 生成测试目录树（含已知的重复文件、大文件、深目录、中文文件名）
2. 扫描 → 断言文件数、字节数、重复组数与预期一致
3. 查重 → 执行硬链接合并 → 断言磁盘占用下降且文件内容不变
4. 构造"唯一副本"场景 → 执行删除 → 断言被拒绝且退出码为 3
5. 导入规则 → 执行分类 → 断言标签正确且磁盘文件未被移动
6. 建立两个位置模拟两台设备 → 配对 → 同步 → 断言记录一致
7. 把一方标记为离线 → 再同步 → 断言记录不丢、统计正确
8. 构造 30 天前的墓碑 → 断言宽限期逻辑正确
9. 两设备改同一字段不同值 → 同步 → 断言生成 pending 冲突且双方快照完整、非冲突字段自动合并
10. 裁决该冲突（keep_mine / restore_delete 各跑一遍）→ 再同步 → 断言对端收敛、冲突不复活、队列清空
11. （M3）两库各起 LAN 面 → 配对码真握手 → 断言指纹写入 `peer` 表且换证书被拒
12. （M3）`fetch` 一个大文件 → 中途断连 → 重跑断言从确认偏移续传、整文件 BLAKE3 一致、placement 已登记
```
