## 1. 目录树（M1–M4 涉及的全部文件）

```
resources-manager/
├── Cargo.toml                    # Rust 工作区配置：成员清单、统一依赖版本
├── rust-toolchain.toml           # 锁定 Rust 编译器版本
├── README.md                     # 项目首页，指向 docs/
│
├── crates/                       # 核心代码库（纯代码，无界面）
│   ├── rm-proto/                # 接口数据结构定义（唯一来源）
│   │   └── src/{lib,msg,event}.rs
│   ├── rm-fs/                   # 文件系统适配
│   │   └── src/{lib,walk,platform/{unix,windows,android_saf}}.rs
│   ├── rm-catalog/              # 数据库
│   │   └── src/{lib,schema,migrations,repo/{content,placement,device,op,rule,job}}.rs
│   ├── rm-scan/                 # 扫描与分层哈希
│   │   └── src/{lib,walker,filter,hash_tier,scheduler}.rs
│   ├── rm-dedup/                # 去重与安全删除
│   │   └── src/{lib,group,safety_delete}.rs
│   ├── rm-semantic/             # 语义层（词条/版本/标签/关系）
│   │   └── src/{lib,entry,version,tag,connection,instance}.rs
│   ├── rm-sync/                 # 记录同步
│   │   └── src/{lib,merge,oplog,tombstone,conflict}.rs
│   ├── rm-transfer/             # 数据同步（M3）：局域网身份/配对/blob 传输/断点续传/策略
│   │   └── src/{lib,identity,base32,protocol,server,client,op_client,policy,error}.rs
│   ├── rm-store/                # 备份存储（M4）：zstd 试压/压缩/解压、池布局、三档迁移
│   │   └── src/{lib,compress,pool,codes}.rs
│   ├── rm-backup/               # 备份流程（M4）：段式格式读写、占位加密、备份/校验/恢复
│   │   └── src/{lib,format,crypt,ops,codes}.rs
│   ├── rm-ai/                   # AI 编排（M5）：确定性提取、Provider 抽象、分级确认、隐私、预算
│   │   └── src/{lib,extract,provider,suggest,privacy,cost,cache,codes}.rs
│   ├── rm-classify/             # 规则引擎
│   │   └── src/{lib,rule,tag}.rs
│   └── rm-plugin/               # 插件壳：对接 ling 清单与 Plugin trait
│       └── src/{lib,methods,methods_m3,methods_m4,methods_m5,events}.rs
│
├── plugins/
│   └── resources-manager/
│       ├── plugin.toml          # ling 清单（格式见 ling/docs/04 §2）
│       └── src/
│           ├── lib.rs            # 入口：只做方法分发，保持薄
│           ├── api.rs            # 对外接口（供其他插件调用）
│           ├── jobs.rs           # 长任务编排（插件自管，内核无作业服务）
│           ├── stream.rs         # 流服务（03 §2.6 契约；M3+ 实现，契约已冻结）
│           └── commands/         # 每个用例一个文件
│               ├── scan.rs  browse.rs  dup.rs  verify.rs
│               ├── entry.rs  version.rs  relation.rs
│               ├── classify.rs  device.rs  sync.rs
│               ├── pool.rs       # 归纳/池管理（§7.9）
│               └── conflict.rs   # 同步冲突裁决（§7.5）
│
├── apps/
│   └── cli/{Cargo.toml, src/{main,client}.rs, src/cmd/*.rs}   # rmgr 命令行
│
├── web/                          # 本插件贡献的前端页面（三端共用一套代码）
│   ├── package.json, vite.config.ts, tsconfig.json
│   └── src/
│       ├── rpc/client.ts         # 接口调用封装（打 core-ui 的 /rpc）
│       ├── pages/{Browse,Duplicates,Entries,EntryDetail,
│       │          Classify,Devices,Sync,Conflicts,
│       │          Pools,Inbox,Suggestions,Settings}.tsx
│       └── components/           # 虚拟列表、进度条、目录树等
│
├── ts/plugin-sdk/                # 前端插件接口 + 自动生成的类型
│
├── docs/                         # 本套文档（5 份）
├── scripts/
│   └── package.sh                # M6 发行包组装（ling + 插件 + rmgr + 服务脚本）
├── packaging/                    # M6 服务注册与安装说明（随发行包分发）
│   ├── INSTALL.txt               # 三端安装说明
│   ├── systemd/resources-manager.service
│   └── windows/{install-service.ps1, uninstall-service.ps1}
└── tests/
    ├── integration/{e2e_flow.rs, sync_two_devices.rs, conflict_queue.rs}
    └── fixtures/
```

> **壳层归属**：窗口壳（Tauri 桌面）与安卓壳（前台服务 + SAF + 网页视图）归 **ling 仓库 `apps/`**——它们是"宿主的壳"，指向 core-ui 的回环端口（`04` §1 原约定）。本仓库 M6 交付**可组装的发行物**（`scripts/package.sh`）与**平台适配**（rm-fs Windows 长路径 / 安卓 SafRegistry 接口占位），不产 APK / Tauri 安装包。

**不在本仓库的东西**（拆分后归属）：

| 东西 | 归属 |
|---|---|
| `ling-kernel`、`ling-sdk`（宿主内核与插件开发包） | ling 仓库 |
| 内置插件（core-ui / core-settings / core-plugin-manager 默认安装；core-job / core-log 可选） | ling 仓库 `builtin-plugins/`（见 ling/docs/06） |
| 窗口壳（Tauri 桌面）、安卓壳（前台服务 + SAF 授权） | ling 仓库 `apps/`——它们是"宿主的壳"，指向 core-ui 的回环端口；设计后补进 ling/docs |
| `rmgr` 命令行 | 本仓库 `apps/cli`（业务命令） |
| `ling` 命令行 | ling 仓库（宿主管理命令） |

## 2. 谁能依赖谁（禁止反向）

```
rm-proto          （不依赖任何其他包）
   ↑
rm-fs             （只依赖平台接口）
rm-catalog        （依赖 proto）
rm-scan           （依赖 fs、catalog）
rm-dedup          （依赖 catalog）
rm-semantic       （依赖 catalog、proto）
rm-sync           （依赖 catalog、proto）
rm-transfer       （依赖 catalog、proto；另依赖 ed25519-dalek、sha2 —— 身份与签名，领域包中唯一持加密依赖者）
rm-store          （依赖 proto；另依赖 zstd —— 压缩/解压与池布局，不碰目录库）
rm-backup         （依赖 proto、store；另依赖 blake3 —— 段式备份读写与校验，不碰目录库）
rm-ai             （依赖 proto、catalog；另依赖 blake3 —— AI 编排：提取/Provider/分级确认/隐私/预算）
rm-classify       （依赖 catalog、semantic）

rm-plugin         （依赖 ling-sdk + 上述领域包；实现 ling 的 Plugin trait）
   ↑
apps/cli          （依赖 rm-plugin 或走网络接口，与插件调同一批 commands）
web/*             （只依赖 ts/plugin-sdk 生成的类型）
```

**规矩**：
1. 领域包之间**不得互相 import**。确实需要共享的逻辑，上提到它们共同依赖的那个包。
2. 领域包**不得依赖 `ling-sdk`**——保持纯代码库，可在命令行 `--standalone`、测试、插件里复用同一份。
3. 只有 `rm-plugin` 对接 ling（清单、Context、方法注册）。

## 3. 新增包的规矩

| 步骤 | 动作 |
|---|---|
| 1 | 先问：能不能塞进已有包？能塞就塞，不为"可能以后用"开新包 |
| 2 | 确实要开 → 包名 `rm-<领域>`，短横线，写进本文档 §1 目录树 |
| 3 | 在 §2 依赖图里写明它依赖谁、谁依赖它 |
| 4 | 遵守 `03-接口与协议.md` §6 代码规范（fmt/clippy/错误处理/入口薄） |
