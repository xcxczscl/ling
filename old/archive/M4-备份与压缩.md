## 范围（对照 `docs/01` §12.1 / §7.7 / §7.9）

- **段式备份**：`manifest.json` + `segments/%06d.seg`（128MB）+ `segments.idx`（JSON Lines）+ `CHECKSUM`（`docs/03` §5.3）
- **占位加密**：BLAKE3(key‖offset) XOR（§5.3.1，明示非真实保密）
- **zstd 阈值压缩**：前 1MB 试压，<95% 才值得；`compress.sample` / `compress.run`（auto/always/off）
- **池归纳/迁移/删除**：`pool.ingest` / `pool.move` / `pool.remove`（三档迁移、F804 回滚、F801 非空拒删）
- **schema V4**：`snapshot` 表 + 两索引
- **方法**：`backup.run|list|verify|restore`、`snapshot.list`、`compress.sample|run`、`pool.create|list|ingest|move|remove`
- **CLI**：`rmgr backup` / `snapshot` / `compress` / `pool`

## 关键决策 / 偏差登记（docs/01 附录 B #13、docs/04 §3）

1. **`pool.create` 实现新增**：03 §2.3 原表无创建入口，归纳/压缩测试无法建池；接口已补进 03。
2. **scattered 原地压缩**：`compress.run` 对 `mode=scattered` 放置做同路径 rename 替换；池内 managed 才走池布局迁移。
3. **部分失败标 failed**：归纳/压缩任一条失败 → 作业 `failed`（F804/F302），避免"done 但没做完"。
4. **WAL checkpoint**：`finish_job` 末尾 `PRAGMA wal_checkpoint(PASSIVE)`，保证外部连接（测试/工具）可见已提交写入。
5. **格式按冻结协议**：段式格式（§5.3）、占位加密（§5.3.1）、schema V4 无偏离；stats_json 固定 `{files, bytes, new_contents, segs}`。
6. **环回/临时目录**：无真多盘/真局域网 → 用 127.0.0.1 与临时目录模拟备份目标与池位置。
